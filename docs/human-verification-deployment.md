# 公网与公司用户：登录注册人机验证

## 两个提供商：本地图形点选（默认离线）与 Turnstile（可选）

人机验证由 `HumanVerificationProvider` 抽象，当前有两个实现，**按配置自动选择**，前端也按策略返回的 `provider` 字段切换渲染分支：

| 条件 | provider | 是否依赖外网 |
| --- | --- | --- |
| 未配置 Turnstile 密钥（默认本地开发） | `local` | **不依赖**：不加载任何第三方脚本 |
| `SMARTOPS_TURNSTILE_SITE_KEY` + `SECRET_KEY` + `HOSTNAMES` 三者齐备 | `turnstile` | 依赖 `challenges.cloudflare.com` |

`local` 的**两步握手**：

1. `GET /api/auth/human-verification?action=login|admin_login|register` —— 返回公开策略与会话挑战。除既有字段外新增 `prompt`、`targets`、`tolerance`、`scene`；`scene` 是服务端生成的完整 `<svg>`（viewBox 恒为 `0 0 300 200`）。
2. `POST /api/auth/human-verification/verify` —— 请求体 `{ "action", "nonce", "clicks": [ { "x", "y" }, … ] }`，坐标基于 viewBox。成功后返回一次性 `token`，再放进既有 `/api/auth/login`、`/api/auth/register` 的 `humanToken` 字段。

**答案从不下发**：正确图形坐标只保存在服务端内存，几何判定（容差 18 单位）在服务端完成；`scene` 里没有 `data-*`、没有目标标记、没有外部引用，前端只做注入渲染与坐标换算。

一次性语义：挑战 TTL 300 秒、用后即焚、每挑战最多 3 次作答、最小作答间隔 600 毫秒（`smartops.security.human-verification.min-response-ms`），同一图形被点两次不算多目标。会话 nonce 绑定、频率限制与「同一 IP/账号失败三次后强制验证」的升级语义与 Turnstile 分支完全一致。

**能力边界（如实说明）**：`local` 的场景是可解析的几何 SVG，脚本可以读结构并结合提示推断目标，最小作答时间也可用「渲染后等待」绕过。它的实际强度来自一次性挑战 + 会话绑定 + 次数上限 + 频率限制，属于**抬高成本**，不是强反机器人。需要更强防护时配置 Turnstile 密钥即自动切回，本地实现未被删除。

## 本期交付与尚未启用的部分

第一阶段代码已接入：注册及管理员入口强制验证；**普通用户层登录默认也要求验证**（`smartops.security.human-verification.always-require-login`，默认 `true`）。公司内网不豁免。原密码规则、CSRF、服务端角色授权、会话轮换及原有登录限制保持不变。

### 为什么用户层登录也默认验证

原先普通登录是"同一 IP/账号 15 分钟窗口内失败三次后才强制"，属于按风险触发。实际的体验问题有两个：

1. 正常用户第一次遇到验证时，验证框是**突然出现**的，容易以为是故障；
2. 用户层与管理员层行为不一致，同一套界面却有两套门槛。

因此改为默认每次登录都验证，两个入口行为对齐。若要恢复按风险触发，把开关设为 `false` 即可——此时代码退回"失败三次后强制"，该模式仍由 `HumanVerificationServiceTest` 覆盖。

### 用户层与管理员层是两个独立前端服务

切换入口不是改一个变量，而是**跨源跳转**：用户层 `127.0.0.1:5173`、管理员层 `127.0.0.1:5174`（见 `docs/layered-frontend-services.md`）。登录页的入口切换、管理员台的「返回用户层」都会整页跳到目标服务，并在登录页提示"将打开哪个地址、需在该入口重新登录"——因为会话 Cookie 按源隔离，跨端口本来就需要重新登录。

本地 dev 默认启用**本地图形点选**（离线可用），因此不再显示「未启用」的开发提示；可用 `SMARTOPS_HUMAN_VERIFICATION_ENABLED=false` 回到未启用状态。`local` 模式下 5173 用户层与 5174 管理员层共用同一后端与同一套策略。

**尚未验收**：真实公网站点、正式 Turnstile 密钥、目标网络连通性仍未接入，本地验证不等同公网验收。

本地运行接入已完成：后端已重新打包并通过项目脚本重启，健康状态为 UP，三个验证策略接口已从旧后端的 401 恢复为 200。当前配置检查确认未设置正式站点公钥、私钥及域名，保持开发模式，不填充测试密钥冒充正式接入。

## 上线配置

1. 在服务商控制台创建正式站点，登记实际登录域名；公司用户优先通过同一 HTTPS 域名访问。
2. 如果内部和公网使用不同域名，两者都要登记；内网浏览器必须能加载第三方验证组件，后端必须能访问验证接口。纯断网环境不适用当前适配器，不能通过关闭验证解决。
3. 通过部署平台密钥管理配置下列后端环境变量。不要把 Secret Key 发到聊天、提交 Git、写进前端或暴露在日志中。

```text
SPRING_PROFILES_ACTIVE=prod
SMARTOPS_HUMAN_VERIFICATION_ENABLED=true
SMARTOPS_TURNSTILE_SITE_KEY=<正式站点公钥>
SMARTOPS_TURNSTILE_SECRET_KEY=<正式站点私钥>
SMARTOPS_TURNSTILE_HOSTNAMES=ops.example.com,ops.internal.example.com
SMARTOPS_SECURE_COOKIE=true
```

域名配置必须是精确 hostname，不含 `https://`、端口或通配符。上例域名仅为占位符。保留原有生产数据库、凭据加密、管理员初始化等配置，不要使用开发默认值。

**必须显式设置 prod profile**：仓库原有 `application.yml` 默认 dev，不能把原开发启动命令直接用于公网。prod 与 dev/test 混用时也不允许禁用验证；正式环境拒绝已知形态的提供商测试密钥。缺少密钥/域名时策略返回不可用，认证提交返回 503，不自动放行。

本地需要联调正式服务时，设置以上三个 Turnstile 配置和 `SMARTOPS_HUMAN_VERIFICATION_ENABLED=true`，并为本地访问地址配置服务商允许的测试环境。测试密钥不得进入生产。

## 服务端校验与错误语义

- `GET /api/auth/human-verification?action=login|admin_login|register` 返回公开策略、站点公钥和会话挑战；`Cache-Control: no-store`，不包含私钥。策略读取不接受账号参数，避免公开账号风险状态。
- 登录/注册 JSON 新增 `humanToken`，仍必须附带原有 CSRF 头和同源会话 Cookie。
- HTTP 428：缺少、过期、重放、跨用途或跨会话验证；客户端重新取得策略和挑战。
- HTTP 429：触发请求限制；验证码不会清除请求次数。
- HTTP 503：配置不完整或验证服务不可用；客户端提供重试，不降级为通过。
- 验证提供商成功后，还需匹配精确 hostname、action、会话随机 cdata 和签发时间。服务端挑战最多存活 300 秒，验证前原子消费，因此并发请求也不能共用一个挑战。
- 普通免验证登录会原子预占账号和 IP 的在途额度；在途尝试也计入三次门槛，密码认证结束后释放。失败先累计再释放，避免并发批次越过门槛。
- 脚本加载 10 秒超时；后端连接 3 秒、读取 5 秒超时，不跟随重定向；验证失败日志不记录密码、令牌、私钥。
- 审计新增 `HUMAN_VERIFY` 类型，管理员审计页面可以筛选。429 不逐条写入数据库，避免防刷日志本身放大数据库压力。

## 限流和代理边界

新增请求上限为每个来源 60 次提交/分钟、全部来源 600 次提交/分钟；策略接口分别为 120/1200 次每分钟。原有更严格的账号、IP 登录/注册限流仍有效。公司共享出口用户较多时须结合实际流量调优，不宜直接取消限制。

**当前计数器与失败窗口为单 JVM 内存状态，重启会清空。** 公网上线必须在反向代理/WAF 处增加持久或独立于应用重启的入口限流。水平扩容前必须实现 Redis 等共享计数与挑战/会话状态，或使用统一网关加会话粘性并明确一致性边界；不能声称当前版本已实现分布式防刷。

应用目前使用 `request.getRemoteAddr()`，不自行信任任意 `X-Forwarded-For`。代理部署时需限制后端仅接受可信代理、剥离客户端伪造转发头，再配置容器的可信代理地址转换。否则所有用户可能被统计成同一个代理 IP，或配置错误导致伪造来源绕过限制。

公网流量必须走 HTTPS，并阻断绕过代理直达后端端口。API、会话与验证策略响应不得由 CDN 公共缓存。检查 CSP 至少允许所需验证脚本和框架来源；不要为方便验证放开任意来源。
