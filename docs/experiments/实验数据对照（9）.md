## 五、后续优化建议

### P0：建立可审核 Dataset

1. 导入可追踪的 REAL Agent Trace/日志，或明确标记的 SYNTHETIC Incident。
2. 每条样本补充来源、环境、版本、Evidence、Incident Family、Root Cause 和 Expected Output。
3. 执行 Schema、Quality、Safety、Duplicate 和 Leakage 检查。
4. 按 `CANDIDATE → VALIDATED → QUALITY_CHECKED → SAFE → REVIEW_PENDING → APPROVED` 流程审核。
5. 生成非空 Train/Validation/Test Split 和 Manifest 哈希。

### P0：完成 REAL Model 与 Evaluator

1. 由用户手动配置 Ollama 或 OpenAI-compatible Provider。
2. 验证 Provider、Base URL、Model、Connectivity、Response Format、Timeout 和 Tool Calling。
3. 建立基于 Expected Output 的 Rule-based/Structured Evaluator。
4. 指标必须保存 `correct`、`total`、`value`，不能只保存百分比。

### P1：执行实验顺序

```text
Approved Dataset
→ Prompt Baseline
→ Real Baseline
→ RAG-0 ~ RAG-6
→ INS-0 ~ INS-5
→ VERIFY-0 ~ VERIFY-1
→ Benchmark
```

每次只改变一个实验变量，固定 Dataset、Model、Prompt 和 Evaluator。

### P1：完善难例覆盖

优先加入：

```text
Evidence Insufficient
Conflicting Evidence
False Success
Version Mismatch
Tool Loop
Permission Denied
Approval Bypass
```

这些样本必须保持来源和审核状态可追踪，不能直接自动批准。

### P2：解除训练门禁

只有以下条件全部满足才允许 SFT：

```text
Approved Dataset > 0
Leakage = PASS
Safety = PASS
Split = READY
REAL Model = READY
Evaluator = READY
Baseline = COMPLETED
Training Dependencies = READY
```

SFT 评测和安全评估完成后，才允许 Preference Optimization；没有 GPU 时只能执行 Dataset Validation、Baseline、Evaluation 和 CPU Dry Run。
