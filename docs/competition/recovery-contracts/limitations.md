# 恢复契约已知限制与失效边界

## 1. 证据类型

| 类型 | 覆盖 | 不覆盖 |
|---|---|---|
| fixture（冻结样例） | 三值、窗口、回执、回放、oracle 对照 | 真实网络抖动、真实采集器 |
| loopback（`127.0.0.1`） | 真实 HTTP 采集、四场景、100 次回放 | 生产平台、跨主机、鉴权链 |
| real（真实平台） | **未执行（BLOCKED）** | — |

## 2. 机制限制

1. **离散采样**：通过只表示采样窗口内被支持，不表示两次采样之间持续健康。
2. **窗口参数冻结**：3 组、组内 ≤1250ms、首末 ≥4000ms、相邻 ≤4000ms、下一组启动 ≥前组+2000ms；未做生产 SLO 标定。
3. **证据年龄 15000ms**：超过即 STALE；生产取值未验证。
4. **预算**：单探针 1s、run 级 12 次、deadline 30s；仅证明机制可收敛，不是容量承诺。
5. **`expires_after` 未生效**（R-05）：无可信合同登记时间前，契约不会自动过期。
6. **来源身份**：V1 schema 无“来源身份是否已确认”字段；单来源组冲突在 oracle 与实现上仍存在 1/42 分歧。
7. **回执 TTL**：`receipt_ttl` 为冻结参数，生产取值 UNKNOWN。

## 3. 平台限制（BLOCKED）

1. N06 未接入：Run 权威、登录主体/scope、持久化与 `StateVerifier` 原始值未与恢复契约打通。
2. `/api/inspector/*` 写接口走内部 token，`X-Run-ID` 由请求头带入且未绑定主体（SEC-02）。
3. Java 构建受 JDK 版本与 Maven 环境限制，平台 E2E `NOT_RUN`。
4. 前端三张卡只有 fixture 数据，未做真实 API 与浏览器 E2E。

## 4. 评测限制

1. N08 为 42 个定向案例，不是概率抽样，无统计显著性。
2. oracle 与实现由同一协调者按同一规范编写，不是外部独立团队；一致率不等于准确率。
3. 三条弱基线是稻草人，假恢复率不能外推到真实系统。
4. 未做人为标注金标准；`expected_verdict` 来自样例标签与构造预期。

## 5. 安全与发布

1. SEC-01 聊天端点无鉴权、SEC-02 `X-Run-ID` 不绑定、SEC-03 MultiExec 自批、SEC-06 SSRF、SEC-07 admin 即 ROOT 均未修。
2. `jsonschema` 未安装，Schema 一致性 `NOT_RUN`，不得宣称已通过。
3. 未部署、未合并、未发布；本记录不构成上线许可。
