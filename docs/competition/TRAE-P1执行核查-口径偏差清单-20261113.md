## 2 值得肯定的两处「超额」，不是曲解

1. **canvas 降级通道**（`b3551ec` §2.3）：指出 ECharts 画在 canvas 上，CSS 的 `prefers-reduced-motion` 与降级选择器完全够不到，因此三处图表统一从 `useVisualMode().motionQuery` 取信号、`animation: !motionQuery?.matches`。**我方案 §6.1 的 G5 只写了 CSS 侧门禁，没覆盖这一层**，这是实质性补强。
2. **三个「会让功能失效」的缺陷自修**（`b3551ec` §3）：`Number(null)===0` 导致异步 KPI 永不滚动；`ml-stagger-cols-*` 引用不存在的 `ml-rise` keyframes 与未定义变量导致整条 shorthand IACVT 失效；`fill-mode:both` 吃掉 hover。其中第 3 条正是我 G3 明确警告过的坑，TRÆ 不仅避开还在新类上复现并修掉了。

另需**为 a11y 正名**：`271a406` 确实真修了侧栏对比度（`color-mix` 主文本色 88% + 取消 `.nav-coordinate` 透明度衰减，注释附实测失败值 1.01:1 / 3.47:1）；`3a84035` 让 axe 等有限次入场动画跑完再扫描，处理的是过渡帧假阳性。**两条都做了，不是靠改测试掩盖真实缺口**。

## 3 偏差清单（按严重度，交实现模型修）

### D1 · 严重｜评审版把「空置的视频槽」写成已实现的「封面动态壁纸」

- **表述**：`全站动效总览-评审版-20261113.md` §2 登录页行写「星尘漂移与闪烁、三层极光、流星、**封面动态壁纸（桌面+平衡视觉）**」。
- **事实**：`LoginView.vue:7` 的 `<video class="login-cover-video">` **只有 `:poster`，没有 `src`**；`fabdea5` 提交说明自己写得很清楚：「**无 src 时 opacity:0，放 mp4 后 CSS 自动淡入**」「架构：零体积」。`frontend/public` 下无任何 mp4 / webm / gif。即：**这是一个刻意预留、当前空置的槽位，实际显示静态 `starfield-placeholder.svg`**。
- **为什么是偏差**：参考库 §7 与方案 §0 明确「零媒体落盘、不下载平台素材」，TRÆ 的代码做法完全正确（不下载、留槽），**错在评审文档把预留槽说成了已交付效果**。评委若点名要看动态壁纸会当场落空。另外评审版 §0 自己说「这套前端不是『会动的壁纸』」，与 §2 自相矛盾。
- **修法**：§2 改为「封面视频槽（当前空置，显示静态 poster；预留合规素材接入位）」，或直接删掉该短语；演示动线 §4 第 1 步也不要指向它。

### D2 · 严重｜评审版沿用了我刚补正的 MLP+GRU 错标来源
