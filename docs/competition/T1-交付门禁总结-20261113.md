## 三、四个关键发现（直接影响后续包写法）

1. **旧规模口径作废**：Python 22,048 非空行 / 278 文件（非 16,536/244）；测试 622（pytest 收集）+ 503（前端），非 108；前端主体为 Vue 177 文件 22,569 行，旧 F02 只统计了 TS。
2. **M02 泛化短板是真实素材**：留出集召回 0.3333、uncertain 50%。技术报告 §8 局限必须写这条，只报开发集 1.0 即触红线②。
3. **M03 首字节口径陷阱**：首个 SSE `run` 事件 P50 仅 16.6ms，是框架事件而非模型输出。真实首 token P50 3589.6ms。任何材料引用时延必须用 first_token / total，并注明本机 CPU 推理。
4. **M04 双轨不一致**：`RiskClassifier` 只按工具名映射，把 docker.compose、docker.restart、redis.restart 三个 `approval_required=true` 的操作全判为 LOW。实际审批链读工具/manifest 声明（`agent/policies/policy_engine.py:23`），故定性为潜在风险而非已发生越权；它是"为什么必须保留人工审批双闸"的实证依据。
