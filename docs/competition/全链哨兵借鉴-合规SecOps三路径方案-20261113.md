## 0. 合规边界声明（必须先读，最高优先级）

用户要求「根据这个视频模式复刻」。经核实，该视频对应的 **全链哨兵 / Full-Chain Sentinel System（PCSS，知攻善防实验室，GitHub `zgsfsec/Full-Chain-Sentinel-System`）** 是一款**授权渗透测试 Agent 工作台**，覆盖 Web / 小程序 / App 三端，价值集中在**攻击侧**（侦察→枚举→漏洞映射→验证→利用→后渗透→报告，含反弹 shell、Frida 动态调试、Nuclei 打 nday、RCE 验证）。

**本方案明确拒绝复刻的部分（法律 + 安全边界）：**
- 不复刻「对任意目标自动攻击」的利用/后渗透引擎；
- 不产出可用于非法入侵的攻击载荷、RCE 链、反弹 shell 脚本、Frida 恶意 hook；
- 不把「全自动攻击 Agent」做成对未授权系统的侦察-攻击闭环。

**本方案明确借用的部分（完全合法，且恰好是 PCSS 最值钱的「治理层」）：**
- 以**资产/项目**为单位的隔离 + **范围白名单（scope allowlist）**；
- **三档执行模式**（审批 / AI 守门 / 自动）把「是否放行」做成旋钮；
- **证据链 + CVSS 定级 + 报告导出**（可交付性）；
- **全量审计**（JSONL 会话树、原始数据留证、人工复核时间线）；
- **多端资产（Web/App/小程序）统一纳管**的工作台形态。

**一句话定位**：把 PCSS 的「攻击 Agent」**反向改写为「安全态势与漏洞治理 Agent（SecOps）」**——只对你**自有或已获书面授权**的资产，做持续的漏洞扫描、合规基线检查、风险定级与修复建议。这既是 AIOps 的自然延伸（安全运维），又是传智杯评分里「AI 技术深度 35% + 实用性 10% + 创新性 25%」的高说服力亮点，且全程合法合规。

## 1. 全链哨兵（PCSS）架构拆解 — 哪些可借、哪些必弃

### 1.1 PCSS 实际构成（据公开资料）
| 层 | 能力 | 我们的处理 |
|---|---|---|
| 资产纳管层 | Web/小程序/App 三端资产登记 | ✅ 借：改造成「自有/授权资产台账」 |
| 编排调度层 | 多级 Agent 把任务拆给子 Agent | ✅ 借：复用 SmartOpsAgent 已有 6 角色分层流水线 |
| 执行引擎层 | Nuclei/Frida/反弹 shell/RCE 验证 | ❌ 弃：替换为**防御型扫描器** |
| 治理层 | scope allowlist + 三档执行模式 + 授权承诺勾选 | ✅ 借：核心合规旋钮 |
| 证据/审计层 | JSONL 会话树 + 原始数据包留证 + 人工复核 | ✅ 借：改成「扫描发现留证 + 修复复核」 |
| 报告层 | CVSS 定级 + 可导出去污报告 | ✅ 借：改成「风险报告 + 加固建议」 |

### 1.2 关键洞察
PCSS 真正值得学的不是「打得多狠」，而是它把**安全动作装进了治理笼子**：每步都要授权、每步可审计、每步有证据。这正是我们做 SecOps 该有的样子——**把「能力」换成「体检」，把「利用」换成「发现 + 建议」**。

## 2. 路径一：防御向 SecOps Agent（推荐，并入 SmartOpsAgent）

> 这是三条路径的主线，直接成为 SmartOpsAgent 的新能力模块，对接用户层巨改后的企业级控制台。

### 2.1 定位与目标
- **一句话**：把「全链路渗透测试 Agent」改写为「全链路安全态势治理 Agent」——为**自有/授权资产**做持续体检、合规打分、风险定级与智能修复建议。
- **目标用户**：企业运维/安全负责人（与 AIOps 主用户重合）。
- **禁止面**：任何非自有/非书面授权资产的扫描请求，一律拒绝并记录。

### 2.2 整体架构（借用治理层 + 替换引擎层）
```
┌──────────────────────────────────────────────────────────┐
│  用户层（企业级控制台 / Bento 首页新增「安全态势」入口）        │
├──────────────────────────────────────────────────────────┤
│  SecOps 治理层（继承 PCSS）                                  │
│   · 资产台账 + scope allowlist（白名单强制）                 │
│   · 三档执行模式：审批 / AI守门 / 自动（仅已授权资产）         │
│   · 授权承诺书（首次进入必须勾选，存证）                      │
├──────────────────────────────────────────────────────────┤
│  SecOps 编排层（复用 SmartOpsAgent 6 角色流水线）            │
│   Planner → Executor → Inspector + policies/kernel/tools    │
├──────────────────────────────────────────────────────────┤
│  防御型执行引擎（替换 PCSS 攻击引擎，全部对接本地/授权）       │
│   · Web：OWASP ZAP（safe/被动模式）/ nuclei safe 模板        │
│   · App：MobSF 静态分析（本地）/ 依赖 CVE（OSV/Trivy）        │
│   · 小程序：配置文件/权限/域名合规审查                        │
│   · 合规基线：等保2.0 检查项、SSL/TLS 配置、依赖漏洞           │
├──────────────────────────────────────────────────────────┤
│  证据/审计层（继承 PCSS）                                    │
│   · 发现项留证（时间/工具/证据/置信度）                       │
│   · CVSS 定级 + 修复建议（RAG 检索加固手册）                  │
│   · 修复复核时间线（人工确认闭环）                            │
└──────────────────────────────────────────────────────────┘
```

### 2.3 核心模块设计
1. **资产纳管（Web/App/小程序）**：登记资产 URL / 包名 / 小程序 AppID，必须与 scope allowlist 匹配；非白名单资产请求直接拦截。
2. **扫描编排**：Planner 把「体检任务」拆为子项（端口/Web 漏洞/依赖/配置/合规），Executor 调用对应本地工具，Inspector 校验发现可信度。
3. **合规基线**：内置等保 2.0 二级/三级常用检查项、SSL Labs 式 TLS 评估、依赖 CVE 比对（OSV API / Trivy）。
4. **风险定级**：CVSS 3.1 向量计算 + 业务影响加权；输出风险矩阵（高/中/低）。
5. **智能修复建议**：RAG 检索内部加固手册 + 公开 CIS 基准，生成「针对该发现的可执行修复步骤」。
6. **证据链与报告**：每发现项带「发现时间/工具/原始证据/置信度/复核人」；一键导出 PDF 风险报告（去敏）。

### 2.4 三档执行模式（直接复用 PCSS 治理旋钮）
| 模式 | 行为 | 适用 |
|---|---|---|
| 审批模式 | 每个扫描动作需人工点「放行」 | 生产资产、首次扫描 |
| AI 守门模式 | Agent 自判风险，仅高危动作需确认 | 日常巡检 |
| 自动模式 | 仅对已授权低危项自动执行 | 内网沙箱/靶场 |

### 2.5 UI 设计（与用户层巨改统一语言）
- 企业级分层风格（surface 三档明度 + hairline + 极柔阴影，见 `前端企业级彻底重构方案-20261113.md`）。
- 首页 Bento 新增「安全态势」卡片：资产健康分、高危项数、合规通过率。
- 三视图：① 资产总览（KPI 网格 + tag chip）② 风险清单（CVSS 色阶 + 证据抽屉）③ 修复时间线（复核流）。
- AI 交互：用「自然语言体检简报」承载（命中 AI 交互体验 3%）。

### 2.6 评分对齐
- **AI 技术深度 35%**：Agent 编排（已有）+ RAG 加固手册检索 + 风险推理，活证据。
- **实用性 10%**：真实能给自有资产做体检、出报告。
- **创新性 25%**：把「攻击 Agent」反向成「治理 Agent」的方法论叙事。
- **工程质量 10% / 用户体验 10%**：复用 T11 已达标基线。

### 2.7 工作包（交其他模型）
- **T26** SecOps 数据模型 + scope allowlist 中间件（门禁：非白名单拦截单测）。
- **T27** 防御型执行引擎接入（ZAP/nuclei-safe/MobSF/Trivy/OSV 本地调用封装）。
- **T28** 风险定级 + RAG 修复建议 + 报告导出（门禁：CVSS 计算单测 + 报告样例）。
- **T29** 用户层安全态势三视图 UI（复用企业级重构令牌）。

## 3. 路径二：PCSS 架构可借鉴性研究文档（纯研究，不落地攻击）

> 用途：作为竞赛答辩/技术文档的「方法论参考」素材，证明我们**懂攻防但对齐合规**。

### 3.1 研究大纲（md，可独立成 `docs/competition/PCSS架构借鉴研究.md`）
1. PCSS 定位与开源现状（知攻善防实验室，Pi agent harness）。
2. 攻击侧能力清单（仅描述，不复现）：侦察→枚举→映射→验证→利用→后渗透。
3. **可借鉴治理架构**提取：scope allowlist、三档模式、证据链、CVSS、审计。
4. **攻击→防御映射表**：每一项攻击能力对应一个合法防御能力（见下表）。
5. 我们的合规改造原则（授权优先、最小权限、留证、可复核）。
6. 对 SmartOpsAgent 的增量设计（即路径一浓缩版）。

### 3.2 攻击 → 防御 映射表（核心，证明「可借鉴不可滥用」）
| PCSS 攻击能力 | 合法防御等价 | 工具/方法 |
|---|---|---|
| 侦察/资产发现 | 资产台账登记（白名单内） | 手动登记 + 允许清单 |
| 漏洞枚举 | 漏洞扫描（被动/安全模式） | OWASP ZAP passive、nuclei safe |
| 配置/暴露面发现 | 合规基线检查 | 等保2.0 项、SSL 评估 |
| 依赖漏洞 | 依赖 CVE 比对 | Trivy、OSV |
| 移动端动态分析 | 静态分析（本地） | MobSF（自有权包） |
| 证据链/报告 | 风险报告 + 修复建议 | CVSS + RAG 加固手册 |
| 后渗透/利用 | ——（明确不做） | 删除 |

### 3.3 交付物
- 研究 md 一篇（不进代码）。
- 答辩用 1 页「合规对齐说明」图（治理旋钮对比）。

## 4. 路径三：授权靶场演示方案（自建军/授权环境，仅方法论展示）

> 用途：竞赛演示「我们如何用 Agent 编排做安全治理」，**全程不对外网做任何真实攻击**。

### 4.1 靶场搭建（仅本地 Docker，零外发）
- 本地拉起授权漏洞练习靶机：**Juice Shop（OWASP）、DVWA、WebGoat**，全部运行在 `127.0.0.1` 隔离网段。
- 小程序/App 端用**自写 Demo 包**（含故意弱配置）作为「自有资产」样例。
- 明确标注：靶场仅用于演示方法论，与真实攻击无关。

### 4.2 演示流（编排 + 证据链可视化）
1. 进入 SecOps 工作台 → 勾选授权承诺书（存证）。
2. 添加靶机为「自有资产」（命中白名单）。
3. 选「AI 守门模式」→ Planner 自动拆体检任务。
4. 实时展示：发现项卡片（CVSS 色阶）+ 证据抽屉（原始响应/工具名/时间）。
5. 生成风险矩阵 + 一键导出 PDF 报告。
6. 强调「若这是真实资产，下一步是人工复核修复」——闭环治理叙事。

### 4.3 证据链可视化 UI（复用企业级重构）
- 会话树（JSONL 式）：每个节点 = 一次体检动作 + 结果 + 置信度。
- 时间线：发现 → 定级 → 建议 → 复核（人工确认）。
- 全程不展示任何 payload/利用细节，只展示「发现 + 证据 + 建议」。

### 4.4 工作包（交其他模型）
- **T30** 本地靶场 docker-compose（Juice Shop/DVWA，仅 localhost）。
- **T31** 证据链可视化组件（会话树 + 时间线，复用令牌）。

## 5. 三路径整合与优先级（省赛 5 天 vs 国赛 12 月）

| 路径 | 价值 | 工作量 | 建议时机 |
|---|---|---|---|
| 路径一 SecOps Agent | 最高（AI深度+实用性+创新） | 大（需接扫描器） | **国赛前**（12 月）做深；省赛可放「轻量版：仅资产台账+合规基线+报告」 |
| 路径二 架构研究 | 中（答辩素材） | 小（写 md） | **省赛前**即可完成，低成本高回报 |
| 路径三 靶场演示 | 中（展示方法论） | 中（Docker+UI） | **国赛答辩**现场演示用 |

**省赛（11-18 截止，仅 5 天）优先级建议**：
1. 先保四件套（仓库公开/文档/视频/在线演示）—— 见 `传智杯AI-WEB打进国赛-完整准备体系`。
2. 路径二研究 md（低成本，直接进技术文档）。
3. 路径一**只做轻量版**（资产台账 + 合规基线检查 + 报告导出，不接重型扫描器），作为「AI 能力延伸」展示。
4. 用户层巨改（企业级重构）与 SecOps UI 复用同一套令牌，避免重复。
