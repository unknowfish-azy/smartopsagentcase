## 0. 结论 + 分工边界

**方向可以做，但要换一种做法**：不要搬那个视频的「炫」，要借它的「动」。核心主张 ——

> **让每一束光都对应一条真实纠察事件。动画不是装饰，是证据链的可视化。**

这样既拿到你要的视觉冲击，又同时命中传智杯的 **AI 技术深度 35%**（Agent 四级纠察可验证）+ **实用性 10%** + **诚实克制**，还不会砸掉 T11 的 Lighthouse 92/95 基线。

## 1. 红框三项定位与「单调」的真实根因

侧栏配置：`frontend/src/navigation/personalSystemNavigation.js:88-102`，分组 `MEMORY / 运维记忆` 下前三项为红框内容：

| 菜单 | 路由 | 页面文件 | 现状 |
|---|---|---|---|
| INSPECTOR DESK / 洞察台 | `/inspector/desk` | `InspectorDeskView.vue` | **已成熟**：同一条时间轴三种投影（events/stats/runs）、时间窗、等级/工具筛选、证据抽屉、DEMO 开关 |
| INSPECTOR CENTER / 纠察中心 | `/inspector` | `InspectorCenterView.vue` | **最单调**：全文件仅 8 行 |
| STATISTICS / 统计 | `/inspector/statistics` | `InspectorStatisticsView.vue` | 用了 `--smart-*` 令牌，但统计是**纯文字 `<p>` 列表** |

### 五个根因（按影响排序）

1. **数据全是 0** —— 截图里 `Total/PASS/WARN/HIGH/CRITICAL` 全 0、`Inspection Timeline` 显示「暂无真实纠察事件」。**再炫的动画盖在空数据上还是空的**，这正是你要接后端/数据库的原因。
2. **8 个维度只是纯文字标签** —— `Agent Behavior / Evidence Quality / Tool Usage / Risk / Approval / Verification / Knowledge / Security` 是 `dimensions` 数组渲染的 `<span>`，**没有数据绑定、没有状态、没有图表、没有交互**。
3. **Timeline 不是时间轴** —— `InspectorTimeline.vue` 只是一个 `<button>` 列表，无时间刻度、无等级轨道、无事件流。
4. **配色是孤岛** —— 纠察中心仍用琥珀金 `#e7c56d / #302610 / #241e0e`，与全站深蓝青绿（`--smart-bg #040B16` / `--smart-primary-strong #7AD7F5`）**完全不统一**，是 T18 令牌重构的漏网之页。
5. **零动效** —— 该页类名 `.page / .panel / .dimensions` 不在 `motion-layer.css` 的自动挂载选择器里，也没挂任何 `ml-*` 类。

> **重要判断**：洞察台已经把「事件时间轴 + 三种投影」做出来了。**不要重复造轮子**，正确做法是把它的可视化能力**反哺**到中心页和统计页，三页共用一条证据链。

## 2. 小红书取证（这次拿到正文了，但结论和直觉相反）

WebFetch 回源成功，笔记标题《19岁日本学生用Claude Code，48小时写了个套利机器人》，正文与评论区要点：

- 内容是**质疑/辟谣**：本金 68 美元→首晚 6732→累计 75 万，**无实名、钱包、交易记录验证**，X 上大量一模一样的复制帖，多为引流；结尾注明「仅为网络信息分享，不构成投资建议」。
- 评论区对**视觉**的原话：「**动画做的不错，话术差了点**」「主打一个编，直接写了一个程序**地球爆炸**了多抓眼球」「一个真正的交易系统讲究效率…**不会有这样大量的无意义的渲染浪费资源**」。
- 外网交叉印证（Economic Times / NDTV Profit / X 原帖镜像）：收益数字**未经独立验证**；X 用户 @NyykaVevo 直指 **「not even an app, it's an AI generated video, un readable text made to seem complex but isn't」** —— 即那段"界面"根本不是真实应用，是 AI 生成的营销视频，文字故意不可读。

### 这意味着什么（必须说清）

你想借的「可视感」= **大规模粒子/球体/流线 + 高速运动 + 看起来很复杂**。但它的公认短板恰好是：**不可读、无信息含义、纯渲染消耗**。

把它原样搬进「AI 纠察中心」会有三个硬伤：
1. 评委点开任何一个光点问「这是什么」，答不上来 → 反而削弱「可验证」叙事；
2. 视频/动图版权不归我们，竞赛公开展示 + 仓库开源 + 答辩录屏构成传播行为（沿用前几轮的版权裁决）；
3. 大视频/重粒子会砸掉 T11 性能基线（Lighthouse 桌面 92 / 移动 95、`blur=0`、四重降级门禁）。

**所以：借「动态语言」，不借「假界面」；用自制 CSS/Canvas/SVG 复刻，零媒体落盘。**

## 3. 核心设计主张：动态 = 证据，不是壁纸

把营销视频的三种视觉手法，逐一改写成**绑定真实数据**的等价物：

| 营销视频手法 | 改写后（数据驱动） | 每个视觉元素代表 |
|---|---|---|
| 满屏漂浮粒子 | **事件粒子流**：粒子沿时间轴从左向右漂移 | 1 个粒子 = 1 条 `/api/inspector/events` 真实纠察事件 |
| 发光球体/地球 | **证据链拓扑球**：中心是 Agent，外圈是工具/知识/验证节点 | 1 个节点 = 1 个真实工具调用或证据源 |
| 高速光带扫过 | **状态传导光带**：Planner→Executor→Inspector 四步链逐段点亮 | 1 段光 = 1 个真实推理步骤的状态 |
| 不可读的"复杂文字" | **可读的等级色阶 + 时间戳 + 可点击证据抽屉** | 点开能看到 `severity / category / traceId / 证据` |

**为什么这比营销视频更拿分**：传智杯 AI 技术深度 35% 看的是 Agent/RAG/纠察「能不能被验证」。当评委点一个光点就能看到一条真实纠察记录与证据链时，动效就从「好看」变成了「**AI 能力活证据**」，同时不违反诚实克制。

## 4. 视觉设计语言（先把孤岛拉回企业级）

### 4.1 令牌统一（P0，最高优先）
- 废弃琥珀金，改用 `--smart-*` / `--ds-*` 企业级令牌：底 `#040B16`、surface 三档、hairline、青蓝 `#7AD7F5` 为唯一 accent。
- **等级色沿用运维语义**：PASS 青绿、WARN 琥珀、HIGH 橙、CRITICAL 红；**不套股票红涨绿跌**（项目既有裁决）。
- 层次靠 surface 明度步进 + 极柔阴影，**不用 `backdrop-filter`**（T11 G3 `blur=0`）。

### 4.2 中心页布局重构
```
┌────────────────────────────────────────────────────────┐
│ 页头：SmartOps Inspector · 实时状态灯 · 时间窗 · 刷新     │
├──────────────┬─────────────────────────────────────────┤
│ KPI 带 5 卡   │  AI 情境简报（自然语言，只基于真实摘要）   │
│ (数字滚动)    │  「近 24h 12 条纠察，2 条 HIGH…」          │
├──────────────┴─────────────────────────────────────────┤
│ 8 维能力矩阵：从文字标签 → 2×4 状态卡                    │
│ 每卡 = 维度名 + 真实计数 + 迷你 sparkline + 等级条        │
│ 点击 → 筛选下方事件流                                    │
├────────────────────────────────────────────────────────┤
│ ★ 事件粒子时间轴（主视觉，占 40% 高度）                  │
│ 横向时间刻度 + 4 条等级轨道 + 粒子按 createdAt 落位       │
│ 粒子颜色=severity，大小=关联证据数，点击=证据抽屉          │
├────────────────────────────────────────────────────────┤
│ 证据抽屉：选中事件的 category / target / traceId / 证据   │
└────────────────────────────────────────────────────────┘
```

### 4.3 三页一致性
- **洞察台**：保留现有三投影，只补「粒子层」与配色同步；它是三页的**证据源**。
- **统计页**：纯文字 `<p>` → 分布环图 + 目标热力条 + 时间趋势（复用已有 `OpsChart` / ECharts，走 `motionQuery` 降级）。
- **中心页**：上述重构，并加「在洞察台打开 / 查看统计」深链保持不变。

## 6. 数据契约（给你接后端 / 数据库用）★

前端现有接口 `frontend/src/api/inspector.ts`：
```
GET  /api/inspector/summary
GET  /api/inspector/events?limit=50
GET  /api/inspector/events/:id
GET  /api/inspector/statistics
POST /api/inspector/check | /verify | /replan
```

**建议数据库表与字段**（前端 `deskModel.js:44-79` 已按此归一化，直接对齐即可）：

| 表 | 字段 | 类型 | 用途 |
|---|---|---|---|
| `inspection_events` | `id` | PK | 事件唯一标识（必需） |
| | `createdAt` | ISO / epoch | 粒子在时间轴上的 X 坐标 |
| | `severity` | `PASS/WARN/HIGH/CRITICAL` | 粒子颜色与轨道 |
| | `taskId` / `task` | string | 列表标题 |
| | `category` | string | 8 维能力矩阵分组 |
| | `target` | string | 统计页 By Target |
| | `traceId` | string | **关键**：与运行记录关联，支撑证据链 |
| | `reason` / `recommendation` | text | 证据抽屉内容 |
| `operation_runs` | `id, toolId, startedAt, endedAt, status, traceId, exitCode, commandCount, failedCommandCount` | — | 三投影的 runs 视图 |
| `inspection_summary` | `total, pass, warning, high, critical` | int | KPI 带 |

**三个状态必须区分**（红线，见 §9）：
- `ready`（有真实数据）→ 粒子流按真实事件渲染；
- `unavailable`（后端未接 / 未登录）→ 显示「巡检接口不可用」，**不画假粒子**；
- `demo`（演示）→ 用 `InspectorDeskView` 已有的确定性合成序列，**必须显著标注「DEMO · 虚构示例，非真实纠察」**。

> `statistics` 建议返回 `{ summary, byCategory:[{category,count}], byTarget:[{target,count}] }`；洞察台的窗口聚合在前端分箱，接口只给全量，别在后端重复算。

## 7. 空态 / 演示态策略（省赛 4 天内的现实解）

后端还没接上时，主界面不能是一片 0。三档做法，**都不伪造真实数值**：

1. **结构占位态**：只显示时间刻度、4 条空轨道、8 维卡片的骨架与流光，中央写「等待真实纠察事件接入」——有动态感、零假数据。
2. **DEMO 态**：复用洞察台的 `demo` 开关，标注必须醒目；演示视频里可明确说「这是确定性合成示例，用于展示可视化能力」。
3. **真实态**：你接完后端后自动切换，粒子按真实 `createdAt/severity/traceId` 渲染。
