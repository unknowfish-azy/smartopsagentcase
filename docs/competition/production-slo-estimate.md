# 智维Agent · 生产环境 SLO 预估报告

> 报告日期：2026-11-20  
> 报告性质：**ESTIMATED / 条件估算，非生产实测**  
> 适用范围：生产容量规划、灰度验收设计与错误预算测算  
> 禁用方式：不得将本文预估值写成生产 SLA 承诺、生产实测成绩或真实模型准确率

## 0. 管理层摘要

1. **当前只能给出条件预估，建议“小流量灰度验证”，不建议直接承诺全量生产 SLO 达标。** 尚未读取生产 Prometheus 窗口数据，也未取得生产 `/api/observability/slo` 事实表结果，生产状态统一视为 `NO_DATA / NOT_RUN`。
2. 在本报告设定的**基准档**假设下，平台 × 模型 × 知识三段串行链路的执行成功率预估为 **99.10%**，高于 99% 目标，但仅剩 **10.23%** 错误预算，按现有规则为 `WARNING`；再增加一个必需工具后降至 **98.61%**，错误预算耗尽。
3. 只有在**高档（优化）**假设下，三段和四段链路才分别预估为 **99.65% / 99.45%**，并保留 **65.03% / 45.10%** 错误预算。该结论完全依赖假设，必须由生产流量验证。
4. M03 真实 LLM/RAG 流式链路实测仅覆盖**本机 CPU、qwen3:1.7b、顺序请求、n=20**。基准档估算首 token P95 为 **3.57s**、流式完成 P95 为 **6.77s**；这是容量模型输出，不是生产分位数。
5. 建议新增 Agent 体验目标：**首 token P95 ≤ 4s、流式完成 P95 ≤ 8s**。这两个目标目前只是规划建议，并非平台已生效 SLO；P99 先观测，不在 n=20 基础上设生产承诺。

## 2. 沿用平台 SLO 的正式口径

| SLI | 目标 | 当前实现口径 | 数据来源 | 最小显示样本 |
|---|---:|---|---|---:|
| HTTP 可用率 | **99.5%** | 非 5xx 请求数 / 全部请求数 | Micrometer → Prometheus | 由 Prometheus 表达式处理 |
| HTTP 延迟 | **P95 ≤ 1s** | `http_server_requests_seconds` 的 5m P95 | Micrometer → Prometheus | 同上 |
| 执行成功率 | **99%** | 窗口内已结束且 `status='SUCCEEDED'` 的运行 / 全部已结束运行；进行中记录不入分母 | `operation_run_record` | 20 |
| 采集新鲜度 | **95%** | 新鲜启用任务 / 全部启用任务；允许阈值为 `max(2×interval_sec,60s)`，从未采集按不新鲜计 | `sentinel_task` | 5 |
| 恢复核验率 | **95%** | `VERIFIED + ACTIVE + valid_until > now` 回执 / 窗口内全部核验回执 | `recovery_receipt_record` | 5 |

口径注意：

- 零分母必须为 `null / NO_DATA`，不能写成 0 或达标；低于最小显示样本为 `DEGRADED / INSUFFICIENT`。
- 采集新鲜度当前是**评估时刻的任务快照**，不是窗口内时间加权可用率；`windowHours` 不会改变其历史覆盖范围。
- HTTP 规则当前未按路由拆分。若流式请求以完整响应耗时进入同一指标，且其流量足以影响总体 P95，则可能与 1s 目标冲突；上线前必须核实 Micrometer 对流式响应的计时语义，并拆分普通同步 API 与流式/长任务 API。
- `operation_run_record` 是否覆盖所有 Agent 问答与工具链请求尚需核实。本文三段/四段链路只有在对应请求进入该事实表时，才可沿用 `execution_success` 作为正式 SLI。
- 最小显示样本只用于避免小样本被展示为稳定结论，**不等于统计验收样本量**。

## 3. 预估模型与假设

### 3.1 可用率和错误预算

对目标 `O`、预估值 `S`：

```text
实际错误率 E = 1 - S
错误预算 B = 1 - O
燃烧率 burn_rate = E / B
剩余预算比例 remaining = (B - E) / B
```

规划判定沿用业务 SLO 规则：`remaining < 0` 为 `EXHAUSTED`；`0 ≤ remaining ≤ 20%` 为 `WARNING`；其余为 `OK`。HTTP 行也使用相同公式做规划比较，不代表 Java 服务新增了对 HTTP 的状态计算。

对每次请求都必须经过的串行依赖，采用独立故障简化模型：

```text
S_chat = A_platform × A_model × A_knowledge
S_toolchain = S_chat × A_tool
```

该模型要求模型、知识检索和工具可用性已经包含各自的超时、重试后最终结果，不能重复扣减。依赖故障相关、共用基础设施或级联重试会使实际结果偏离该模型；降级或容错路径可能改善结果，但必须另建分支模型并实测。

### 3.2 时延模型

以 M03 实测分位数为基准，采用“比例缩放 + 固定附加开销”的情景模型：

```text
L_scenario,p = k_scenario × L_M03,p + O_scenario,p
p ∈ {P50, P95, P99}
```

- `k`：生产模型服务、硬件与并发排队相对本机 CPU 基准的综合倍率。
- `O`：Java 边缘、认证签发、生产网络及未覆盖调度的附加开销。
- M03 已包含 knowledge 与 ai-service 链路，`k` 不是额外的 RAG 固定耗时，避免重复计算。
- 该公式用于敏感性分析。真实 P95/P99 必须由同一批生产端到端请求分别计算，不能把不同请求的独立分位数直接相加当作实测值。

### 3.3 三档规划输入（全部为假设，不是实测）

| 假设项 | 低档（保守） | 基准档 | 高档（优化） |
|---|---:|---:|---:|
| HTTP 非 5xx 比例 `S_http` | 99.70% | 99.90% | 99.95% |
| 执行链平台环节 `A_platform` | 99.70% | 99.90% | 99.95% |
| 模型最终成功概率 `A_model` | 98.50% | 99.50% | 99.80% |
| 知识链路成功概率 `A_knowledge` | 99.00% | 99.70% | 99.90% |
| 单个必需工具成功概率 `A_tool` | 98.00% | 99.50% | 99.80% |
| 启用任务新鲜比例 | 94.00% | 97.00% | 99.00% |
| 有效恢复回执比例 | 90.00% | 96.00% | 99.00% |
| 时延综合倍率 `k` | 1.20 | 0.70 | 0.40 |

### 4.1 可用率、成功率与错误预算

下表单元格格式为：**预估值；燃烧率；剩余预算；条件判定**。所有数值均为模型输出，不是生产观测值。

| SLI / 链路 | 目标 | 低档（保守） | 基准档 | 高档（优化） |
|---|---:|---|---|---|
| HTTP 可用率 | 99.5% | 99.70%；0.60x；40.00%；OK | 99.90%；0.20x；80.00%；OK | 99.95%；0.10x；90.00%；OK |
| 三段执行链：平台 × 模型 × 知识 | 99% | 97.22%；2.778x；耗尽；EXHAUSTED | 99.10%；0.898x；10.23%；WARNING | 99.65%；0.350x；65.03%；OK |
| 四段执行链：三段链 × 一个必需工具 | 99% | 95.28%；4.722x；耗尽；EXHAUSTED | 98.61%；1.393x；耗尽；EXHAUSTED | 99.45%；0.549x；45.10%；OK |
| 采集新鲜度 | 95% | 94.00%；1.20x；耗尽；EXHAUSTED | 97.00%；0.60x；40.00%；OK | 99.00%；0.20x；80.00%；OK |
| 恢复核验率 | 95% | 90.00%；2.00x；耗尽；EXHAUSTED | 96.00%；0.80x；20.00%；WARNING | 99.00%；0.20x；80.00%；OK |

错误预算的直观量级：

| 目标 | 允许错误量 | 说明 |
|---|---:|---|
| HTTP 99.5% | 每 100 万请求最多 5,000 个 5xx | 请求口径，不能直接换算成停机分钟 |
| 执行成功率 99% | 每 10,000 个已结束运行最多 100 个失败 | 仍在运行的记录不进入当前分母 |
| 采集新鲜度 95% | 每 100 个启用任务最多 5 个不新鲜 | 当前实现为快照口径 |
| 恢复核验率 95% | 每 100 个回执最多 5 个非有效回执 | 过期、非 ACTIVE、非 VERIFIED 均不计为有效 |

串行依赖的反推要求：若三段环节可靠性相同，要达到总体 99%，每段至少约 **99.6656%**；若四段环节相同，每段至少约 **99.7491%**。因此，“单个依赖达到 99%”并不足以支撑端到端 99%。

与建议体验目标比较：

## 5. 关键未知项与风险

1. **生产事实数据缺失**：请求量、并发、路由占比、5xx、运行状态、真实任务新鲜度、恢复回执和依赖可用性均未知。
2. **SLI 覆盖未知**：需确认 Agent 问答、ReAct、DAG 和工具重试是否完整写入 `operation_run_record`，以及一次用户请求对应多少条运行记录。
3. **模型与硬件未知**：生产模型版本、量化方式、GPU/CPU、批处理、上下文长度、输出长度和并发策略均未给定；时延倍率只能作为假设。
4. **尾部风险未量化**：n=20 顺序请求不足以支撑生产 P95/P99，尤其 P99 主要受少量尾部样本影响。
5. **故障相关性未量化**：模型、知识库、数据库和工具可能共享网络或基础设施，独立假设可能偏乐观；重试风暴和队列积压可能进一步放大尾延迟。
6. **HTTP 聚合口径风险**：普通 API 与流式/长任务混在同一 P95 中会导致目标失真，需先拆分再验收。
7. **成功率不等于回答质量**：执行成功、HTTP 非 5xx 和场景契约通过均不证明模型回答正确；真实准确性需要独立质量评测。
8. **回归遗留项**：前序全量 Agent 回归记录为 **391 passed / 1 failed**，失败项为 DAG 并发墙钟阈值断言，尚未定位修复。该结果不纳入 SLO 计算，但不得宣称全量测试全绿。

## 6. 生产灰度验收方案

### 6.1 先补齐观测

1. 为每次用户请求贯通 `trace_id`，记录请求接收、首 token、完成、模型、知识、工具、重试、排队和 Java 边缘耗时。
2. 按路由拆分 HTTP 可用率和时延，至少区分普通同步 API、流式问答和长任务执行；保留总体指标用于平台概览。
3. 核实所有目标请求是否进入业务事实表，并固定一次用户请求与运行记录的映射口径。
4. 在生产或准生产环境读取 24h 与 168h 窗口；零分母保持 `NO_DATA`，不得用离线故障注入结果填充。
5. 保留现有 HTTP 快烧告警（1h >14.4x，持续 2m）和慢烧告警（6h >6x，持续 30m），灰度期间同时观察业务 SLO 的燃烧率与剩余预算。

只读业务接口：

```http
GET /api/observability/slo?windowHours=24
GET /api/observability/slo?windowHours=168
```

### 6.2 用生产等价负载替换假设

- 固定生产模型、硬件、上下文与输出长度分布，分别复现低、基准、高三档并发和流量配比。
- 同批请求采集首 token、完成时延和最终状态，再计算 P50/P95/P99；不得跨批次拼接分位数。
- 分别验收无工具问答、单工具链、多工具 DAG、依赖失败、超时、重试耗尽和恢复链路。
- 工具链按实际必需依赖数展开模型；可选工具或降级成功路径单独统计，不能直接套用四段公式。

### 6.3 样本量参考

若采用“零失败、单侧 95% 置信下界达到目标”的严格参考，所需最小样本为：

```text
n ≥ ln(1 - 0.95) / ln(SLO目标)
```

| SLO 目标 | 零失败参考样本量 |
|---|---:|
| 95% | 59 |
| 99% | 299 |
| 99.5% | 598 |

这只是零失败情形的统计参考，不是建议用少量全成功样本替代长期窗口。生产验收仍应覆盖完整业务周期、峰值和真实失败分布；现有 20/5/5 最小显示样本不能替代上述验证。

### 6.4 建议发布门禁

- 数据门禁：目标 SLI 无 `NO_DATA / DEGRADED`，数据来源、窗口、分子、分母可复核。
- 错误预算门禁：正式承诺前，核心 SLI 在 24h 与 168h 窗口均达到目标，且剩余预算大于 20%，避免以 `WARNING` 状态签稳定承诺。
- 时延门禁：普通 HTTP API 与流式 Agent 分路由达标；Agent 建议目标为首 token P95 ≤4s、完成 P95 ≤8s，同时报告 P99 和样本量。
- 依赖门禁：四段及更多必需工具链必须单独达到端到端 99%，不能只看单工具或平台成功率。
- 恢复门禁：恢复只接受有效 `VERIFIED + ACTIVE + 未过期` 回执，告警关闭不能替代业务恢复证据。
- 工程门禁：遗留回归失败须修复或形成明确风险裁决，不得隐去失败记录。

## 7. 最终建议

**建议采用“基准档作为灰度容量目标、低档作为压力风险边界、高档作为优化方向”的策略。** 当前基准档三段链虽然条件预估略高于 99%，但预算余量不足；四段工具链预估不达标。因此，在完成生产等价压测和 24h/168h 事实窗口验收前，只建议小流量灰度，不建议签署全量生产 SLO 达标结论。
