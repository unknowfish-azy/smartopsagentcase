# 第一部分 · 15 分钟录播版

## 开场（约 40 秒）

各位老师好，我是"早点睡觉"队的黄亮，作品叫智维 Agent，英文名 SmartOpsAgent。

一句话介绍：这不是一个会聊天的运维助手，而是一套**把 AI 的每一步都留下证据、把每一次动手都关进审批**的运维平台。

知识库、AI 对话、健康诊断这几页比较直观，我不占时间。下面重点讲八块：云原生、Harbor、智能体、纠察、恢复契约、哨兵和工单、模型中心。

## 一、云原生工程（约 1 分 50 秒）

【打开 `/cloud-native`，停在顶部】

这一页叫云原生工程。请看副标题：**先明确目标，再选择知识与只读工具；此页不连接集群，不执行命令。**

这是个刻意的取舍。很多同类作品会在这里画一张很漂亮的集群拓扑，看起来什么都能监控，但背后没有真实连接权限，那些状态其实是编的。我们反过来，只做两件事：收敛目标，给人可执行的检查路径。

【指"目标上下文"】

上面是目标上下文：环境、集群 Context、Namespace、时间范围。看这句提示——"手动填写的目标意图，不代表集群已连接或权限已验证，不要填写密码或令牌"。切到生产环境，右上角会变成"⚠ 生产环境 · 操作前核对"；点应用之后提示"目标意图已保存，尚未连接集群"。它只存意图，不会偷偷去连。

【指四张卡片，任点一个】

下面四个领域：容器与集群、指标日志与追踪、发布与配置、供应链与权限。点进去是一层只读工具加知识条目，比如 K8s 资源检查、Pod 日志、PromQL 查询、RBAC 权限检查。每个条目固定六段：任务说明、前置条件、检查步骤、常见问题、结果验证、安全边界，并且明确标着"内置参考资料 · 未人工核验 · 执行前确认版本、真实 Context 和权限"。

我们不把内置资料包装成权威结论。这一页的价值不是"我能看到集群"，而是**动手之前，先把目标、范围、检查路径和边界固定下来**。

## 二、Harbor 工作台（约 2 分钟）

【打开 `/harbor`】

Harbor 工作台。副标题：项目、镜像仓库与 Containerd 接入状态集中查看，所有读取结果来自已配置的真实 Harbor。

【指右上角】

右上角这个徽标请老师注意：**READ ONLY · 只读，不会执行推送、删除或权限变更。** 整页能做的"最重"的动作，就是重新检查连接。

【点一次"重新检查连接"】

连接状态这里写得比较抠：**地址已配置，不等于服务健康。** 配了地址只说明有对象可查，不说明对面还活着。检查完显示检查时间，并且注明"五分钟后过期，不自动请求"——拿五分钟前的"正常"当现在的结论，就是假证据。下面还带 TraceId，出问题能对着日志查。

【指项目列表，点一个仓库】

再往下是真实数据：左边项目带仓库数和公开私有；点进去是仓库，再点进去是制品，显示 tag、digest、平台、大小、推送时间。这里有一句必须念的——**未读取扫描报告，不表示安全评估通过。** 镜像能拉下来，不等于它没有漏洞。

【点开底部一张说明卡】

底部四张运维说明卡，点开是放大浮窗：Containerd 怎么配 hosts.toml 和 CA、TLS 和 401/403 怎么区分、项目和仓库怎么治理、Harbor 怎么安装验证。里面写着硬规矩，比如"禁止用关闭 TLS 校验掩盖证书问题"、"生产优先用不可变 digest"。

一句话总结：**能看见的都来自真实接口；看不见的，比如扫描报告和写操作，我们就明说没有。**

## 三、智能体（约 2 分 40 秒，含执行轨迹）

【打开 `/agent`】

这是最能代表这个作品的一页，Agent Command Center。副标题：分析 → 记忆 → 决策 → 复盘 → 学习回写，**全部基于真实闭环记录**。请留意"闭环"和"真实"这两个词，这是它和普通对话机器人的分界线。

【指统计卡和流水条】

上面四个数：闭环总数、已复盘、复盘解决率、记忆回写次数——它们是流水线的产物，不是装饰。中间这条流水五段：分析看现象和证据，记忆召回同类历史处置，决策给建议并判断要不要审批，复盘填处置后的验证结论，学习把置信度回写。这条流水**单调向前**，做到第几步就停在第几步。

【点开一条记录，从上往下】

点开一条，右边是全过程。分析里，每条证据都带来源和相关度，不写"我觉得"，只写"哪份材料、多可信"。记忆召回列的是历史处置动作、置信度和命中次数，可以点"召回记忆"再查一次，这是查库不是凭感觉。决策把建议、结论、依据分开写，勾上"需要人工审批"，页面就出现"该处置需要人工审批后才能执行"——**AI 可以给方案，但不能给自己发许可。**

复盘之后人会填根因和可复用点，然后"提交复盘并学习"。学习回写那句写得最直白：**解决则置信度上调，未解决则降权或失效。** 这套记忆会因为失败而变弱，不是只会越记越自信。

【切到 `/agent/trace`，先指顶部深色卡片】

这一页是执行轨迹，副标题是"只展示可审计 Reasoning Summary，不展示隐藏 Chain-of-Thought"。先说清最上面这块深色卡片：它标着 **PREVIEW DATA · VIRTUAL TRACE，演示执行轨迹**——这是我们特意标注的样式预览，不是真实运行记录，我把它标出来就是不想让它冒充证据。

【指下面八个格子】

真实的部分在下面八个格子：工具、证据数、风险、审批、执行、验证、纠察、人工复核。横着排一眼能看出链子断在哪一环——比如执行了却没验证，或者验证没跑就标了通过。

这两页合起来回答一个问题：**AI 做过什么、凭什么做、做完有没有验证、错了会不会记住教训。**

## 四、纠察（约 1 分 15 秒）

【打开 `/inspector`】

SmartOps Inspector，AI 纠察中心。副标题一句话点题：**监督 AI 自己：行为、证据、工具、风险、审批与验证。**

在这个作品里 AI 是执行者，那谁来审它？就是这一页。它不审人，它审 AI。

【指五个数字，再指维度一排（一句带过），最后指时间线】

最上面五个数：Total、PASS、WARN、HIGH、CRITICAL，是对已发生事件的分级统计。下面这排是它覆盖的维度：行为、证据质量、工具使用、风险、审批、验证、知识引用、安全——它不只看"答得对不对"，还看"证据够不够、工具用没用越界、审批有没有被绕过"。

主体是 Inspection Timeline，一条就是一次真实纠察事件，点开能看到这次的证据、问题清单和命中的规则。

我想强调一个原则：**纠察只判定、不执行。** 它能标记、能降级、能要求人工复核，但它没有权力改系统。判和做分开，审计才成立。

## 五、恢复契约（约 1 分 20 秒）

【打开 `/operations/recovery`，停在"真实数据"】

恢复契约中心。副标题：按恢复契约 v1 语义展示已登记的契约、回执、义务缺口与回放差分，**四轴状态互不替代**。

先解释名字。运维里"修好了"最容易被滥用：重启了一下、进程起来了、监控不红了，都能叫好了。我们要的是**可核验的恢复**，所以写成契约：谁在什么目标上、声称恢复了什么、谁签发回执、有效期多久、什么条件下失效。

【指三张卡】

点开一条，固定三张卡。契约卡里有四轴：**动作轴、纠察轴、恢复轴、授权轴**，互不替代——动作成功不等于业务恢复，纠察通过也不等于恢复，授权齐全更不等于恢复，四件事各说各的。缺口卡回答"这次还差什么证据"。回放卡把当时的输入和探针录下来，事后在同一份证据上重放，结论变了就说明当时的判定站不住。

另外，顶部"真实数据"和"演示样例"是物理隔离的两套，样例不会混进真实账本；页面还写着"本页不做三值判定"——判定在服务端，前端不改判。

【空态备用】如果列表为空，页面写的是"暂无已登记的恢复契约"，并说明只展示内部写入方上报的契约与回执，"这里不会用样例数据填补空态"。这时就说：这个空态本身就是设计的一部分——没有真实登记就承认没有。

## 六、哨兵与工单（五个子页，约 3 分 30 秒）

【打开 `/sentinel`，哨兵监控台，约 50 秒】

先说总的设计：哨兵是**常驻监听**，不是定时巡检。页面第一句就写了——持续采指标、监听日志关键字，命中阈值并且持续时间达标才报，避免一次抖动就告警。

中间是"哨兵在网 · 节点在巡"：青是在线采集，红是离线，橙是采集异常，灰是缺运行连接，小蜘蛛巡向最近一次采样的节点，把"这些任务活着"这件事可视化。下面是任务表：名称、类别、采集目标、状态。没有任务时空态会提示"需要绑定一个已授权的运行连接"——**它不能凭空监控一台机器，必须先有授权。**

【打开 `/sentinel/scripts`，脚本库，约 50 秒】

在线脚本库，支持 Shell、Python、Bat、PowerShell，保存即产生版本，带标签和风险级别。关键在这句：执行仍然走既有链路，**预览 → 二次确认 → 执行 → 记录 → 审计，本模块不新增执行通路。** 加功能就顺手加一条执行通道，最后审计追不到，我们反过来做。另外，高危预检是**防御性预检，不是沙箱**，它拦明显危险写法，不负责"跑一遍看看会不会出事"。

【打开 `/sentinel/alerts`，告警中心，约 45 秒】

告警中心接哨兵的异常，按规则选通知渠道，给 AI 研判和脚本推荐，处置结果回填工单。页面顶部专门写了一块"为什么不做告警直接执行"：受控执行，所以做成建议加待审批；P0、P1 和高危脚本一律停等人工；只有 P2、P3 且脚本已发布已授权才允许策略自动发起，但仍然要过预览和审批闸门。

四个操作各有分工：研判只给建议不改状态；通知站内真实发出，邮件和 Webhook 如实标"待投递"；沉淀要告警已关闭才可点，把已关闭的整理成知识候选；走团队审批则生成预览、创建待审批运行。

【打开 `/incidents`，工单中心，约 35 秒】

工单中心把告警、分析、审批、执行、复盘收进同一次故障处理，状态机 OPEN → ACK → MITIGATING → RESOLVED → CLOSED。两条硬规则：**关闭必须填根因、处置过程、复盘结论**，不填关不掉；误报可直接关，已关闭可重开。我们不想让"关闭"变成点一下按钮就完事的动作。

【打开 `/sentinel/guardian`，守护 Agent，约 45 秒】

守护 Agent 干两件事。一是自动取证：告警一产生，30 秒内补齐历史指标、同类告警、运维记忆，只读数据库，不执行脚本、不改状态。二是基线学习：拿每个指标最近 200 个样本学出均值和 P95，样本少于 20 个不做结论，建议值和当前阈值差不到 10% 就标"稳定"，不打扰人。

最该讲的一条边界：**学习结果只产出阈值建议，必须人工确认后才写回阈值模板。** 它不自己改生产阈值，也不顺手执行脚本。AI 在这里是提意见的，不是拍板的。

## 七、模型中心（四页，约 1 分 50 秒）

【打开 `/model-settings`，接入，约 30 秒】

模型中心四页。接入这页管"平台能用哪些模型"：连接名称、服务商、Base URL、模型 ID。保存后可以做一次真实的文本测试，看它到底通不通——不靠"填完就算接好了"，靠一次真实调用证明。

【打开 `/model-gateway`，网关，约 40 秒】

统一模型网关解决的问题是：模型一多，密钥就散在每个人手里。做法是**一个 SmartOps Key 访问已授权的模型分组，Provider 密钥留在服务端**。链路是虚拟 Key → 模型分组 → 上游 Provider。Key 只在创建时完整显示一次，之后只留前缀，可以配 24 小时请求数加 Token 双配额，也能撤销。运行观测页看近 24 小时的请求数、成功率、平均耗时、Token 总量，以及每条路由的健康状态，OPEN 就是被暂时摘掉了。

【打开 `/model-strength`，约 20 秒】

模型强度这页，先请看这句注解：这里说的"强度"是**调用表现，不是通用能力评分**。成功率等于有效回复除以已完成调用，耗时只算成功调用的完整响应时间，不是首 Token 延迟。我们只报自己测得到的数。

【打开 `/token-usage`，约 20 秒】

Token 用量与额度。口径写在页面上：按 UTC 自然日统计，只汇总服务商已上报的输入和输出，差额算"未知或待确认"，**不按零补齐**——缺的数据当零，账面上就会永远比实际剩得多。

## 收尾（约 30 秒）

这些页面走下来就三句话：**看得见的证据**，每个结论都标来源，没证据就写没有；**守得住的边界**，只读就只读，要动手走审批，AI 不给自己发许可；**留得下的痕迹**，契约、回执、纠察、复盘、审计，事后能回放。

智维 Agent 想做的不是更聪明的运维助手，而是**一个可以被审计的运维同事**。谢谢各位老师。

## 二、Harbor 工作台（约 3 分钟）

【打开 `/harbor`】

第二页，Harbor 工作台。副标题：项目、镜像仓库与 Containerd 接入状态集中查看，所有读取结果来自已配置的真实 Harbor。

【指右上角徽标】

右上角这个徽标请老师注意："READ ONLY / 只读 · 不会执行推送、删除或权限变更"。整页是只读的，能做的"最重"的动作就是重新检查连接。

【点一次"重新检查连接"，等结果出来】

这块连接状态设计得比较抠。它写的是"地址已配置，不等于服务健康"——配了地址只说明我们有对象可查，不说明对面还活着。检查完会显示检查时间，并且注明"五分钟后过期，不自动请求"。为什么让它过期？因为 Harbor 的健康状态是会变的，拿五分钟前的"正常"当现在的结论，就是假证据。下面还带一个 TraceId，出问题能拿这个号去后端对日志。

【指项目列表】

再往下是真实数据：左边是 Harbor 里的项目，每个项目后面跟"多少个仓库、公开还是私有"；点一个项目，右边列出它下面的仓库和制品数量。可以翻页，可以按名字筛选，但筛的是"仅本页"，我们不假装做了全量搜索。

【点一个仓库，指制品卡】

点进仓库能看到制品：tag、digest、平台、类型和大小、推送时间。这里有一句必须念的——"未读取扫描报告，不表示安全评估通过"。镜像能拉下来、能部署，不等于它没有漏洞，这两件事我们分得很清楚。

【滑到底部四张说明卡，随便点开一张】

页面底部是四张运维说明卡，点开是放大浮窗：Containerd 怎么配 hosts.toml 和 CA 去拉 Harbor 镜像、TLS 和 401/403 怎么区分、项目和仓库怎么治理、Harbor 怎么安装验证。里面写了几条硬规矩，比如"禁止用关闭 TLS 校验掩盖证书问题"、"生产部署优先用不可变 digest"、"删除、推送、扫描策略不在本页执行"。

一句话总结这页：**能看见的都来自真实接口；看不见的，比如扫描报告和写操作，我们就明说没有。**

【空态备用】如果这台机器没配 Harbor，页面会显示"尚未配置 Harbor · 请由管理员配置后端 Harbor 地址与只读凭据。此处不展示或收集密码"。这时就说：这页的诚实点就在这里——没配就显示未配置，不会给你一个假的镜像列表。

## 三、智能体（约 5 分钟）

【打开 `/agent`】

接下来是我认为最能代表这个作品的一页：Agent Command Center，智能体控制中心。

副标题是"分析 → 记忆 → 决策 → 复盘 → 学习回写，全部基于真实闭环记录"。请注意"闭环"和"真实"这两个词，这是我们和普通对话机器人的分界线。

【指四个统计卡】

上面四个数：闭环总数、已复盘、复盘解决率、记忆回写次数。它们不是装饰，是后面流水线的产物——有复盘才有解决率，有学习才有回写次数。

【指五阶段流水条】

中间这条流水就是它的骨架，五段：分析，看现象、证据、影响面；记忆，召回同类历史处置；决策，给出处置建议并判断要不要人工审批；复盘，处置之后填验证结论；学习，把置信度回写进记忆库。这条流水是**单调向前**的，做到第几步就停在第几步。

【指左侧列表】

左边是闭环记录列表。注意每条前面的来源标记：INSPECTOR 是纠察自动派生的，另一种是人工新建。也就是说，AI 干完活，纠察会自己生成一条待复盘的记录，不需要人记得去建。

【点开一条，从上往下讲】

点开一条，右边是它的全部过程。

第一块，分析：现象是什么、分析结论是什么、支撑的证据有几条，每条证据都带来源和相关度百分比。这里不写"我觉得"，只写"哪份材料、多可信"。

第二块，记忆召回：列出历史上同类的处置动作、它的置信度、被证据命中的次数。可以点"召回记忆"再查一次。这不是模型凭感觉回忆，是查库。

第三块，决策：建议、决策结论、决策依据三段分开写。下面有一个"需要人工审批"的勾选，勾上之后页面出现一行字——"该处置需要人工审批后才能执行"。**AI 可以给方案，但不能给自己发许可。**

第四块，复盘：处置之后人回来填根因、有效动作、下次可复用点，然后点"提交复盘并学习"，判断这次是已解决还是未解决。

第五块，学习回写：页面写得很直白——"复盘后会真实回写 operator_memory：解决则置信度上调，未解决则降权或失效"。也就是说，这套记忆会**因为失败而变弱**，不是只会越记越自信。

【切到 `/agent/trace`】

这是它的姊妹页，Execution Trace 执行轨迹。副标题：只展示可审计 Reasoning Summary，不展示隐藏 Chain-of-Thought。我们不做"把模型的思考过程掏出来给你看"这种事，我们展示的是可审计的摘要。

【指顶部深色卡片，重点停一下】

先说清楚：最上面这块深色卡片，左上角标着 PREVIEW DATA · VIRTUAL TRACE，写的是"演示执行轨迹"。**这是我们特意标注的样式预览，不是真实运行记录**，那四步只是展示"一条轨迹长什么样"。我把它标出来，就是不想让它冒充证据。

【指下面八个格子】

真实的部分在下面：Tool 用了什么工具，Evidence 几条证据，Risk 风险等级，Approval 审批状态，Execution 执行状态，Verification 验证结果，Inspector 纠察结论，Human Review 是否需要人工复核。八个格子横着排，一眼能看出这条链在哪一环断了——比如执行了但没有验证，或者验证没跑就标了通过。

这两页合起来回答一个问题：**AI 做过什么、凭什么做、做完有没有验证、错了会不会记住教训。**

【空态备用】如果闭环列表是空的，就说："空态写的是'暂无闭环记录，可从 Inspector 自动派生或手工新建'。我现在点新建，手工走一条。"然后真的点一次，别光讲。

## 四、纠察（约 2 分钟）

【打开 `/inspector`】

这一页叫 SmartOps Inspector，AI 纠察中心。副标题一句话点题："监督 AI 自己：行为、证据、工具、风险、审批与验证。"

在这个作品里，AI 是执行者，那谁来审它？就是这一页。它不审人，它**审 AI**。

【指上方五个数字】

最上面五个数：Total、PASS、WARN、HIGH、CRITICAL。这是纠察对已发生事件的分级统计，PASS 是通过，往后依次是警告、高危、严重。

【指维度那一排，一句带过，不要停】

下面这一排是纠察覆盖的维度：Agent Behavior 行为、Evidence Quality 证据质量、Tool Usage 工具使用、Risk 风险、Approval 审批、Verification 验证、Knowledge 知识引用、Security 安全。也就是说，它不只看"答得对不对"，还看"证据够不够、工具用没用越界、审批有没有被绕过"。

【指时间线】

主体是 Inspection Timeline，每一条都是一次真实的纠察事件。点开一条会进详情页，能看到这次的证据、问题清单，以及每个问题命中的规则。

这里我想强调这套设计的一个原则：**纠察只判定、不执行**。它发现问题之后，能做的是标记、降级、要求人工复核，它自己没有权力去改系统。判和做分开，是审计能成立的前提。

【点右上"查看统计"】

右上角"查看统计"进统计页，页面写明"仅展示数据库中的真实纠察数据"，按类别和目标做分布统计，用来回答"这套 AI 最近是不是变毛躁了"。

【录视频注意，不要念】这一页维度那一排里，混着四个 `Preview:` 开头的静态标签（Preview: Evidence 86%、Preview: Risk PASS、Preview: Loop WARN、Preview: Verify N/R）。这是前端代码里写死的占位标签，不是实时指标。录的时候不要指着它们说"这是我们的指标"；评委追问就答：那是维度占位标签，真实数字在上面五个统计卡和时间线里。正文里用"维度"这个词带过，不展开。

## 五、恢复契约（约 3 分钟）

【打开 `/operations/recovery`，确认停在"真实数据"这一侧】

这一页是恢复契约中心。副标题：按恢复契约 v1 语义展示平台已登记的契约、回执、义务缺口与回放差分，四轴状态互不替代。

先解释名字。运维里"修好了"这三个字最容易被滥用：重启了一下、进程起来了、监控不红了，都能叫"好了"。我们要的是**可核验的恢复**，所以把它写成一个契约：谁在什么目标上、声称恢复了什么、由谁签发回执、有效期多久、什么条件下失效。

【指顶部两个 tab】

顶部有两个数据来源：真实数据、演示样例。这两套是**物理隔离**的，切到演示样例时卡片会明确标成样例，不会混进真实账本。演示时我们就停在真实数据这一侧。

【指运行 ID 过滤和那句提示】

真实模式可以按运行 ID 查。这里写了一句"本页不做三值判定"——判定在服务端做，页面只负责把服务端的结论和依据摆出来。前端不改判，这是我们刻意守的边界。

【点开一条契约，指三张卡】

详情是固定三张卡。

第一张契约卡：契约编号、目标、声明、回执状态，以及"四轴状态、互不替代"——**动作轴、纠察轴、恢复轴、授权轴**。为什么强调互不替代？因为动作成功不等于业务恢复，纠察通过也不等于业务恢复，授权齐全更不等于恢复。四件事各说各的，谁也不许替谁下结论。

第二张缺口卡：契约里承诺的义务有哪些、实际拿到了哪些、缺的那几项算不算数，还有探针决策和预算。它回答"这次还差什么证据"。

第三张回放卡：把当时的输入和探针录下来，事后在同一份证据上重放一遍，看结论会不会变。如果重放结论和当时不一致，说明当时的判定站不住。

【空态备用，这一页大概率为空，务必准备】

如果列表是空的，页面会写"暂无已登记的恢复契约"，并说明：平台只展示内部写入方，也就是 agent 或只读探针带内部令牌上报的契约与回执，"这里不会用样例数据填补空态"。这时就说：这个空态本身就是设计的一部分——没有真实登记就承认没有，不拿样例糊弄。想看卡片长什么样，可以切到"演示样例"，但我会明确告诉老师这是样例。

## 六、哨兵与工单（五个子页，约 5 分钟）

### 6.1 哨兵监控台（约 1 分 10 秒）

【打开 `/sentinel`】

先说总的设计：哨兵是**常驻监听**，不是定时巡检。页面第一句就写了这个区别——它持续采系统指标、监听日志关键字，命中阈值并且持续时间达标才报，避免一次抖动就告警。

【指拓扑】

中间这块叫"哨兵在网 · 节点在巡"。每个节点对应一个真实哨兵任务：青色是在线采集，红色离线，橙色采集异常，灰色是缺运行连接。小蜘蛛会巡向最近一次采样的节点，这是把"这些任务活着"这件事可视化，不是装饰动画。

【指状态栏和任务表】

下面是任务表：名称、类别、采集目标、状态。没有任务时，空态会告诉你"哨兵任务需要绑定一个已授权的运行连接"，并给一个去连接中心的入口。也就是说，**它不能凭空监控一台机器，必须先有授权连接**。

### 6.2 脚本库（约 1 分钟）

【打开 `/sentinel/scripts`】

这一页是在线脚本库，支持 Shell、Python、Bat、PowerShell，保存即产生版本，带标签和风险级别。

关键在这句话：执行仍然走既有的受控链路，**预览 → 二次确认 → 执行 → 记录 → 审计**，本模块不新增执行通路。我们看到太多作品，加一个功能就顺手加一条执行通道，最后审计追不到。我们反过来：脚本库只负责"写和存"，动手还是回到原来那条唯一的通道。

【指表格的审批列】

表格里能看到每个脚本的风险级别和审批状态，高危脚本写的是"待管理员审批"，没过审批不能用于告警联动。

【指在线编辑器和高危预检】

下面是编辑器和"高危预检"。这里要说清一句：**高危预检是防御性预检，不是沙箱**。它在提交前拦明显的危险写法、给你提示，它不负责"在里面跑一遍看看会不会出事"。把预检说成沙箱，就是吹牛。

### 6.3 告警中心（约 1 分钟）

【打开 `/sentinel/alerts`】

告警中心接收哨兵报上来的异常，按规则选通知渠道，给出 AI 研判和脚本推荐，处置结果回填工单。

页面顶部有一块说明，标题是"为什么不做告警直接执行"。答案有三条：我们是受控执行，所以做成"建议加待审批"；P0、P1 和高危脚本一律停等人工；只有 P2、P3 且脚本已发布、已授权时，才允许策略自动发起，但仍然要过预览和审批闸门。

【指四个统计，再逐个说操作按钮】

四个数：待处理、待审批、处置中、已关闭。

每条告警有四个操作。研判，只给建议和证据，不改状态、不执行；通知，站内真实发出，邮件和 Webhook 会如实标成"待投递"，不假装已经送到了；沉淀，把已关闭的告警整理成知识候选进团队复核，没关闭的按钮是灰的，因为没查清就沉淀等于把猜测写进知识库；走团队审批，生成预览，在团队侧创建一条待审批运行，还是人批了才动。

### 6.4 工单中心（约 1 分钟）

【打开 `/incidents`】

工单中心把告警、AI 分析、审批、执行、复盘收进同一次故障处理。状态机是 OPEN → ACK → MITIGATING → RESOLVED → CLOSED，五态单向推进。

两条硬规则：**关闭必须填根因、处置过程、复盘结论**，不填关不掉；误报可以直接关闭，已关闭的可以重开。我们不想让"关闭"变成点一下按钮就完事的动作。

【指列表】

列表按等级和创建时间排序，带 SLA、负责人、来源，可以按状态、等级、负责人筛选。

### 6.5 守护 Agent（约 1 分钟）

【打开 `/sentinel/guardian`】

最后一页是守护 Agent，它干两件事。

第一件，自动取证：告警一产生，30 秒内自动补齐证据——历史指标、同类告警、运维记忆。取证只读数据库，不执行脚本、不改告警状态。

第二件，基线学习：拿每个指标最近 200 个样本学出均值、P95，再给出一个阈值建议。样本少于 20 个不做结论；建议值和当前阈值差不到 10% 就标成"稳定"，不打扰人。

这里有一条我认为最该讲的边界：**学习结果只产出阈值建议，必须人工确认后才写回阈值模板**。它不会自己改生产阈值，也不会顺手执行脚本。AI 在这里是提意见的，不是拍板的。

【哨兵五页的空态备用】如果后端没接上，会出现"后端未接入"或"还没有哨兵任务"的提示。就说：这是设计里的空态，我们没有用假数据把页面填满；需要演示数据的地方，都单独做了标注。

## 七、模型中心（四页，约 3 分钟）

### 7.1 模型接入（约 40 秒）

【打开 `/model-settings`】

模型中心一共四页，先看接入。这一页管"平台能用哪些模型"：连接名称、服务商标识、Base URL、模型 ID。

【打开一个连接卡片或点测试】

保存之后可以做一次真实的文本测试，发一句"请用一句话说明你可以如何帮助排查系统故障"，看它到底通不通。我们不靠"填完就算接好了"，要靠一次真实调用来证明。

### 7.2 统一模型网关（约 1 分 20 秒）

【打开 `/model-gateway`，停在总览】

这一页解决的问题是：模型一多，密钥就散落在每个人手里。网关的做法是——**一个 SmartOps Key 访问已授权的模型分组，Provider 的密钥留在服务端**。

【指总览里的链路】

总览里这条链是：虚拟 Key → 模型分组 → Provider。请求进来先验 Key，再看这个 Key 能进哪个组，最后由组里的路由选一个上游。

【切到 VIRTUAL KEYS】

虚拟 Key 页：完整 Key 只在创建时显示一次，之后列表里只留前缀和状态。可以给 Key 配 24 小时配额，请求数和 Token 两个维度都限；不用了直接撤销。

【切到 AUDIT / HEALTH】

运行观测页：近 24 小时的请求数、成功率、平均耗时、Token 总量，以及每条上游路由的健康状态——优先级、失败次数、READY 还是 OPEN。OPEN 就是这条路由被暂时摘掉了。

### 7.3 模型强度（约 30 秒）

【打开 `/model-strength`】

模型强度这一页，请老师先看这句注解："模型强度"在这里指调用表现，不是通用能力评分。成功率等于有效回复除以已完成调用；耗时只统计成功调用的完整响应时间，不是首 Token 延迟。

为什么强调这个？因为"哪个模型更强"很容易变成一句宣传语。我们只报自己测得到的：每日调用成功率、平均响应耗时，还有按模型或连接拆开的调用次数、输入输出 Token、待确认用量。

### 7.4 Token 用量（约 30 秒）

【打开 `/token-usage`】

最后一页，Token 用量与额度。口径全部写在页面上：按 UTC 自然日统计，只汇总服务商已上报的输入和输出；和总数的差额算"未知或待确认"，**不按零补齐**。

这句话很重要——缺的数据不能当零，否则账面上会永远比实际剩得多。

【注意，不要点】页面有个"查看虚构案例"按钮，点进去是明确标注的虚构数据。录视频时不要点；非要演示就说一句"这是虚构案例，不计入真实账本"。

## 收尾（约 30 秒）

这些页面走下来，其实就三句话：

**看得见的证据**——每个结论都标来源，没证据就写没有；
**守得住的边界**——只读的地方就只读，要动手就走审批，AI 不给自己发许可；
**留得下的痕迹**——契约、回执、纠察、复盘、审计，事后能回放。

智维 Agent 想做的不是更聪明的运维助手，而是**一个可以被审计的运维同事**。谢谢各位老师。

# 附录 B · 评委最可能追问的七个问题

**1. 这个 Agent 到底是不是自主的？**
不是自主执行型，是受控决策型。它自主的部分是分析、取证、召回记忆、给建议；动手必须过审批。我们宁可少自动化一步，也不留一条绕开审批的路。

**2. 云原生页都不连集群，那它有什么用？**
正因为它不连，它才敢说实话。真实连接需要凭据和安全边界，那部分放在只读工具页和连接中心。这一页负责把目标、范围、检查路径固定下来。我不想用一张假拓扑换掌声。

**3. 纠察是不是就是个日志页？**
不是。日志回答"发生了什么"，纠察回答"这件事合不合规"。它按行为、证据质量、工具使用、风险、审批、验证、知识引用、安全八个维度判定，输出 PASS 到 CRITICAL，而且只判定、不执行。

**4. 恢复契约和健康检查有什么区别？**
健康检查回答"现在指标正不正常"；恢复契约回答"这次处置到底有没有把业务恢复，凭什么这么说，有效期到什么时候，什么情况下作废"。它带回执、带回放、带失效条件。

**5. 哨兵和现成的监控告警平台什么关系？**
现在是平台内置的常驻采集、阈值加防抖，指标来源可以是系统命令，也可以是 HTTP 探测。它更强调的是治理那条线——阈值建议必须人工确认才写回。如果接 Prometheus，是换采集层，不改处置链路。

**6. 模型网关为什么自己做，不用现成的？**
我们要的不是转发，是治理：Key 只存哈希和前缀、按分组授权、24 小时双维度配额、连续失败自动摘路由。这些在通用网关里要定制，我们直接做进业务里。

**7. 这么多页面，多少是真能跑的？**
（诚实版，别答"全部"）核心链路是完整可跑的：登录会话、AI 对话、知识库、健康诊断、工具预览到审批执行、审计、模型接入与调用。哨兵、恢复契约、工单这几块是接口和页面已就绪，但要真实连接、真实事件才会有数据，空态是我们有意保留的，没有拿假数据填。
