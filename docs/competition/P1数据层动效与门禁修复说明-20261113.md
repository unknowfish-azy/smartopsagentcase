## 2. 关键实现决策

### 2.1 `KpiNumber` / `useCountUp`（数字滚动）

- **900ms + easeOutCubic**，只滚一次：真实值从 0 滚到目标值；之后的数据刷新**直接更新文本**，不反复滚动（避免看板一直闪）。
- `format` / `decimals` 透传宿主原有格式；`font-variant-numeric: tabular-nums` 防止数字宽度变化引起布局抖动。
- 组件本身 `aria-hidden="true"`，滚动过程不污染读屏；非数字值（如 `—`）直接显示、不启动动画。
- 组件只在目标值变化时重渲，滚动帧只改 `display` 文本，不触发父组件更新。

### 2.2 网格错峰（`ml-stagger-cols-2/3/4`）

- 复用编排层既有 `ml-stagger` 的语义：`ml-rise-in`（2px 抬升 + 淡入）、40ms 步进、只覆盖前 12 个子项。
- **只加类名，不改 grid 布局**：列数仍由各页面自身 grid 决定，`ml-stagger-cols-*` 仅负责子项动画与延迟。

### 2.3 图表动效走 ECharts 配置而不是 CSS

这是本次最重要的技术取舍：**ECharts 画在 canvas 上，CSS 的 `prefers-reduced-motion` 与降级选择器对它完全无效**。因此三处图表统一从 `useVisualMode().motionQuery` 取降级信号：

- `animation: !motionQuery?.matches`——命中降级时直接 `false`，入场/更新动画整段关闭；
- `OpsChart`（通用封装）：600/480/480ms、`cubicOut`、类目索引 90ms 错峰、阈值 3000、更新 300ms；
- `v-chart-bar`：柱 360ms、散点 520ms（散点额外按 `symbolSize` 错峰）。

### 2.4 AI 逐行揭示

- 仅在 `role === 'assistant'` 时加 `ml-stream-lines`，用户消息不加；
- 按 `\n` 拆成 `<span class="ai-chat-message__line">`（`display:block`），保留原有 `white-space: pre-wrap`；
- 空行给 `min-height: 1.65em`，避免空行塌缩导致段落间距丢失；错误文本行单独染 `--smart-danger`；
- `line.style` 提供 `--ml-index`（从 1 起），与编排层 `nth-child(n)` 延迟对应。

## 3. 审查修掉的 3 个实质缺陷（重点）

> 这三处都不是「风格问题」，而是**功能不生效**或**破坏已验收交互**。

### 3.1 `useCountUp` 在真实异步场景下永远不滚动

- **现象**：KPI 数字直接出现终值，看不到滚动。
- **根因**：`onMounted` 里 `Number(targetRef.value)`——KPI 数据异步拉取，挂载时多为 `null`，而 **`Number(null) === 0`**，被当成有效数字，于是 `started = true; animate(0)`（从 0 滚到 0，无视觉效果）。真实值随后到达时走 `watch` 分支，只做 `display = format(value)`，**滚动一次都不会发生**。
- **修法**：新增 `toNumber()`（`null/undefined/''` 与非有限数一律视为「暂无数据」），把启动逻辑收敛到 `startIfNeeded()`，`onMounted` 与 `watch` 都调用；只有拿到首个有效数字才置 `started` 并滚动。另补 `onBeforeUnmount(stop)` 取消 rAF。

### 3.2 `ml-stagger-cols-*` 的动画声明整条失效

- **现象**：网格错峰完全不动。
- **根因**：子项写的是 `animation: ml-rise var(--ml-duration-base) var(--ml-ease-out) both`，但 **`ml-rise` 这个 keyframes 不存在**（编排层定义的是 `ml-rise-in`），且 `--ml-duration-base` / `--ml-ease-out` 两个变量**从未定义、也无 fallback**，`var()` 解析失败使整条 shorthand 变为无效值（IACVT）。
- **修法**：统一为 `ml-rise-in var(--ds-duration-spring, 200ms) var(--ds-ease-out, cubic-bezier(.22,1,.36,1)) backwards`。

### 3.3 错峰动画吃掉卡片 hover 抬升

- **根因**：`animation-fill-mode: both` 会让动画**终态 `translateY(0)` 永久留在元素上**，而动画在层叠中优先于普通声明，于是 `.ops-card--interactive:hover` 的 `translateY(-1px)` 被覆盖——正是编排层注释里专门规避过的坑（自动挂载用纯 `opacity` 的 `ml-fade-in` 就是为这个）。
- **修法**：`ml-stagger` 与 `ml-stagger-cols-*` 统一改 **`backwards`**：延迟期间应用 from 帧，动画结束后不保留终态，transform 交还给 `:hover`。
- **附带**：窄屏（`max-width:768px`）与 reduced-motion 的降级选择器列表补上 `[class*='ml-stagger-cols'] > *`，与既有 `ml-stagger` 对齐。

## 4. 顺带定位的两个门禁问题（非 P1 引入）

### 4.1 a11y 16 条 `color-contrast` serious = 入场动画过渡帧假阳性

- **取证**：在套件真实上下文里给 `axeScan` 临时加 `failureSummary` + 计算样式链，拿到 axe 报告的前景色 `#4d7e9a`（4.4:1）、`#5f8aa4`（3.71:1），而元素自身 `color` 是 `#084b73`（对白底 9.28:1）、`opacity` 为 1——即 axe 采到的是**被透明度混合后的中间帧**。
- **根因**：`PersonalSystemNavigation.vue` 的 `.navigation-group { animation: nav-arrive 240ms ease both; animation-delay: calc(var(--nav-order) * 12ms) }`（opacity 0→1 + 分组错峰）。axe 在动画进行中采样，把半透明文本判成对比度不足；命中节点随各组延迟漂移，所以同一页面每轮命中的节点不同（冷启动慢时甚至 0 条）。
- **修法**（`test/accessibility.browser.mjs`）：
  - `settle()` 在跑 axe 前等「有限次动画」跑完，`iterations: Infinity` 的呼吸/脉冲不等待，结果稳定可复现；
  - `open()` 重试时清空上一轮 `pageerror`，Vite 冷编译的 `Failed to fetch dynamically imported module` 抖动不再让门禁失败。

### 4.2 375 视口横向溢出 = T19 遗留的主区左偏移

- **根因**：`global.css` 的 `.app-layout:not(.app-layout--sidebar-collapsed) > .main-area { margin-left: calc(var(--ds-sidebar-width,256px) + 20px) }`（T19 `5615502` 引入）**不分断点生效**。窄屏下侧栏是整宽顶部条而非固定导轨，主区仍被推开 276px，内容只剩 99px 宽、`documentElement.scrollWidth` 达 572。
- **修法**：`@media (max-width:767px)` 下把两种主区选择器的 `margin-left` 归零。

## 7. 维护注意事项

1. **跑浏览器契约测试期间不要改 `src`**：Vite HMR 会整页刷新，`login-layout` 的几何/对比度断言会随机失败（本次复现 2 次，停笔后连续 3 次全 PASS）。失败先看是否同期有文件变更，再决定是否当真回归。
2. **新增错峰类请沿用三件套**：`ml-rise-in` + `var(--ds-duration-*) / var(--ds-ease-*)` + `fill-mode: backwards`；不要再引入未登记的 keyframes 名或变量。
3. **canvas 动效必须走 `motionQuery`**：CSS 降级够不到 ECharts，新增图表时记得同时给 `animation` 与各类 `animationDelay/Duration` 接降级。
4. **数字滚动只播一次是刻意设计**：若后续要「每次刷新都滚」，改 `useCountUp` 的 `watch` 分支即可（代码内已留注释），不要在外层重复触发 `animate`。
5. **门禁清单**：`npm test` / `typecheck` / `lint` / 双 build / a11y / login-glass / login-layout / meteor；a11y 与 `visual-suite` 自带 server，不要设 `SMARTOPS_BROWSER_BASE_URL` 覆盖。
