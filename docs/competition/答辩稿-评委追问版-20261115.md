## 使用说明（先读这段）

**应答结构：结论先行 → 一句话证据 → 一句路线图。** 每道题先给结论（10 秒），再给可核对的证据（数字带 n= / 代码位置），最后落到诚实边界或下一步。**不背全文，背"要点"。**

**三条心法：**
1. **先承认边界，再给路线图，比硬撑更得分。**
2. **数字只从 fact-sheet 抄，禁编"准确率 9X%"，禁跨快照拼数。**
3. **被质疑时把话题从"模型效果"拉回"系统能力可演示可验证 + 诚实评测框架"。**

**五句必背金句：**
- 一句话：AI 负责思考，人负责授权，系统负责留痕。
- 三道锁：证据锁 / 边界锁 / 留痕锁；一本账：审计账。
- 差异不在模型，在约束——模型可换，这套约束不换。
- 一个诚实标注"哪些实测、哪些 NOT_RUN"的评测框架，比什么都敢报的系统更可信。
- 安全不是演示出来的，是架构逼出来的。

## 第一部分 · 开场陈述稿（约 6 分钟，可按 4 分钟版压缩）

各位评委老师好，我们是 ×× 团队，作品是**智维Agent**——一个面向中小企业的可信 AI 智能运维与知识协同平台。

**先说一个场景。** 凌晨两点，一台 MySQL 连接数打满，值班工程师翻了七个帖子、试到第三条命令，服务彻底挂了。人手少、系统杂、知识散，这是中小企业运维的常态。今天的大模型能"说"，却不敢让它"做"——结论没有证据、动作没有边界、过程没有留痕。我们这个作品，就是把这三件事补上。

**所以我们做的不是"更会聊天的运维机器人"，而是一个敢把生产环境交给它的 AI 同事。** 它把一次运维任务拆成监测、分析、知识检索、证据验证、规划、风险判断、人工审批、安全执行、结果验证、审计留痕、经验沉淀，十一环连成一个闭环。用户只说一句话，十一环自动跑完；但有三道关口，由规则和人把守。

**第一道，证据。** 运维知识最痛的是查到旧版本——Ubuntu 22.04 的答案套在 CentOS 6 上就是错的。我们给每个知识切片打版本字段，检索按目标环境过滤；BM25 加向量双路召回，0.6:0.4 融合、重排取前五；每条证据的来源、版本、支持度聚合成可信度评分。回答里每句话都能点回具体条目。

**第二道，边界。** AI 可以规划，但不能自己决定动手。策略引擎按权限与风险给每个动作定级，高危动作必须转人工审批，批准后才在沙箱与命令黑白名单约束下执行。**AI 负责思考，人负责授权，系统负责执行。**

**第三道，留痕。** 执行完不算结束。我们做四级核查，L4 状态核验专抓"假成功"——Agent 声称重启成功，探针事实显示服务没起来，就判不通过并重新规划。延伸到恢复环节就是恢复契约：目标、版本、新鲜度、轮次、来源全部达标才算真恢复。冻结案例里弱基线产生 21 次假恢复，我们的实现假恢复 0 次，与独立判定高度一致。

**这不是 PPT 项目。** 后端 Spring Boot + MySQL，331 个 Java 文件、3.69 万行、477 个接口、119 张表；前端 Vue 3 双入口、234 个组件；三层测试全量可复跑：前端 733 项、Python 622 个用例、后端 774 项，最近一次回归 0 失败。Bento 首页、手机相册式知识照片墙、时序预测面、洞察台三视图联动，全部可离线演示；AI 侧接本地 Ollama，不联网、不需要任何密钥，评委在自己电脑上就能复现。

**当然也有边界，我们主动说清。** 当前向量嵌入是可复现的哈希方案，没有真实语义，接口已留好可换真实 embedding；规划器以规则为主，大模型规划模板已就绪；数据集 14 条全 DRAFT，我们不编准确率数字，每一条都带 n= 和口径。这是阶段性取舍，不是包装。

**一句话收尾：我们做的不是"接个大模型就完事"的运维助手，而是一个每句话有出处、每个动作有授权、每个结果有核验的可信运维智能体。** 汇报完毕，请各位评委批评指正。

### 主题 A · 项目定位与真实性

**A1 主问：一句话说清你做了什么？**
> 结论：可信 AI 智能运维平台，把大模型从"会回答"变成"可信地完成运维任务"。证据：十一环闭环 + 三道关口，四端全栈可运行。路线图：AI 思考、人授权、系统留痕。

**A2 追问：这是不是就是个运维知识库套了个大模型？**
> 结论：不是，知识库是零件、我们是整机。证据：知识库只解决"查得到"，我们解决"查得对版本 + 答得有证据 + 做得有边界 + 过程能复盘"，四端里 Spring Boot 后端、Agent 五模块、inspector 四级核查都是知识库没有的。路线图：可打开架构图逐层对照。

**A3 再追问：你们团队几个人，真做得完这么大规模？**
> 结论：按模块切分 + 门禁防单人阻塞。证据：331 Java 文件/477 接口/234 Vue 组件是真的，但由前端/后端/AI 三条线并行 + 733/622/774 三层测试兜底，交接靠文档与脚本。路线图：强调"测试门禁是不因某个人请假而崩的保证"。（团队人数按实际填，别虚报）

### 主题 B · 技术深度（算法创新赛重中之重）

**B1 主问：你们的"算法创新"具体在哪？**
> 结论：三点可量化设计。证据：①版本感知混合检索——BM25+向量并行→版本过滤→词法重排→聚合 trust_score；②四级核查（规则→证据→AI→状态核验）降假成功；③工具级风险策略引擎 + 人工审批双闸。路线图：每点都有代码位置与演示路径（`knowledge/retrieval/`、`agent/inspector/pipeline.py`、`agent/policies/risk.py`）。

**B2 追问：RAG 为什么不用 LangChain / LlamaIndex？**
> 结论：现成框架解决"召回"，解决不了"版本过滤 + 证据表达 + 可信度聚合"。证据：我们在 `version_filter.py`、`knowledge/evidence/` 做了场景化扩展，且保留可评测指标（M01）。路线图：框架是工具、算法是自己写的，接口留好可插拔。

**B3 再追问：trust_score 怎么算，是不是黑盒？**
> 结论：不是黑盒，是证据强度的量化。证据：由命中 Citation（来源/chunk/版本/分数）聚合而来，可逐条溯源到具体知识条目与版本。路线图：现场点开回答里的一条引用给用户看。

**B4 追问：向量嵌入用的什么？效果如何？**
> 结论：默认可复现哈希 embedding，可一键切真实模型。证据：当前诚实数据是 Recall@3=0.50、MRR=0.43（n=14，DRAFT），含 AI 改写变体 0.70/0.66（n=70，有效独立≈14，不当显著性）。路线图：BGE `bge-small-zh-v1.5` 接口已留好，接真实 embedding 即可出数。

**B5 追问：Agent 是单次 LLM 调用吗？**
> 结论：不是，是多模块协作。证据：planner 拆带依赖的步骤、executor 逐步调工具、inspector 逐步核查、memory 沉淀经验、policies 每步前判风险，kernel 提供插件注册/事件总线/生命周期。路线图：这是"策略与审批优先"的执行模型，不是 chain 串接。

**B6 再追问：四级核查里的"AI 判定"不会引入新幻觉吗？**
> 结论：所以是四级融合而非单靠 AI。证据：规则做硬约束、证据做一致性校验、AI 只做语义补充、L4 状态核验用事实兜底，结论需多路一致；AI 级无 LLM 时降级为空发现。路线图：全程留痕可追溯，误判可被上层拦下。

**B7 追问：多智能体 / 团队 Agent 体现在哪？**
> 结论：单智能体闭环 + 团队级协同两层。证据：后端 `TeamAgentRunService` + `DecisionLoopService` 支撑团队运行与决策循环，前端有团队工作区、Agent 运行与审批、通知。路线图：两层能力分开讲清。

### 主题 C · 创新与竞品对比

**C1 主问：最大创新点是什么？**
> 结论：可信闭环工程化。证据：把权限、风险、审批、核查、审计做成可运行代码路径，而非文档理念。路线图：每个点有代码位置 + 演示路径可验证。

**C2 追问：和 ChatGPT + 提示词有什么区别？**
> 结论：差异不在模型，在约束。证据：版本感知检索、证据验证与可信度评分、风险分级与人工审批、审计与经验回流——模型可换，这套约束不换。路线图：ChatGPT 给答案，我们给"可负责任的运维动作"。

**C3 追问：和传统 AIOps / 监控告警比呢？**
> 结论：补上四块短板。证据：传统 AIOps 多有日志无推理、有自动化缺审批；我们补"证据可信度 + 风险审批 + 透明推理 + 审计沉淀"，且是 AI Native 对话式入口。路线图：不是替代监控，是把处置环节变可信。

**C4 压力追问："创新点别人都能做，凭什么获奖？"**
> 结论：单点或许能做，系统性整合并工程化才是壁垒。证据：把版本过滤 + 证据聚合 + 风险审批 + 透明推理 + 全程审计串成可运行、可演示、可复现的闭环，每点有代码与演示路径。路线图：这种工程纪律本身就是难点。

### 主题 D · 数据 / 评测（高频陷阱，必须练熟）

**D1 主问：准确率多少？效果数据呢？**
> 结论：我们不编数字，每条带 n= 和口径。证据（分条给）：假成功检出——开发集 47 条 F1=1.0（词表过拟合，禁当泛化），留出集 20 条 F1=0.48/召回 0.33（如实报，10 条漏检落"无法判定"，静默放过 0）；风险分级一致性 0.76（全量 21 操作枚举）；真模型 Ollama qwen3:1.7b，20 问首 token P50=3590ms。路线图：检索 Recall@3=0.50 是 DRAFT 小样本、M05 真人盲评 NOT_RUN——这些我们明说了没跑。一个诚实标注哪些实测、哪些 NOT_RUN 的评测框架，比什么都敢报更可信。

**D2 追问：为什么说开发集 F1=1.0 不能当性能？**
> 结论：那是样本内过拟合。证据：开发集 47 条是冻结合成集，换说法的留出集 20 条立刻掉到 F1=0.48/召回 0.33。路线图：所以我们**主动同时给两组**，只报 1.0 属于选择性呈现，是红线。

**D3 追问：没真实数据凭什么说你好？**
> 结论：好分两层。证据：系统能力已可演示可验证（闭环、检索、审批、审计都在跑）；模型效果需要真实数据，如实标注未跑。路线图：竞赛看算法设计与工程实现，这两层我们拿得出手。

**D4 追问：消融实验做了吗？**
> 结论：设计完成、尚未执行。证据：RAG 六组、Inspector 五组设计就绪，但缺真实模型/数据集/evaluator 三件套，门禁不允许空跑。路线图：设计本身是严谨工作的体现，执行是下一步。

**D5 追问：为什么用 mock 模型，是不是根本没接真模型？**
> 结论：mock 是为零密钥可复现，不是能力上限。证据：`model_gateway` 支持 Ollama 与 OpenAI 兼容，运行期切换；M03 已用真模型 qwen3:1.7b 实测 20 问。路线图：评委可自己拉下来接真模型复现。

**D6 追问：M04 说高危操作被判 LOW，是不是有越权风险？**
> 结论：是双轨不一致的潜在风险，**不是已发生越权**。证据：3 个 `approval_required=true` 操作（docker.compose/restart、redis.restart）被分类器判 LOW，但实际审批链读的是工具/manifest 声明（`policy_engine.py:23`），分类器不决定放行。路线图：这正论证了为什么保留人工审批双闸，不能据此说分类器可靠。

### 主题 E · 安全与可信（"敢不敢"类）

**E1 主问：你说可信，敢不敢现场把高危动作真执行？**
> 结论：故意不敢——这正是设计意图。证据：高危动作必须人工审批，批准后仅在沙箱执行。路线图：现场我会展示"被拦截→审批→执行→审计"完整链路，但绝不绕过审批直接动生产。**安全不是演示出来的，是架构逼出来的。**

**E2 追问：模型答错了怎么办？**
> 结论：三层兜底，答错不会变成事故。证据：提示词约束"无证据不下确定结论"；证据链供用户核对；高风险动作必须人工审批。路线图：可核对 + 可拦截 + 可追溯。

**E3 追问：AI 自动执行会不会很危险？**
> 结论：架构层卡死。证据：权限注册表 + 风险策略引擎 + 沙箱三重约束，高危人工审批，执行后 inspector 核查 + 审计。路线图：三重约束逐一讲。

**E4 追问：数据安全怎么保证？**
> 结论：全链路措施齐备。证据：BCrypt(12)、CSRF、会话固定防护、管理员 MFA + 恢复码、AES-GCM 密钥加密、附件 `nosniff` + CSP sandbox、关键事件结构化审计、关键密钥 fail-closed。路线图：按账户/会话/请求/密钥/执行分层讲。

**E5 追问：多模态是不是"假多模态"？**
> 结论：诚实回答——当前是隐私边界内的有限多模态。证据：图像仅文件名级参与链路、内容不上传（刻意隐私取舍）；语音浏览器内识别、音频不出端；3D 与图表是真可视化。路线图：仓库已有 OCR 模块，授权后接内容级理解。我们不把"传文件名"包装成"看懂图片"。

**F4 追问：大屏 / 3D / 737 格会不会卡？**

### 主题 H · 压力 / 陷阱题（练心态）

**H1 "我觉得你这项目没什么技术含量。"**
> 理解您的视角。技术含量不在"训练了一个大模型"，而在**把可信约束工程化**——版本感知检索、四级核查、风险策略引擎、可复现评测框架，每一处都是针对"AI 运维可信"这一真实难题的算法与系统设计。欢迎就任意模块深入切磋。

**H2 "现场演示失败怎么办？"**
