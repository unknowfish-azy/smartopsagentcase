## 1. 国赛前端评分标准（自洽推导）

互联网+ 评审规则（教育 30 / 创新 20 / 团队 20 / 商业 / 就业 / 引领）并不直接考"美观"，但结合"AI Web 网页设计"赛道与 2026 行业规范，可推导**前端专属 6 维评分标准**。评委读界面时实际在验证这些。

| # | 评分维度 | 评委潜台词 | 我们的对应做法 | 验收门禁（要点） |
|---|---|---|---|---|
| D1 | **视觉专业度与一致性** | "这团队懂设计系统吗？" | Dark-First 设计系统、令牌统一（`--ds-*`）、单一 accent | 全站色/字/距遵循令牌；无 6+ 色杂用 |
| D2 | **信息架构与可读性** | "一眼能找到重点吗？" | Bento 网格、卡片层级、图表规范 | 首页 Bento 化；KPI 卡结构统一（标签→值→变化）；图表单高亮 |
| D3 | **交互与微体验** | "用着顺手吗？" | 微交互、状态反馈、骨架屏、WCAG 对比 | 悬停/提交/加载有反馈；正文对比度≥4.5:1；ARIA 到位 |
| D4 | **技术创新与主题契合** | "有亮点且贴题吗？" | 登录页 Liquid Glass+果冻+星空；控制台 AI 自适应雏形 | 品牌层有记忆点；不堆无关特效；与"可信运维"定位一致 |
| D5 | **性能与工程完整性** | "卡不卡、稳不稳？" | Lighthouse、rAF≤3、blur≤12px、虚拟滚动 | 控制台 `backdrop-filter` 元素 = 0；首屏无长任务 |
| D6 | **诚实与克制** | "有没有花架子？" | 不假大空、不炫技、不 emoji 图标、不渐变按钮 | 无装饰性大写侧栏、无彩虹 donut、无开场问候语 |

> **推导逻辑**：D1/D2 对应"教育维度"里的专业素养呈现；D4 对应"创新维度"；D3/D5 是工程基本功；D6 是诚信（与项目"可信"主张同源，评委最敏感）。**其中 D6 最易被忽视却最致命**——花哨界面会削弱"可信运维"的严肃感。

### 2.2 抖音 / 行业 2026 热门风格（与抖音热门一致）

| 风格 | 2026 定位 | 落到本项目 |
|---|---|---|
| **Liquid Glass 2.0** | 动态光学扭曲、空间层级、克制（浮层/状态面板/导航，不承载大段阅读） | 登录卡片 + 控制台浮层 |
| **Bento Grid** | 模块大小表达信息权重，SaaS dashboard 标配 | 控制台首页 KPI 区 |
| **果冻 / 3D 材质** | 高光泽、充气质感、弹性反馈按钮/卡片 | **登录页核心记忆点**（已方向正确） |
| **Aurora / 弥散渐变** | 柔和光斑营造氛围，hero 区 | 登录页星空底（已用内联 SVG 占位） |
| **Dark-First / Neumorphism / Micro-interactions / 技术单色** | 暗色为起点、柔内嵌阴影、微动画、终端风 | 控制台基调 |

> **结论**：你之前定的"星空+果冻登录 / 简约控制台"完全踩中 2026 主流，无需推翻，只需**按 Dribbble 实证规范把控制台做"对"**。

### 2.3 专业 Dashboard 实证规范（Dribbble/Behance 16 例研究，digitalapplied/ai-design-check）

**✅ 强设计一致做法（直接当控制台门禁）**
- Stat 卡自上而下：muted 标签 → 大数值 → 变化+周期（"+1.5% vs last month"）
- 卡片头统一：标题左、一个控制右（周期 / See all / ⋯）
- 图表：非激活系列浅灰，仅一个高亮用 accent 并直接标值（不彩虹）
- 浅/深底 + raised 卡片，**几乎无重阴影**
- 扁平主按钮；页头仅一个填充主操作
- 状态用小色块 pill + 点，同状态同色
- Hero 数值小数/分位暗化（$422,525.82）
- 单一 accent 色，少量使用
- 一套线性图标、一个尺寸
- 真实感数据（非 placeholder/乱码）

**❌ 反模式（门禁明确禁止）**
- 开场问候语（"Welcome back"）— 每日打开的屏幕，标题行最值钱
- 渐变按钮（尤其 AI 功能上的 sparkle 渐变）
- 彩虹 donut（5–6 色）— 弱设计标志
- 全大圆角（每张卡 20px+）— 风格非规则
- 装饰性大写侧栏标签（"MAIN MENU"）
- emoji 当图标

## 3. SmartOpsAgent 两界面设计方向

### 3.1 控制台（工具层 · 演示核心）
- **基调**：Dark-First 深色背景 + 微弱 raised 面板 + **单一 accent**（建议青/绿，贴合"可信·安全"语义，与红/黄告警形成系统色阶）。
- **布局**：首页 Bento 化（大 KPI 卡 + 图表 + 列表），模块大小表达权重；统一卡片头（标题左/操作右）。
- **图表**：非激活灰、单高亮 accent + 直接标值；状态用 tinted pill+dot。
- **微交互**：hover 抬升、提交反馈、骨架屏/进度；rAF ≤ 3（性能预算），不引入 WebGL 背景。
- **禁止**：全屏 blur、WebGL 背景、装饰大写侧栏、渐变按钮、emoji 图标、开场问候、彩虹 donut。

### 3.2 登录页（品牌层 · 记忆点）
- **底**：Aurora/星空渐变（内联 SVG 占位，已落地，去掉 1MB 位图）。
- **卡片**：Liquid Glass——blur ≤ 10px、单层内高光、细描边、14px 圆角（已定）。
- **果冻微交互**：聚焦 spring 形变落到 `::before` 装饰层（已修；`login-glass` 契约要求 `.login-form` 几何恒为 none）。
- **追光**：保留 `--login-light-x` 变量并降频（已做）。
- **语义**：星空+玻璃=高级可信，与"可信运维"主张一致，不花哨。
- **验收**：`login-glass` / `login-layout`(8 视口) / `meteor` 契约通过。

## 4. 验收门禁（交给其他大模型执行）

### 4.1 控制台门禁清单（来自 §2.3 + §3.1）
- [ ] 全站遵循 `--ds-*` 令牌，无硬编码 6+ 色
- [ ] 首页 Bento 化，KPI 卡结构统一（标签→值→变化+周期）
- [ ] 卡片头统一（标题左/单控制右）；图表单高亮 + 直接标值
- [ ] 状态 pill+dot 同状态同色；单一 accent
- [ ] 一套线性图标一个尺寸；数据真实感（无 placeholder 乱码）
- [ ] 无渐变按钮 / 无 emoji 图标 / 无装饰大写侧栏 / 无开场问候 / 无彩虹 donut
- [ ] 性能：控制台 `backdrop-filter` 元素 = 0、rAF ≤ 3、首屏无长任务

### 4.2 登录页门禁清单（来自 §3.2 + 既有契约）
- [ ] 星空底为内联 SVG（非位图）；Liquid Glass blur ≤ 10px、14px 圆角、细描边
- [ ] 果冻聚焦形变仅在 `::before` 装饰层，`.login-form` 几何恒 none（`login-glass.browser.mjs`）
- [ ] 追光 `--login-light-x` 变量保留且降频（≤ rAF 节流）
- [ ] `login-layout` 8 视口 + `meteor` 契约通过

### 4.3 全局性能门禁
- [ ] Lighthouse 性能 ≥ 90（桌面）；移动端可交互 ≤ 3s
- [ ] 双入口构建通过（dist / dist-admin）；既有 503 测试 + 前端契约零回归
