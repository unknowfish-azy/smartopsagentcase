## ④ 评委追问 Q&A（背要点）

**Q1：死循环怎么检测？为什么不用 LLM 自己判断？**
> 执行器维护滑动窗口内的动作指纹（工具名 + 参数规范化 JSON）。同一指纹在窗口内重复失败达阈值 → 强制终止并标记 `aborted_loop`。规则检测是 O(1) 确定性的，且不额外烧 token——LLM 判断只在反思层做，且反思次数有硬上限。

**Q2：为什么重试只对"幂等工具"开放？**
> 工具契约里有 `idempotency` 声明：`SAFE_RETRY`（只读）才允许指数退避重试；`AT_MOST_ONCE`（写库、下单类）**永不自动重试**——写操作重试可能造成真实损失，失败只能上报换方案。

**Q3：断点续跑怎么保证写操作不重复执行？**
> 每步执行完立即落盘 checkpoint（`PlanStore`）。恢复时按 `completed_step_ids` 过滤，**已成功的步骤直接跳过**。这对高危写操作是关键语义：宁可少做，不可重做。

**Q4：LLM 生成的计划可信吗？**
> 三重防线：① 计划里出现的工具必须在工具目录里存在，否则整体降级规则 Planner；② 参数必须是合法对象；③ **不信任 LLM 输出的 requires_approval**——按工具声明风险强制覆盖，HIGH/CRITICAL 一律要求人工审批。最终放行权在 PolicyEngine，不在 Planner。

**Q5：注入检测为什么用规则不用模型？**
> 与红线一致：这是**声明式规则分级**，不是"AI 识别风险"。规则可解释（每条命中规则都返回）、可热更、零成本、零延迟；输出带风险分 + 净化文本。模型审核可作为 checker 插件接入，但不是必需路径。

**Q6：记忆会不会越存越脏？**
> 四个机制：TTL 过期自动清除（写入/检索时双重触发）；owner 隔离（检索与按键取回双向，用户 B 检索不到用户 A 的私有记忆）；容量压缩（超限合并摘要而非无限增长）；幻觉固化问题由"反思失败即上报人工"兜底，不让错误结论自我确认。

**Q7：LLM 挂了整个 Agent 会不会瘫？**
> 三层降级：模型层 FallbackModelProvider 主→备切换（响应记录 `fallback_used` 链路）；规划层 LLM 失败自动落规则 Planner（标注 `rule-fallback` + 原因）；反思层评审失败退化规则裁决（有失败即重规划）。每一层都"永不中断、来源可溯"。
