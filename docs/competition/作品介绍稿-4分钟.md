## 二、正文（可直接朗读）

各位评委好，我们的作品是**智维Agent**——一个面向中小企业的可信 AI 智能运维与知识协同平台。

先说一个真实场景。【短停顿】凌晨两点，一台 MySQL 连接数打满，值班工程师打开搜索引擎，翻了七个帖子，试到第三条命令，服务彻底挂了。【长停顿】人手少、系统杂、知识散，这是中小企业运维的常态。

而今天的大模型，能"说"，却不敢让它"做"。【短停顿】结论没有证据，动作没有边界，过程没有留痕。【短停顿】这个作品，就是把这三件事补上。

所以我们做的不是一个"更会聊天的运维机器人"，而是一个**敢把生产环境交给它的 AI 同事**。

它把一次运维任务拆成监测、分析、知识检索、证据验证、规划、风险判断、人工审批、安全执行、结果验证、审计留痕、经验沉淀，十一个环节连成一个闭环。【短停顿】用户只说一句话，十一环自动跑完；但有三道关口，由规则和人把守。【长停顿】

**第一道，证据。** 运维知识最痛的不是"查不到"，而是"查到的是旧版本"——Ubuntu 22.04 的答案，套在 CentOS 6 上就是错的。【短停顿】我们给每个知识切片打上版本字段，检索时按目标环境过滤；召回走 BM25 关键词加向量双路，按 0.6 比 0.4 融合、重排取前五条；最后把每条证据的来源、版本、支持度，聚合成一个可信度评分。【短停顿】回答里的每句话，都能点回到具体条目。

**第二道，边界。** AI 可以规划，但不能自己决定动手。【短停顿】Agent 把故障拆成带依赖的步骤，策略引擎按权限与风险给每个动作定级；重启服务、改配置这类高危动作，必须转入人工审批，批准之后才在沙箱和命令黑白名单的约束下执行。【短停顿】一句话：AI 负责思考，人负责授权，系统负责执行。

**第三道，留痕。** 执行完不算结束。【短停顿】我们做了四级核查：L1 规则查风险分级与循环调用，L2 证据查版本一致性，L3 是可选的大模型判定，L4 状态核验专门抓"假成功"——Agent 声称"已重启成功"，但探针事实显示服务没起来，就直接判为不通过并重新规划。【短停顿】把这条思路延伸到恢复环节，就是我们的恢复契约：目标、版本、新鲜度、轮次、来源全部达标，才算真的恢复。【短停顿】42 个冻结案例里，"任意 200 就算恢复"的弱基线产生了 21 次假恢复；我们的实现与独立判定 42 比 42 完全一致，假恢复 0 次。【长停顿】

这不是一个 PPT 项目。【短停顿】后端 Spring Boot 加 MySQL，321 个 Java 文件、3.4 万行代码、422 个接口、119 张表；前端 Vue 3 双入口，175 个单文件组件；三层测试全量可复跑：前端 494 项、Python 610 个用例、后端 671 项，最近一次回归 0 失败。【短停顿】AI 侧接本地 Ollama，不联网、不需要任何密钥，也能完整跑通——评委在自己电脑上就能复现。

当然也有边界，我们主动说清楚。【短停顿】当前的向量嵌入是可复现的哈希方案，没有真实语义，接口已经留好，可以换成真实 embedding；规划器目前以规则为主，大模型规划的模板也已就绪。【短停顿】这是阶段性取舍，不是包装。

一句话收尾：【短停顿】我们做的不是"接个大模型就完事"的运维助手，而是一个**每句话有出处、每个动作有授权、每个结果有核验**的可信运维智能体。

汇报完毕，请各位评委批评指正。
