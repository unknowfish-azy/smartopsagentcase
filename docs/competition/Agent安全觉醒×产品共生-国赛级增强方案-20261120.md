# 智维Agent「安全觉醒 × 产品共生」国赛级增强方案

> 项目：智维Agent / SmartOpsAgent
> 日期：2026-11-20
> 定位：本方案解决两件事——**让 Agent 真正"有安全意识"**、**让 Agent 与产品功能长在一起**。
> 目标：国赛技术分（LLM 8 + Agent 8 + RAG 6 + 多模态 5 + 安全 4 + MCP 4 = 35%）逐项可证，演示可复现，答辩可攻防。

---

## 0. 一句话结论

现在项目里"安全"是一排**闸门**，"Agent"是一个**独立聊天框**。
国赛要拿奖，必须把它们变成：**一个有安全意识、能调用产品全部能力、每一步都留痕的运维主体**。

三句话打法：

1. **安全从"拦截"升级为"意识"**：Agent 先讲风险、再讲方案、讲不清就停、被攻击会说。
2. **Agent 从"聊天"升级为"产品大脑"**：同一身份、同一权限、同一份真实数据，跨 8 个页面侧翼、4 类事件驱动、5 类写回闭环。
3. **可信从"日志"升级为"账本"**：每次 run 的输入、风险、工具、证据、审批、结果，串成可校验哈希链，前端一键验证。

### 1.2 三个真实断点（必须修，否则演示会被问穿）

**断点 A：Agent 执行链与线上产品链路是两条线。**
- 线上：前端 → `ai-service` chat（LLM + RAG），`ChatService` 只做问答。
- 线下：`agent/assembly.py::build_agent_assembly()` 才是带安全基线的执行器，但**只被 `python -m agent` 和测试调用**，产品入口从未装配。
- 更关键：`agent/planner/react_agent.py::build_react_planner()` 创建 `AgentExecutor` 时**没有注入 `security_engine`**（第 70-74 行），也就是说 ReAct 规划路径绕过了 L0-L3。
- `agent/orchestrator/direct_executor.py` 直接 HTTP 调后端 `/api/robot/*`，同样不经过基线闸门。

> 评委只要问一句"你的 L0-L3 到底在哪个线上入口生效"，现在答不圆。

**断点 B：Agent 工具不覆盖产品真实能力。**
- 现有工具：`filesystem`、`shell`、`server`、`knowledge`、`nn_perception` + docker/k8s/mysql/nginx/redis/robot 插件 + `http`/`mcp`/`python` 适配器。
- 产品已有 60+ 控制器，但**没有** sentinel、inspector、security posture、incident、SLO、audit、knowledge candidate 的工具。
- 结果：Agent 只能"泛泛而谈运维"，不能"说出这个系统此刻发生了什么"。

**断点 C：安全只拦不说，产品里看不见。**
- 拦截发生在 `ChatService` 内部，前端只看到一句拒答。
- 审计链只在 `data/security_audit/*.jsonl`，没有页面入口。
- 用户不知道"为什么被拦、谁批的、改了什么、怎么回滚"。

### 3.1 一脑：统一 Agent Runtime

新增 `ai-service/app/services/agent_runtime.py`，作为**唯一 Agent 入口**：

```python
# 伪代码，接线示意
class AgentRuntime:
    def __init__(self):
        self.assembly = build_agent_assembly(
            tools=build_product_tools(...) + build_nn_perception_tools(),
            dag=True,
            security_enabled=True,
        )

    async def run(self, req: AgentRunRequest) -> AgentRunResult:
        # 1) 输入闸门（L1 注入 + 合规）
        # 2) 意图与风险定级（规则 + 产品上下文）
        # 3) 生成 SecurityBrief（确定性组装，LLM 只写叙述）
        # 4) 需要审批 → 返回 pending，不执行
        # 5) 执行（DAG，工具级 PolicyEngine）
        # 6) 结果核查（Inspector）
        # 7) 写回 + 审计事件
```

接入策略（低风险、可回滚）：
- `ChatService` 保持现状处理"纯问答"。
- 新增意图分流：命中"变更/执行/巡检/处置/根因"关键词或页面显式 `mode=agent` 时，转 `AgentRuntime`。
- **不删除任何现有路径**；`AgentRuntime` 内部复用 `ChatService` 的 RAG 与模型网关。
- `build_react_planner()` 的 `executor` 默认改为注入 `security_engine`（修断点 A 的最小改动，1 行接线 + 1 条回归测试）。

## 4. 左翼详细设计：安全意识六感（S-Aware）

### 4.1 六感定义

| 感知 | 回答的问题 | 数据来源 | 确定性/模型 |
|---|---|---|---|
| 风险感 Risk Sense | 这个请求有多危险？ | 意图规则 + 工具 `risk_level` + L0/L2 红线 | 确定性优先 |
| 影响感 Blast Radius | 会波及谁？ | `/api/cloud/resources`、`/api/servers`、`/api/incidents`、资产关系 | 确定性 |
| 约束感 Policy Sense | 允许我做什么？ | 会话权限、`PolicyEngine`、限流、审批 | 确定性 |
| 自省感 Introspection | 我是不是被诱导了？ | `InjectionDetector`、零宽字符、base64、越权承诺 | 确定性 |
| 证据感 Evidence Sense | 我凭什么这么说？ | RAG 引用、工具返回、审计事件 | 确定性 |
| 止损感 Rollback Sense | 出事怎么退？ | 变更类工具必须声明回滚与验证 | 确定性模板 + 人工确认 |

> 关键设计：**六感由确定性代码生成，LLM 只负责把 JSON 翻译成人话**。这样"安全意识"不会变成模型幻觉，答辩时敢说"每一条风险都有规则来源"。

### 4.2 SecurityBrief 契约（前后端共用）

```json
{
  "schema": "smartops.security_brief.v1",
  "run_id": "run_01J...",
  "intent": "restart_service",
  "risk_level": "HIGH",
  "risk_reasons": ["L2_DESTRUCTIVE_RESTART", "BLAST_RADIUS>=3"],
  "blast_radius": {
    "assets": ["svc-order-api", "svc-order-worker"],
    "services": ["order"],
    "estimated_users": 1200,
    "data_refs": ["/api/cloud/resources?business=order"]
  },
  "preconditions": ["确认无进行中的发布", "确认备份可用"],
  "rollback_plan": "保留旧镜像 digest，失败 60s 内回滚",
  "verification_plan": ["健康检查 200", "错误率 < 0.5% 持续 5 分钟"],
  "required_approvals": ["operator:admin", "change_window"],
  "evidence_refs": ["knowledge:doc_123#L40", "audit:evt_88", "sentinel:alert_9"],
  "confidence": 0.82,
  "data_sources": ["POSTURE", "SENTINEL", "RAG", "AUDIT"],
  "honesty_note": "影响面为规则估算，非实际压测值"
}
```

前端渲染为 `SecurityBriefCard.vue`：风险等级色带 + 影响面 + 回滚/验证 + 证据抽屉 + "为什么这样判断"展开。

### 4.3 七条行为准则（写进系统提示 + 确定性后校验）

| 编号 | 准则 | 落点 |
|---|---|---|
| S1 | 先说风险，再说方案 | 系统提示 + brief 必填 |
| S2 | 高危操作必须回答"影响面/回滚/验证"三问 | 缺一项则补全模板不通过 |
| S3 | 不确定就停，交给人 | `confidence < 0.6` → `requires_human=true` |
| S4 | 越权不做，工具白名单 + scope | `PolicyEngine` + ToolBus scope |
| S5 | 被攻击要报告 | 注入命中 MEDIUM 及以上 → 明示"该输入包含可疑指令" |
| S6 | 不泄露、不编造 | 输出审核 + 证据引用 |
| S7 | 每个结论带证据与置信度 | `evidence_refs` 非空校验 |

**S5 是差异化亮点**：大多数参赛项目被注入就静默拦截；本项目会告诉用户"你这段输入里有指令覆盖模式，我没有执行"。这是"安全意识"最像人的地方。

### 4.4 落地改动

- 新增 `agent/awareness/brief.py`：确定性 `SecurityBriefBuilder`。
- 新增 `agent/awareness/intent_risk.py`：意图 × 工具 × 上下文三维评分（复用 `agent/router/complexity.py` 的 L0-L4）。
- 新增 `agent/awareness/narrator.py`：模板化叙述（不调 LLM 也能出简报，保证 fail-closed 可用）。
- `SecurityBaselineEngine.evaluate_input()` 返回值扩展 `awareness_hint` 字段（可选，不破坏现有契约）。
- 系统提示新增 S1-S7 段落，但**只作为表达层**，判定仍由代码负责。

    name: str
    method: str
    path: str
    risk: RiskLevel
    requires_approval: bool
    scopes: tuple[str, ...]      # 例如 ("knowledge:read", "robot:control")

### 5.2 身份与权限透传（这是"强结合"的命门）

- 工具调用必须携带**当前用户会话**，不使用超级账号偷看数据。
- 复用既有 `getCurrentUser` / `@CurrentUser` 权限模型，工具 scope 与页面权限一致。
- `SMARTOPS_AGENT_TOKEN` 仅用于**系统级只读巡检**，且工具表标注 `principal=system`，在审计里区分"人发起 / 系统发起"。
- 新增单测：普通用户调用 `robot.task.create` 必须 403；`audit.chain` 只返回本用户可见范围。

### 5.3 页面侧翼：8 个页面，各回答一个"此刻"的问题

新增通用组件 `frontend/src/components/agent/AgentCopilotDock.vue`，接收页面上下文：

```ts
interface PageContext {
  path: string;        // 已在 ChatRequest.context 中支持
  section?: string;
  entity?: { type: 'alert'|'event'|'finding'|'device'|'doc'|'incident'; id: string };
  snapshot?: Record<string, unknown>; // 白名单只读摘要，禁止整页 DOM
}
```

| 页面 | 侧翼入口文案 | 注入上下文 | Agent 能力组合 |
|---|---|---|---|
| 哨兵 `/sentinel` | "解释这条告警并给出处置建议" | 当前告警 id + 指标窗口 | sentinel.alerts → sentinel.metrics → knowledge.search |
| 纠察 `/inspector` | "这条事件根因是什么？" | 事件 id | inspector.events → knowledge.search → inspector.event.create |
| 知识空间 `/knowledge/space` | "这条内容能入库吗？" | 文档 id | knowledge.search → knowledge.candidate.submit |
| 安全态势 `/security` | "这个 CVE 影响哪些资产？先修哪个？" | finding id/target | security.posture → cloud.assets → runbook.draft.create |
| 机器人 `/robot` | "接管前风险自查" | 设备 id | robot.fleet → robot.device.live → 风险简报 |
| 运维 `/operations` | "这台机器为什么慢？" | server id | servers.list → server.metrics → 日志诊断子智能体 |
| 模型网关 `/model` | "这个连接为什么限流？" | connection id | model.gateway.status → 失败率证据 |
| 诊断 `/diagnostics` | "把这次诊断沉淀成 Runbook" | diagnostic run id | 诊断结果 → runbook.draft.create |

> 关键：侧翼**不是新聊天页**，是"带着本页实体来问"。这样演示时评委会看到"点了告警旁边的按钮，Agent 直接说出这条告警的指标和影响面"，而不是"打开一个通用聊天框"。

### 5.4 事件驱动：Agent 主动上岗（只读、只写 REVIEW）

```text
Sentinel 告警/纠察事件
   → backend 内部触发 POST /api/internal/agent/trigger （X-Internal-Token，fail-closed）
   → AgentRuntime 只读诊断（sentinel.alerts + metrics + knowledge.search）
   → 生成 SecurityBrief + 处置建议
   → 写入 inspector 事件（status=REVIEW, requiresHuman=true）
   → 前端纠察页出现"AI 初诊"卡片，人工确认后才可执行
```

硬约束（必须写进方案与代码）：
- 只读工具白名单固定，禁止写操作。
- 模型不可用时**不生成事件**，只记 WARN，绝不伪造结论（沿用诚实性铁律）。
- 单资源 5 分钟防抖，避免告警风暴刷屏（复用 `alert_correlation` 口径）。
- 每次触发计入 `agent_run`，可审计、可回放。

### 5.5 写回闭环（回答不是终点）

| Agent 产出 | 写回目标 | 状态 | 后续动作 |
|---|---|---|---|
| 故障结论 | `inspector.event` | REVIEW | 人工复核 → 关闭 |
| 知识解释 | `knowledge.candidate` | PENDING_REVIEW | 审核 → 入库 → 下次召回 |
| 处置步骤 | `runbook` | DRAFT | 人工完善 → 发布 |
| 风险判断 | `security_brief` + `audit_event` | 落链 | 可验链 |
| 操作执行 | `audit_event` + `agent_run` | 落链 | 可回放 |

演示时可现场点"采纳为知识候选"，展示从对话到知识库的真实链路。

## 6. 三条端到端主线（演示与材料共用）

### 主线 1：疑似入侵响应（跨 6 页，3 分半）

1. 哨兵页出现异常分升高 + 登录失败激增告警。
2. 点侧翼："解释这条告警" → Agent 调 `sentinel.metrics` + `knowledge.search`，给出"疑似暴力破解"结论 + 证据 + 置信度 0.78。
3. 纠察页出现 AI 初诊事件（REVIEW）。
4. 安全态势页：Agent 关联 Trivy 命中（openssh 版本）+ 影响资产清单。
5. 提出处置方案：封禁 IP / 升级组件 / 轮换密钥。前三项为 HIGH，进入审批。
6. 管理员审批 → 执行只读验证 → 审计链一键校验 ok。
7. 结论写回知识候选，现场采纳。

**评委看到的是**：同一份数据、同一个身份、跨页面连续推理、每一步有闸门、每一步留痕。

### 主线 2：高危变更（拦截 → 审批 → 灰度 → 回滚预案）

- 用户输入"帮我把 order 服务重启一下"。
- Agent 不直接执行，先出 `SecurityBrief`：影响 2 个服务/约 1200 用户/无进行中发布才可执行/回滚方案/验证指标。
- 用户确认 → 工具 `restart` 为 HIGH → 审批卡 → 管理员批准 → 执行 → 验证失败 → 一键回滚（dry-run 已验证回滚路径）。
- 审计链展示"谁批的、批的什么参数、执行结果"。

**这是"敢让它动手"的最强证明。**

### 主线 3：知识沉淀（一次故障变下一次能力）

- 诊断 → Runbook 草稿 → 知识候选 → 审核入库。
- 下一次同类告警，RAG 直接召回刚沉淀的文档，附引用。
- 展示"知识版本 + 引用片段 + 命中次数"。

## 12. 诚实边界（红线，答辩必答）

1. 不宣称"自动修复"：只做"受控执行 + 人工授权 + 可回滚"。
2. 不宣称"漏洞扫描"：安全态势只接入 Trivy/kube-bench/Falco 报告，主动扫描不在范围（`SecurityPostureController` 注释已明示）。
3. 不宣称"零误杀"：给出误杀率与降权机制，承认边界。
4. 影响面是规则估算，标注"非压测值"。
5. 数据集小：指标带 n，不做"准确率 9X%"式宣传。
6. 多租户隔离是应用层，不宣称物理隔离。

## 14. 答辩 10 问速答

1. **你的安全和别人有什么不同？** 别人是护栏，我们是六感能力，且确定性生成、可追溯。
2. **L0-L3 在哪个线上入口生效？** 统一 Runtime 三入口（chat/agent/trigger），W1 有测试证明。
3. **Agent 会不会乱调工具？** 17 个工具全部声明风险与 scope，HIGH 必须审批，CRITICAL 禁止自动执行。
4. **注入怎么防？** 规则 + 零宽/base64 + 学习语境降权 + 输出侧越权承诺改写；红队语料 ≥60 条。
5. **影响面怎么算的？** 资产关系 + 事件 + SLO 三源，规则估算并明确标注。
6. **审计能证明什么？** 哈希链可校验、可定位到 run/工具/审批/参数。
7. **模型挂了怎么办？** 简报与验链走确定性路径，模型不可用时不产结论、不伪造。
8. **和产品怎么结合？** 12 读 5 写工具、8 页侧翼、事件驱动、5 类写回。
9. **有什么没做？** 主动扫描、自动修复、物理隔离——直说，反而显成熟。
10. **怎么证明不是 PPT？** 现场跑 3 条主线 + 一键验链 + 指标 CSV。
