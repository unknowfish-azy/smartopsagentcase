# M05 真人评者协调方案

- 版本：2026-11-13｜状态：待规划者确认评者人选与截止日
- 目标：产出 3 个维度（有用性 / 准确性 / 可信度）的均分与两两 Cohen's κ，n 与缺失情况如实标注
- 判定口径：**κ > 0.6 才能在材料中写"一致性良好"**；未达标只能报数值与分歧说明，禁止写"专家一致认可"
- 已有工具：`scripts/eval_blind_review.py`（κ 经 sklearn 交叉验证）、`reports/t1-20261113/m05_ratings_template.csv`（30 样本 × 3 评者 × 3 维度空白表）

## 1. 前置条件（未满足前不要发评分表）

| 前置 | 现状 | 负责方 |
|---|---|---|
| 30 条**真实系统回答**正文 | **已就绪（2026-11-13）**：`reports/t1-20261113/m05/answers.jsonl`，30/30 成功无空回答。S27 首次采集命中 ai-service 开发桩兜底，已重采替换并归档原始记录（`answers_replaced_S27.jsonl`） | 实现模型（已完成） |
| 样本脱敏与编号 S01–S30 | **已就绪**：`scripts/prepare_blind_packs.py` 生成，敏感词扫描通过，三份乱序评分包在 `m05/packs/`（种子 20261114/15/16 可复现），私有映射表 `answers_mapping_private.csv` 不随包发出 | 实现模型（已完成） |
| 评者 3 人确认 | 待做 | 规划者 / 队长 |
| 评分细则培训用练习样本（3 条，不计入正式 n） | 待做，从补采样本外的问题中选取 | 实现模型 |

> 红线：30 条回答必须是系统真实输出，不得人工润色、不得挑选"好看的"、不得用 AI 生成"标准答案"替代。抽样规则（见 §2）确定后不得因评分结果更换样本。

## 2. 样本集制作

1. 题目来源：M03 已用的 20 条固定提问 + 追加 10 条同风格运维提问（覆盖 7 类场景），共 30 题。
2. 每题取一次完整回答，保留原始文本；记录 `sample_id / question / answer / 采集时间 / 模型版本`。
3. 脱敏：删除系统名、模型名、版本号、界面截图标识、任何"本系统/我们的 Agent"字样；统一为纯文本"问题 + 回答"。
4. 编号映射表 `answers_mapping_private.csv` **只由协调人保管，不发给评者**。
5. 发给评者的只有 `S01–S30` 的题目与回答，顺序按评者分别随机打乱（防顺序疲劳偏差）。

## 3. 评者构成与要求

| 角色 | 建议人选 | 要求 |
|---|---|---|
| R1 | 有运维/后端经验的成员或同学 | 能判断技术准确性 |
| R2 | 非本项目的教师/助教或高年级同学 | 外部视角，未看过本项目材料 |
| R3 | 第三方（其他组成员/校友/实习同事） | 与开发无利益关联 |

共同约束：**未参与回答生成、不阅读源码与技术报告、评分期间互不讨论、独立完成后才允许集中复核**。
利益冲突申报：凡参与过本项目开发或答辩稿撰写的人不能当评者，只能做协调人。

## 4. 评分细则（1–5 分行为锚点，培训时逐条讲清）

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| 有用性 usefulness | 给出可立即执行的排查/处置步骤，顺序合理 | 有方向但缺少可操作细节 | 泛泛而谈，无法指导行动 |
| 准确性 accuracy | 技术事实正确，命令/路径/概念无误 | 大体正确但有明显瑕疵或过时信息 | 存在事实性错误或危险建议 |
| 可信度 trust | 结论有依据、边界清楚，不编造不夸大 | 结论基本可信但依据不充分 | 断言无据、编造细节或过度承诺 |

规则：每格必填整数 1–5；确实无法判断的格子**留空**，汇总脚本会跳过并按实际 n 报告，禁止猜分凑满。

## 5. 执行流程（按阶段推进，日期由规划者填）

| 阶段 | 动作 | 产出 | 完成标志 |
|---|---|---|---|
| P0 准备 | 补采 30 条回答、脱敏、编号、生成 3 份乱序评分包 | 评分包 ×3 + 私有映射表 | 协调人抽检脱敏无遗漏 |
| P1 校准 | 3 人同做 3 条练习样本，逐条讨论锚点理解 | 练习记录（不计入正式） | 对"5/3/1 分"理解一致 |
| P2 正式评分 | 各自独立完成 30 条 × 3 维度，共 90 格/人 | R1/R2/R3 三份已填 CSV | 回收率、空格数登记 |
| P3 校验 | 检查 score 是否 1–5、维度是否齐全、有无整列同分 | 校验记录 | 异常项由评者本人确认，协调人不得代改 |
| P4 计算 | 合并三份为长表，运行脚本出均分与 κ | `m05_summary.json` | 结果可复现 |
| P5 复核与归档 | 分歧样本复核、原始表与脚本输出归档 | 归档包 | 见 §7 分歧处理 |

回收文件命名：`m05_ratings_R1.csv` / `_R2` / `_R3`，合并为脚本要求的长表格式 `sample_id,rater,dimension,score`。

## 6. 计算与结果引用

```bash
python scripts/eval_blind_review.py --ratings reports/t1-20261113/m05_ratings_filled.csv \
  --json reports/t1-20261113/m05_summary.json
```

输出含每维度 `n_ratings / n_samples / mean / pairwise_kappa(R1|R2、R1|R3、R2|R3) / mean_pairwise_kappa`；某评者零方差时 κ 为 null 并给原因，此时**不得**改用其他指标冒充一致性。

引用模板（按实际结果填，不许先写结论后凑数）：
> 30 条真实回答经 3 名独立评者盲评（每人 90 格），有用性均分 X.XX（n=）、准确性 X.XX（n=）、可信度 X.XX（n=）；两两 Cohen's κ 分别为 …，平均 κ=0.XX。κ 低于 0.6 的维度，本报告仅呈现数值并说明分歧来源。

## 7. 分歧处理

- κ ≤ 0.6：先检查是否锚点理解偏差（练习环节是否到位），再抽取分歧最大的 5 条样本做**集中讨论**，但**原始评分不得修改**。
- 如评者愿意修订，启动第二轮评分并另存文件；报告中**两轮结果并列**，禁止只保留变好的一轮（红线②）。
- 出现整列同分、全 5 分或全 3 分等无效评分模式：该评者数据标记为无效并说明，宁可降级为 2 人结果，也不纳入凑数。

## 8. 降级方案（人手不足时）

| 可用评者 | 可交付 | 材料口径 |
|---|---|---|
| 3 人 | 均分 + 两两 κ（完整方案） | 可写"3 名独立评者"，κ>0.6 才写一致性良好 |
| 2 人 | 均分 + 单对 κ | 明写"2 名评者"，不得暗示三人一致性 |
| 1 人 | 仅均分，**κ 不可计算** | M05 的 κ 仍标 NOT_RUN；只描述单人评阅结果 |
| 0 人 | 无 | M05 整体 NOT_RUN，保留本方案作为协议，禁止用 AI 自评替代 |

样本量不足 30 时同样允许，但所有引用必须带真实 n，且不得与 30 样本口径混排比较。

## 9. 红线与归档

1. 评分必须来自真人；AI 代评、补分、润色回答均违规。
2. 原始评分表、合并长表、汇总 JSON、私有映射表一并归档（建议 `reports/t1-20261113/m05/`），供复核抽查。
3. 材料中只引用脚本输出值，保留 n=；禁止"准确率 9X%""专家一致认可"等无证据表述。
4. 评者信息在公开材料中匿名化（R1/R2/R3 + 背景描述），联系方式不出现在仓库。
