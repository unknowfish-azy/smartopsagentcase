# SmartOps 通用单片机固件协议（generic-mcu-v1）

> 协议版本：v1<br>
> 适用链路：`robot-bridge` ↔ 单片机固件<br>
> 传输方式：BLE 或串口<br>
> 当前范围：P0 运动控制与遥测（`HELLO / HELLO_ACK / MOVE / STOP / TELEMETRY / CMD_ACK / EVENT`）<br>
> 参考实现：[generic_mcu_v1.py](../../robot-bridge/protocols/generic_mcu_v1.py)、[bridge.py](../../robot-bridge/bridge.py)

本文是配套固件的实现契约，不冒充任何厂商私有协议。文中的“必须”表示接入 SmartOps 的必要条件，“应”表示推荐实现，“可”表示可选能力。

**安全边界：协议联调通过不等于真机安全验收通过。首次测试必须架空驱动轮或断开执行机构，确认急停、TTL 停车和断连停车后再落地测试。**

---

## 1. 协议范围与角色

```text
前端 / Agent
      │ WebSocket / REST
      ▼
SmartOps backend
      │ WebSocket（JSON，不属于本文协议）
      ▼
robot-bridge
      │ BLE Write / Notify，或串口字节流（本文协议）
      ▼
单片机固件 → 电机驱动、里程计、电量计、避障与急停电路
```

- 桥向固件发送：`HELLO`、`MOVE`、`STOP`。
- 固件向桥发送：`HELLO_ACK`、`TELEMETRY`、`CMD_ACK`、`EVENT`。
- P0 仅支持 `MOVE/STOP` 两类运动命令。`PTZ/SPEAK/CAPTURE/PATROL` 不在本协议中编码，桥会明确拒绝，不得使用保留类型自行透传。
- 后端控制租约 `leaseId/epoch`、 stopped 证明、多机任务租约不属于 v1 P0，不得伪造相关能力。

## 2. 传输约定

### 2.1 BLE

协议不固定 UUID，部署时必须通过桥 CLI 显式配置以下三个 UUID，并确保与固件 GATT 一致：

| GATT 项 | 固件要求 | 桥参数 |
|---|---|---|
| 自定义服务 | 包含下列两个特征值 | `--service-uuid` |
| 指令特征值 | 支持 **Write With Response**，接收完整二进制帧 | `--write-char-uuid` |
| 遥测特征值 | 支持 **Notify**，上报 `HELLO_ACK/TELEMETRY/CMD_ACK/EVENT` | `--notify-char-uuid` |

- 不要在 BLE 包中额外添加长度前缀、ASCII 十六进制、JSON 或 `0D 0A`。
- 当前最长标准报文是 20 字节的 `TELEMETRY`，其余 P0 报文均不超过 16 字节，可放入默认 ATT MTU 23 的 20 字节应用负载。
- 桥按流式解析处理通知；固件仍应每次通知发送一个完整帧，避免不必要的跨通知拆包。
- BLE 配对/绑定策略由设备安全设计决定，协议字段不携带配对密钥或桥 token。

### 2.2 串口

默认参数：

```text
115200 baud，8 data bits，no parity，1 stop bit（8N1），无硬件流控
```

串口没有天然报文边界。固件接收端必须支持半包、粘包、噪声和跨包帧头 `AA 55`，不能假设一次 `read()` 恰好返回一帧。

## 3. 二进制帧

### 3.1 帧布局

所有多字节整数均使用**大端序（big-endian）**。

```text
AA 55 | version:u8 | type:u8 | seq:u16 | length:u16 | payload[N] | crc16:u16
```

| 字节偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | `SOF` | 固定 `AA 55` |
| 2 | 1 | `version` | 帧格式版本，v1 固定 `01` |
| 3 | 1 | `type` | 消息类型，见第 4 节 |
| 4 | 2 | `seq` | 本帧序号，大端 `u16` |
| 6 | 2 | `length` | `payload` 字节数 `N`，大端 `u16`，范围 0～512 |
| 8 | N | `payload` | 消息负载，可以为空 |
| 8+N | 2 | `crc16` | CRC16/CCITT-FALSE，大端 `u16` |

总长度为 `N + 10` 字节。CRC 覆盖从 `version` 到 `payload` 末尾的全部字节，即帧内 `[2, 8+N)`，**不包含 `AA 55`，也不包含 CRC 字段自身**。

### 3.2 序号规则

- 每个发送方向独立维护 `seq`，固件和桥无需使用相同序号。
- 序号从 1 开始，每发送一帧递增；达到 `0xFFFF` 后回绕到 `0x0001`，跳过 `0x0000`。
- `HELLO` 也占用桥发送序号。正常首会话中，桥通常发送 `HELLO.seq=1`、首条 `MOVE.seq=2`，但固件不得硬编码该假设。
- `CMD_ACK.commandSeq` 必须填写被确认的 `MOVE/STOP` 的 `seq`，而不是 ACK 自身的 `seq`。
- 重连后必须重新握手。桥会清理半包和待确认命令，但保持自身命令序号单调，避免旧 ACK 误配新命令。
- v1 桥不依据序号去重；固件可记录最近命令序号用于诊断，但不得仅因序号不连续而拒绝安全 `STOP`。

### 3.3 CRC16/CCITT-FALSE

参数：

| 参数 | 值 |
|---|---|
| 宽度 | 16 bit |
| 多项式 | `0x1021` |
| 初始值 | `0xFFFF` |
| 输入反射 | 否 |
| 输出反射 | 否 |
| 结果异或 | `0x0000` |

标准校验串 ASCII `123456789` 的 CRC 必须为 `0x29B1`。

固件可直接使用以下 C 实现：

```c
#include <stddef.h>
#include <stdint.h>

uint16_t smartops_crc16(const uint8_t *data, size_t length) {
    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < length; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (unsigned bit = 0; bit < 8; ++bit) {
            crc = (crc & 0x8000u)
                ? (uint16_t)((crc << 1) ^ 0x1021u)
                : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

计算时，`data` 指向帧内偏移 2 的 `version`，长度为 `6 + N`。

### 3.4 接收与重同步

固件接收状态机必须满足：

1. 搜索 `AA 55`，帧头前的噪声直接丢弃。
2. 不足固定头或完整负载时保留缓冲区，等待后续字节。
3. `length > 512` 时丢弃当前候选帧头并重新搜索，禁止按该长度分配内存。
4. `version != 1`、CRC 错误、类型未知或负载长度不符合消息定义时，不生成有效命令或遥测。
5. 正确处理 `AA 55` 被拆在两次读取之间，以及多帧被合并在一次读取中的情况。
6. 非法帧不得触发运动；解析失败可使用本地日志计数，不得猜测负载含义。

## 4. 消息类型总览

| 类型 | 值 | 方向 | 负载长度 | 必需性 |
|---|---:|---|---:|---|
| `HELLO` | `0x01` | 桥 → 固件 | 4 | 必须 |
| `HELLO_ACK` | `0x02` | 固件 → 桥 | 4 | 必须 |
| `MOVE` | `0x10` | 桥 → 固件 | 6 | 必须 |
| `STOP` | `0x11` | 桥 → 固件 | 0 | 必须 |
| `TELEMETRY` | `0x20` | 固件 → 桥 | 10 | 必须 |
| `CMD_ACK` | `0x30` | 固件 → 桥 | 4 | 必须 |
| `EVENT` | `0x31` | 固件 → 桥 | 2 | 必须 |

## 5. 消息定义

### 5.1 HELLO（0x01）与 HELLO_ACK（0x02）

两者负载结构相同：

| 负载偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | `protocolVersion` | 大端 `u16`，v1 固定 `0x0001` |
| 2 | 2 | `capabilities` | 大端 `u16` 能力位图 |

能力位：

| 位 | 值 | 能力 | P0 要求 |
|---|---:|---|---|
| bit 0 | `0x0001` | `MOVE` | 必须声明 |
| bit 1 | `0x0002` | `TELEMETRY` | 必须声明 |
| bit 2 | `0x0004` | `CMD_ACK` | 配套固件必须声明 |
| bit 3～15 | 其他 | 保留 | 发送 0 |

标准能力值为 `0x0007`。

握手时序：

1. 桥建立传输连接后发送 `HELLO`。
2. 固件必须在 **5 秒内**回复 `HELLO_ACK`。
3. 桥只接受 `protocolVersion=1`，且能力同时包含 `MOVE|TELEMETRY` 的应答。
4. 超时、版本不符、能力不足或传输断开时，桥不会向后端声明真机在线。
5. 握手成功前，电机输出必须保持安全停止。握手成功后固件才开始正常运动命令处理。
6. 每次重连都必须重新执行握手，不得沿用上一次连接的运动状态。

### 5.2 MOVE（0x10）

负载固定 6 字节：

| 负载偏移 | 长度 | 类型 | 字段 | 范围与单位 |
|---:|---:|---|---|---|
| 0 | 1 | `int8` | `x` | -100～100，前进/后退量 |
| 1 | 1 | `int8` | `y` | -100～100，横移量 |
| 2 | 1 | `int8` | `theta` | -100～100，转向量 |
| 3 | 1 | `uint8` | `speed` | 0～100 % |
| 4 | 2 | `uint16` | `ttlMs` | 50～500 ms，大端 |

桥从后端归一化参数转换：`x/y/theta = round([-1,1] × 100)`，`speed = round([0,1] × 100)`。

配套固件统一采用以下方向约定：

- `x > 0` 前进，`x < 0` 后退。
- `y > 0` 向左横移，`y < 0` 向右横移。
- `theta > 0` 逆时针转向，`theta < 0` 顺时针转向。
- 不支持横移的差速平台必须将 `y` 按 0 处理，不得把横移量映射成前进或转向。
- `speed=0` 或三个轴均为 0 时，应保持停止并刷新安全状态，不得沿用上一次非零速度。

**TTL 是固件本地安全要求，不是网络提示：**

1. 每收到一条合法 `MOVE`，启动或重新装载本地单调计时器，超时时间为该帧 `ttlMs`。
2. 在 TTL 内未收到新的合法 `MOVE` 或 `STOP`，必须撤销运动输出并停车。
3. 推荐使用 200 ms 默认周期接收续传；即使后端或桥仍显示在线，TTL 到期也必须独立停车。
4. TTL 到期后可上报 `EVENT/STOPPED(value=2)`。不得等待后端再次确认才停车。
5. `ttlMs < 50` 或 `ttlMs > 500` 的帧必须拒绝并回复 `CMD_ACK(status=INVALID)`，不得钳位后执行。

### 5.3 STOP（0x11）

负载长度必须为 0。

- `STOP` 是最高优先级协议命令，必须立即撤销运动输出，不等待当前运动段结束。
- 收到 `STOP` 后必须清除或取消 MOVE TTL 续跑状态，后续不得因旧定时器或旧队列恢复运动。
- 建议在运动输出已撤销后回复 `CMD_ACK(status=OK)`。
- 若本地急停或驱动故障使状态无法确认，应回复相应失败状态并上报 `TELEMETRY/EVENT`。
- 本地安全策略要求锁存急停时，固件必须保持锁存，收到后续 `MOVE` 也不得自行解除。
- P0 的 STOP ACK 只表示设备对停止命令的处理结果，不构成 P1 的租约化 `stopped` 证明。

### 5.4 TELEMETRY（0x20）

负载固定 10 字节：

| 负载偏移 | 长度 | 类型 | 字段 | 单位与说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | `battery` | 电量百分比 0～100；大于 100 非法 |
| 1 | 2 | `int16` | `x` | 位姿 X，厘米 |
| 3 | 2 | `int16` | `y` | 位姿 Y，厘米 |
| 5 | 2 | `int16` | `theta` | 航向角，0.1° |
| 7 | 2 | `uint16` | `obstacle` | 最近障碍距离，厘米；`0xFFFF` 表示未知 |
| 9 | 1 | `uint8` | `flags` | 状态位，见下表 |

`flags`：

| 位 | 值 | 含义 | 固件行为 |
|---|---:|---|---|
| bit 0 | `0x01` | 本地急停 | 置位时必须已停止运动输出 |
| bit 1 | `0x02` | 障碍停车 | 避障触发期间置位 |
| bit 2 | `0x04` | 低电量 | 达到固件低电阈值时置位 |
| bit 3～7 | 其他 | 保留 | 发送 0 |

其他要求：

- 位姿可使用固件里程计原点，但同一次运行会话内必须连续，单位与轴向必须与第 5.2 节一致。
- `theta` 例：`900` 表示 `90.0°`，`-450` 表示 `-45.0°`。
- 障碍传感器不可用时必须发送 `0xFFFF`，不得用 0 冒充“零距离”。
- 桥会将电量除以 100、位姿 X/Y 和障碍距离除以 100 转成米、航向除以 10 转成度。
- 固件必须周期上报遥测，静止时也不能停止。推荐周期 **200 ms（5 Hz）**；正常情况下连续遥测间隔必须小于后端默认 600 ms 心跳超时。
- `simulated=false` 是桥生成的后端 JSON 字段，不在 MCU 二进制帧中传输。

### 5.5 CMD_ACK（0x30）

负载固定 4 字节：

| 负载偏移 | 长度 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| 0 | 2 | `uint16` | `commandSeq` | 被确认的 MOVE/STOP 序号，大端 |
| 2 | 1 | `uint8` | `status` | 处理状态 |
| 3 | 1 | `uint8` | `reason` | 原因码，0 表示无附加原因 |

`status`：

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | `OK` | 命令已接受并执行相应处理 |
| 1 | `INVALID` | 类型、负载长度或参数非法 |
| 2 | `BUSY` | 当前本地状态暂不能执行 |
| 3 | `EXPIRED` | 保留给后续带新鲜度信息的命令；P0 通常不使用 |
| 4 | `FAILED` | 驱动或本地执行失败 |

配套固件使用以下 `reason`；当前桥仅透传数值，不据此推断安全状态：

| 值 | 名称 | 建议场景 |
|---:|---|---|
| 0 | `NONE` | 无附加原因 |
| 1 | `INVALID_PARAM` | 参数或负载长度非法 |
| 2 | `ESTOP_ACTIVE` | 本地急停锁存 |
| 3 | `OBSTACLE_STOP` | 障碍停车状态拒绝运动 |
| 4 | `LOW_BATTERY` | 低电保护拒绝运动 |
| 5 | `DRIVER_FAULT` | 电机驱动或执行器故障 |

确认规则：

- 每条被完整解析的 `MOVE/STOP` 应回复一个 ACK，包括参数拒绝和执行失败。
- `HELLO` 使用 `HELLO_ACK`，不要再回复 `CMD_ACK`。
- `TELEMETRY/EVENT/CMD_ACK` 不需要固件等待桥 ACK。
- 桥根据 `commandSeq` 补回命令操作名。未知或过期序号的 ACK 只会被透传，固件不应重复发送旧 ACK 冒充新命令结果。

### 5.6 EVENT（0x31）

负载固定 2 字节：

| 负载偏移 | 长度 | 类型 | 字段 | 说明 |
|---:|---:|---|---|---|
| 0 | 1 | `uint8` | `kind` | 事件类型 |
| 1 | 1 | `uint8` | `value` | 事件值或原因 |

事件定义：

| `kind` | 名称 | `value` 约定 |
|---:|---|---|
| 1 | `ARRIVED` | P0 填 0；路点语义待 PATROL 协议启用后定义 |
| 2 | `OBSTACLE_STOP` | 触发时填 1；持续状态同时由遥测 bit1 表示 |
| 3 | `FAULT` | 非零固件故障码；同时保持停车并更新遥测 |
| 4 | `LOW_BATTERY` | 当前电量百分比 0～100；同时设置遥测 bit2 |
| 5 | `STOPPED` | 停车原因，见下表 |

`STOPPED.value`：

| 值 | 含义 |
|---:|---|
| 0 | 收到正常 STOP |
| 1 | 本地急停 |
| 2 | MOVE TTL 到期 |
| 3 | 障碍保护停车 |
| 4 | 传输连接断开或会话结束 |
| 5 | 低电保护停车 |

当前桥只将 `kind` 映射成名称，`value` 原样透传。事件不能替代周期遥测，也不能作为后端已经确认停车的证明。

## 6. 固件状态时序

### 6.1 正常遥控

```text
上电：关闭电机输出，清空旧命令
  ↓
接收 HELLO → 回复 HELLO_ACK(version=1, capabilities=0x0007)
  ↓
周期发送 TELEMETRY
  ↓
接收 MOVE(seq=N)
  ├─ 参数非法/安全状态拒绝 → 保持停车 → CMD_ACK(N, 非 OK)
  └─ 合法且允许运动 → 刷新本地 TTL → 执行 → CMD_ACK(N, OK)
  ↓
接收 STOP(seq=M) → 立即撤销运动输出 → CMD_ACK(M, OK) → EVENT/STOPPED
```

### 6.2 TTL、断连与重连

- 最后一条 MOVE 超过其 `ttlMs` 未续传：本地停车，不依赖任何网络消息。
- BLE/串口断开：立即进入安全停止，清空未执行运动队列，上报通道若仍可用则发送 `STOPPED(value=4)`。
- 重连后保持停车，重新等待 `HELLO`；不得自动恢复重连前的速度。
- 后端 600 ms 看门狗和桥重连只是外层保护，不能替代固件本地 TTL 和硬件急停。

## 7. 标准报文样例

以下报文均由当前 `generic-mcu-v1` Python 实现生成，可直接作为固件收发单元测试向量。空格仅用于阅读，线上只发送原始字节。

```text
HELLO（seq=1，version=1，capabilities=0x0007）
AA 55 01 01 00 01 00 04 00 01 00 07 13 EF

HELLO_ACK（seq=1，version=1，capabilities=0x0007）
AA 55 01 02 00 01 00 04 00 01 00 07 3E AB

MOVE（seq=2，x=50，y=-25，theta=100，speed=40%，ttl=200ms）
AA 55 01 10 00 02 00 06 32 E7 64 28 00 C8 A9 E7

STOP（seq=3，空负载）
AA 55 01 11 00 03 00 00 BC EB

TELEMETRY（seq=10，电量=82%，x=120cm，y=-340cm，theta=90.0°，障碍=45cm，flags=0）
AA 55 01 20 00 0A 00 0A 52 00 78 FE AC 03 84 00 2D 00 34 31

CMD_ACK（自身 seq=11，确认 MOVE.commandSeq=2，status=OK，reason=NONE）
AA 55 01 30 00 0B 00 04 00 02 00 00 D6 37

EVENT（seq=12，OBSTACLE_STOP，value=1）
AA 55 01 31 00 0C 00 02 02 01 04 09
```

注意：示例中的 `MOVE.seq=2` 是因为此前 `HELLO` 占用了序号 1。固件必须根据实际收到的命令序号回复 ACK。

## 8. 固件最小验收清单

### 8.1 无硬件运动输出的协议测试

- [ ] CRC 标准串 `123456789` 得到 `0x29B1`。
- [ ] 正确解析并回复第 7 节全部报文，逐字节 CRC 一致。
- [ ] `AA 55` 跨两次读取、帧跨多次读取、多帧一次读取均能解析。
- [ ] 噪声、错误 CRC、错误版本、非法长度和非法电量不会生成有效消息或运动。
- [ ] 不回复 HELLO_ACK、版本不符或能力不足时，后端不会显示真机在线。
- [ ] ACK 的 `commandSeq` 与实际 MOVE/STOP 序号一致。
- [ ] 未知消息类型和越界参数默认拒绝，不执行猜测行为。

### 8.2 架空执行机构的安全测试

- [ ] 上电、握手前、空闲和重连后均无运动输出。
- [ ] MOVE 各轴方向、速度百分比和定点单位符合本文定义。
- [ ] 连续 MOVE 可刷新 TTL；停止续传后在指定 TTL 内停车。
- [ ] 50 ms 与 500 ms 边界有效，越界 TTL 返回 INVALID。
- [ ] STOP 在任意运动状态下立即撤销输出，不被命令队列阻塞。
- [ ] 本地急停、障碍、低电和驱动故障能停车并正确设置遥测/事件。
- [ ] BLE/串口断开后本地停车，重连不恢复旧速度。
- [ ] 静止和运动中均持续上报遥测，周期满足后端心跳要求。

### 8.3 落地真机测试

- [ ] 在封闭区域低速验证前进、后退、转向及平台横移约束。
- [ ] 验证松手停车、后端急停、本地急停、避障停车和断连停车。
- [ ] 核对里程计方向、距离单位、电量和障碍距离与实测值一致。
- [ ] 重复进行至少 20 次断连/重连，始终重新握手且无误动作。

## 9. 当前版本边界

- v1 不包含摄像头帧、音频、PTZ、喊话、PATROL 路点或固件升级。
- v1 不定义控制租约、epoch、命令时间戳或后端 stopped 证明。
- 协议解析成功不代表电机功率级、机械限位和独立硬件急停已经验收。
- 若实际设备不能修改固件，应依据真实抓包单独实现厂商 `ProtocolAdapter`，不得把本协议直接套用到未知设备。
