# 智能巡检机器人接入方案

> 覆盖形态：智能巡检车、智能巡检蜘蛛、智能巡检机器狗、智能巡检机器人（人形/轮式云台机）
> 能力：语音 + 视觉 + 蓝牙连接；运行模式：自主态（模型大脑）与人工态（遥控/遥操）双态切换
> 状态：草案 v1（2026-11-16）
> 详细设计：[巡检机器人详细设计.md](巡检机器人详细设计.md)（数据契约/API/状态机/文件级任务拆解）

---

## 1. 设计原则

1. **形态即配置，不是分支**：四类机器人统一抽象为「巡检设备（PatrolRobot）」，差异下沉到 `form_factor` + `capability` 元数据，业务层不写 if-else 判断车型/狗型。
2. **复用现有闭环，不另起炉灶**：视觉复用 `VisionInspectionEngine`，事件复用纠察中心 `InspectorEventService`，人工复核复用 `verifyInspection`，任务规划复用 AgentForge P3 DAG 调度，设备台账扩展 `/devices`。
3. **自主态 fail-closed**：自主态默认关闭，需显式开启；所有下发命令走白名单校验；紧急停止（E-STOP）永远优先于任何模型决策。
4. **人工态低延迟**：遥控链路不经过任何 LLM，端到端指令延迟目标 ≤150ms。

## 2. 总体架构

```
┌───────────────────────────── 前端（Vue，/robot 路由）─────────────────────────────┐
│  RobotConsoleView：视频回传 | 虚拟摇杆/手柄 | 双态切换 | 语音面板 | 任务队列      │
└──────────────▲──────────────────────────────▲───────────────────────────────────┘
        WebSocket(遥控指令/遥测/视频信令)      REST(任务/事件/台账)
┌──────────────┴──────────────────────────────┴───────────────────────────────────┐
│  backend（Java Spring）                                                          │
│  ├─ RobotGatewayController   WS端点：/ws/robot/{deviceId}                        │
│  ├─ RobotControlService      双态状态机 + 命令白名单 + 速率限制 + E-STOP          │
│  ├─ RobotBrainService(自主态) 感知→规划→执行→反思，复用 AgentForge Planner        │
│  ├─ VisionInspectionEngine   现有视觉引擎，抽帧 base64 → qwen2.5vl               │
│  └─ InspectorEventService    巡检结论写纠察事件（source=ROBOT_*）                 │
└──────────────▲──────────────────────────────▲───────────────────────────────────┘
        本地桥(localhost)                      内部token
┌──────────────┴──────────────────────────────┴───────────────────────────────────┐
│  robot-bridge（新增 Python 脚本，运行在蓝牙主机上）                               │
│  ├─ BLE Adapter（bleak）        连接四类机器人蓝牙外设                            │
│  ├─ 协议适配器 ProtocolAdapter  按厂商/形态适配：指令编码、遥测解码                │
│  └─ 视频通道                     MJPEG/分帧转发（WiFi 型设备直连 RTSP，蓝牙型走分帧）│
└──────────────────────────┬───────────────────────────────────────────────────────┘
                           ▼
        设备层：巡检车 / 巡检蜘蛛 / 机器狗 / 巡检机器人
```

**蓝牙链路选型**（关键决策）：

| 方案 | 说明 | 结论 |
|---|---|---|
| Web Bluetooth 直连 | 浏览器内直接连 BLE，零中间件 | 仅 Chrome/Edge 桌面支持，iOS/Safari 不支持，且无法与后端共享连接 → **不采用** |
| 后端直接蓝牙 | Java 进程内操作 BLE | Java BLE 生态弱，Windows 下依赖厂商库，风险高 → **不采用** |
| **robot-bridge 本地桥** | Python(bleak) 脚本跑在与机器人配对的 PC 上，经 localhost WS/HTTP 与 backend 通信 | 跨平台、生态成熟、backend 与蓝牙解耦 → **采用** |

四类机器人若各自带 WiFi/RTSP 能力（机器狗常见），视频走直连；纯蓝牙低带宽设备（巡检车/蜘蛛）采用「蓝牙遥控 + 摄像头经 WiFi 热点独立上行」的混合链路，蓝牙只走控制指令。

## 3. 双态运行设计

### 3.1 状态机

```
DISCONNECTED ──配对──▶ IDLE ──┬──自主任务下发──▶ AUTONOMOUS_EXECUTING
                              │                        │
                              ├──遥控接管──▶ HUMAN_CONTROL ◀──一键接管（随时）
                              │                        │
                              └──┴──────────┴────▶ E_STOP / FAULT
E_STOP 仅能人工确认后复位；AUTONOMOUS 与 HUMAN_CONTROL 互斥，切态需持锁。
```

### 3.2 自主态（大脑 = 模型）

感知 → 规划 → 执行 → 反思 四步，全部挂接到现有闭环：

| 步骤 | 实现 | 复用 |
|---|---|---|
| 感知 | 摄像头抽帧 → `VisionInspectionEngine.analyze(imageBase64)`；麦克风语音 → 指令/环境音识别 | VisionInspectionEngine、ai-service |
| 规划 | 巡检路线（/patrol 现有 route 概念扩展到机器人位姿点）+ 异常处置计划 | AgentForge P3 LLM Planner + DAG 调度 |
| 执行 | 计划节点翻译为白名单命令（move / ptz / speak / capture / patrol） | RobotControlService 命令通道 |
| 反思 | 视觉结论 → 纠察事件（status=REVIEW, requiresHuman=true）→ 人工复核；连续异常触发重规划 | InspectorEventService、verifyInspection |

**自主态安全约束**：
- 命令白名单 + 参数钳位（最大速度、最大转角、禁行区域围栏），类比 OutboundUrlPolicy 的集中校验；
- 自主执行期间持续心跳（200ms），桥断连 3 个心跳 → 自动 E-STOP；
- 模型结论不直接判定安全（与现有视觉巡检口径一致），一切异常结论进人工复核；
- 注入检测复用输入侧钩子：语音转文本先过注入检测再进 Planner。

### 3.3 人工态（遥控）

- 输入：键盘 / Gamepad API / 虚拟摇杆（前端），映射为统一 `RobotCommand(move.x, move.y, move.theta, ptz, speed)`；
- 链路：前端 → WS → backend（仅鉴权+钳位，零模型调用）→ robot-bridge → BLE Write；
- 视频回传叠层显示遥测 HUD（电量、位姿、障碍提示）；
- 语音对讲：前端麦克风 → ai-service TTS → 机器人喇叭（巡检机器人喊话场景）。

## 4. 数据契约（初稿）

```jsonc
// 设备档案，扩展 /devices 台账，新增 deviceType=ROBOT
DeviceProfile {
  id, name,
  formFactor: "CAR" | "SPIDER" | "DOG" | "ROBOT",   // 四形态
  capabilities: ["MOVE","PTZ","MIC","SPEAKER","LIDAR"...],
  transport: { type: "BLE", mac, protocolId },       // 指向协议适配器
  firmware, battery, lastSeenAt
}

// 统一命令（白名单校验对象）
RobotCommand { op: "MOVE|PTZ|SPEAK|CAPTURE|PATROL|STOP", params{}, ttlMs }

// 遥测
RobotTelemetry { battery, pose{x,y,theta}, obstacleDistance, mode, ts }

// 巡检结论（写纠察事件）
source: "ROBOT_VISION" | "ROBOT_VOICE"，关联 deviceId + traceId 幂等
```

## 5. 分期落地路线

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M0 设备接入** | robot-bridge 脚本 + BLE 配对；`/devices` 增加 ROBOT 类型与 DeviceProfile；文档录入各形态协议适配器清单 | 台账可见设备、在线状态真实反映 |
| **M1 人工态 MVP** | WS 遥控链路 + 虚拟摇杆 + E-STOP 大按钮；单台巡检车跑通 move/stop | 遥控端到端 ≤150ms，断连自动停 |
| **M2 视觉闭环** | 摄像头抽帧 → VisionInspectionEngine → 纠察事件 → 人工复核 | 异常场景产生真实事件并可复核 |
| **M3 自主态大脑** | 巡检路线（位姿点）+ 模型规划 + 语音指令 + 反思重规划；双态状态机完整 | 自主巡检一圈，异常进复核，一键接管可用 |
| **M4 多机队** | 多设备并发调度（复用 DAG 并发上限）、按能力分配任务、四形态适配器补齐 | 多台同时巡检互不干扰 |

## 6. 安全与降级清单

- **鉴权**：robot-bridge 与 backend 间使用独立内部 token（fail-closed，未配置拒绝启动），与恢复契约口径一致；
- **配对**：未在台账登记的蓝牙设备拒绝连接，MAC 白名单；
- **E-STOP**：前端常驻大按钮 + 机器人本地硬停止优先级最高；
- **数据**：语音/视频不落盘原始内容，事件脱敏沿用框架级日志脱敏；
- **降级**：模型不可用 → 自主态拒绝启动（fail-closed），人工态不受影响；蓝牙链路丢包 → 命令指数退避重发 ≤2 次，失败即停；
- **视觉模式档位**：前端控制台遵循现有 lightweight/reduced-motion 降级规则（视频 HUD 动效、摇杆动效）。

## 8. 主要风险

1. **蓝牙带宽**：纯 BLE 无法承载视频，蜘蛛/车类必须混合 WiFi 链路或降低帧率至 1-2fps 抽帧巡检；
2. **四形态 SDK 差异**：机器狗（宇树等）多走 SDK/UDP 而非裸 BLE，Adapter 需按厂商分套，M0 阶段先锁定 1-2 个真实厂商型号再定协议；
3. **浏览器手柄兼容**：Gamepad API 在部分浏览器需用户手势激活，M1 需准备虚拟摇杆兜底；
4. **自主态误动作**：第一阶段自主态只开放「巡检+拍照+上报」，运动类自主决策在积累数据后再放开。
