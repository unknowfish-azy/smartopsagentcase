## 2. 数据契约

### 2.1 数据库迁移（Flyway）

新增 `V20261117.1__robot_fleet.sql`：

```sql
-- 设备档案
CREATE TABLE robot_device (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  device_key    VARCHAR(64)  NOT NULL UNIQUE,          -- 业务主键，如 robot-car-01
  name          VARCHAR(128) NOT NULL,
  form_factor   VARCHAR(16)  NOT NULL,                 -- CAR / SPIDER / DOG / ROBOT
  capabilities  JSON         NOT NULL,                 -- ["MOVE","PTZ","MIC","SPEAKER","CAMERA"]
  transport     JSON         NOT NULL,                 -- {"type":"BLE","mac":"AA:BB:..","protocolId":"generic-ble-car-v1"}
  status        VARCHAR(16)  NOT NULL DEFAULT 'OFFLINE', -- OFFLINE/IDLE/AUTONOMOUS/HUMAN_CONTROL/E_STOP/FAULT
  enabled       TINYINT(1)   NOT NULL DEFAULT 0,       -- 新设备默认禁用，显式启用后才可控制
  firmware      VARCHAR(64),
  last_seen_at  DATETIME,
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 命令审计（谁在什么模式下了发什么）
CREATE TABLE robot_command_log (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  device_key   VARCHAR(64) NOT NULL,
  mode         VARCHAR(16) NOT NULL,                  -- AUTONOMOUS / HUMAN_CONTROL
  op           VARCHAR(16) NOT NULL,                  -- MOVE/PTZ/SPEAK/CAPTURE/PATROL/STOP
  params       JSON,
  accepted     TINYINT(1) NOT NULL,                   -- 白名单/钳位校验结果
  reject_code  VARCHAR(32),                           -- 拒绝规则码，不回显内部细节
  operator     VARCHAR(64),                           -- 用户名或 brain:planId
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_rcd_device_time (device_key, created_at)
);

-- 任务（自主态巡检任务，复用 DAG planId 关联）
CREATE TABLE robot_task (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  device_key   VARCHAR(64) NOT NULL,
  plan_id      VARCHAR(64),                           -- agent 包 DAG 计划 ID，断点续跑复用
  route        JSON NOT NULL,                         -- [{x,y,theta,actions:["CAPTURE"]}]
  status       VARCHAR(16) NOT NULL DEFAULT 'PENDING',-- PENDING/RUNNING/PAUSED/DONE/FAILED/CANCELLED
  progress     INT NOT NULL DEFAULT 0,                -- 已完成路点数
  created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

遥测不入库，仅保内存最新快照（`ConcurrentHashMap<deviceKey, RobotTelemetry>`），避免高频写库；E-STOP/FAULT 等关键状态变化才写一条 `robot_command_log`（op=STOP，mode 由当前态决定）。

### 2.2 REST API（backend，前缀 `/api/robot`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/robot/devices` | 设备列表（含最新遥测快照、在线状态） |
| PUT | `/api/robot/devices/{key}/enabled` | 启用/禁用（body: `{enabled:boolean}`），审计 |
| GET | `/api/robot/devices/{key}/status` | 单设备状态+遥测 |
| POST | `/api/robot/devices/{key}/task` | 下发自主巡检任务（body: route），仅启用且 IDLE 可受理 |
| POST | `/api/robot/tasks/{id}/cancel` | 取消任务 |
| GET | `/api/robot/commands?deviceKey=&limit=` | 命令审计查询 |
| GET | `/api/robot/status` | 桥连接状态、各设备健康、配置自检（类比 `/api/inspector/vision/status`） |

错误口径统一：设备不存在 404、被禁用 409、状态机不允许 409（附规则码）、白名单拒绝 400（仅规则码，如 `ROBOT_OP_NOT_ALLOWED`、`ROBOT_PARAM_OUT_OF_RANGE`）、桥未配置 fail-closed 503。

### 2.3 WebSocket 消息协议（`/ws/robot`，仿 OperationsWebSocketConfig）

连接：`/ws/robot?deviceKey=...`，握手复用现有会话鉴权；**桥连接**使用独立内部 token 头 `X-Robot-Bridge-Token`（fail-closed，未配置即拒绝连接）。

消息为 JSON 信封 `{type, ts, payload}`：

```jsonc
// 下行（前端/大脑 → 桥）
{"type":"cmd","payload":{"op":"MOVE","params":{"x":0.2,"y":0,"theta":0,"speed":0.5},"ttlMs":200}}
{"type":"cmd","payload":{"op":"STOP"}}
{"type":"mode","payload":{"mode":"HUMAN_CONTROL"}}        // 双态切换指令

// 上行（桥 → backend；backend 转发/处理后 → 前端）
{"type":"telemetry","payload":{"battery":0.82,"pose":{"x":1.2,"y":3.4,"theta":90},"obstacleDistance":0.45}}
{"type":"frame","payload":{"imageBase64":"...","quality":"low"}}   // 低频关键帧，JPEG 0.4 质量，仅自主态/M2 抽帧用
{"type":"event","payload":{"kind":"OBSTACLE_STOP|FAULT|ARRIVED","detail":"..."}}
{"type":"bridge_hello","payload":{"deviceKeys":["robot-car-01"],"protocols":["generic-ble-car-v1"]}}
```

规则：
- `MOVE` 必带 `ttlMs`（≤500ms），桥侧超时未收到续传命令自动 STOP（dead-man switch）；
- `frame` 仅在 `CAPTURE` 或自主态抽帧节流（≥2s/帧）时出现，遥控态不传帧，保带宽给指令；
- backend 是唯一路由器：前端不直连桥，桥不感知前端。

### 2.4 大脑工具契约（agent 插件）

`agent/plugins/installed/robot/`，manifest + tools，与 docker 插件同构：

```python
# 工具清单（risk 分级走现有 risk_registry）
robot_status(device_key)                       # risk: LOW
robot_capture(device_key, target)              # risk: LOW  → 调 backend /api/inspector/vision 链路
robot_speak(device_key, text)                  # risk: MEDIUM, text 过 injection.py
robot_move(device_key, x, y, theta, speed)     # risk: HIGH → 走 approval.py 审批门
robot_patrol(device_key, route)                # risk: HIGH → 审批门 + route 白名单钳位
robot_estop(device_key)                        # risk: CRITICAL, 任何上下文可执行，无需审批
```

LLM Planner 输出 DAG 时，机器人工具按现有 `planner/confirm.py` 的执行前确认门呈现（节点数/工具清单/预估 token）。自主态 M3 阶段 route 由确定性模板（预设巡检点）+ Planner 仅做编排与异常处置决策，不让模型自由生成运动轨迹。

## 3. 状态机与并发控制

```
             ┌────────── 配对/启用 ──────────┐
DISCONNECTED ────▶ IDLE ──task──▶ AUTONOMOUS_EXECUTING
                    │  ▲                    │
              takeOver│  │release            │异常/完成
                    ▼  │                    ▼
              HUMAN_CONTROL ◀──────────────┘
                    │         AUTONOMOUS → HUMAN 事件触发 task 自动 PAUSE
                    ▼ 任何时刻
                 E_STOP ──人工确认+复位──▶ IDLE
FAULT: 桥断连3心跳(600ms)、低电<15%、BLE错误 → 自动进入，仅人工复位
```

实现（backend `RobotControlService`）：
- 每设备一把 `ReentrantLock`，双态切换与命令下发持锁；
- 状态机用枚举 + 显式转移表（`Map<State, Set<State>>`），非法转移 409 + 规则码（如 `ROBOT_INVALID_TRANSITION`）；
- 人工态接管事件：前端 WS 发 `mode=HUMAN_CONTROL` → 若处于 AUTONOMOUS，先 PAUSE 当前 task（robot_task.status=PAUSED，planId 保留供断点续跑）再切态；
- E-STOP 为最高优先级旁路：不排队、不等锁校验来源（但必须审计）。

### M6 连续异常自动重规划 ✅ 已完成（2026-11-17）

> 真机接入时，重规划可替换为调用 Python agent DAG planner 的绕行工具（更精准、支持避障/路径规划）；
> 当前确定性实现（当前点 x+2/y+2 绕行）无外部依赖，纯后端闭环，fail-closed 不中断任务。

1. **重规划触发链路**：
   - `RobotBrainService` 构造器注入 `InspectorEventService` + 两个配置项：
     - `smartops.robot.replan.threshold`（默认 2）：窗口内 WARN/CRITICAL 条数阈值
     - `smartops.robot.replan.window-ms`（默认 30000）：时间窗口
   - 路点执行完（MOVE → 停顿 → CAPTURE → 停顿）后调 `shouldReplan(deviceKey, taskId)`：
     ```sql
     SELECT COUNT(*) FROM inspector_event
      WHERE task_id LIKE CONCAT('robot-', deviceKey, '-%')
        AND severity IN ('WARN', 'CRITICAL')
        AND created_at >= NOW() - INTERVAL #{windowMs} MILLISECOND
     ```
   - COUNT ≥ threshold → 调 `replanAround(route, i, deviceKey)` 原地替换当前 index：
     ```java
     // 用当前点附近 (x+2, y+2) 生成绕行点，替换 route[i]
     // 保持 i 不变 → while 循环 continue → 立即执行绕行点
     // route 实时 UPDATE robot_task SET route=?
     ```
   - 循环从 `for (i++)` 改为 `while (i < route.size())` —— 重规划保持 i 原地、续跑不变。

2. **simulated-abnormal 降级**（VisionInspectionService）：
   - 测试模式开启时，**无条件**合成 WARN 事件绕过真实模型输出：
     ```java
     if (simulatedAbnormal) {
         abnormal = true;
         modelName = "sim-abnormal";
         summary = "[SIM] 连续异常：模拟视觉模型检测到画面异常，触发重规划";
     } else if (!engine.configured()) {
         // 未配置真实模型 → 诚实地降级为 INFO（不伪造异常）
         abnormal = false; modelName = "unconfigured";
     } else {
         VisionAnalysis analysis = engine.analyze(imageBase64);
         ...
     }
     ```
   - 默认 false —— 真实联调不会被模拟干扰；由 E2E 脚本/后端启动参数显式覆盖。

### M7 DAG planner 绕行替换 ✅ 已完成（2026-11-17）

> M6 的重规划把"触发条件"和"执行器"独立了，但"怎么生成绕行点"还是硬编码的 x+2/y+2。
> M7 把这一层抽象为 `ReplanStrategy` 接口，真机接入时可切换到：
> - 基于 obstacle sensor 的启发式绕行（多形态物理模型）
> - 调用本地/远端 LLM planner（`OllamaReplan`）
> - Agent DAG planner 工具链（后端 HTTP → agent `robot.replan_route` tool）
>
> **Fail-closed**：任何策略异常/超时/解析失败 → `FallbackResult` → 自动降级 `DeterministicReplan`，
> 绝不阻塞任务。

1. **策略接口**（`com.smartops.robot.replan.ReplanStrategy`）：
   ```java
   public interface ReplanStrategy {
       String name(); // 日志/trace 用，如 "deterministic" / "ollama-qwen2.5vl:3b"
       ReplanResult replan(List<Map<String, Object>> route, int currentIndex, String deviceKey);

       sealed interface ReplanResult permits SuccessResult, FallbackResult {
           boolean isFallback();
           long elapsedMs();
       }
       record SuccessResult(List<Map<String, Object>> newRoute, String routeSource, long elapsedMs) {}
       record FallbackResult(String reason, long elapsedMs) {}
   }
   ```

2. **两个默认实现**：

   | 策略 | name() | 行为 |
   |---|---|---|
   | `DeterministicReplan` | `"deterministic"` | 当前点 (x+2, y+2) 生成绕行点，替换 `route[i]`。**始终可用**（兜底） |
   | `OllamaReplan` | `"ollama-" + model` | HTTP POST 本地 Ollama `/api/generate`，要求输出 JSON route 段。model 空/不可达/解析失败 → `FallbackResult` |

3. **RobotBrainService 策略级联注入**：
   ```java
   // 构造器参数
   List<ReplanStrategy> strategies,  // Spring 自动注入所有 @Component 策略
   @Value("${smartops.robot.replan.strategy:deterministic}") String primary

   // 策略选择（按 name().split("-")[0] 匹配）
   Map<String, ReplanStrategy> byName = ...;
   this.fallbackStrategy = byName.getOrDefault("deterministic", new DeterministicReplan());
   this.primaryStrategy  = byName.getOrDefault(primary, this.fallbackStrategy);
   ```
   `replanAround()` 执行主策略 → fallback 时自动降级兜底策略：
   ```java
   ReplanResult result = primaryStrategy.replan(route, currentIndex, deviceKey);
   if (result.isFallback()) {
       log.warn("主策略 {} 请求兜底：{}", primary.name(), ((FallbackResult)result).reason());
       result = fallbackStrategy.replan(route, currentIndex, deviceKey);
   }
   ```

4. **per-task 15s 冷却防死循环**（M6→M7 联调发现的问题）：
   - **根因**：`simulated-abnormal=true` 时每次 CAPTURE 都产生 WARN → shouldReplan 窗口内 COUNT 永远 ≥ threshold → 原地无限重规划卡死
   - **修复**：`RobotBrainService` 新增 `Map<Long, Long> lastReplanAt`（taskId → 上次重规划时间戳），`shouldReplan()` 先检查冷却（15s 内不重复触发），通过后再查 DB
   - 任务完成/失败时 finally 清理：`lastReplanAt.remove(taskId)`

5. **Agent Plugin 对等实现**（`agent/plugins/installed/robot/tools/replan_route.py`）：
   - `RobotReplanRouteTool` 暴露 `robot.replan_route` 工具，供 agent DAG planner 链路调用
   - 参数：`route`（完整巡检路线）、`anomalyIndex`（异常路点索引）、`deviceKey`
   - 行为与后端 `OllamaReplan.java` 一致：LLM 可用时调 Ollama，不可用时 deterministic 兜底
   - 注册到 `agent/plugins/installed/robot/manifest.yaml`（permission + risk=MEDIUM）

6. **配置**（`application.yml`）：
   ```yaml
   smartops:
     robot:
       replan:
         strategy: ${SMARTOPS_ROBOT_REPLAN_STRATEGY:deterministic}  # 主策略名
         ollama:
           base-url: ${SMARTOPS_ROBOT_REPLAN_OLLAMA_BASE_URL:http://127.0.0.1:11434}
           model: ${SMARTOPS_ROBOT_REPLAN_OLLAMA_MODEL:}  # 空=不启用，自动 fallback
           timeout-ms: ${SMARTOPS_ROBOT_REPLAN_OLLAMA_TIMEOUT_MS:5000}
   ```
