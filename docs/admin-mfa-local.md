# 本地管理员二次认证使用说明

## 范围与入口

管理员登录后进入 **管理员层 → 二次认证**（`/admin/security`）。该功能不依赖公网、人机验证供应商或邮件服务。现有管理员不会被自动绑定，账号和密码不变；普通用户不开放此设置。

TOTP 是密码之外的第二因子，不是人机验证，也不能防止前端代码被查看。管理员一旦启用，从普通用户入口登录同样需要第二因子。

## 首次绑定

1. 打开二次认证页面，输入当前管理员密码并创建绑定草稿。
2. 在支持标准 TOTP 的认证器中手动添加账号，填写页面展示的账号名和密钥。参数为 HMAC-SHA1、6 位数字、30 秒周期；本版使用手动密钥输入，不提供二维码。
3. 输入认证器当前动态码确认绑定。草稿五分钟有效，离开页面后需要重新开始。
4. 离线妥善保存页面仅展示一次的 **10 个恢复码**，确认保存后再关闭展示。不要把密钥或恢复码放进工单、聊天记录、共享截图或代码仓库。

电脑、后端服务器和认证器设备需保持时间准确。同一个动态码不能重复使用；刚绑定后立即登录遇到已使用提示，请等待下一个周期。

## 登录和日常管理

- 先验证账号密码，再输入动态码；认证器不可用时，可输入一枚未使用的恢复码。
- 待验证登录五分钟有效，未完成之前没有业务权限；五次验证失败后需重新进行密码登录。账号和来源 IP 另有限流，遇到 429 请等待，不要持续重试。
- 每枚恢复码只能使用一次。恢复码丢失或使用后，建议在仍能登录时生成新的一组；旧的一组立即失效。
- 重新生成恢复码或关闭 MFA 都需要当前密码及有效动态码/恢复码；关闭还需勾选确认。
- 绑定、轮换或关闭后撤销其他会话；当前重新验证的会话保留。已建立终端也会在下一条命令检查 MFA 版本。
- 页面显示当前账号最近 50 条站内安全提醒，覆盖 MFA 验证失败、恢复码使用和设置变化；没有邮件、短信或离线推送，不声称识别异地登录。

## 丢失因子与备份

如果认证器和全部恢复码都丢失，本版没有只凭密码在线重置 MFA 的入口，也没有已实现的自动身份核验恢复流程。请联系受信任运维人员，经独立身份核验后制定受审计的离线恢复方案，勿直接通过修改数据库绕过认证。

数据库只保存加密认证器密钥和恢复码摘要。应分别保护数据库备份与服务端加密主密钥，并验证备份可恢复；丢失或随意更换加密主密钥会使已有认证器密钥无法解密。数据库备份也应按敏感数据保护。

## 部署与验证

Windows 本地部署先运行 `scripts/windows/migrate-local.ps1`：脚本在变更前执行数据库备份，核对历史迁移摘要，再执行 V005 增量迁移。V005 只新增三张空表，不修改现有账号或自动绑定。后端构建完成后，使用 `scripts/windows/restart-local-backend.ps1` 更新运行版本；重启会使现有内存会话失效。

自动测试使用独立 H2 数据库；浏览器功能测试拦截写入，不替真实管理员绑定认证器。运行态冒烟检查只发起匿名只读请求，真实绑定由账号所有者自行操作。

后端完整回归使用每个测试类独立 JVM，避免既有测试共享 H2 数据库引发建表冲突：

```powershell
cd backend
mvn.cmd -s .mvn/smartops-settings.xml '-Dmaven.compiler.fork=false' '-DreuseForks=false' package
```

## 尚未启用的外部能力

- 公网 Turnstile 仍需真实站点和密钥；本地 dev 明确禁用，不使用演示密钥冒充生产保护。
- 邮件/短信通知、WAF、反向代理和公网 HTTPS 验收未交付。
- 账号/IP 计数器及待验证会话仍是单实例内存状态，重启会清空。多实例部署前需共享状态及入口限流，本版不宣称分布式防刷。
- 本期是自愿启用 MFA，不是公司管理员全员强制绑定策略。
