## 0. 先钉口径

- 该小红书短链在浏览器外**打不开**（跳 `www.xiaohongshu.com` 需登录）。所以这不是对某段视频的逐帧复刻，而是把你说的"三块绑定在一个界面里"做成一套**可实现的联动模型**。文档、代码注释、提交说明都不许写"还原视频交互"。
- 「48 小时」「19 岁」是标题信息，与本设计无关；本设计只取"一个界面把多视图绑在一起"这一条语义。
- 本模块**不引入新依赖**：不新增图表库、不新增动画库，画布用原生 Canvas 2D。

## 1. 现状问题（逐条有代码位置）

| # | 问题 | 证据 | 后果 |
| --- | --- | --- | --- |
| 1 | **纠察中心有编造的指标** | `views/inspector/InspectorCenterView.vue:4` 的 `dimensions` 数组里塞了 `Preview: Evidence 86%`、`Preview: Risk PASS`、`Preview: Loop WARN`、`Preview: Verify N/R` 四条，和 8 个真实维度一起当卡片渲染 | 违反「无证据不呈现为事实」：这 4 个数没有任何来源 |
| 2 | **三个页面各拉一次 summary** | 纠察中心与统计都渲染 `InspectorSummary`，各自请求 `/api/inspector/summary` | 同一个数在两页可能不同步；切页多一次请求 |
| 3 | **统计没有时间窗** | `InspectorStatisticsView.vue` 只调 `/api/inspector/statistics`（全量） | 用户无法回答"过去 24 小时怎么样" |
| 4 | **运行记录与纠察零交叉** | `RunHistoryView.vue` 只有自己的筛选器；纠察侧没有 run 链接 | 看到一条纠察，找不到它落到的命令；反过来也一样 |
| 5 | **关联键存在但没用起来** | 运行记录有 `traceId`（`useRunHistory` filters.traceId），纠察事件侧字段未暴露到列表 | 唯一可靠的关联键被浪费 |
| 6 | **视觉身份分裂** | 纠察中心用金色皮肤（`#e7c56d`/`#241e0e`），运行记录用标准工具面 | 同一组里的三页像两个产品 |

## 2. 设计概念：一条轴，三种投影

```
            同一条时间轴（24h / 7d / 30d）
   ┌──────────────────────────────────────────────┐
   │ 纠察  ·  每个事件 = 一个点（等级泳道）          │
   │ 统计  ·  同一批事件按时间分箱 = 堆叠柱          │
   │ 运行  ·  每条命令执行 = 一根横条（工具泳道）     │
   └──────────────────────────────────────────────┘
        共享：时间窗 · 选中对象 · 等级/工具筛选 · 证据抽屉
```

- **点 / 柱 / 条**不是三个页面，是同一批证据的三种粒度：一条纠察事件（点）会被聚合成一根柱，也可能落到一条命令执行（条）。
- 切视图时**坐标轴不动**，只做 420ms 的交叉淡入 + 8px 位移；选中对象的高亮带、右侧卡片、抽屉内容全部保留。
- 右侧固定三块：**选中对象**（是什么、关联到谁）、**在另外两个视图里**（它在那两个投影里落在哪）、**全量统计**（服务端全量，标注"不受时间窗影响"）。

## 3. 版式

```
┌ 页头：eyebrow · 洞察台 · 一句话 ──────────────── 时间窗 / 数据源 / DEMO ┐
├ 三个投影切换（纠察 · 统计 · 运行，各带一行说明）──────────────────────┤
├ 工具栏：等级 chips · 工具 chips · 只看已关联 · 窗口摘要 ────────────────┤
├──────────────────────────────────────────┬───────────────────────────┤
│ 共享时间轴（Canvas）                       │ 选中对象                   │
│  · 纠察：4 条等级泳道 + 点 + 关联小点       │ 在另外两个视图里            │
│  · 统计：分箱堆叠柱 + 选中箱描边            │ 全量统计（服务端）          │
│  · 运行：5 条工具泳道 + 时长条 + trace 刻线 │                           │
│  · 底部：密度带（与统计同一组分箱）          │                           │
├ 证据抽屉（证据 / 输出 / 轨迹）──────────────────────────────────────────┤
└──────────────────────────────────────────────────────────────────────┘
```

- 桌面：主轴 `1fr` + 右栏 344px；`≤1180` 右栏变两列、主轴全宽；`≤760` 全部单列，轴高 320。
- 主轴卡片高度跟随右栏（`align-items: stretch` + `flex: 1`），不会在下方留空洞。
- 抽屉默认收起为一行，`Enter` 展开、`Esc` 收起；展开后在页面底部，不遮挡时间轴。

## 4. 三个投影的规格

| 投影 | x | y | 标记 | 选中 | 悬停 |
| --- | --- | --- | --- | --- | --- |
| 纠察 | 事件时间 | 4 条等级泳道（严重/高/警告/通过） | 半径 4 的实心点 + 1px 竖须；已关联运行的点下方 2px 青色小点 | 半径 6 + 10px 外环 + 全高竖带 | 十字线 + 卡片 |
| 统计 | 分箱起点（24h=12 箱、7d=14、30d=15） | 堆叠计数，整数刻度 | 柱宽 ≤26px、分箱内居中；空箱不画 | 选中箱描边 | 该箱的时间范围 + 各等级条数 |
| 运行 | 开始时间 | 5 条工具泳道，每泳道 3 小行防重叠 | 时长条（`duration/40 × 54px`）+ 状态色；有 traceId 时下方 2px 青刻线 | 白描边 | 工具 / 结果 / 退出码 / 时长 |

- 颜色语义（沿用项目 G7）：`PASS/SUCCESS = 绿`、`WARN/TIMEOUT = 琥珀`、`HIGH = 橙`、`CRITICAL/FAILED = 红`。**不用红绿表示涨跌**。
- 时间刻度：宽屏 6–7 格；窄屏（<640）减到 3 格，24h 只标 `16时`。
- **密度带**：纠察视图底部一条 18px 带，用与统计视图**同一组分箱**画事件密度 —— 它是"点→柱"的视觉桥，提醒用户这三个视图是同一批数据。

## 5. 关联契约（这是"绑定"的实质）

| 场景 | 判定 | 界面文案 |
| --- | --- | --- |
| 事件有 `traceId`，运行里有同 trace | **已关联** | `已关联 RUN-5521 · 切到「运行」可看到高亮` |
| 事件有 `traceId`，运行里没有 | 未命中 | `有 traceId（tr_xxx），但运行记录里没有命中——可能超出窗口或未被采集` |
| 事件没有 `traceId` | 无法关联 | `没有 traceId · 无法定位运行记录` |
| 运行有 trace，纠察里没有 | 未命中 | `有 traceId，但纠察里没有命中（可能超出窗口）` |

**硬规则**：**禁止用"时间邻近"猜关联**。两条记录时间相近不代表同一件事；宁可显示"未关联"，也不编一条假链路。

## 6. 交互

| 交互 | 行为 |
| --- | --- |
| 三个投影切换 | 420ms 交叉淡入 + 输入方向 8px 位移；`prefers-reduced-motion` 下直接切换 |
| 时间窗 24h / 7d / 30d | 三个投影同时重算；选中清空；URL 同步 |
| 等级 / 工具 chips | 过滤当前投影的标记；"只看已关联"同时作用于两个数据集 |
| 点/条/箱 | hover 出十字线与卡片；点击选中（箱不参与选中） |
| 键盘 | `1/2/3` 切投影，`←/→` 在可见项间移动选中，`Enter` 开抽屉，`Esc` 关抽屉并清选中 |
| 证据抽屉 | 三个 tab：证据（字段 + JSON）、输出（stdout 样例）、轨迹（trace 骨架） |
| 深链 | `?view=events&window=24h&id=EV-1042`，刷新/分享后回到同一状态 |

## 7. 数据契约

复用现有三个接口，**只需要后端补一个过滤参数**：

```http
GET /api/inspector/events?limit=200                 # 已有
GET /api/inspector/summary                          # 已有
GET /api/inspector/statistics                       # 已有
GET /api/operations/runs?startedFrom=&startedTo=&pageSize=  # 已有
GET /api/inspector/events?traceId=tr_8f3a           # ★ 需要补：按 trace 反查纠察
```

- 事件的 `traceId` 字段需要出现在**列表**响应里（当前只在详情页可见）。若后端暂不提供，前端只能在已加载的 `limit` 条内做客户端 join，并必须在界面注明"仅在已加载的 N 条内关联"。
- 事件列表 `limit=50` 对 30d 窗口不足；洞察台请求 `limit=200`，后端需支持。
- 统计接口返回全量聚合，**不能**当窗口统计用；窗口聚合由前端按分箱计算，并在图例注明"窗口内前端聚合"。

## 8. 证据与降级

| 状态 | 表现 |
| --- | --- |
| 正常 | 三个投影 + 右栏 + 抽屉 |
| 无数据 | 每个投影各自的空态文案（"窗口内没有纠察事件"，不是空白画布） |
| 接口失败 | 该投影显示 `—` + 原因 + 重试；不影响另外两个投影（各自独立请求） |
| 演示模式 | 全页 `DEMO · 虚构示例` 角标 + 页脚声明；演示数据不得写入任何持久化 |
| 关联缺失 | 按 §5 的四种文案，不猜 |

## 9. 动效与性能

- **一个 rAF**：仅在视图切换期间运行（约 460ms），空闲时停止；悬停用 `pointermove` 直接重绘。
- 30fps 节流（项目 `motionScheduler`），`document.hidden` 时暂停。
- Canvas 单次绘制 ≤ 200 个标记；`ResizeObserver` + DPR 重算。
- 无 WebGL、无粒子、无 `backdrop-filter`、无扫光。
- 数值不做 count-up（会制造"实时刷新"的错觉）。

## 10. 可访问性

- Canvas `role="img"` + `aria-label`；**同时**在 DOM 里渲染一个视觉隐藏的列表（`class="sr-only"`），把当前投影的每一项写全（时间、等级/状态、任务/工具、关联状态），屏幕阅读器与"复制为文本"都能用。
- 投影切换是 `role="tablist"` + `tab` + `aria-selected`；面板 `role="tabpanel"` + `aria-labelledby`。
- 抽屉是 `aria-expanded` + `aria-controls`；焦点进入后 `Esc` 关闭并把焦点还给触发按钮。
- 键盘全程可达（见 §6）；触控目标 ≥ 30px。
- 对比度：正文 `#E8F2F7` / `#92A6B5` 在 `#0E1116` / `#151A21` 上 ≥ 4.5:1；等级色只用于标记与图例，不单独承载信息（点旁有竖须与文字图例）。

## 11. 与既有三页的关系

- 洞察台是**新增的入口**（MEMORY 组首项），原三页**保留**：
  - 纠察中心 → 顶部加「在洞察台打开」（按当前时间窗/选中）；
  - 统计 → 同上；
  - 运行记录 → 同上（带上 `traceId`）。
- 三页保留的原因：详情页 `/inspector/events/:id`、运行详情、知识候选创建这些深操作仍在原页完成；洞察台负责"看与选"，不负责"改"。
- 顺手修掉 `InspectorCenterView.vue:4` 的 4 条 `Preview: …` 假数据（见 §1 #1），改为真实的 8 个维度；缺数据的维度显示"未采集"，不显示数值。

## 12. 设计稿怎么用

`index.html` 自包含、离线可开：

- `1/2/3` 切投影，`←/→` 选对象，`Enter` 开抽屉，`Esc` 关；
- 时间窗 24h/7d/30d 会重算三个投影；
- 所有数据为确定性合成（`DEMO` 角标 + 页脚声明），**不要**把稿里的数字当接口返回。
