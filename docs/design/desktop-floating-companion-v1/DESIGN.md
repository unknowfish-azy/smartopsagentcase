- 日期：2026-11-16
- 状态：**P0 已实施**（D1–D3 按默认裁决执行：Electron / 自动识别默认关 / 会话不互通；待实机端到端验收）
- 用户诉求：增加「大学搜题酱」式悬浮窗能力——开启后悬浮球常驻桌面，Agent 可自动识别屏幕内容并与用户对话，形态类似 DeepSeek 桌宠「小鲸鱼」。

## 二、目标与非目标

**目标（P0）**
1. 悬浮球常驻桌面（置顶、可拖拽、半透明态），单击展开悬浮对话面板，双击截屏向 Agent 提问。
2. 截屏提问走**现有 ai-service 带图聊天链路**（Ollama 视觉模型，流式输出），不新增大模型接入代码。
3. 「自动识别屏幕」作为**可选开关（默认关）**：检测屏幕显著变化后自动把当前画面交给 Agent 解读并主动搭话。

**非目标（本期不做）**
- 不做手机端悬浮窗（参考产品是 Android 场景，本项目为 Windows 桌面）。
- 不做屏幕内容的服务端留存/入知识库（隐私红线，见第七节）。
- 不做语音唤醒、VRM 3D 形象（`agent-avatar-3d-v1` 已有积累，留 P2）。

## 三、D1 技术选型：桌面壳（必须先裁决）

| 选项 | 做法 | 影响 |
|---|---|---|
| **A（推荐）Electron** | 新建 `desktop/` 目录；主进程提供悬浮窗（`transparent` + `alwaysOnTop`）与 `desktopCapturer` 截屏；渲染层直接复用 Vue 组件 | 与 Vue 3 生态无缝；截屏/透明窗/托盘均为内置 API，社区方案最成熟；代价是包体与内存 |
| B Tauri v2 | 同架构，Rust 壳；截屏需官方 screenshot 插件 + 圈选区域需自绘 | 包体小、内存低，但 Rust 侧开发成本高，截屏能力不如 desktopCapturer 开箱即用 |
| C 浏览器扩展 / 纯 Web | — | **不满足诉求**：无法 always-on-top 悬浮于其他应用之上，无法捕获屏幕画面（`getDisplayMedia` 需每次用户确认且无法后台自动识别） |

**默认按 A 执行**，除非用户明确选 B。理由：本项目前端是 Vue + Vite，Electron 可直接加载现有构建产物；「悬浮球 + 截屏 + 置顶面板」三件套在 Electron 全部是一等公民 API，P0 最快闭环。

## 四、整体架构

```
┌─────────────────── Electron 桌面壳（新增 desktop/）───────────────────┐
│                                                                       │
│  主进程（Node）                          渲染进程（复用 Vue）          │
│  ├ Tray 托盘（开启/退出/设置）           ├ 悬浮球窗口（小、透明、置顶）│
│  ├ 悬浮球窗口管理（拖拽/显隐）           ├ 伴侣面板窗口（聊天+截屏卡） │
│  ├ capture 模块：desktopCapturer        └ 复用 AiChatPanel 逻辑（精简）│
│  │   → PNG base64（仅触发时截取）                                      │
│  ├ changeWatcher：感知哈希差分（自动模式，P1）                         │
│  └ IPC：capture→panel、panel→chat                                     │
└──────────────────────────────┬────────────────────────────────────────┘
                               │ HTTP SSE（复用现有端点，不新增服务）
                    ┌──────────▼──────────┐
                    │  ai-service 带图聊天 │
                    │  /stream (SSE)      │
                    │  Ollama 视觉模型    │
                    │  不可用→如实报错    │
                    └─────────────────────┘
```

要点：
1. **服务端零新增大模型代码**——悬浮面板发出的请求与 `/chat` 页面同构，仅消息里多一张截屏图。
2. 悬浮球与面板是两个独立 BrowserWindow：球常驻，面板按需显隐（对标搜题酱「一键截屏 悬浮出答案」）。
3. 桌面壳通过 IPC 完成截屏→注入面板输入流，渲染层不直接持有 capture 权限。

## 五、交互定义（对标搜题酱 + 小鲸鱼）

### 5.1 悬浮球（常驻）

| 手势 | 行为 | 对标 |
|---|---|---|
| **单击** | 展开悬浮对话面板（贴近球的位置弹出，点击外部/ESC 收起） | 搜题酱「单击出答案」 |
| **双击** | 截屏提问：进入圈选模式（拖框选取屏幕区域）→ 选取后自动作为图片消息发送 | 搜题酱「双击拍照搜」 |
| **长按 3s** | 弹出确认气泡（开启/关闭自动识别、退出悬浮球），防误触 | 搜题酱「长按 3s 关闭」 |
| 拖拽 | 自由移动，贴边吸附半隐藏 | 小鲸鱼 |
| 状态态 | 球体颜色/微动效承接 Companion 三态：SEE（识别中）/ THINK（推理中）/ KNOW（已回答）；降级时变警示色 | `CompanionStatus.vue` 既有语义 |

### 5.2 悬浮对话面板

- 紧凑单列（默认 320×420，可拉伸），消息流 + 输入框 + 「截屏提问」按钮。
- 截屏消息显示缩略图芯片，点击可放大。
- 流式输出、思考过程、降级提示全部沿用 `AiChatPanel.vue` 的交互与样式约定（体积原因抽成 `FloatingChat.vue` 精简版，共享消息渲染组件而非复制逻辑）。
- 面板打开期间球切换为「对话中」态。

### 5.3 自动识别模式（默认关，P1）

1. 开启时弹出**授权确认卡**（对标截图 1 的「整个屏幕」授权弹窗）：明示「开启后将读取屏幕画面用于 AI 解读，谨防密码、付款信息等内容泄露」，需用户点「开始」。
2. 桌面壳每 2–5s 对屏幕做**感知哈希（pHash）差分**：变化低于阈值不动作；显著变化且距上次解读 ≥ 30s 才截屏送视觉模型。
3. Agent 返回结构化简述（一两句话）以**气泡推送**形式从悬浮球弹出，点击进入面板细聊；QUIET 提醒模式下只更新球体状态不弹气泡。
4. 用户正在使用**黑名单窗口**（银行/支付/密码管理器，内置可配置）时暂停识别，球显示「已暂停」。

## 六、屏幕识别链路（截屏提问的五个真实步骤）

```
① 触发：双击圈选 / 面板按钮 / 自动模式显著变化
② 捕获：主进程 desktopCapturer 取全屏 → 按圈选裁剪 →
        本地缩放（长边 ≤ 1280px）+ PNG 压缩（目标 ≤ 1MB）→ base64
③ 发送：面板组装带图消息走现有 SSE 链路（ai-service /stream，
        images=[dataURL]），复用 ChatService 视觉分支
④ 生成：Ollama 视觉模型流式输出；TTFT 与推理指标照常并入 metadata.llm_perf
⑤ 回显：流式渲染进悬浮面板；失败如实报错（视觉模型不可用不降级 mock）
```

**诚实性红线（继承现有铁律）**：`llm.py:138-143` 明确带图请求绝不降级 mock。悬浮窗同样如此——未配置视觉模型 / Ollama 不可达时，面板如实提示「视觉模型不可用」，绝不输出假装识别了屏幕的答案。

## 七、数据与隐私红线

1. **截屏仅在触发时发生**：手动模式由用户手势触发；自动模式由用户显式开启且随时可停。绝不后台静默录制。
2. **服务端不留存**：截屏 base64 仅在 ai-service 请求内存中中转，不落库、不写日志（需核对现有 chat 日志脱敏策略，实施时把 image 字段排除出日志序列化）。
3. **本地最小化**：截屏本地压缩后再传输；自动模式仅传差分显著帧。
4. **排除自身**：截屏时剔除桌面壳自身窗口，避免「球截自己」递归。
5. **一键停止**：长按球 / 托盘菜单均可立即关闭自动识别并清空本地缓存帧。
6. **授权提示文案**对标截图 1：首次开启自动模式必须展示风险提示 + 「取消 / 开始」双按钮，小米/vivo 式的系统级前置说明对应到 Windows 即「首次运行时 Smart Defender/杀软可能提示录屏权限，属正常现象」的 FAQ。

## 八、实施分期

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0 最小闭环** | `desktop/` Electron 壳（悬浮球 + 托盘 + 面板两个窗口）；双击圈选截屏提问；复用 SSE 带图聊天链路；视觉不可用如实报错 | 全新目录可独立 `npm run dev`；截屏提问端到端流式回答；长按可退出 |
| **P1 自动识别** | changeWatcher 差分检测 + 节流；授权确认卡；黑名单窗口暂停；气泡推送；面板消息抽共享组件 | 自动模式默认关；开启后有授权卡；黑名单应用聚焦时不识别 |
| **P2 人格与打磨** | 球体三态动效承接 Companion（SEE/THINK/KNOW）；贴边吸附；开机自启开关；与 `xiaoyu-avatar-v1` / `agent-avatar-3d-v1` 形象打通 | 桌宠状态与 companion store 状态一致 |

代码落位：
- 新增 `desktop/`（Electron 主进程 + 精简 Vue 入口，构建产物可复用 `frontend/` 组件）。
- `ai-service`、`backend` **不改**（P0/P1）；若悬浮会话需要与 Web 端会话历史互通，再评估挂到现有会话存储（另立裁决）。

## 九、风险与降级

| 风险 | 应对 |
|---|---|
| Ollama 视觉模型本地推理慢（TTFT 高） | 面板显示真实 TTFT；截屏压缩到 ≤1MB 降低预填充开销；球体 THINK 态给等待反馈 |
| 视觉模型未配置 | 如实报错并给配置指引（`LLM_VISION_MODEL`），绝不 mock |
| Electron 包体/内存 | 仅打包悬浮壳所需模块；面板懒加载 |
| Windows DPI 缩放导致截屏模糊/坐标偏移 | 按 `scaleFactor` 换算圈选坐标（P0 就要处理，4K 高分屏常见坑） |
| 自动模式误触发频繁 | pHash 阈值 + 30s 节流 + QUIET 模式静默 |
| 竞赛演示场景 | 悬浮球是答辩演示的高光交互（评委桌面上直接圈选提问），P0 优先保证演示路径稳定 |
