## 2. 性能实测

| 指标 | 实测 | 方法 |
| --- | --- | --- |
| 布局（10 域 + 737 卡） | **1.6 – 2.5 ms** | 页面 `performance.now()` 打点，状态行直接显示 |
| 总览 DOM 卡片 | **0** | L0 只用 SVG 批量块（737 个 `<rect>`） |
| 68% 缩放 DOM 卡片 | **200（上限）** | 视口裁剪 + 200 张封顶 |
| 135% 阅读档 DOM 卡片 | **53 – 153** | 视口内可见卡片数，peak 200 |
| 首屏 | 一次 `applyCamera` 完成 | 无异步资源、152 KB 数据内联进 `<script>` |
| 帧时 | **本机 headless 不可信**（p50 66.6ms / p95 350ms） | 见下方说明 |

**帧时为什么不能当结论**：headless Chrome 用 SwiftShader 软合成，且 `--disable-gpu` 会跳过合成步骤，测出来的 66ms 是假数。原型内置了采样器（状态行显示 `帧 p50 / p95`），**在真实浏览器里打开即可读到真值**。这一条写进文档而不是删掉，是因为"没测到"和"测出好数字"必须能分开。

## 3. 三档 LOD 的实测行为

| 档 | k | 屏幕上 | DOM | 看起来 |
| --- | --- | --- | --- | --- |
| L0 总览 | 0.34 | 737 个色块（城市肌理） | 0 | 分区块 + HUD 域标签 + 迷你地图 |
| L1 域内 | 0.63–0.95 | 61×38 px 的卡，只显示 2 行标题 | ≤200 | 标题纹理，用来看"这一片在讲什么" |
| L2 阅读 | ≥0.95 | 98×61 px 起，标题 + 摘要 + 类型 | ≤200 | 真的能读，点开右侧侧栏 |

**卡片内容三档（按屏幕像素，不是按世界像素）**：

| tier | 触发 | 显示 |
| --- | --- | --- |
| `micro` | 宽 <44 或 高 <22 | 只有色条 |
| `title` | 44–124 | 2 行标题 |
| `full` | ≥124 且高 ≥80 | 标题 + 2 行摘要 + 类型 chip |

判据用**屏幕像素**：因为缩放会让同一张卡在不同档位可读性不同，用世界尺寸判断会在 68% 时误显示文字。

## 4. 两套渲染器怎么共处（本项目的关键）

| 观察 | 处理 |
| --- | --- |
| L0 挂 737 个 DOM 卡会卡 | 用 `<svg>` 批量画 737 个 `<rect>`，一次绘制 |
| 但 SVG 块和 DOM 卡同时出现会"两套视觉" | **按域切换**：某域挂载卡片 >4 张时，关掉它的 SVG 层（`.zone.bulk-off svg{opacity:0}`） |
| 邻居域没轮到 DOM 额度 | 保留 SVG 纹理——视觉上读作"更远"，反而是正确的 LOD 暗示 |

这就是 [DEEP-REVERSE.md §2.1](DEEP-REVERSE.md) 那条结论的落地版：**几何用 SVG，文字用 DOM，按"要不要读字"分工**。

## 5. 过程中撞到的真 bug（值得记）

| # | 现象 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 卡片左侧出现一个占卡片 1/4 宽的色块 | 卡片色条用了 `class="bar"`，**撞上页面顶栏的 `.bar`**（顶栏有 `height:54px; padding:0 14px`） | 改成 `.cbar`，并把 `height:auto;padding:0` 写死 |
| 2 | 首屏卡片是"细长条" | 网格只按"宽高比"选列数，没约束填空率 | 搜索 1–20 列，评分 = 宽高比偏差 + 空位比例 |
| 3 | 68% 时文字糊成一团 | tier 用世界像素判断 | 改用**屏幕像素**（乘 `cam.k`） |
| 4 | 域内卡片铺不满、下半截空 | 同上（列数选小） | 同上 |

第 1 条是这类设计最典型的坑：**新的视觉层复用了页面级通用类名**。已在 `PROMPT.md` 里加进红线。

## 7. 还没做的（明确的下一步）

1. **域清单对齐**：`network / web-lamp / linux-services` 三个域没有中文名与 detail，现在靠 `build-data.mjs` 里的兜底表。应写回 `knowledgeCatalog.js`。
2. **显式关系字段**：连线仍靠 `platform` 推断（本实装版甚至没画连线——737 条会把画面变毛线，需要先有关系数据）。建议加 `related: string[]`。
3. **接入真实路由**：原型是独立文件；接进 `/knowledge` 需要按 `PROMPT.md` 的组件拆分重写，不能直接搬。
4. **真浏览器帧时**：在有 GPU 的 Chrome 里打开 `?demo=fly`，把 `帧 p50/p95` 记进 §2。
