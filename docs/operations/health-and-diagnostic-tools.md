# 健康诊断与实用工具

## 功能范围

第一阶段提供四类只读能力：

- 健康诊断中心：展示当前账号可见的会话、智维 Mini、授权目标和管理员依赖状态。
- HTTP / API 可用性检查：只允许检查后端配置的授权目标，支持 `GET`、`HEAD`、状态码和受限 JSON 字段断言。
- HTTPS 证书检查：检查授权 HTTPS 目标的 TLS 握手、证书颁发者、SAN 和有效期。
- 配置差异检查：在浏览器本地比较两份文本，默认脱敏密码、令牌、密钥和私钥内容。

第一阶段不包含定时任务、告警通知、自动修复、任意 URL 探测、任意命令执行、诊断历史持久化或付费模型调用。

## 配置授权目标

后端通过 `smartops.diagnostics.targets` 配置固定目标，默认值为空，因此未配置时前端显示“未配置”，不会虚构探测成功。

示例只使用文档保留地址和占位域名：

```yaml
smartops:
  diagnostics:
    targets:
      - id: example-api
        displayName: 示例 API
        scheme: https
        hostname: api.example.invalid
        port: 443
        path: /health
        pinnedAddresses:
          - 203.0.113.10
        allowedUserIds:
          - 1001
        expectedStatus: 200
```

目标必须明确指定 `http` 或 `https`、端口、路径和固定 IP。浏览器只提交 `targetId`，不能提交任意 URL、主机名或 IP。管理员账号需要同时满足 `role=admin` 和 `portal=admin`，普通用户还必须出现在目标的 `allowedUserIds` 中；要求修改初始密码的账号不能执行主动探测。

固定地址策略拒绝回环、链路本地、组播、特定云元数据地址、共享地址空间和 IPv6 ULA 等目标。管理员可以明确配置 RFC1918 内网固定地址，因此白名单应只包含可信、已授权的服务。服务端不跟随重定向，连接超时为 3 秒，读取超时为 10 秒，响应体最多读取 256 KiB；每用户最多 2 个并发探测，全局最多 8 个。

## 结果解释

- `HEALTHY`：本次检查的证据满足预期，不代表所有业务功能都正常。
- `UNHEALTHY`：本次检查失败、状态码不符、断言失败或 TLS 校验失败。
- `UNCONFIGURED`：功能或授权目标未配置。
- `NOT_CHECKED`：前置检查失败，后续项目没有被虚构为成功。
- `FORBIDDEN`：当前账号没有该目标或管理员检查的权限。

证书检查不是完整 TLS 审计，不会替代漏洞扫描、证书链资产管理或密码套件审计。域名校验和 SNI 由 TLS 握手执行，页面展示的 SAN 仅是服务端证书中的名称集合。

## 配置差异的隐私边界

配置差异只在当前浏览器内计算，不上传后端、不调用 AI、不写入 `localStorage` 或其他持久化存储。单侧输入最多 256 KiB、5000 行，并限制差异计算量。敏感行保留“发生变化”的证据，但隐藏具体值；文本通过 Vue 文本节点渲染，不按 HTML 执行。

清空按钮会同时清除两侧原文、差异结果和敏感值预览。若配置包含真实密钥，仍建议使用测试副本并在比较后主动清除剪贴板和页面内容。

## 访问入口

- 普通用户：`/health` 查看自己的摘要，并只能使用被授权的目标。
- 管理员：管理员门户的“服务接入检查”查看数据库、关键业务表、Mini、观测数据源、Harbor 和诊断目标配置摘要。
- 工具中心：`/tools/service-http-check`、`/tools/service-certificate-check`、`/tools/config-diff`。

主动探测需要后端已配置目标。没有授权目标时，工具显示“当前没有授权目标”，不会发出探测请求。

## 第二阶段语义与轻量模式

- 视觉模式与浅色/深色主题独立：`balanced` 保留首页异步增强视觉，`lightweight` 使用 Canvas 轻量路径，`reduced-motion` 静态绘制 Canvas、关闭首页轮播自动播放并禁用过渡动画；非首页不预加载 Three.js。模式即时生效并保存显示偏好；切换轻量模式会卸载增强组件，但无法撤回此前已经下载的资源。
- 健康结果只在最近五分钟内视为新鲜。刷新失败时保留最近结果作为过期参考，明确显示“结果可能已过期”，不会把旧的 `HEALTHY` 继续标记为当前健康。
- 主动探测错误使用稳定分类：`CONFIGURATION`、`AUTHORIZATION`、`TIMEOUT`、`NETWORK`、`ASSERTION`、`NOT_CHECKED`。页面不展示响应正文、请求凭据、固定地址或异常堆栈。
- 管理员策略摘要仅展示授权目标数量、并发限制、连接/读取超时、响应大小上限和 Mini、观测源、Harbor 的配置状态。所有主动检查均为手动、只读、受白名单控制。

本阶段仍不提供定时告警、后台通知、自动修复、任意 URL 探测、Shell 或任意命令执行；诊断结果不写入服务端历史，也不交给外部模型。

新鲜度计时器只更新页面标签，不发起后台检查。Mini 的“已配置”表示应用已加载并校验本地模型配置，不表示模型运行时当前可用；实际可用性以健康检查项为准。状态字段保持兼容，HTTP 和证书探测返回可选 `errorCategory`；鉴权和参数校验仍由原有 HTTP 错误边界拒绝，前端将其转换为脱敏分类文案。
