# 智维Agent · 神经网络组件评估指标体系（完整版）

> 适用对象：智维Agent 内四类神经网络插件
> - **AnomalyTransformer**（时序异常检测）
> - **PatchTST**（单指标多步时序预测）
> - **GNN / GAT / GraphSAGE**（根因定位）
> - **TinyBERT / TextCNN**（日志文本分类 / 聚类）
>
> 版本：v1.1 ｜ 最后更新：2026-11-18
>
> 约定：每个指标给出「**公式**」与「**采集口径**」，采集口径按
> `数据来源 → 统计步骤 → 边界处理` 三段展开，确保可落地复算。

---

## 0. 使用说明与分层原则

### 0.1 一套体系，两层口径

评估必须区分两个层次，不能混用同一张表：

| 层次 | 回答的问题 | 指标来源 |
|---|---|---|
| **组件指标**（本文档） | 每个神经网络插件「本身准不准、快不快」 | 离线测试集、故障注入、人工标注 |
| **Agent 端到端指标** | 插件「是否让巡检 Agent 变好」 | 任务成功率、人工介入率、平均完成轮次、返工率 |

本文档只覆盖**组件指标**。

### 0.2 混淆矩阵统一约定

| 符号 | 含义 |
|---|---|
| TP | 异常被报为异常 |
| TN | 正常被报为正常 |
| FP | 正常被误报为异常 |
| FN | 异常被漏报为正常 |

### 0.3 四个模块的指标归属

| 模块 | 任务类型 | 核心指标 | 辅助指标 |
|---|---|---|---|
| AnomalyTransformer | 逐点/逐事件二分类 | PR-AUC、事件级 F1、TTD、NAB Score | FPR、FNR、Delay、Coverage |
| PatchTST | 多步回归预测 | MAE、MSE、区间覆盖率 | 逐步 MAE、平均区间宽度、基线提升率 |
| GNN 根因定位 | 候选排序 | A@1、A@3、MRR | MAP、NDCG、Hit Rate |
| TinyBERT 日志分类 | 分类 | F1、PR-AUC | Recall@k、Specificity |
| TinyBERT 日志聚类 | 聚类 | ARI | AMI、Silhouette |

## 1. 通用分类指标

> 适用于：日志分类、告警识别，以及时序异常检测的基础指标。

### 1.1 Recall（召回率 / Sensitivity）

**定义**：真实异常中被成功检出的比例，侧重**不漏报**。

$$Recall = \frac{TP}{TP + FN}$$

**采集口径**
- **数据来源**：带标注的测试集；标签来自①人工标注（日志/告警）或②故障注入记录（时序）。
- **统计步骤**：逐点或逐事件比对预测标签与 ground-truth，统计 TP、FN。
- **边界处理**：正负不均衡时 Recall 更能暴露漏报风险；报告须注明「逐点」还是「逐事件」。

**答辩**：★★★ 必放。漏报 = 事故。

### 1.2 Precision（精确率）

**定义**：模型判为异常的样本中真正是异常的比例，侧重**不误报**。

$$Precision = \frac{TP}{TP + FP}$$

**采集口径**
- **数据来源**：同 Recall，一套测试集同时出 P 与 R。
- **统计步骤**：分母为模型输出为正的样本数，分子为其中与 ground-truth 一致的真异常数。
- **边界处理**：负样本远多于正样本时，少量 FP 就会显著拉低 P。

**答辩**：★★★ 必放。误报多会淹没值班。

### 1.3 F1-Score

**定义**：Precision 与 Recall 的调和平均。

$$F1 = \frac{2 \times P \times R}{P + R} = \frac{2TP}{2TP + FP + FN}$$

**采集口径**
- **数据来源**：由 1.1 / 1.2 的 P、R 计算。
- **统计步骤**：单阈值下计算；报告时必须写明阈值（默认 0.5，或验证集上的最优阈值）。
- **边界处理**：P=R=0 时 F1 无定义，记 0；不同阈值下 F1 不可直接比较。

**答辩**：★★★ 必放。

### 1.4 Accuracy（准确率）

**定义**：全部样本中预测正确的比例。

$$Accuracy = \frac{TP + TN}{TP + TN + FP + FN}$$

**采集口径**
- **数据来源**：同套测试集。
- **统计步骤**：正确样本数 / 总样本数。
- **边界处理**：正负悬殊时虚高，**AIOps 场景不建议作为主指标**。

**答辩**：✗ 慎用 / 不放。

### 1.5 Specificity（特异度）

**定义**：正常样本中被正确判定为正常的比例。

$$Specificity = \frac{TN}{TN + FP}$$

**采集口径**
- **数据来源**：同套测试集。
- **统计步骤**：分母为 ground-truth 正常样本数。
- **边界处理**：与 Recall 互补，用于区分「对正常波动的容忍度」。

**答辩**：★★ 可选。

### 1.6 ROC-AUC

**定义**：ROC 曲线下面积，描述不同阈值下的整体区分能力。

$$TPR = \frac{TP}{TP+FN},\quad FPR = \frac{FP}{FP+TN}$$

$$AUC = \int_{0}^{1} TPR(FPR)\,dFPR$$

**采集口径**
- **数据来源**：模型输出的**概率/分数**（连续值），不能是硬标签。
- **统计步骤**：对分数排序，以每个分数为阈值算 (FPR, TPR) 点集，梯形法求面积。
- **边界处理**：模型只输出 0/1 时无法计算；正负极度不均衡时 ROC 偏乐观。

**答辩**：★★ 可选。

### 1.7 PR-AUC（Precision–Recall 曲线下面积）

**定义**：PR 曲线下面积。

$$PR\text{-}AUC = \int_{0}^{1} Precision(Recall)\,dRecall$$

**采集口径**
- **数据来源**：同 ROC-AUC，需连续分数。
- **统计步骤**：扫描阈值得 (Recall, Precision) 点集求面积；曲线起点插值到 Recall=0 处 Precision=1。
- **边界处理**：正负不均衡下比 ROC-AUC 更敏感，**异常检测首选**。

**答辩**：★★★ 异常检测首选 AUC。

## 2. 时序指标：异常检测与预测

> 2.1–2.7 适用于 AnomalyTransformer 异常检测；2.8–2.10 适用于 PatchTST 多步预测。两类任务不可混用指标。

### 2.1 FPR（假阳性率 / 误报率）

**定义**：正常点被误判为异常的比例。

$$FPR = \frac{FP}{FP + TN}$$

**采集口径**
- **数据来源**：逐点标签。
- **统计步骤**：分母为正常点总数，分子为被误报的正常点数。
- **边界处理**：按固定阈值（或对应固定 Recall 的阈值）报告，注明阈值。

**答辩**：★★ 推荐，目标压低。

### 2.2 FNR（假阴性率 / 漏报率）

**定义**：真实异常未被识别的比例。

$$FNR = \frac{FN}{TP + FN} = 1 - Recall$$

**采集口径**
- **数据来源**：逐点标签。
- **统计步骤**：分母为异常点总数。
- **边界处理**：与 FPR 构成一对权衡，通常固定其一看另一个。

**答辩**：★ 可选。

### 2.3 TTD（Time To Detect，检测时延）

**定义**：故障真实发生时刻到模型首次输出异常的时间差。

$$TTD = t_{alert} - t_{fault}$$

**采集口径**
- **数据来源**：故障注入平台的时间戳（`t_fault`）+ 模型告警流时间戳（`t_alert`）。
- **统计步骤**：每个注入故障取「第一次告警时刻 − 注入时刻」。
- **边界处理**：未检出的故障不计入 TTD 均值（或记超时惩罚，须注明）；时间戳精度需到秒/毫秒。

**答辩**：★★★ 必放，体现「检测快不快」。

### 2.4 Delay（平均检出延迟）

**定义**：一批异常的 TTD 均值。

$$Delay = \frac{1}{N}\sum_{i=1}^{N} TTD_i$$

**采集口径**
- **数据来源**：同上，取全部被检出故障的 TTD。
- **统计步骤**：算术平均。
- **边界处理**：与「检出率」一起报，否则漏检多时 Delay 会虚低。

**答辩**：★ 可选。

### 2.5 NAB Score（NAB 评估分数）

**定义**：Numenta Anomaly Benchmark 标准打分，**鼓励早检出、惩罚延迟与误报**。

**采集口径**
- **数据来源**：模型告警序列 + 标注异常窗口（NAB 格式）。
- **统计步骤**：用 NAB 官方评分脚本（`nab/detectors` + `nab/score`）计算标准分。
- **边界处理**：正常段记 0；漏检、延迟、误报均按 NAB 权重扣分；跨数据集比较须用同一 NAB 版本。

**答辩**：★★★ 必放，AIOps 论文通用。

### 2.6 Anomaly Coverage（异常覆盖度）

**定义**：连续异常段内被识别出的时间占比。

$$Coverage = \frac{\text{识别出的异常时长}}{\text{真实异常总时长}}$$

**采集口径**
- **数据来源**：按事件窗口标注的异常段。
- **统计步骤**：逐段算「被命中的时长 / 段总时长」再求和归一。
- **边界处理**：适用于持续型异常，单点尖峰场景退化为点级 Recall。

**答辩**：★ 可选。

### 2.7 关键口径：点级 vs 事件级

> 指标流逐点，但运维关心「一次故障事件」。

- **点级 F1**：逐点判定，可能把同一次故障切成零散告警。
- **事件级 F1**：先按「相邻告警间隔 < N 秒」合并为一次事件，再算 F1。

**采集口径**：事件级必须写明窗口参数 N；**优先报事件级 F1**，更贴合 Agent 使用。

### 2.8 MAE / MSE（PatchTST 点预测误差）

设测试样本数为 `N`，预测步数为 `H`，第 `i` 个样本第 `h` 步的真值和预测值分别为 `y_{i,h}`、`ŷ_{i,h}`：

$$MAE = \frac{1}{NH}\sum_{i=1}^{N}\sum_{h=1}^{H}|y_{i,h}-\hat{y}_{i,h}|$$

$$MSE = \frac{1}{NH}\sum_{i=1}^{N}\sum_{h=1}^{H}(y_{i,h}-\hat{y}_{i,h})^2$$

**采集口径**
- **数据来源**：独立测试集的未来真值 + PatchTST 逐步点预测；训练、验证、测试按指标实体和时间隔离。
- **统计步骤**：将预测逆归一化到原始指标单位后计算总体 MAE/MSE，并按 `h=1...H` 单独报告逐步 MAE。
- **边界处理**：不同量纲指标的 MAE/MSE 不能直接横向比较；缺失真值不得静默填充为预测值；测试窗口不得与训练窗口泄漏重叠。

**答辩**：★★★ 必放。MAE 便于运维解释，MSE 用于暴露大偏差。

### 2.9 PICP / MPIW（预测区间覆盖率与平均宽度）

$$PICP = \frac{1}{NH}\sum_{i=1}^{N}\sum_{h=1}^{H}\mathbb{1}[L_{i,h}\le y_{i,h}\le U_{i,h}]$$

$$MPIW = \frac{1}{NH}\sum_{i=1}^{N}\sum_{h=1}^{H}(U_{i,h}-L_{i,h})$$

**采集口径**
- **数据来源**：同一点预测实验的真值、逐步下界 `L` 和上界 `U`。
- **统计步骤**：95% 区间报告 PICP 与标称 0.95 的差值，同时报告 MPIW；必要时按 horizon 分组。
- **边界处理**：当前 `value ± 1.96 × residual_std` 是残差正态近似，标称 95% 不代表实际 PICP 必为 0.95；未经独立验证集校准不得称为校准置信区间。

**答辩**：★★★ 区间能力必放，覆盖率与宽度必须成对出现。

### 2.10 朴素基线提升率

以最后观测值重复（last-value naive）或季节朴素预测为基线：

$$Improvement = 1 - \frac{MAE_{PatchTST}}{MAE_{baseline}}$$

**采集口径**
- **数据来源**：完全相同测试窗口上的 PatchTST 与基线预测。
- **统计步骤**：分别计算 MAE 后代入上式；正值表示 PatchTST 优于基线，零表示无增益，负值表示逊于基线。
- **边界处理**：统计 fallback 的 linear/seasonal_naive 结果不得计入 PatchTST 指标；训练冒烟或合成数据结果不得写成生产提升。

**答辩**：★★★ 必放，用于证明神经模型不是“复杂但无增益”。

## 3. GNN 根因定位（排序任务）专用指标

> GNN 输出是**候选根因排序列表**，须用排序指标，不用 F1。

### 3.1 A@k（Accuracy@k / Top-k 命中率）

**定义**：真实根因出现在前 k 个候选中的故障占比。

$$A@k = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\big[\,R_i \cap Top_k(\hat{y}_i) \neq \varnothing\,\big]$$

**采集口径**
- **数据来源**：每故障的 ground-truth 根因节点集合 `R_i`（演练/人工复盘）+ 模型排序列表 `ŷ_i`。
- **统计步骤**：判断 Top-k 候选与 `R_i` 交集是否非空，命中记 1。
- **边界处理**：k 固定取 1/3/5；`R_i` 含多节点时「命中任一」即记命中。

**答辩**：★★★ 必放，优先报 A@1 与 A@3。

### 3.2 MRR（Mean Reciprocal Rank）

**定义**：真实根因排位倒数的均值，排位越靠前越接近 1。

$$MRR = \frac{1}{N}\sum_{i=1}^{N}\frac{1}{rank_i}$$

**采集口径**
- **数据来源**：同 A@k。
- **统计步骤**：`rank_i` 为第 i 个故障**第一个命中**的真实根因位次。
- **边界处理**：未命中的故障贡献记 0（不能忽略，否则 MRR 虚高）。

**答辩**：★★★ 必放。

### 3.3 MAP（Mean Average Precision）

**定义**：多根因场景的平均精度均值。

$$AP = \frac{1}{|R|}\sum_{k=1}^{n} P@k \cdot rel(k),\quad P@k = \frac{|\{Top_k\} \cap R|}{k},\quad MAP = \frac{1}{N}\sum AP_i$$

**采集口径**
- **数据来源**：`R` 为多根因集合，`rel(k)` 为第 k 位是否命中。
- **统计步骤**：对每个故障算 AP 再平均。
- **边界处理**：仅多根因场景有意义；单根因场景退化为 MRR 等价量。

**答辩**：★★ 可选。

### 3.4 NDCG（Normalized Discounted Cumulative Gain）

**定义**：给靠前位置更高权重，适合有主次的多根因。

$$DCG@k = \sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)},\quad NDCG@k = \frac{DCG@k}{IDCG@k}$$

**采集口径**
- **数据来源**：`rel_i` 为相关度等级（主根因=2 / 次根因=1 / 无关=0）。
- **统计步骤**：`IDCG` 为理想排序下的 DCG，作归一化。
- **边界处理**：相关度分级须人工定义，报告时写清分级规则。

**答辩**：★★ 可选。

### 3.5 Root Cause Hit Rate（根因命中率）

**定义**：至少命中一个真实根因的故障占比。

$$HitRate = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\big[\,R_i \cap \hat{y}_i \neq \varnothing\,\big]$$

**采集口径**
- **数据来源**：同 A@k，但不限 Top-k，看整张排序列表。
- **统计步骤**：整列表与 `R_i` 交集非空记 1。
- **边界处理**：是 A@k 的放宽版，适合粗筛。

**答辩**：★ 可选。

## 4. 文本分类 / 聚类指标（TinyBERT / TextCNN）

### 4.1 ARI（调整兰德指数）

**定义**：聚类与人工标注分组的一致性，校正随机一致。

$$ARI = \frac{\sum_{ij}\binom{n_{ij}}{2} - \left[\sum_i\binom{a_i}{2}\sum_j\binom{b_j}{2}\right]/\binom{n}{2}}{\frac{1}{2}\left[\sum_i\binom{a_i}{2}+\sum_j\binom{b_j}{2}\right] - \left[\sum_i\binom{a_i}{2}\sum_j\binom{b_j}{2}\right]/\binom{n}{2}}$$

**采集口径**
- **数据来源**：人工标注的告警分组（真实簇）+ 模型簇标签。
- **统计步骤**：`n_ij` = 同时属于真实簇 i 与预测簇 j 的样本数；`a_i`、`b_j` 为行/列和。
- **边界处理**：取值 [-1,1]，接近 1 好，0 = 随机水平，负 = 差于随机。

**答辩**：★★ 推荐，无监督聚类首选。

### 4.2 AMI（调整互信息）

**定义**：聚类与标注的互信息，经随机校正。

$$AMI = \frac{MI(U,V) - E[MI(U,V)]}{\max(H(U),H(V)) - E[MI(U,V)]}$$

**采集口径**
- **数据来源**：真实簇与预测簇的联合分布。
- **统计步骤**：由联合分布算互信息 MI 与熵 H，减随机期望后归一。
- **边界处理**：接近 1 好；对簇数量敏感，可与 ARI 交叉印证。

**答辩**：★ 可选。

### 4.3 Silhouette Coefficient（轮廓系数）

**定义**：无标注时评估向量聚类紧凑度。

$$s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}$$

**采集口径**
- **数据来源**：无标注的嵌入向量。
- **统计步骤**：`a(i)`=到同簇其余样本平均距离，`b(i)`=到最近邻簇平均距离；全样本取均值。
- **边界处理**：单簇或某簇仅 1 个样本时无法计算，需排除。

**答辩**：★ 可选。

### 4.4 Recall@k / Precision@k

**定义**：向量检索场景下，Top-k 相似历史故障的召回/精确度（RAG 向量模型）。

$$Recall@k = \frac{|Top_k \cap R|}{|R|},\quad Precision@k = \frac{|Top_k \cap R|}{k}$$

**采集口径**
- **数据来源**：人工标注的相似故障集合 `R` + 模型 Top-k 检索结果。
- **统计步骤**：分别按上式统计，k 固定（如 5/10）。
- **边界处理**：`R` 为空无法算 Recall@k；k 与 `|R|` 量级需匹配。

**答辩**：★ 可选。

## 5. 模型效率指标（工程维度，答辩加分）

| 指标 | 公式 / 口径 | 答辩 |
|---|---|---|
| **Inference Latency** | $$Latency_p = \text{第 }p\text{ 百分位的单样本端到端耗时}$$ 口径：含特征提取→推理→后处理的完整链路，采≥1000 条样本，报 P50/P95 | ★★ 推荐 |
| **Throughput** | $$Throughput = \frac{\text{处理样本数}}{\text{耗时(秒)}}$$ 口径：批量推理下的稳态吞吐，排除首包冷启动 | ★ 可选 |
| **Params / FLOPs** | 参数量 = 模型可训练参数总数；FLOPs = 前向一次浮点运算次数。口径：用 `torchinfo`/`thop` 统计，用于 TinyBERT vs BERT 轻量对比 | ★★ 推荐 |
| **Memory Usage** | 推理时显存/内存峰值占用。口径：`nvidia-smi` 或 `tracemalloc` 采样峰值 | ★ 可选 |
| **Training Cost** | 训练轮次 + 所需标注样本量。口径：记录收敛 epoch 与标注条数，无监督模型在此体现优势 | ★ 可选 |

---

## 6. 鲁棒性指标（拔高、适合消融实验）

### 6.1 性能衰减率

**定义**：输入加噪后指标下降幅度，下降越少越鲁棒。

$$衰减率 = \frac{M_{clean} - M_{noisy}}{M_{clean}}$$

**采集口径**
- **数据来源**：原始测试集 + 扰动测试集（指标加噪 / 日志乱码 / 拓扑缺边）。
- **统计步骤**：分别测 F1 / A@k，代入上式。
- **边界处理**：扰动强度需量化（如 SNR、缺边比例），报告时写明。

**答辩**：★★ 推荐，消融标配。

### 6.2 OOD 召回率

**定义**：分布外、训练集未见过的故障能否识别。

$$OOD\text{-}Recall = \frac{TP_{ood}}{TP_{ood} + FN_{ood}}$$

**采集口径**
- **数据来源**：与训练分布不同的故障测试集（新故障类型）。
- **统计步骤**：统计 OOD 集上的 Recall。
- **边界处理**：须证明测试集与训练分布确实不同（如新故障类别）。

**答辩**：★ 可选，拔高项。

## 8. 避坑清单

1. 异常检测不放 Accuracy（不均衡虚高）。
2. GNN 不用 F1（排序任务用 A@k / MRR）。
3. 区分点级与事件级 F1，优先报事件级。
4. 区分组件指标与端到端指标。
5. 报 AUC 须用概率/分数，硬标签无法画曲线。
6. MRR 未命中根因记 0，不能忽略漏检。
7. PatchTST 是预测模型，不能用 PR-AUC/F1 代替 MAE/MSE；`risk_score` 不是校准概率。
8. 95% 残差近似区间必须同时报告实际覆盖率和区间宽度，不能只报告标称 95%。
9. **安全基线 FN 必须为 0**——红线漏拦 = 破坏性操作被执行 = P0 事故，不存在"权衡取舍"。
10. **fail-closed 启动验证率必须 100%**——任何篡改都不能让装配继续，这是基线与普通检查器的核心差异。
11. **审计落盘覆盖率必须 100%**——拦截决策不落盘意味着"事后不可追溯"，白名单缺项是配置缺陷。
12. 安全基线评估不替代组件评估——神经网络的"准不准"是组件问题，基线的"拦没拦、fail-closed 了没"是执行链问题，两者独立评估。

## 9. 采集口径汇总（原始数据字段清单）

| 指标族 | 所需原始数据 |
|---|---|
| 分类（F1 / AUC / Recall） | 逐样本 ground-truth 标签 + 模型输出分数/标签 |
| 异常检测（TTD / NAB / Coverage） | 带时间戳的故障注入记录 + 模型告警时间戳 + 事件窗口参数 |
| 时序预测（MAE / MSE / 区间覆盖率） | 固定采样周期的历史序列 + 未来真值 + 逐步点预测/上下界 + 数据切分记录 |
| 根因（A@k / MRR / MAP / NDCG） | 每故障的 ground-truth 根因集合 + 模型排序列表 |
| 聚类（ARI / AMI / Silhouette） | 人工标注告警分组 + 模型簇标签（或嵌入向量） |
| 效率（Latency / FLOPs / Throughput） | 推理耗时采样 + 模型结构参数 + 批量吞吐采样 |
| 鲁棒性（衰减率 / OOD） | 加噪前后指标对比 + 分布外测试集 |
| **安全基线（第 10 节）** | 规则 ID + 审计落盘路径 + 篡改注入脚本 + 多源传感器标签 + 重启装配日志 |

## 10. 安全基线 / Agent 执行链评估指标

> 适用于：SmartOpsAgent 安全基线框架（L0 合规 / L2 运维红线 / L1 限流 / L3 多模态仲裁）与生产执行链组合根
> - 与前 1–6 节的**组件指标**不同，本章覆盖**执行链闸门效能**——「拦住了多少、放行的有没有、审计可不可信、fail-closed 是不是真 fail 了」
> - 每个指标的 ground-truth 来自**人工标注 + 故障注入 + 篡改脚本**三类手段，具体见各指标的「采集口径」

### 10.1 红线拦截率（Redline Block Rate）

**定义**：应被红线（L0 合规 + L2 运维）拦住的命令中，实际被基线闸门拦截的比例。**越高越好，漏拦意味着破坏性操作可能被执行**。

$$BlockRate = \frac{TP}{TP + FN}$$

| 符号 | 含义 |
|---|---|
| TP | 应被拦截且实际被拦截的命令（`action=BLOCK`，`layer=L0` 或 `L2`） |
| FN | 应被拦截但实际放行的命令（最危险的一类，**必须为 0**） |

**采集口径**
- **数据来源**：含 50+ 条危险命令的标准语料（`rm -rf /`、`DROP TABLE`、非法网络扫描等），每条标注「应被哪层拦截」；生产运行的审计链中 `baseline.redline_hit` 与 `baseline.compliance_hit` 事件。
- **统计步骤**：逐命令注入执行器 → 比对实际拦截结果与标注 → 统计 TP、FN。
- **边界处理**：FN > 0 视为 P0 缺陷（破坏性操作漏拦）；L0 合规层的漏拦同样算 FN。

**答辩**：★★★ 必放，红线漏拦 = 事故。

### 10.2 红线误杀率（Redline False Positive Rate）

**定义**：安全命令中被红线误判为危险的比例。过高会导致正常运维动作被阻塞。

$$FPR_{redline} = \frac{FP}{FP + TN}$$

**采集口径**
- **数据来源**：含 100+ 条正常运维命令的语料（`rm -rf ./tmp/cache`、`iptables -L`、`nginx -s reload` 等，全部标注「应放行」）。
- **统计步骤**：逐命令注入执行器 → 统计被判 BLOCK 的数量。
- **边界处理**：阈值取 ≤ 1%；高于 5% 会显著降低 Agent 可用性。

**答辩**：★★★ 必放。

### 10.3 审计事件落盘覆盖率

**定义**：所有应产生审计事件的基线决策中，实际在哈希链中落盘的比例。**必须 100%**——这是"安全"可审计性的基本保证。

$$Coverage_{audit} = \frac{\text{落盘的决策事件数}}{\text{应落盘的决策事件数}}$$

**采集口径**
- **数据来源**：生产或测试环境中 24 小时内的基线拦截记录 + 对应审计 JSONL 文件。
- **统计步骤**：遍历所有 BLOCK/ESCALATE 决策（这些按规则必须落盘）→ 逐一核对在审计链中是否能查到，且 `audit_required_events` 白名单覆盖对应事件类型。
- **边界处理**：低于 100% 意味着白名单缺项或 sink 异常，视为配置缺陷；放行（ALLOW）决策默认不落盘，不计入分母。

**答辩**：★★★ 必放，审计是安全的"事后可追溯"保障。

### 10.4 fail-closed 启动验证率

**定义**：故意破坏审计历史后，生产装配是否正确拒绝启动的比例。**必须 100%**——这是安全基线"启动闸门"的 fail-closed 承诺。

$$FailClosedRate = \frac{\text{篡改后装配抛 ValueError 的次数}}{\text{篡改总次数}}$$

**采集口径**
- **数据来源**：篡改脚本（活动行内容篡改 / 分段删除 / manifest 篡改 / 夹带未登记文件）+ `build_agent_assembly()` 或 `build_security_baseline()` 调用日志。
- **统计步骤**：对每种篡改手段重复 3 次 → 记录装配是否抛 ValueError（允许的唯一出口），不得静默跳过或降级启动。
- **边界处理**：只要有一次篡改后装配仍能启动，FailClosedRate < 100% 视为启动闸门缺陷，优先级 P0。

**答辩**：★★★ 必放，fail-closed 是基线与普通检查器的核心差异。

### 10.5 审计哈希链验证率

**定义**：生产运行中 `verify_audit_chain()` 返回 `ok=True` 的占比。

$$ChainOKRate = \frac{\text{verify 返回 ok=True 的运行次数}}{\text{运行总次数}}$$

**采集口径**
- **数据来源**：每小时触发一次 `assembly.verify_audit_chain()` 的巡检脚本结果。
- **统计步骤**：逐日汇总 `ok` 字段。
- **边界处理**：低于 100% 的原因通常是磁盘损坏或人工误删审计文件，需要告警；与篡改检出（10.4）一起形成事前-事后双重验证。

**答辩**：★★ 推荐。

### 10.6 多模态仲裁准确率（L3）

**定义**：多源传感器输入时（视觉 + 温感 + 机械力矩等），仲裁决策与人工复盘结论的一致率。单源输入永远不能授权破坏性动作（机器人拉闸/断电），这是仲裁层的硬约束。

$$ArbAccuracy = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\big[\,decision_i = ground\_truth_i\,\big]$$

**采集口径**
- **数据来源**：故障注入平台产生的多源传感器读数 + 每场景的人工复盘结论（ALLOW / ESCALATE / BLOCK）。
- **统计步骤**：逐场景比对仲裁器输出与 ground-truth；单源破坏性动作场景必须全部判定 ESCALATE（否则视为 FN）。
- **边界处理**：单源 + 破坏性动作 → 永远 ESCALATE，绝不允许 ALLOW；两个异质源确认 → 允许 ALLOW。

**答辩**：★★ 推荐，L3 仲裁是物理安全的核心。

### 10.7 L1 注入/脱敏拦截率

**定义**：含有注入向量（SQL 注入、Prompt 注入、命令注入）的输入文本中，被 L1 层正确 BLOCK 或 REDACT 的比例。

$$InjectionBlockRate = \frac{\text{被拦截/脱敏的注入输入数}}{\text{注入输入总数}}$$

**采集口径**
- **数据来源**：OWASP Top 10 注入攻击语料 + 内部积累的 Prompt 注入样本（各 ≥ 100 条）。
- **统计步骤**：逐样本通过 `SecurityBaselineEngine.evaluate_input()` → 比对输出 `action` 与 `redacted_text`。
- **边界处理**：Prompt 注入通常走 REDACT（避免泄露给下游模型），SQL/命令注入走 BLOCK。

**答辩**：★★ 推荐。

### 10.8 闸门决策延迟

**定义**：基线闸门（L0 + L1 + L2 + L3）从收到输入到返回决策的 P95 延迟。基线决策发生在 PolicyEngine 之前，延迟会直接叠加到端到端工具调用耗时。

$$Latency_{gate}^{P95} = \text{第 95 百分位的决策耗时}$$

**采集口径**
- **数据来源**：基线引擎内部埋点（`emit_event` 前记录时间戳）或执行器侧日志。
- **统计步骤**：≥ 1000 次调用的延迟样本，排除冷启动。
- **边界处理**：基线决策是纯 CPU 正则 + 查表，延迟应在 **亚毫秒级**；超过 5ms 需要排查（通常是审计 sink I/O 阻塞）。

**答辩**：★ 可选，工程维度加分。

### 10.9 安全基线三阶段评估清单（可直接进 PPT）

| 评估阶段 | 核心指标 | 合格门槛 |
|---|---|---|
| **闸门效能** | 红线拦截率（≥ 99%）、红线误杀率（≤ 1%）、注入拦截率 | FN 必须为 0 |
| **可信审计** | 审计落盘覆盖率（100%）、哈希链验证率（≥ 99.9%） | 白名单无缺项 |
| **fail-closed** | 篡改后拒绝启动率（100%） | 任何篡改都不能让装配继续 |

> **与组件指标的关系**：安全基线评估不替代前 1–6 节的神经网络组件评估。神经网络的"准不准、快不快"由组件指标覆盖，安全基线的"拦没拦、审没审、fail-closed 了没"由本章覆盖。两者是 SmartOpsAgent 质量保障的互补维度。
