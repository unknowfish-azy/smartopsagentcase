## 1. 为什么现在不能写实证论文：三条硬证据

### 1.1 标签—探针循环（最致命，本轮新发现）

`EXP-CIRC-001`（`reports/label-probe-circularity.{json,md}`）：

- 全量 144 条：探针健康 ⇒ `SUCCESS`（36）；探针不健康 ⇒ `FALSE_SUCCESS`(48) /
  `FAILED`(30) / `UNKNOWN`(30)。列联**完美对角**，Fisher 精确单侧
  **p ≈ 9.1e-13**。
- 主指标二分类分母 n=72 上，平凡规则「不健康 ⇒ FALSE_SUCCESS」复现 **72/72**，
  反极性对照 **0/72**。逐 split：train 28/28、validation 22/22、test 22/22，
  反极性全部为 0。
- **含义**：`EXP-BASELINE-001` 的 P/R/F1=1.0000 **不需要任何 claim 语义理解**——
  核验器等价于 `prediction = f(probe_health)`，而标签本身也是
  `g(probe_health, claim_state)`。两者共享同一决定性输入，构成**循环论证**。
- 生成器自陈（`build_controlled_dataset.py:519` `LABEL_CONTRACT`）：
  "合成 fixture：标签由探针断言直接推出，非真实业务观测"。
  **这不是数据造假**——DATA-CARD 亦声明合成性质。问题是**指标被误用为能力证据**。
- 分割稳定性（`EXP-CEIL-001`）：随机半组分割 **200 次**，主指标准确率恒为
  **1.0000–1.0000（零波动）**，平凡规则复现率同样恒为 1.0。有效单元数却随切分变化
  （p50 可判 n=36）。**指标对样本量不敏感 = 无效指标的特征**。

### 1.2 措辞泛化未检验（同源循环）

`EXP-WORDING-001`（`reports/wording-holdout.{json,md}`）：

- 24 组每组仅 **2 场景 × 3 模板**，唯一 claim 串 3–6 条/组，跨场景模板复用率高。
- 按变体切分后两侧仍**精确重叠 13 条**、≥8 字符公共片段 **645 个** →
  `wording_holdout_feasible = false`，**措辞层留出不可行**。
- 词表本身取自这 144 条 claim（`state_verifier.py` L76–145 的覆盖清单），
  **词表与评测集同源**。
- 同组配对一致性（单位=`root_cause_group`，n=24）：两侧均全对 12 组、一致率 0.50。

### 1.3 信息量上限与既有口径

`EXP-CEIL-001`（`reports/dataset-ceiling.{json,md}`）：

- 组内标签唯一 ⇒ 独立信息单元 = **24**（SUCCESS 6 / FALSE_SUCCESS 8 / FAILED 5 /
  UNKNOWN 5），**不是 144 条**。任何「n=144」「n=48」口径把信息量高估 6 倍与 2 倍。
- 主终点子集有效 n 上界 **4**（`EXP-ICC-001`），Wilson 区间偏窄。
- RAG 侧对照链仍 **`NOT_RUN`**：受控集 `knowledge` 字段为空、无检索真值；
  RAG 消融唯一数据源是 Linux 领域集 14 条（全 DRAFT）。

## 2. 路线 A：可写，且本轮发现正是它的贡献

### 2.1 定位

**标题方向**：《合成基准中的标签—探针循环：运维 Agent 假成功检测评测的效度陷阱与修复协议》

核心论点：**用「探针期望」构造标签、再用同一探针核验结论，会让任何指标退化为读探针**。
这个陷阱在 AIOps/Agent 评测里具有普遍性（只要标签从 verifier 的输入导出就会发生），
而现有工作很少把它当作方法学问题正式报告。

### 2.2 贡献清单（三条，全部已有机器证据）

| # | 贡献 | 证据 | 状态 |
|---|---|---|---|
| C1 | **循环的形式化与检测脚本**：单比特可分性判据 + 反极性对照 + Fisher 关联强度 | `EXP-CIRC-001`、`tests/scripts/test_validity_audits.py`（11 passed） | 已完成 |
| C2 | **措辞独立性判据**：模板复用结构度量 + 措辞隔离校验（重叠串与公共片段） | `EXP-WORDING-001` | 已完成 |
| C3 | **信息量口径与修复成本模型**：独立单元 = 标签族数；精度—工时换算 | `EXP-CEIL-001` | 已完成 |

### 2.3 还缺什么（缺口可控，不依赖 GPU / 真实数据）

1. **修复验证**（必须，否则只是指出问题）：
   - 设计对抗单元（探针健康但标签非 SUCCESS；探针不健康但标签 SUCCESS），
     使平凡规则不再全对；
   - 标签改由**独立观测或人工判定**产生；
   - 引入**真人书写的新措辞**（2 名标注者即可，无需平台数据）。
2. **对照基线**：至少一个「不看 claim、只看探针」的平凡基线和一个「只看 claim
   措辞、不看探针」的基线，证明真核验器优于两者。**当前缺第二条**。
3. **外部数据集三角验证**（可选加分）：AIOpsLab / ITBench-SRE 等公开基准上复现循环判据。

### 2.4 目标 venue 与篇幅

- 会议 workshop / 短论文：AIOps Workshop（co-located with ICSE/FSE/ASE）、
  NeurIPS *Datasets and Benchmarks*（short）、ICLR *Tiny Papers*。
- 中文刊：《软件学报》《计算机研究与发展》实习性论文可用，但需完整实验。
- 篇幅：6–8 页；图表 ≤6（循环列联图、分割稳定性图、独立单元直方图、成本曲线）。

### 2.5 审稿风险

## 3. 路线 B：缺口清单（若目标是实证论文）

| 缺口 | 现状 | 解锁动作 | 依赖 |
|---|---|---|---|
| real model 端到端 | `NOT RUN`（`is_llm=false`） | 本机 Ollama 或云服务跑 LLM 链路，回填 M 系列 | GPU/云资源 |
| 数据集批准 | `approved=False`，2 名真人标注者缺失 | 填 `review/pack.jsonl` 评分表 → `dataset_approval_gate.py --score` | 2 名真人 |
| 真实 incident 数据 | 六表 2–7 行 | 生产环境导出或公开数据集 | 真实数据授权 |
| 标签来源独立 | 循环成立 | 对抗单元 + 独立判定 | 设计 + 标注 |
| RAG 对照 | `NOT_RUN` | 需语料 chunk 与检索真值 | 数据工程 |
| 措辞泛化 | 未检验 | 真人书写新措辞 | 2 名真人 |

**判断**：B 需要 ≥4 项外部条件，其中 2 名真人标注者与真实数据不可由本机补齐。
