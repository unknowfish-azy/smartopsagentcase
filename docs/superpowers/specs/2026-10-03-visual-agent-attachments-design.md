# 视觉 Agent、聊天附件与协作治理：增补设计

日期：2026-10-03。状态：总体设计，正在分批实施；不能按本文功能列表宣称全部交付。

第一批已实现的代码范围与验收进度见 `docs/superpowers/plans/2026-10-03-chat-attachments-phase1.md`，使用边界见 `docs/chat-attachments.md`。它只覆盖附件所有权与基础输入，不包含截图 / 拍照 / OCR / 视觉理解；格式暂限 PNG / JPEG / UTF-8 文本，裁剪和遮盖使用本地工具。

## 1. 批准基础与交付边界

用户已确认推荐方向：个人 / 团队空间、管理员治理、自动故障识别、习惯适配、Skill / 脚本草案、轻量 Agent 协作，以及控制台优化。本次增补截图、拍照、本地文件、Ctrl+V、拖放与视觉分析。以下配额、格式和布局为推荐默认值，不表示已上线。

已交付的是团队成员 / 邀请 / 角色 / 冻结等第一批基础，以及主菜单团队协作入口。团队知识库、共享 Agent、任务审批、视觉附件和生成资产仍是后续里程碑。继续遵守：自动识别、授权只读诊断、生成草稿；发布、生产写操作必须人工确认。

本轮只更新设计，不启动摄像头、截屏或采集剪贴板，不修改真实账号、权限、数据库和模型配置。

## 2. 当前实现约束

- `frontend/src/components/ai/AiChatPanel.vue` 的附件按钮仍为提示占位，发送依赖非空文本。
- `frontend/src/stores/aiChat.js` 与 `frontend/src/domain/chat/history.js` 以账号隔离的浏览器文本会话为主，不是服务端团队会话库。保留账号切换保护、分会话草稿和输入法组合输入行为。
- `backend/src/main/java/com/smartops/controller/AssistantController.java` 的聊天输入与历史为文本；需要兼容扩展消息结构，不能把图片塞进文本字段。
- 现有 Skill 工作区是本地存储；自定义插件是已有功能入口清单，不等于安全的外部代码执行环境。
- Agent 控制中心当前存在演示队列及以事件存在代替真实阶段状态的逻辑；重排布局同时必须建立真实任务状态，不能仅换皮。

## 3. 路线比较与推荐

1. 仅加上传按钮：交付快，但不能解决图片理解、团队隔离和知识复用，不作为完整方案。
2. 统一附件服务 + 可插拔 OCR / 视觉适配器：推荐。聊天、诊断、知识入库共用安全基础，模型能力按需接入。
3. 桌面常驻录像 / 自动鼠标操作：权限、隐私和运维成本明显扩大，首版不做；如未来需要须独立授权和设计。

## 4. 五种输入与统一交互

| 输入 | 推荐行为 | 失败退路 |
| --- | --- | --- |
| 截屏 | 点击截屏，浏览器选择授权窗口 / 标签页 / 屏幕，捕获一帧后停止全部媒体轨道 | 系统截图后粘贴或上传 |
| 拍照 | 用户点击后请求相机，预览、拍摄、重拍、确认；不请求麦克风 | 选择已有照片 |
| 本地文件 | 多选文件，显示类型、大小及解析支持情况 | 不支持格式时提供转换说明 |
| Ctrl+V | 编辑器内粘贴图片形成附件，普通文字保持正常粘贴 | 系统未提供文件数据时使用文件选择器 |
| 拖放 | 拖入聊天区显示投放提示，落入附件队列，不让浏览器打开文件替换页面 | 键盘可访问的上传入口 |

统一流程：本地待发送 → 预览 / 裁剪 / 手工遮盖敏感区域 → 确认发送 → 上传和校验 → 解析 / OCR → 模型分析 → 可追溯回复。

- 附件区在输入框上方，图片缩略图、文档卡片、大小、状态、删除、取消和单文件重试均可见。图片或文件可以单独发送。
- 同一队列处理所有入口，一次粘贴 / 拖放不重复创建附件；发送和重试使用幂等标识。
- 未就绪附件不能悄悄丢弃后继续发送；允许明确移除失败项再发。保留 Enter 发送、Shift+Enter 换行及中文输入法保护。
- 本地草稿绑定账号、空间及会话；切换时提示保留到原会话或丢弃，不挪入新空间。退出账号销毁暂存 Blob、预览 URL 并取消异步任务。
- 首版不跨刷新保存本地二进制草稿；提示未发送附件会丢失。图片 Base64、二进制和敏感凭据不进入 localStorage。
- 截屏捕获结束立即停流；拍照弹窗关闭、路由切换、权限取消、异常和迟到返回的媒体流均须清理。无后台截屏、全局剪贴板轮询、隐式摄像头开启。
- 适配浅 / 深色及轻量视觉：附件、预览、弹窗、拖放层同步主题；状态用文字和图标表达，不只依赖颜色。手机使用单列预览和文件 / 相机兜底。

## 5. 视觉能力与模型路由

明确分开文件接收、文本抽取、OCR 和图像理解。能收图片不表示 Mini 已能看图；能识别字符不表示能理解拓扑或图表。

- 本地 OCR 适合提取终端报错、日志和截图文字，提供区域、原文及手动修正。OCR 引擎、语言包和资源预算需单独评估后安装，不默认宣称存在。
- 视觉模型用于界面异常、监控图、拓扑和设备照片的辅助解释。输出区分观察事实、推测原因、缺失信息和建议验证，不承诺仅凭照片确诊。
- 能力信息至少区分 text、vision、支持的图片格式 / 大小、可接受的文档处理方式、服务可用性。能力配置需受控验证，不能从模型名称推断。
- Mini 默认服务于其具备的能力；未接 OCR / 视觉时明确提示不可用，可提供用户手动输入识别文字的路径，不伪造图像分析结果。
- 不静默切换外部模型。发送前显示目标提供方、模型、发送的是图片还是提取文本、所属空间；涉及外发时须满足管理员策略及用户明确确认。
- 未经外发授权，不在重试、回退、后台 OCR 或遥测中转发原图 / 文本。团队凭据只在后端使用。
- 截图、文档、OCR 内容均是不可信证据；其中的命令或提示词不能改变系统权限、触发工具调用或绕过审批。

## 6. 服务端所有权与附件安全

先建设服务端会话 / 消息所有权，再接入团队共享。推荐实体为 conversation、message、message_part、attachment、processing_job；消息部件支持 text / image / file 和附件 ID，兼容既有纯文本消息。

- 会话明确 personal 或 team 范围；个人归属用户，团队归属指定团队并受成员权限约束。浏览器历史仅供本人主动迁移，不自动变为团队会话。
- 上传、绑定消息、预览、下载、OCR / 检索和模型调用均由后端检查身份、空间、资源状态与权限；不可凭附件 ID 或前端筛选授权。
- 附件对象私有存储，预览 / 下载经鉴权服务输出；不提供长期公开链接。缓存策略防止用户退出或团队移除后读取旧私有响应。
- 成员移除 / 团队冻结后重新检查未完成任务，阻断不再授权的调用；运行中的处理结果不能写入或返回未经授权的空间。已交付到用户终端的数据无法远程收回，应明确告知。
- 默认只上传用户确认后的遮盖版本，不暗藏未遮盖原图；需要保留原件必须单独明确选择。服务器派生预览继承同一权限，图像尽可能重新编码并移除 EXIF。
- 初期允许 PNG / JPEG / WebP、TXT / LOG / Markdown。第二阶段再开放 PDF / DOCX 的隔离解析；不执行宏，不自动加载外链，不接收 HTML / SVG / 压缩包 / 可执行文件作为首版可分析附件。
- 后端验证扩展名、MIME 和文件签名，生成存储键，不使用用户文件名拼路径；转义文件名和 OCR 文本，避免主动内容渲染。
- 建议初始限制：单图 10 MB、单文档 20 MB、单次 5 个且合计 40 MB；图片不超过 2000 万像素，文档最多解析 100 页。均为待实施的可配置值，超限明确拒绝而非静默截断。
- 解析任务隔离运行，禁用网络，限制内存 / CPU / 页数 / 解压体积 / 超时 / 并发；恶意或未通过校验文件隔离，不进入模型和知识库。PDF / DOCX 支持需以沙箱和恶意样本测试为前置门槛。
- 上传与消息绑定分阶段但可恢复：暂存文件建议 24 小时后清理；发送失败可按幂等标识重试，无主附件定期回收。长期保留按空间配额和管理员策略执行。
- 删除立即撤销在线访问 / 检索，异步清理原件、派生文件和索引；处理作业检查删除标志，不能让迟到结果复活资源。备份清除周期另行配置并公示，审计不保存图片正文。

## 7. 接入诊断、知识和生成资产

推荐处理链：用户提交证据 → 授权检查 / 脱敏 → 抽取和视觉识别 → 故障假设 → 授权只读工具验证 → 解释结论 → 生成知识 / Skill / 脚本草稿。

- 延续一个协调器和证据、诊断、验证、知识四种轻量角色，按需调用和复用模型，不等于部署四个常驻大模型。视觉作为证据角色的能力适配器，不增加无条件并行调用成本。
- 从经授权的报错、监控和操作结果触发故障识别，不监控整个桌面。用户习惯学习须可开关、解释、修正和删除；习惯不能授予权限或降低审批强度。
- 知识薄弱点基于用户同意使用的诊断 / 学习记录生成学习建议与知识候选，不自动发布个人能力画像。
- 聊天附件不自动入知识库。用户选择个人库或有权限的团队库，预览抽取结果、脱敏和引用后确认入库。系统知识库发布权限独立。
- 向团队分享是显式复制 / 发布动作，提示可见范围；不得把个人原始附件链接嵌入团队资产泄露数据。向量索引、原文和引用的权限一致。
- Skill 指令、脚本和可执行插件分开建模并版本化：草稿 → 静态检查 / 脱敏 → 隔离测试 → 人工审核 → 发布不可变版本 → 授权调用 → 结果验证。
- 禁止直接执行图片 / 文档内命令或模型新生成脚本。生产写操作绑定具体版本、参数、目标及审批，有超时、取消、最小权限和回滚 / 恢复说明。

## 8. 控制台和管理员布局

用户控制中心建议：顶栏显示空间、模型、连接状态和当前风险；左侧任务 / 会话；中间对话与真实诊断时间线；右侧证据、引用、授权和待审批动作；底部附件输入区。窄屏证据区改抽屉，不压缩对话主体。

任务状态明确为 queued、collecting、analyzing、awaiting_approval、executing、verifying、completed、failed、cancelled，允许合法跳转并记录时间和错误；不能因创建事件就点亮所有阶段。演示模式单独标注，不混入真实成功率。

管理员控制台建议按四组组织：

1. 概览与待办：服务健康、待审核项、失败任务、容量预警，卡片下钻到真实列表。
2. 身份与空间：用户、团队、角色、配额、冻结与审计，不默认查看私人聊天附件。
3. AI 与资产：模型能力 / 外发策略、知识发布、共享 Agent / Skill / 脚本版本和审批。
4. 平台运行：OCR / 解析任务健康、存储与保留策略、执行节点、预算及异常重试。

后台查看私人内容需单独设计受控授权 / 审计流程，平台管理员身份本身不是无限读取授权。保留液态玻璃外框，正文和数据表使用可读的低透明度底色，浅深色共用语义色变量。

## 9. 推荐阶段与完成标准

- P0：服务端会话 / 附件所有权、消息部件、空间授权、兼容迁移与生命周期。完成标准：跨账号 / 跨团队越权测试通过，旧文本会话可继续使用。
- P1：文件 / 图片选择、Ctrl+V、拖放、预览 / 手工遮盖、纯附件发送、取消与重试。完成标准：五种失败态可理解、无重复上传 / 消息、切换空间不串数据。
- P2：截图、拍照、权限提示和媒体清理。完成标准：支持设备的真实授权测试及拒绝 / 取消 / 不支持兜底均验证；不能以模拟流测试代替真实设备验证。
- P3：可选本地 OCR、视觉能力协商和模型适配、受限文档解析。完成标准：无视觉时明确降级、外发获得明确授权、恶意文档不能越权或执行代码。
- P4：视觉证据诊断、个人 / 团队知识入库、轻量角色及 Skill / 脚本草稿。完成标准：每个结论可追溯证据，发布和写操作审批不能绕过。
- P5：共享 Agent / 资产版本、协作任务审批与控制台治理完整交付。完成标准：端到端团队权限、撤权、失败恢复、主题 / 移动端验收。治理基础随 P0 起建设，不等最后才做权限。

## 10. 验收重点与非目标

- 文本粘贴和输入法不受影响；一次图片粘贴只添加一次；拖放不导航离开页面；文件选择取消不改变原草稿。
- 上传失败、解析超时、模型不支持、配额超限分别提示；重连 / 重试不重复计费、创建消息或处理任务。
- 登出、账号 / 团队切换和页面离开清理预览及媒体；晚到的网络 / 授权响应不能串入新会话。
- 对附件猜 ID、预览缓存、下载、OCR 作业、引用及检索进行跨用户 / 团队测试；团队冻结 / 撤权中途生效。
- 对提示词注入、路径穿越、伪造类型、超大像素、解析炸弹与外发策略做安全回归。
- 375 / 900 / 1440 宽度，浅 / 深色和轻量视觉验证；键盘操作、焦点返回、控件名称、加载和错误状态可读。
- 真实相机 / 截屏验收须由用户主动授权，本次未运行。无公网域名不阻止 localhost 开发；外网 / 内网普通 HTTP 的可用性不能默认等同 localhost，应使用 HTTPS 并检测能力。
- 首版不做持续录像、远程桌面控制、人脸识别、自动采集剪贴板、任意可执行插件运行、静默共享或静默模型外发。

浏览器依据：MDN 的 MediaDevices.getDisplayMedia、MediaDevices.getUserMedia、Element paste event、Secure contexts 文档。实现前按目标浏览器重新检查安全上下文、瞬时用户激活、权限与兼容性。
