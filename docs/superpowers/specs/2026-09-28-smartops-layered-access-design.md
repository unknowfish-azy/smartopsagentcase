# SmartOps 分层访问与管理层设计

## 目标

将智维 Agent 的七层架构和八波训练目标落到可使用的软件入口，明确用户层与管理层边界，并为后续后端鉴权、审计和配置中心提供稳定契约。

## 设计

- `frontend/src/security/accessModel.js` 是前端访问模型的唯一来源，定义角色、能力、架构层和训练波次。
- 用户角色继续使用现有运维、知识、Agent、模型和连接工作流；管理员角色增加管理控制中心和架构总览。
- 登录预览会话保存 `username`、`role`、`capabilities` 和时间戳。没有角色的历史会话按 `operator` 兼容处理。
- 路由通过 `meta.roles` 做前端入口保护；后端仍可独立接入同名角色和能力声明，不把前端状态当作生产鉴权。
- 管理控制中心只展示和编辑管控域入口，不直接执行危险运维动作；高风险动作继续由现有 Agent 审批流程承接。

## 验收

- 未登录用户访问受保护页面会回到登录页。
- 用户角色不能进入 `/admin`，管理员可访问 `/admin` 和 `/architecture`。
- 用户与管理员侧栏显示不同入口，原有用户页面保持可用。
- 架构总览明确七层职责、关键技术和对应训练波次。
- 测试覆盖角色解析、能力判断、路由元数据和导航分组。
