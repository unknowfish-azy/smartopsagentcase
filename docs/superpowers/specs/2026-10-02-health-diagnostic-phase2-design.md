# 健康诊断与前端体积优化第二阶段设计

**日期：** 2026-10-02  
**状态：** 已实施并完成代码验收，详见 `docs/operations/2026-10-02-health-diagnostic-phase2-acceptance.md`
**范围：** C2 轻量视觉模式、健康诊断增强、管理员安全配置说明

## 目标

在不开放任意 URL、Shell、自动修复、定时告警或真实数据变更的前提下，继续降低首页视觉资源对首屏的影响，并让健康诊断结果更容易解释、重试和审计。

## 非目标

- 不删除 Three.js 依赖，不修改现有首页视觉组件的基础契约。
- 不提高 Vite `chunkSizeWarningLimit`，不以隐藏警告代替优化。
- 不增加任意 URL 探测、扫描网段、自定义请求头或认证凭据传递。
- 不增加定时任务、告警通知、自动修复、任意命令执行或诊断结果持久化。
- 不修改真实账号、密码、数据库数据或生产环境凭据。

## 方案一：C2 轻量视觉模式

### 用户体验

在主题/显示设置中增加“视觉效果”选项：

- `balanced`：默认模式，非首页使用 Canvas 2D；首页使用当前首页视觉能力。
- `lightweight`：所有页面优先使用 Canvas 2D，降低 CPU、内存和首屏网络负担。
- `reduced-motion`：复用浏览器降动效语义，保持低密度、静态或缓慢动画。

设置只保存显示偏好，不保存账号凭据或诊断原文；切换后当前页面即时更新，浅色/深色主题变量继续由同一套 CSS 变量驱动。

### 加载边界

- `CanvasParticleWhale`、`CanvasAmbientField` 和现有 Canvas 粒子逻辑作为轻量默认路径。
- Three.js 仅在 `balanced` 模式且确实进入首页增强视觉路径时异步加载。
- 非首页路由不得因为视觉设置加载 Three.js。
- 首页轻量模式不得创建 Three.js 动态导入。

### 验证

- 单元测试验证模式归一化、默认值、非法值回退和主题切换。
- 浏览器测试验证三种模式、首页/非首页资源边界、375/1440 宽度无横向溢出。
- 构建测试继续断言没有提高 `chunkSizeWarningLimit`，并记录 `vendor-three` 实际体积。

## 方案二：健康诊断增强

### 前端状态

健康检查结果在组件内增加以下展示语义：

- `checkedAt` 与本地格式化时间。
- `fresh`：结果在 5 分钟内；超过 5 分钟显示“结果可能已过期”。
- 主动刷新时保留旧结果但标记为“检查中”，请求失败后旧结果必须标记为过期，不能继续显示为当前健康。
- 失败重试按钮保持当前目标和表单参数，不重复提交空请求。

### 后端结果

不改变现有接口路径和统一结果字段。补充稳定的错误分类字段时必须向后兼容：

- `CONFIGURATION`：未配置或配置不完整。
- `AUTHORIZATION`：当前账号无权访问。
- `TIMEOUT`：连接或读取超时。
- `NETWORK`：连接拒绝、TLS 或其他网络失败。
- `ASSERTION`：状态码或 JSON 断言失败。
- `NOT_CHECKED`：前置依赖失败，后续检查未执行。

页面只展示脱敏摘要，不展示响应正文、Authorization、Cookie、异常堆栈或固定地址明细。

### 管理员说明

管理员健康页增加“策略边界”摘要：

- 固定白名单目标数量。
- 每用户/全局并发限制。
- 连接、读取和响应大小限制。
- 是否启用 Mini、观测源和 Harbor 配置。

只展示是否配置和限制值，不展示令牌、密码、内网地址或其他敏感值。配置说明链接到操作文档，不新增白名单 CRUD 页面。

## 方案三：管理员安全后续

本阶段只增加安全说明和手动操作提示：

- 在管理员诊断页明确“所有主动检查均为手动、只读、受白名单控制”。
- 对未配置、未检查、无权访问和检查失败使用不同状态文案。
- 不触发外部模型、SSH、Shell、自动修复或后台定时任务。
- 后续若设计告警，必须单独形成审批、限流、审计、回滚和数据保留规格，本阶段不预留隐式执行入口。

## 数据流与错误处理

1. 用户选择显示模式，前端存储显示偏好并更新响应式状态。
2. 路由渲染根据显示模式选择 Canvas 或异步 Three.js 组件；视觉加载失败时回退到 Canvas，不阻断业务页面。
3. 健康中心请求现有诊断接口，收到结果后记录本地组件时间戳，不把结果写入服务端历史。
4. 请求失败时保留最近一次结果作为过期参考，并显示重试入口；不能把失败状态覆盖为 `HEALTHY`。
5. 管理员策略摘要只返回布尔配置和数值限制，服务端负责权限隔离。

## 测试策略

- 前端单元：显示模式状态、非法值回退、过期状态、失败后重试参数保持。
- 前端浏览器：浅色/深色同步、三种视觉模式、首页与非首页 Three.js 隔离、移动布局、错误重试。
- 后端单元：错误分类映射、权限隔离、未配置目标、过期结果语义和不泄露敏感字段。
- 后端全量回归：保持既有认证、管理员、Mini 和操作工具契约。
- 构建：`npm.cmd run build`，不修改 `chunkSizeWarningLimit`；记录 `vendor-three` 警告是否仍存在及其体积。

## 交付文件方向

- 修改：`frontend/src/stores/app.js` 或现有主题/显示设置状态模块。
- 修改：`frontend/src/layouts/MainLayout.vue`、首页视觉组件和相关 Canvas/Three.js 加载边界。
- 修改：`frontend/src/components/diagnostics/HealthCheckList.vue`、管理员健康组件及诊断 API 类型处理。
- 修改：后端诊断结果 DTO/服务，保持现有接口兼容。
- 新增或修改：对应 Node、Playwright、JUnit 测试和 `docs/operations/health-and-diagnostic-tools.md`。

## 验收标准

- 轻量模式下非首页和首页均不加载 Three.js。
- 默认模式不破坏既有首页视觉；非首页仍不加载 Three.js。
- 浅色和深色模式下文字、状态徽标、按钮和 Canvas 均清晰可读。
- 诊断失败、超时、无权、未配置和未检查状态可区分，并且不会显示敏感值。
- 前端全量测试、后端全量测试和浏览器验收通过。
- `vendor-three` 如仍超过 500 KB，必须在最终报告中明确实际体积，不能隐藏警告。
