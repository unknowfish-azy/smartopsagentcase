# SmartOpsAgent 双区知识库与个人本地工作区设计

## 1. 目标

将知识库明确拆分为系统知识库和用户个人知识库。系统知识库由系统维护、所有用户只读；个人知识库按用户隔离，用户可以创建知识库、管理目录、编辑内容，并将经过确认的故障分析和视觉分析沉淀为个人知识。

本设计还需要为后续团队共享和审批发布保留边界，但本阶段不把个人内容自动公开到团队空间。

## 2. 范围

本阶段包含：

- 知识库界面双区切换：系统知识库、我的知识库。
- 用户个人知识库的创建、重命名、归档、删除和恢复入口。
- 每个用户独立的本地知识目录。
- Markdown 正文、附件和索引文件的本地存储。
- 数据库中的权限、元数据、状态和审计记录。
- 个人知识条目列表、详情、编辑、导入、导出和搜索。
- 视觉事件、故障分析生成个人知识候选，用户确认后发布。

本阶段不包含：

- 个人知识自动共享给团队。
- 系统知识库的在线编辑。
- 未经用户确认的 Agent 自动发布。
- 跨用户目录访问或目录合并。

## 3. 信息架构

知识库主页面顶部使用两个一级标签：

1. **系统知识库**：展示内置运维知识、来源、版本、风险和适用范围；用户只读。
2. **我的知识库**：展示当前用户的个人知识库和条目；所有读写操作都绑定当前用户。

“我的知识库”采用三栏布局：

- 左栏：知识库树、全部知识库、归档区和待确认候选。
- 中栏：条目列表、全文搜索、标签/来源/验证状态筛选、排序和分页。
- 右栏：条目详情或 Markdown 编辑器，显示来源、附件、关联故障和验证状态。

顶部操作包括新建知识库、新建条目、导入、导出、从故障生成和从视觉事件生成。系统知识库不显示编辑和删除操作。

## 4. 存储模型

数据库是权限、元数据和审计的权威来源；本地文件系统保存正文、附件和索引。

推荐目录结构：

```text
data/knowledge/users/{userId}/
├── libraries/{librarySlug}/
│   ├── library.json
│   ├── index.json
│   ├── entries/*.md
│   └── attachments/*
├── inbox/
├── exports/
└── trash/
```

`{userId}`必须由服务端会话身份生成，不能由请求参数指定。库名只用于显示；目录名由服务端生成安全 slug，并附带短唯一后缀，避免路径穿越、重名和非法字符。

数据库至少记录：

- `user_id`、知识库 ID、名称、描述、目录 slug、状态。
- 条目 ID、所属库、Markdown 相对路径、摘要、标签、来源类型和来源引用。
- 验证状态、版本号、创建/更新时间和归档时间。
- 文件内容哈希、索引状态和最近一次索引错误。

文件写入使用临时文件加原子替换，避免进程中断留下半个 Markdown 文件。目录删除采用回收站策略，先归档再移动到用户自己的 `trash`，不直接递归删除。

## 5. 创建与编辑流程

### 创建知识库

1. 用户输入名称、描述、分类和标签。
2. 服务端校验当前用户身份和名称长度。
3. 生成唯一目录 slug。
4. 创建用户目录、`library.json`、`index.json` 和空的 `README.md`。
5. 在数据库事务中写入知识库元数据。
6. 返回知识库详情，并将其选中。

如果文件系统创建成功但数据库写入失败，执行补偿清理；如果数据库写入成功但文件系统不可用，标记为 `STORAGE_ERROR`，禁止继续写入并提供重试。

### 编辑条目

编辑器保存时先进行用户和知识库归属校验，再写临时文件、计算哈希、原子替换 Markdown，最后更新数据库元数据和索引任务。每次保存增加版本号；删除使用归档状态，物理删除需要显式二次确认。

## 6. Agent 知识沉淀

视觉事件、聊天故障分析和运行记录只能生成个人知识候选：

```text
原始证据 -> Agent 分析 -> 知识候选(DRAFT) -> 用户确认 -> Markdown 条目(PUBLISHED)
```

候选必须保存原始会话、截图/OCR、分析结果、来源引用、生成时间和模型版本。候选状态至少包括 `DRAFT`、`CONFIRMED`、`REJECTED`、`PUBLISHED`。

未确认内容不得进入正式个人知识检索，也不得进入操作员长期记忆。图片中的命令、OCR 文本和 Agent 建议不得自动执行。

## 7. 权限隔离

- 系统知识库：所有已认证用户只读；只有系统发布流程可以更新。
- 个人知识库：查询条件必须包含当前会话用户 ID；用户只能读写自己的库和条目。
- 管理员默认不能读取个人正文，只能查看存储健康、容量和审计元数据。
- 团队共享必须创建独立的共享副本或发布版本，不能直接暴露个人目录。
- 导入、导出、下载和删除都记录审计事件。

## 8. 搜索与索引

搜索结果必须显示来源标签：`系统知识库`、`我的知识库`、`待确认候选`。个人搜索优先返回当前用户已发布内容，再返回系统知识库参考内容。

索引字段包括标题、摘要、Markdown 正文、标签、服务名、错误码和经用户确认的 OCR 文本。索引失败不影响原始 Markdown 保存，但条目标记为 `INDEX_ERROR`，界面提供重建索引操作。

## 9. 错误与恢复

- 存储目录不可写：显示明确的存储错误，保留编辑器草稿，不标记保存成功。
- 文件存在但数据库记录缺失：后台健康检查列出孤儿文件，不能自动公开索引。
- 数据库记录存在但文件缺失：条目标记为 `MISSING_FILE`，详情页提供恢复或重新导入入口。
- 导入格式不支持或超过配额：逐文件报告失败原因，不影响其他文件。
- 删除、归档和恢复操作使用审计记录和可恢复回收站。

## 10. 实施分期

1. 双区界面与路由状态。
2. 个人知识库目录模型和文件系统适配器。
3. 创建、编辑、归档、导入、导出和个人搜索。
4. 文件哈希、索引任务和健康检查。
5. 视觉事件/故障候选转个人知识。
6. 团队共享副本和审批发布。

## 11. 验收标准

- 用户 A 无法通过 API、路径参数或下载地址读取用户 B 的个人知识库。
- 新建个人知识库后，数据库记录和用户专属目录同时存在。
- Markdown 编辑保存后可重新加载，进程中断不会产生半文件。
- 系统知识库仍可离线搜索，且没有编辑/删除入口。
- 未确认的 Agent 候选不会出现在正式个人知识搜索结果中。
- 归档、恢复、导入、导出和失败场景均有可追踪审计记录。
