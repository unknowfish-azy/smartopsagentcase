# 三工作台第一阶段：可信基础

## 已确认范围

落实用户批准的第一阶段：Harbor 状态和制品只读浏览、统一知识来源与相关性检索、云原生环境上下文和单层详情。第二阶段诊断闭环、审核发布以及第三阶段生产治理不在本次范围。

## 设计

- Harbor 保留已有配置接口，新增有时间戳的真实读取检查；区分认证、授权、TLS、超时、网络及无效响应。检查成功只证明当前凭据可读取项目，不宣称全部组件健康。项目、仓库和制品读取均保留操作审计，禁止重定向和任意上游 URL；支持嵌套仓库名称的安全编码。界面区分配置、检查结果与新鲜度，切换项目或仓库时废弃旧请求。
- 知识内容继续以既有 JS 目录和 Markdown 为源，不批量改写资料。建立规范化模型和确定性导出，将同一目录投影为后端内置 JSON 索引，Mini 同时保留原有受限本地 Markdown 检索；明确未人工验证状态，不伪造审核信息。页面提供多词加权检索、中文别名、来源和命中说明。构建前校验或同步快照，测试防止前后端索引漂移。
- 云原生工作台保留四领域和既有工具，改为页内单层详情；统一 Markdown 渲染。目标上下文仅是用户明确选择的诊断意图，不伪称已连接集群。不把 URL 上下文直接用于执行；工具入口携带环境提示，实际远程会话和参数仍由工具页校验和确认。生产环境明确标记，切换上下文后清空旧详情。
- 所有新增控件沿用语义主题变量；键盘可操作、小屏不横向溢出，不引入重型前端依赖或公共 Three.js 导入。

## 安全与边界

- 不更改账号密码、真实数据库、Harbor 配置、诊断白名单；不新增外部 AI 请求、集群写权限或 Shell 执行入口。
- 既有实例使用管理员配置的凭据，本阶段不把它包装成已完成的多租户项目 ACL；连接配置及治理写操作不开放给普通用户。新接口复用现有会话认证。
- 不增加自动诊断、后台轮询或持久化敏感证据；知识快照仅收录仓库内置资料，不导出用户候选或私有运行记录。
- 不重置、提交、清理或建分支；在已有大量未提交工作上做局部修改。

## 验收

Harbor 上游模拟服务验证真实 HTTP 路径、编码、分页、失败分类和脱敏；知识验证规范化、排名、快照一致性及 Mini 引用；浏览器使用明确标注的模拟会话检查浅深色、375/1440px、状态过期、切换竞态和上下文保留。真实登录态及未配置的外部服务不得被模拟结果替代。
