# Linux Shell 知识与远程只读诊断设计

日期：2026-09-23
状态：待用户审阅
范围：知识库补充与远程运维工具首期增强

## 目标

1. 在知识空间中加入可查阅的 Linux Shell 输入输出与管道资料，使用简易中文说明概念、场景和风险。
2. 让资料可从知识目录、搜索结果和详情页打开；详情页提供上一条、下一条切换，并保留来源与关联知识。
3. 让运维工具使用已有 SSH 会话执行有限的只读诊断任务，并把结果作为后续排查证据。
4. 不改变现有桌宠、连接中心、终端和命令审批的行为；设计验证不连接真实生产主机，也不执行变更操作。

## 不在首期范围

- 任意远程命令输入、脚本上传或 Shell 管道执行。
- 远程文件修改、删除、服务重启、配置修改、数据库变更。
- AI 自动执行、自动发布知识、题库自动生成和题库持久化。
- 新的远程凭据存储、服务器资产管理或 SSH 协议替换。

## 方案

采用结构化知识资料与固定只读诊断任务。知识内容作为本地知识资源进入现有知识目录及目录索引；远程任务使用服务器端维护的任务 ID 映射到静态命令模板，不能由请求传入命令字符串或参数。诊断必须使用当前用户拥有且仍在线的 SSH runtime。

现有 `OperationRuntime.write()` 面向交互式 Shell，现有多命令预览服务最终也把文本写入该 Shell；关键词风险等级判断不构成命令安全边界。因此，诊断不复用这两条路径。新增独立只读能力接口，由 SSH runtime 使用已认证 SSH session 建立 exec channel，且不开放给一般交互式 runtime。

## 知识资料

新增 `knowledge/linux/shell_io_pipeline.md`，以简易中文说明：

- FD、stdin、stdout、stderr，以及进程与 `/proc/<pid>/fd` 的关系。
- `>` 覆盖、`>>` 追加、`2>` 错误输出、`<` 输入、合并输出，以及多个重定向的顺序差异。
- `command >file 2>&1` 的兼容写法；说明 `&>` 属于 Bash 扩展，不是 POSIX Shell 通用语法。
- 管道、`tee`、`xargs`、`wc`、退出码与 `pipefail` 的适用场景。
- 安全收集命令输出、保存证据、处理文件名空格和换行的示例。
- 风险提示：重定向可能覆盖文件；`xargs` 会把输入变成参数；删除命令须人工复核；避免以 `ps | grep` 作为可靠进程查询示范，优先解释自匹配问题及更合适的查法。

新增内容登记到现有知识目录数据源，包含稳定 ID、标题、简述、正文、领域、标签、来源、难度和风险级别。详情视图展示可读正文；相邻文章依当前搜索/筛选结果排序，箭头在没有相邻条目时禁用。首期不新增数据库表或导入 Markdown 的通用解析器。

## 远程诊断结构

### 后端边界

- 新增只读诊断 capability/service；通过 `OperationRuntimeRegistry.requireOwned(runtimeId, userId)` 校验会话所有权，并拒绝离线或不支持该能力的 runtime。
- SSH runtime 单独实现受限命令执行接口；固定任务映射在服务端维护。初期任务限于低敏、只读的进程摘要、失败服务摘要和近期服务错误摘要，不接受任务参数、路径、服务名或命令文本。
- 每个任务设置执行超时、stdout/stderr 合并后的字节上限和输出截断标记；错误信息及返回内容经 `OperationRedactor` 处理。不得把凭据、完整环境变量或任意文件内容作为任务输出。
- 结果包含任务 ID、状态、退出码、开始/结束时间、耗时、截断标记和脱敏后的输出。拒绝命令时明确失败，不回退到交互 Shell。
- 记录最小审计元数据（用户、runtime、任务 ID、时间、结果状态）；不在审计记录中保存未脱敏输出。

### 接口草案

`POST /api/operations/runtimes/{runtimeId}/diagnostics`

请求只允许 `{ "taskId": "process-summary" }` 形式的数据。响应为统一 `ApiResponse`，包含受限诊断结果。未知 taskId 返回客户端错误；无权访问 runtime 返回既有未找到语义；不支持或已断开的 runtime 返回明确冲突/不可用错误。接口不得接受 `command`、`args`、`path` 等可影响命令内容的字段。

### 前端流程

1. 在远程运维工具中选择已连接 SSH 会话和诊断任务。
2. 展示任务名称、只读属性、数据范围及可能包含主机/进程信息的提示。
3. 用户点击运行后调用只读诊断 API；运行中显示状态，完成后按文本显示脱敏结果、退出状态和是否截断。
4. 没有在线会话时引导打开连接中心；失败时保留任务选择并展示可理解的错误，不自动重试。
5. 诊断结果可关联到知识条目，但首期不自动写入 Incident 或知识原文。

## 错误与安全处理

- Runtime 所有权、在线状态和能力校验在服务端执行，不能信任前端传来的连接状态。
- SSH exec channel 只接收服务器定义的静态命令；用户输入不能进入 shell 字符串。
- 通过超时、并发限制和输出上限保护远程主机及本地服务。
- 诊断超时、非零退出码、SSH 通道错误、输出超限均作为独立结果状态返回；不尝试执行替代命令。
- 本功能不提供写操作，因此不进入现有多命令审批流程；未来新增写操作必须另行设计审批、预览、回滚和审计。

## 主要改动边界

- `knowledge/linux/shell_io_pipeline.md`：Shell 知识源。
- `frontend/src/views/knowledge/knowledgeCatalog.js` 及知识详情逻辑：登记条目、分类/检索字段和详情相邻导航；保留用户已有改动并基于当前文件增量编辑。
- `backend/src/main/java/com/smartops/operations/`：只读命令能力接口、受限结果模型及 SSH runtime 实现。
- `backend/src/main/java/com/smartops/service/` 与 `controller/`：受限任务映射、所有权校验和只读诊断 API。
- `frontend/src/api/operations.js` 与远程工具页面：任务调用、会话选择、结果展示与状态处理。
- 对应后端单元/控制器测试及前端知识与运维工具测试。

不改动现有任意命令审批实现、SFTP 能力、桌宠架构和知识数据库 schema。

## 验收标准

1. 用户能用中文关键词搜索到 Shell I/O 资料、打开详情并用上一条/下一条切换。
2. 知识解释准确区分覆盖/追加、重定向求值顺序、Bash 与 POSIX 语法，并包含命令风险提示。
3. 在线且归属当前用户的 SSH runtime 可以运行允许列表内的诊断任务；未知任务不能触发远程命令。
4. 请求任意 `command`、参数或路径不能扩大执行内容；离线、越权和不支持的 runtime 均失败关闭。
5. 任务具有超时与输出上限，返回脱敏结果和截断状态；无执行权限的诊断不会走交互终端。
6. 既有 SSH 连接、终端、多命令审批、SFTP 行为不回归。

## 验证计划

- 后端单测：任务 ID 到静态命令映射、拒绝未知任务、runtime 所有权、能力/在线状态、超时、输出上限、脱敏和失败状态。
- SSH runtime 测试：exec channel 生命周期、退出码读取、stdout/stderr 收集及异常关闭；尽量用 mock，不连接真实生产服务器。
- 控制器测试：请求不接受任意命令字段、不同用户不能访问别人的 runtime、错误状态映射。
- 前端测试：知识检索/详情导航、工具在线与离线状态、执行状态/结果/错误展示。
- 项目验证：运行相关测试，再按项目脚本运行前端 lint/build 和后端测试；不连接真实服务器。
