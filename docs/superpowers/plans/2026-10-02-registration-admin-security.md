# 普通用户注册与管理入口加固

用户已确认：普通用户开放注册并持久保存；管理员禁止公开注册，增加安全验证；不改变已有管理员密码，不恢复任意密码登录，不增加假 MFA 开关。

## 约定

- 在现有脏工作区延续开发，不清理、不提交、不切换分支或 worktree。后端/迁移/文档由主线程负责，前端独立 worker 只改 frontend/**。
- 沿用服务端 HttpSession、CSRF 与真实数据库。注册后回到用户登录，不自动登录；自行设置的密码不要求再次首次修改。
- 注册用户名沿用 3–64 位字母、数字、点、下划线、短横线。普通新密码至少12字符，管理员新密码至少16字符，均不超过72 UTF-8字节。旧账号仍可用原密码登录；提升为管理员后强制改密满足管理策略。
- 新增 singleton registration_policy 表持久保存 enabled，默认 true。注册与关闭开关通过行锁序列化；不修改任何已应用 SQL 迁移，新增 V003__registration_policy。
- 普通账号登录失败限额10次/5分钟；管理员账号跨两个入口共享5次/15分钟，按IP与稳定账号ID分别限制。管理敏感操作与自助改密共用当前密码验证限额，管理员5次/15分钟。注册先按IP最多5次/10分钟，再扣全局100次/分钟，已被IP限流的请求不占全局预算；仅使用服务端remoteAddr，不信任伪造转发头。计数单节点内存、重启清空，生产多节点需共享限流。
- 管理会话空闲10分钟、用户30分钟。新增管理员密码门槛不重置已有管理员凭据。
- 所有 /api/admin/** 变更请求须 `X-Admin-Password` 当前管理员密码，并保持 CSRF。密码仅瞬时发送，不写存储/日志/审计，不以普通确认弹框冒充身份复核。
- 审计新增 REGISTER、REGISTRATION_POLICY、ADMIN_VERIFY。已有权限版本、最后管理员保护、事务后撤销保留。

## API 契约

响应仍为 `{code,message,data}`。

- GET /api/auth/registration（匿名允许）：`{enabled,usernameMinLength:3,userPasswordMinLength:12,adminPasswordMinLength:16,passwordMaxBytes:72}`。
- POST /api/auth/register（匿名允许，必须CSRF）：`{username,password,confirmPassword}`；成功返回安全 AccountView（role固定operator，mustChangePassword=false），不接受任何自授角色。密码不一致/非法输入400，重复409，注册关闭403，限流429。
- GET /api/admin/registration：与公开策略相同，需管理权限。
- PUT /api/admin/registration：`{enabled:boolean}`，需CSRF与X-Admin-Password，返回策略，事务写审计。
- 已有管理账号/会话变更路径保持，只增加 X-Admin-Password 请求头；缺失/错误403（保持当前会话），限流429。普通用户和用户入口仍不能调用管理接口。
- 登录、注册不区分透露密码错误细节；注册明确提示重复账号。公开页面显示注册状态和密码说明，设置失败不得显示已保存。
