# 管理员 MFA、恢复码与本地安全提醒

## 已确认范围

用户明确要求继续执行不依赖公网的剩余方案。本阶段实现管理员主动绑定 TOTP、一次性恢复码及站内安全提醒，不要求公网或邮件服务。不替真实账号绑定，不默认强制未绑定管理员，不使用测试验证码作生产后门。

## 设计与接口

- TOTP 使用 JDK HMAC-SHA1，20 字节随机密钥、30 秒步长、6 位数字、前后各一个窗口；以 RFC 6238 测试向量验证。数据库记录已消费步长，行锁防并发重放。
- 密钥以现有 AES-GCM 服务加密并绑定 user id；恢复码为 10 个 128 位随机码，数据库仅存绑定 user id 的 SHA-256 摘要，明文只在生成响应中返回一次。
- 管理员选择用户入口也不能绕过已绑定 MFA。密码通过后返回 `mfaRequired/challenge/expiresIn`，服务端匿名会话只保存五分钟待验证身份，不授予业务权限。`POST /api/auth/mfa/complete` 提交 challenge/code；五次失败后废弃挑战，账号/IP 同步限流。
- `POST /api/auth/mfa/cancel` 放弃待验证身份。完成前仍需 CSRF，成功后轮换 session id、CSRF 并登记业务会话。
- 管理端 `/api/admin/mfa` 状态；`/setup` 生成五分钟会话草稿；`/enable` 以草稿 challenge+动态码确认；`/recovery` 以现有动态码或恢复码轮换；`/disable` 以现有第二因子关闭。所有写操作复用 X-Admin-Password 重新认证。
- 安全变更增加 MFA 版本，当前已重新验证的会话更新版本，其他会话撤销；每个已登录管理员请求校验版本，防止旧会话和其他入口绕过。
- `GET /api/admin/mfa/notices` 只展示当前账号最近 50 条提醒；`POST /api/auth/mfa/notices/{id}/read` 标记本人的提醒，要求管理员身份、管理入口及 CSRF，不要求再次输入密码。记录二次验证失败、恢复码使用、绑定/关闭/恢复码轮换，不虚构邮件送达或风险地区判断。
- 管理导航新增“二次认证”，浅深色共用语义色，所有秘密只保留于组件内存，离开即销毁，不放入 URL、localStorage 或日志。
- 数据库迁移仅增加三个表，不改账号密码。正式运行前先备份再迁移；测试只使用独立 H2 与模拟浏览器身份。

## 重点验收

错误因子不发放会话；登录换入口不能绕过；过期/跨会话/重放挑战拒绝；动态码与恢复码并发只允许一次；修改密码/撤权/禁用后待验证身份失效；安全变更旧会话失效；其他用户不得读取提醒或操作 MFA；缺 CSRF/密码/第二因子不得关闭；事务失败不消费恢复码或更新版本；生产无测试后门。

## 边界

本期站内提醒不是邮件/短信/推送，必须登录后查看。无公网不影响认证器离线生成动态码，但终端时钟需同步。丢失认证器及全部恢复码时不提供仅靠旧密码的在线重置后门，须离线身份核验及受审计运维恢复。计数器仍为单实例内存，水平扩容需共享状态。
