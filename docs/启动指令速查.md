# SmartOpsAgent 启动指令速查

> **一键拉起 / 停止全部后台功能（推荐）**
> ```powershell
> D:\SmartOpsAgent\scripts\windows\start-platform.ps1           # 启动全部
> D:\SmartOpsAgent\scripts\windows\start-platform.ps1 -Status   # 看状态
> D:\SmartOpsAgent\scripts\windows\start-platform.ps1 -Stop     # 停止
> ```
> 双击入口：`scripts\windows\start-platform.cmd`，或桌面 `SmartOpsAgent-启动全部后台功能.cmd` / `SmartOpsAgent-关闭全部后台功能.cmd`。
> 脚本会跳过已在运行的服务、统一注入 `.env`、对每个服务做 HTTP 健康门禁，未就绪时以退出码 1 失败；日志在 `.runtime\logs\`。
> 桌面那两个 `.ps1` 只是转发，逻辑只有仓库里这一份。

## 桌面入口的完整用法

两个桌面脚本是"带体检的转发壳"：不重复实现启停逻辑，只负责定位仓库、前置检查、参数转发、失败留窗口。
（`.cmd` 与 `.ps1` 必须放在同一目录，`.cmd` 只做启动器，逻辑同样是转发给 `.ps1`。）

```powershell
# 启动
.\SmartOpsAgent-启动全部后台功能.ps1                  # 启动全部九个服务
.\SmartOpsAgent-启动全部后台功能.ps1 -Status          # 只看状态，不启动
.\SmartOpsAgent-启动全部后台功能.ps1 -SkipMockSsh     # 演示模式：不起 mock SSH
.\SmartOpsAgent-启动全部后台功能.ps1 -Restart         # 重启
.\SmartOpsAgent-启动全部后台功能.ps1 -Open            # 启动成功后自动打开 5173
.\SmartOpsAgent-启动全部后台功能.ps1 -Dev             # 后端走 mvn spring-boot:run（改代码即时生效，多约 400MB）
.\SmartOpsAgent-启动全部后台功能.ps1 -KeepAlive       # 起完不退出（CI / 受管会话保活）
.\SmartOpsAgent-启动全部后台功能.ps1 -TimeoutSeconds 300   # 调健康门禁超时

# 停止
.\SmartOpsAgent-关闭全部后台功能.ps1                  # 停止并逐端口核对
.\SmartOpsAgent-关闭全部后台功能.ps1 -Status          # 只看不停
.\SmartOpsAgent-关闭全部后台功能.ps1 -Force           # 停止后对残留端口补刀
```

行为约定（这两个入口共有的，别再各写一套）：

| 场景 | 表现 |
| --- | --- |
| 仓库不在 `D:\SmartOpsAgent` | 依次找 `SMARTOPS_ROOT` → `D:\SmartOpsAgent` → 脚本所在目录及上级 → 各盘符根目录下的 `SmartOpsAgent`；都找不到则退出码 2 并给出 `setx` 指引 |
| 缺 `.env` | 只提醒不阻塞（口令/密钥可能缺失） |
| 启动失败 | 打印退出码、日志目录、最近三个日志文件名，并停住窗口等回车 |
| 停止后 | 逐端口核对八个服务，残留的报出 PID 与进程名；`-Force` 才补刀 |
| MySQL | 系统服务，停止流程不动它，仅标注仍在运行 |
| 标准输入被重定向 | 不暂停（`SMARTOPS_NO_PAUSE=1` 也可强制不暂停），便于 CI 调用 |

## 单服务启动命令

```bash
# 1. MySQL —— 本机已作为服务运行于 3306；或用 Docker
docker compose -f deploy/docker/docker-compose.yml up -d mysql

# 2. Redis —— 本机 redis-server（scoop 安装路径）
C:\Users\33908\scoop\apps\redis\8.8.0\redis-server.exe --port 6379 --bind 127.0.0.1
# 或用桌面版：C:\Users\33908\Desktop\redis-server.exe

# 3. Mini / Ollama（AI 模型，需 qwen3:1.7b）
powershell -ExecutionPolicy Bypass -File scripts/windows/start-mini.ps1
# 模型缺失时拉取：.runtime\mini\runtime\ollama.exe pull qwen3:1.7b

# 4. Spring Boot 后端（需先有 MySQL / Redis）
cd backend
mvn -Dmaven.repo.local=.m2/repository spring-boot:run

# 5. AI 服务（Python）
cd ai-service
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8001

# 6. 知识服务（Python）
cd D:\SmartOpsAgent
python -m uvicorn knowledge.server:app --host 127.0.0.1 --port 8002

# 7. 用户前端
cd frontend
npm run dev            # 5173

# 8. 管理前端
cd frontend
npm run dev:admin      # 5174
```

## 前提与排错

- **Docker Desktop 未安装**：原脚本的容器步骤会失败，已改为回退到本机 MySQL/Redis。MySQL 需本机服务先起；Redis 由脚本自动用本机 `redis-server` 拉起。
- **Redis 起不来**：确认 `C:\Users\33908\scoop\apps\redis\8.8.0\redis-server.exe` 或桌面 `redis-server.exe` 存在；否则 `scoop install redis`。
- **端口占用**：就绪检查显示 `[DOWN]` 即未起；若端口被旧进程占用，先结束占用进程再重跑脚本。
- **日志位置**：`D:\SmartOpsAgent\.runtime\logs\`（backend-live.log / frontend-live.log / redis-live.log / docker-start.log 等）。
- **人工核验**：内置于后端 8080 的 `/api/auth/human-verification`，本地全离线运行，无独立核验服务。
