# 私有聊天附件：第一批使用说明

日期：2026-10-03。本批是证据保存与权限基础，不是已完成视觉 AI。

## 如何使用

在 AI 对话页点击回形针选择文件，也可以在输入框粘贴截图，或将文件拖进聊天面板。支持 PNG / JPEG 图片和 UTF-8 TXT / LOG / Markdown 文件。

选择有效附件会建立独立的“个人附件会话”，原来的普通文本会话和历史不会自动上传。未发送的文字说明可随附件进入新草稿。确认文件和敏感信息处理后点击发送，允许只发附件、不填文字。

- 输入框上方显示文件名、大小、待发送 / 上传中 / 已上传待保存 / 失败状态。
- 图片支持发送前预览，已保存图片需鉴权后预览；文本文件下载，不作为 HTML 渲染。
- 上传失败保留文件，点击发送重试；已上传文件不重复传输，原样重试消息不会重复保存。
- 取消发送不能保证服务器尚未提交；可核对服务端记录或原样重试，不能把取消提示理解为服务端回滚。
- 切换会话或离开路由前提示清除待发附件；刷新可能丢失本地 File 草稿，界面及浏览器离开提示均有提醒。
- 附件会话保存在服务器，可从历史列表重新打开；普通文本历史仍只在原浏览器，不隐式迁移。
- 删除附件会话会同时删除在线数据库中的消息和二进制附件；已有备份按部署保留策略清理，不承诺从备份立即抹除。

## 当前能力边界

回执明确显示“附件保存回执 · 非 AI 分析”。附件及其说明不调用 Mini 或外部模型，不自动进入知识库。附件会话内的纯文本仅作为证据说明保存；正常 AI 文本问答请点“新建文本问答”。

尚未交付：浏览器截屏、拍照、OCR、视觉模型、WebP / PDF / DOCX 解析、内置裁剪 / 遮盖编辑器、团队聊天页面、知识入库、共享 Agent 和生成 Skill / 脚本流水线。需要遮盖敏感信息时，先在本地处理，再选择处理后的文件；不要上传未脱敏原件。

团队附件 API 已具备成员 / 角色 / 冻结鉴权；当前 UI 只使用个人范围，不会因为切换运维知识空间或团队导航而共享个人附件。平台管理员不能以管理员身份直接读取他人的个人附件。

## 配额与存储

| 项目 | 本批限制 |
| --- | --- |
| 单张 PNG / JPEG | 10 MiB，解码像素最多 2000 万 |
| 单个 UTF-8 文本 | 20 MiB |
| 单次发送 | 5 个文件，合计 40 MiB |
| 同一会话未发送暂存 | 最多 5 个 / 40 MiB |
| 每个个人 / 团队空间 | 200 MiB 附件、100 个附件会话 |
| 单个附件会话 | 200 条消息（包含保存回执） |

初期二进制内容保存在私有数据库 BLOB，不开放静态文件路径。图片服务端解码并重新编码，不保留隐藏的原始图片副本；文本原样保存为 UTF-8。拒绝伪造类型、无效图片、二进制文本和不支持的扩展名。暂不支持病毒扫描和任意文档解析，因此不扩大文件格式范围。

未绑定消息的暂存附件 24 小时后过期，访问检查会清理；后台每小时按空间分批回收，每轮最多 100 个空间，包括停用账号和冻结团队。已发送附件不按暂存规则删除。服务停机或回收积压会延迟物理清理，过期附件读取仍被拒绝。

后台清理默认开启，可通过 `smartops.attachments.cleanup-enabled` 和 `smartops.attachments.cleanup-interval-ms` 配置。测试环境关闭自动调度，由测试显式调用清理，避免操作真实账号。

## 部署与验证

后端需要 V007 增量迁移；`scripts/windows/migrate-local.ps1` 会先备份，再校验历史迁移校验和并执行新表创建。不更改已有迁移文件。建议 MySQL `max_allowed_packet` 至少 64 MiB，为文件内容与传输封装留出空间。

新接口位于 `/api/assistant/conversations`，写操作继续要求登录会话与 CSRF。每次操作在账号行锁内重新验证账号状态；团队操作再锁定团队并验证成员、角色与冻结状态。私有内容返回 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。管理审计只记录动作 / 资源 ID，不保存文件名或附件正文。

验证分为：H2 后端集成、隔离模拟 API 的浏览器交互、前端单元与构建、本地运行只读检查。模拟浏览器不证明相机 / 屏幕授权，也不等于真实账号写入联调；本批不会自动使用真实账号上传测试文件。
