# 个人空间、团队空间与管理控制台

## 本批已交付的入口

登录用户层后，页面顶部提供 **个人空间 / 团队空间** 切换，收起侧栏或手机屏幕也能看到。个人空间保持原有知识、AI、运维工具及数据；团队空间使用独立的团队与成员页面，不把个人功能换个标题冒充多人协作。

主菜单新增 **团队协作 / TEAM SPACE**，直接进入 `/teams` 的团队清单与邀请管理。尚未实现的共享 Agent、团队知识和协作任务不会提前放置可点击的假入口。

- `/teams`：我加入的团队、待处理邀请、创建团队。
- `/teams/:teamId`：当前团队资料、成员角色、邀请管理。
- `/admin/teams`：平台管理层查看团队及成员元数据，冻结/恢复团队。
- `/admin`：集中显示账户统计与团队、账号、会话、审计、MFA、接入检查的快捷入口。

## 用户使用步骤

1. 在用户层切换到团队空间，创建名称和描述。当前账号成为所有者；每个账号最多创建 10 个团队。
2. 输入已注册账号的用户名，选择团队角色并发送站内邀请。不需要公网或邮件服务。
3. 被邀请者自行登录，进入团队空间接受或拒绝。邀请七天有效，未接受不具备成员权限。
4. 所有者可编辑资料、管理成员角色及撤销邀请；团队管理员仅能管理普通成员和只读成员。
5. 非所有者可以退出。所有者退出、团队删除和所有权交接暂未实现，避免在资源交接规则未完成时丢失团队控制权。

团队最多 100 名成员、50 条有效待处理邀请。页面采用分页读取团队和收件箱。邀请过期、被撤销或已处理后不能重复接受；邀请人退出、被移除或角色调整后，已发出的待处理邀请自动撤销。邀请人账号禁用后也不能再接受其邀请。

## 权限说明

| 角色 | 当前能力 |
| --- | --- |
| 所有者 | 修改团队资料，邀请和管理 admin/member/viewer，不能移除自己或创建另一所有者 |
| 团队管理员 | 修改团队资料，邀请和管理 member/viewer，不能管理所有者或其他管理员 |
| 成员、只读成员 | 查看团队基础信息和成员名单，可退出；本批没有共享资源，暂不赋予两者不同的资源写入能力 |
| 平台管理员（管理层） | 检索团队元数据、查看成员角色、冻结/恢复；不自动成为团队成员 |

角色不互相继承：团队管理员不是平台管理员；平台管理员账号从用户层登录也不能使用管理层接口。

## 管理控制台

导航分为「管理工作台」「身份与空间」「安全与审计」「服务与部署」。团队管理支持名称检索、状态过滤、分页、成员名单及状态变更。冻结/恢复需当前管理员密码复核和 CSRF，密码每次提交后清空，不写入浏览器存储。

冻结后禁止修改团队资料、邀请成员、接受邀请和修改其他成员；允许查看基础信息、拒绝邀请及非所有者退出。冻结团队不冻结成员个人账号。恢复后仍有效且未处理的邀请可以继续接受。

团队创建、资料修改、邀请/接受/拒绝/撤销、角色变更、移除/退出、冻结/恢复均记录平台安全审计。界面可按这些操作筛选。审计与数据库变更同事务，审计写入失败则变更回滚。

本批只展示成员用户名、角色与账号启用状态，不暴露密码、私人会话或知识正文。团队管理员界面的业务边界始终由服务端验证，不依赖隐藏按钮。

## 数据与部署

V006 仅新增 `team_workspace`、`team_member`、`team_invitation` 三张空表，不改变现有账号、知识、服务器、凭据、MFA 或会话归属。历史个人资料不自动迁移到团队。

先使用 `scripts/windows/migrate-local.ps1` 备份数据库并核对迁移摘要，再用 `scripts/windows/restart-local-backend.ps1` 更新已验证的后端包。重启会使内存登录会话失效。测试使用独立 H2 和浏览器 API 拦截，不自动创建真实团队或邀请真实用户。
