# 脚本库编辑器使用指南

> 面向脚本库（`/sentinel/scripts`）使用者的上手文档，覆盖编辑器升级后的四项能力：
> **常用模板、风险自动判定、实时安全检查与语法高亮、平台变量点击插入**。
>
> 设计原则不变：执行仍走既有受控链路（预览 → 二次确认 → 执行 → 记录 → 审计），
> 编辑器只提升"写与看"的体验，**不新增任何执行通路**。

---

## 一、快速上手（新手三步）

1. **选一个模板**：在「常用模板」卡片区点 **使用此模板**，内容会自动填进编辑器并滚动到位；
2. **改成自己的**：按模板注释里的提示改参数（比如把 `nginx` 换成你的服务名、`8080` 换成你的端口）；
3. **试运行再保存**：输入过程中系统实时做安全检查与风险判定，确认无误后再谈保存与执行。

## 二、常用模板

内置 6 个最常用场景，每个都尽量短、带一句"改哪里"的注释：

| 模板 | 语言 | 用途 | 默认风险 |
| --- | --- | --- | --- |
| 磁盘空间检查 | Shell | `df -h` 查看挂载点使用率 | 低 |
| 服务状态巡检 | Shell | `systemctl status` 检查服务是否在运行 | 低 |
| 端口探活 | Shell | `ss -tlnp` 确认端口是否在监听 | 低 |
| 内存占用 Top10 | Shell | 按内存排序定位占用大户 | 低 |
| 过期日志清理（预览） | Shell | 先只列出 7 天前的旧日志；确认后去掉注释才真正删除 | **中** |
| HTTP 接口健康探测 | Python | 请求健康检查接口验证可用性 | 低 |

> 日志清理模板被有意判为**中危**：它的注释里保留了 `find … -delete` 这一行作为教学示例——
> 注释中的危险写法同样计入风险判定（见下一节）。

## 三、风险自动判定（不需要也不允许手选）

风险级别由 `inferRiskLevel` 按脚本内容自动判定，界面会给出**升级原因**。判定规则从高到低：

| 级别 | 触发条件 | 示例 |
| --- | --- | --- |
| **高** | 命中高危黑名单（`DANGEROUS_PATTERNS`） | `rm -rf`、`mkfs`、`dd of=/dev/…`、`shutdown/reboot`、Fork 炸弹、清空防火墙、删用户、`DROP TABLE` 等 |
| **中** | 命中中危规则（`MEDIUM_RISK_PATTERNS`）：写入类但通常可逆 | 删除文件（`rm`/`del`）、`find … -delete`、`systemctl restart/stop`、`kill` 系、装/卸软件包、`chmod/chown`、移动覆盖文件、写系统目录、Windows 的 `format`/`Remove-Item` 等 |
| **低** | 未命中任何写入类规则，按只读查询处理 | `df -h`、`ps aux`、`systemctl status` 等 |

三条重要约定：

1. **注释里的危险写法同样计入**：宁可误判升级，也不放过真正的危险操作；
2. **每次升级都带原因**：界面如实展示命中了哪条规则，用户从"出题人"变成"确认人"；
3. **预检是防御性检查，不是沙箱**：它拦住明显误操作；真正的边界在服务端
   （固定命令、参数校验、最小权限、超时与审批）。

高风险脚本保存后需管理员审批，才可用于告警联动（与升级前规则一致）。

## 四、实时安全检查与语法高亮

### 4.1 输入即检

- 停止输入约 **250ms** 后自动完成一次高危预检（`lintScript`），不再需要手动点按钮；
- 结果分三种：**预检通过** / **命中高危规则（已拒绝）** / **疑似语法问题**（括号不配对粗检）；
- 内容清空时提示自动收起，不打扰。

### 4.2 语法高亮

编辑器使用零依赖的轻量高亮层（透明输入区叠加只读高亮层，滚动实时同步），
支持 Shell / Python / Bat / PowerShell 四种语言的四类着色：

| 着色 | 含义 |
| --- | --- |
| 灰色斜体 | 注释（引号里的 `#` 不会被误判为注释） |
| 绿色 | 字符串 |
| 蓝色加粗 | 语言关键字与常用命令 |
| 琥珀色底纹 | 平台变量占位符（`${主机IP}` 等） |

**安全约定**：所有脚本内容先做 HTML 转义再着色，脚本内容永远不可能注入标记（有专门测试钉死）。
识别不出的内容原样展示，高亮只是阅读辅助，不影响编辑。

## 五、平台变量点击插入

1. 展开「什么是平台变量？什么时候用得上」折叠区；
2. **点击任意变量**，即插入到编辑器当前光标处（光标落在插入内容之后）；
3. 变量在**告警联动执行时由平台自动替换**成真实值；手动执行时也可以在「发起执行」表单里填写。

变量清单（与服务端 `SentinelVariables.SUPPORTED` 一致）：
`${主机IP}`、`${主机名}`、`${告警指标}`、`${告警值}`、`${阈值}`、`${告警级别}`、
`${告警标题}`、`${脚本名}`、`${执行人}`、`${时间}`。
未提供的变量会保持原样并在界面上提示未替换项。

## 六、常见问题

**Q：为什么我的脚本只是写了注释也被判中危？**
判定对注释同样生效（宁升不放过）。删掉注释里的危险写法，级别会自动降回来。

**Q：为什么没有"运行高危预检"按钮了？**
检查已经变成输入即触发，按钮是多余的。风险判定也同时自动刷新。

**Q：模板能覆盖我的场景吗？**
先选最接近的模板再改参数，比从空白开始快；空白编辑也完全支持。

**Q：保存后的版本与审批规则变了吗？**
没有。脚本保存后即产生 v1 版本；高风险脚本仍需管理员审批才能用于告警联动。
