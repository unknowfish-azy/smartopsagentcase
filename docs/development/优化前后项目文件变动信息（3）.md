## 八、优化建议

### P0：建立可评测的数据基础

1. 导入少量经过人工审核、来源可追踪的 REAL 样本，或明确标记为 SYNTHETIC 的候选样本。
2. 严格执行 Schema → Rule/Safety → Deduplication → Grouped Split → Leakage → Human Review。
3. 只有 `APPROVED` 样本进入正式训练集，并重新生成 Manifest 与哈希。

### P0：完成真实 Baseline

1. 配置一个真实可调用模型或本地模型。
2. 固定 Dataset Version、Prompt Version、Knowledge Version 和 Evaluator。
3. 先运行 Baseline，再比较 RAG、Evidence、Inspector 与 Verification；不要用 Mock 结果代替 Baseline。

### P1：打通数据闭环

优先完成：

```text
Agent Trace
→ Inspector
→ Verification
→ Human Review
→ Training Candidate
→ Quality Gate
→ Approved Dataset
```

这条链路应先于大规模 GPU 训练，因为它决定数据是否可信、可追踪、可复现。

### P1：补齐评测与消融

按顺序真实运行：

```text
Baseline
→ RAG
→ RAG + Evidence
→ RAG + Evidence + Inspector
→ RAG + Evidence + Inspector + Verification
```

每个实验必须保存配置、数据版本、指标分母、原始输出、报告和制品哈希。

### P2：训练准备

启动 SFT/Preference 前检查：

- PyTorch、Transformers、Datasets、PEFT、TRL 是否真实安装；
- CPU/CUDA/GPU、驱动和显存是否满足要求；
- 模型许可、模型路径和数据集版本是否明确；
- dry-run、断点恢复、失败状态和报告是否可用。

没有 GPU 时继续做 Dataset Validation、Config Validation 和 Evaluation-only，不标记为 GPU 训练成功。

### P2：工程收口

1. 对 Frontend 做路由级懒加载和按需拆包，处理主 chunk 警告。
2. 在具备服务和可选依赖的环境中重跑 24 个 skipped 项。
3. 持续检查日志、Dataset 和报告，确保不会出现密码、API Key、Token 或密文。
4. 所有 API 扩展继续保持增量兼容，不删除或重命名既有接口。

## 九、最终结论

SmartOpsAgent 已从基础 Agent 项目扩展为具备安全执行、Inspector 产品链路和训练工程基础设施的系统。目前可以真实声明的是：训练数据结构、质量门禁、分组切分、泄漏检查、评测边界和模型注册基础已经实现并通过相应自动化测试。

目前不能声明已经完成真实模型训练或取得模型指标，因为正式 Dataset 仍为 0 个批准样本，Baseline、SFT、Preference Optimization 和 GPU 训练均为 `NOT RUN`。下一阶段最合理的工作是先建立少量高质量、可追踪的批准数据，并完成真实 Baseline Evaluation。
