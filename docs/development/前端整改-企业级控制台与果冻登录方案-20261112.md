## 1. 执行摘要：先接受一个反直觉的结论

**你的前端不是「不够好看」，而是「太满、太散、太重」。** 这是本次整改的起点，也决定了方案方向是**做减法 + 分级**，而不是再堆组件或引入新 UI 库。

代码事实：
- `frontend/src` 有 **177 个 `.vue`**（views 69 / components 105 / layouts 2 / App 1），约 80 条路由**全部懒加载**（`router/index.js:10-114`、`router/admin.js:17-44`）。
- 设计体系**至少 6 套并存**：`--smart-*`（`variables.css`）、`--el-*`（Element Plus 映射）、`--admin-*`（`admin.css:12-35`，且反向覆盖 `--smart-*`）、`--login-glass-*`（`LoginView.vue:334`）、`--lggc-*`（第三方液态玻璃库）、以及各 `.vue` 的 scoped 硬编码色值；另有 `--pet-*` / `--smart-effect-*` 子体系。
- 登录页 `/` 已经**同时挂载** Canvas 星野（70/130 星）、6 条 CSS 流星、360 粒子 SVG 果冻水母、Canvas 鲸、竖排《滕王阁序》水印、OPS 渐变大字、指针追光、20px 圆角 + 22px 模糊的双层流光玻璃卡（`LoginView.vue:4-35,334-370`）。
- 用户层壳层 `MainLayout.vue:4-12` 在首页 `balanced` 模式同时挂 **7 个视觉层**（WebGL 银河 + 星野 + 流星 + WebGL 鲸 + SVG 水母 + 桌宠 + 抽屉），全库约 **20 处 rAF 循环**。
- `design-system/MASTER.md:35` 明文要求「0–4px 圆角、卡片只用于表单/弹窗」，实际 8/9/10/11/12/14/16/20px 圆角遍地 + 大量玻璃卡片 —— **规范和实现已经互相矛盾**。

**三条核心决策**：

1. **表现层 / 工具层分离**：登录与品牌页 = 宇宙星空 + 果冻玻璃（保留情绪价值）；控制台 = 企业级简约高密度扁平（工具属性）。**不要让控制台也跑星空和玻璃**。这是同时拿到「企业级简约」与「高性能」的唯一路径，也直接消掉大部分性能负担。
2. **果冻感用「形变 + 内高光」，不用「每帧追光」**：现有 22px `backdrop-filter` + 指针每帧写 CSS 变量会持续触发 `::before` 的 radial-gradient 重绘。简约果冻 = 12–14px 圆角 + `blur 8–12px` + 单层内高光 + 聚焦时轻微 spring 形变 + 静态边缘光，性能成本低一个数量级。
3. **先收敛令牌与契约，再动页面**：仓库有 `build-optimization.test.mjs`、`login-glass.browser.mjs`、`login-layout.browser.mjs` 等**精确字符串硬断言**，大规模改 `.vue` 很容易「视觉对了、门禁全红」。必须先冻结契约清单（§6），按 P0→P3 分阶段改，每阶段跑完整门禁。

| 层级 | `--ds-z-*`（base/dropdown/sticky/modal/toast） | 取代散落的 `z-index` 数字 |

**约束**：`variables.css:56-80` 的 `--el-*` 映射**不能动**（Element Plus 全线依赖）；`admin.css:12-35` 的 `--admin-*` 逐步收敛到 `--ds-*`；`global.css` 的 41 处 `!important` 分阶段降到 ≤10 处。

| 项 | 现状 | 目标 |
|---|---|---|
| 卡片圆角 | 20px | 14px（8 字形轻微形变，`border-radius: 14px 14px 14px 14px / 13px 13px 15px 15px`） |

| 性能门控 | 无显式预算 | `hover:none` 禁用追光；低帧率（连续 3 帧 >50ms）自动切 blur-only；`@supports` 回退；`visibilitychange` 暂停 |

## 5. 面向「AI Web 网页设计」的创新叙事（不只是换皮）

竞赛评审会问「AI 体现在哪」。仅有星空和玻璃不够，建议把整改本身做成 4 个可讲、可测的 AI 原生界面机制：

1. **自适应视觉预算（Adaptive Visual Budget）**：采集 FCP/LCP、长任务、`devicePixelRatio`、`prefers-reduced-motion`、连续帧耗时，自动在 `balanced / lightweight / reduced-motion` 之间切换，并把决策理由展示在界面上（可解释性）。这是把已有 `visualMode.js` 从「用户手选」升级为「系统自适应 + 用户可覆盖」。
2. **上下文感知密度**：按角色（运维/管理员/访客）、任务阶段（监控/排障/审批）自动切换 `compact/default/comfortable`，减少无关信息。
3. **AI 证据链 UI 语法**：把已有的「思考阶段可视化 / 引用证据 / trust_score / 四级核查」统一为一套组件语法（证据卡、置信度条、核验状态、审计时间线），让「AI 结论可验证」在界面上可读 —— 这直接呼应项目定位与 AIC「技术实现 20 分」。
4. **自然语言 → 界面意图**：扩展现有 `CommandPalette.vue`，让自然语言不仅能执行命令，还能切换视图密度、定位证据、生成临时看板，并保留可撤销路径。

每项都要能给出「改造前后」的量化对照（任务完成时间、误点数、FCP/LCP、长任务数），否则只是叙事。

## 9. 风险与局限

1. **视觉参考不可核验**：两条抖音链接均无法在公开 Web 侧访问，本方案基于用户口述 + 公开开源资料；不是对原作品的复刻。若用户提供授权截图，需重新校准配色与构图。
2. **静态分析**：本轮未运行前端、未构建、未跑任何测试，所有性能与视觉结论来自源码与既有文档；实际数值须以 `npm run perf:baseline` 前后对照为准。
3. **测试契约是硬约束**：§6 的精确字符串断言意味着「大改」必须分批 + 显式更新测试，不能一次性重写 `LoginView.vue` 或 `MainLayout.vue`。
4. **typecheck 假绿**：`tsconfig.json` 不覆盖 `.vue`，改造后必须靠 `test:visual` / `test:a11y` / 浏览器脚本兜底。
5. **双入口同步**：改 `main.js` 需同步 `admin-main.js`；改 `vite.config.js` 需同步 `vite.config.admin.mjs`；新增管理端路由必须确认 `router/admin.js` 已注册（5174 有 `adminHtmlFallback` 中间件会吞非资源 GET）。
6. **Liquid Glass 浏览器兼容**：`backdrop-filter: url(#filter)` 仅 Chromium 完整支持，Safari/Firefox 必须保留 blur-only 回退；项目已有 `@supports` 回退，不可删。
7. **开源元数据**：star / 许可证为 2026-11-12 GitHub API 快照；`@daviduo/liquid-glass-web` 的 GitHub 归属未核实（仅 npm 包声明 MIT）；`arco-design-pro-vue` 最近推送 2024-05，活跃度低；三个星空仓库 star 0–6，仅作实现思路参考，不建议作为生产依赖。
8. **REA 边界**：未对任何第三方系统做资产剥离或逆向；目标仅为用户自有仓库与公开资料；产物为方案文档，改动实施阶段需保证「可编译或可运行」（每阶段跑 §7 门禁）。
