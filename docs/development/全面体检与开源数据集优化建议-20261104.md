# SmartOpsAgent 全面体检与开源数据集优化建议

检查日期：2026-11-04  
项目根目录：`D:\SmartOpsAgent`  
目标：先把答辩演示变成可复现、可解释、可验收的闭环，再逐步产品化。本文只记录已取得的本地证据和公开资料；未把待抓取仓库写成已验证事实。

本文件的失败数与运行证据为实施前基线；已批准项目的后续结果见[产品质量优化实施记录](产品质量优化实施记录-20261104.md)。结构统计已依据排除依赖/构建物后的原始 inventory 更正。训练硬件以本批新鲜检查为准，历史 readiness 不代表当前机器状态。

## 1. 结论先行

项目“功能很多”，但“质量闭环还不够硬”。当前主要问题不是缺少更多 Agent 框架，而是四条链没有完全统一：

1. **鉴权链（初检）**：全量 Python 有 16 个旧 API/E2E/集成测试收到 401/403，与测试预期不一致；匿名拒绝和登录后成功没有统一 fixture。
2. **真实演示链**：Node 前端单测已 470/470，通过不等于登录态浏览器、真实 AI provider、SSE 中断和故障恢复已经连通；8001 AI 进程也没有重启验证当前源码。
3. **数据质量链（初检）**：训练代码和 schema 很完整，但历史 readiness 为 BLOCKED；候选池 40 条、全部 SYNTHETIC、approved=0、leakage=NOT_RUN，现有 Golden 是从候选派生的，不能当独立测试集。
4. **运行与演进链**：Knowledge 默认入口已经 READY，但索引仍以当前进程装载为主；持久化、迁移、租户过滤、备份恢复和配置版本还没有形成可验收产品契约。

建议暂缓整体迁移 LangGraph/LlamaIndex/Phoenix 等框架。先把主流程的身份、目标、证据、审批、执行、验证和回滚串成同一个 `request_id/task_id/run_id` 记录，再用同一 workload 做组件对照。

## 5. 推荐优化路线

### 第一阶段：答辩稳定（1 个迭代）

1. 修复 16 个鉴权契约测试：匿名请求明确断言 401/403；登录 fixture 只使用隔离账号和测试数据库。
2. 固化一条 Playwright 黄金路径：登录 → 发送运维问题 → 展示引用 → 触发人工审批 → 模拟工具失败 → 展示失败审计/重规划。
3. 将 `request_id/task_id/run_id/step_id` 显示到前端诊断抽屉和导出记录；每个演示断言都能跳回日志。
4. 为演示准备固定 Knowledge corpus manifest/hash 和一键 readiness 检查；启动失败时停止演示，不显示“已完成”。
5. 保持训练门禁 BLOCKED 的真实状态，答辩材料用“数据治理框架已建、真实训练未放行”表述。

### 第二阶段：可产品化（2—3 个迭代）

1. 把审批记录从 Python 进程内模型升级为平台事件协议：创建、批准、拒绝、过期、消费、执行结果、验证结果都有不可变事件。
2. Knowledge 引入版本化索引：`corpus_id/version/hash/schema`，支持原子切换、回滚、增量重建和多实例只读加载。
3. 增加 RAG 质量门禁：引用支持率、空命中率、过期知识率、跨租户泄漏率、查询延迟 P95；不只看 Recall@3。
4. 用 OTel 先统一 trace context 和脱敏规范，再评估 Collector；Phoenix 因 ELv2 暂不放入默认托管路径。
5. 建立 dependency/许可证清单，锁 tag/commit；引入项目必须有退出路径和离线启动验证。

### 第三阶段：数据与模型（证据充分后）

1. 建立四层数据：REAL 脱敏事件、DEMO 演示事件、SYNTHETIC 扩展事件、ADVERSARIAL 安全样本；来源、时间、版本、风险、审批状态全入 manifest。
2. 独立 Golden 集至少按事件族、环境、时间切分，禁止从候选池派生；每条样本需有 evidence、expected risk、approval_required、verification_plan。
3. 先做检索/规划/证据判断基线，再考虑 SFT 或 preference optimization；本批新鲜检查识别 RTX 4060 Laptop/CUDA、torch 和 transformers，datasets/peft/trl 仍缺失。历史“无 GPU/mock provider”描述不再作为当前结论；审核数据不足，训练仍未放行。
4. 以真实运维任务比较模型：任务完成率、证据支持率、危险动作率、人工接管率、重规划成功率、P95 延迟、token 成本和恢复时间。

## 6. 暂不建议做的事

- 同时迁移 LangGraph、LlamaIndex、Qdrant、Phoenix，形成多套状态、索引和观测源。
- 用 GitHub stars、合成数据 F1 或单次模型回答替代真实运维验收。
- 为消除红灯关闭 CSRF/权限、批量 skip 测试或把 mock provider 当真实基线。
- 在没有许可、数据来源和删除机制审阅前下载并混入训练集。
- 在默认启动脚本中自动执行高风险修复动作；审批、目标绑定和验证必须留在同一运行记录中。
