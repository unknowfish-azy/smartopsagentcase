# nginx 配置实机校验（2026-11-07）

> 补掉 SEC-01 残余项「`/ai-api` 内网 CIDR 隔离」的本机可验证部分。
> 此前只有配置级改动 + 一次临时镜像里的 `nginx -t`，没有在原生 nginx 上跑过真实请求。

## 环境

- nginx **1.26.2 for Windows**（官方 `nginx.org/download/nginx-1.26.2.zip`，解压即用，无安装）
- 被测配置：仓库里的 `deploy/nginx/nginx.conf`（**只有路径适配，规则一行未改**）
- 后端上游：本机在跑的 8080 / 8001 / 5173 三个服务（jar 模式的平台栈）

## 路径适配（仅为让 Linux 配置能在 Windows 起来）

| 原值 | 校验用值 | 说明 |
| --- | --- | --- |
| `include /etc/nginx/mime.types;` | `<prefix>/conf/mime.types` | 系统路径换成便携包自带 |
| `/var/log/nginx/smartops-*.log` | `logs/smartops-*.log` | 日志落前缀目录 |
| `root /opt/smartops/frontend;` | `D:/SmartOpsAgent/frontend/dist` | 用已构建产物 |
| `listen 80` / `listen [::]:80` | `listen 8088` / `[::]:8088` | 避免占用 80 |

`location`、`allow`/`deny`、`proxy_pass`、`proxy_set_header`、超时、`proxy_buffering off` 等
业务规则**全部保持原样**。

## 结果

### 1. 语法与指令合法性

```
nginx: the configuration file .../conf/smartops.conf syntax is ok
nginx: configuration file .../conf/smartops.conf test is successful
```

### 2. 真实请求（nginx 监听 8088）

| 请求 | 期望 | 实测 |
| --- | --- | --- |
| `GET /ai-api/health` | 放行并反代到 `127.0.0.1:8001/api/health` | **200**，返回 `{"status":"UP","service":"smartops-ai-service"}` |
| `GET /` | 静态站点 | **200** `text/html` |
| `GET /api/actuator/health` | 反代到后端 | **401**（后端自身安全过滤拒绝匿名，说明请求已到达应用） |

第 1 条同时验证了两件事：`allow 127.0.0.1` 生效，以及 `/ai-api/` → `/api/` 的路径改写正确
（这个改写此前没有实跑过，属于"配了但没验证"的高风险点）。

### 3. allow/deny 两个分支

真实公网来源无法在本机伪造，所以在**测试专用配置**（`conf/smartops.test.conf`，不进生产）
里放了一个 8089 server，用同一套 allow/deny 写法，靠真实静态文件走完 access 阶段：

| 用例 | 规则 | 来源 | 期望 | 实测 |
| --- | --- | --- | --- | --- |
| A | 与 `/ai-api` 完全相同的 allowlist + `deny all` | 127.0.0.1 | 放行 | **200** |
| B | 仅 `allow 10.0.0.0/8` + `deny all` | 127.0.0.1 | 拒绝 | **403** |

> 踩坑记录：第一次用 `return 200` 做被测内容，B 用例返回了 200。原因是 `return` 属 **rewrite 阶段**，
> 早于 **access 阶段**执行，allow/deny 根本没参与判断。换成本地静态文件（`alias html/`）后
> 200/403 才正确。这条对以后写 nginx 访问控制测试很重要：**不能用 `return` 验证 `allow/deny`**。

## 结论与残留

- 配置本身可加载、指令合法、反代与路径改写正确、allow/deny 语义与顺序符合预期（默认拒绝）。
- **残留**：真实公网来源访问 `/ai-api/` 是否 403，需要部署在带公网出口的环境里复验；
  本机只能证明规则写法与执行阶段正确。
- 另注：`docs/security/audit-20261105/remediation-order.md` 记录过一次临时镜像里的 `nginx -t`；
  本次是在原生 Windows nginx 上的独立复验，两者结论一致。

## 复现

```bash
# 解压官方包后，按上表改 4 处路径/端口，生成 conf/smartops.conf
cd <nginx-prefix>
./nginx.exe -t -p <nginx-prefix> -c conf/smartops.conf
./nginx.exe -p <nginx-prefix> -c conf/smartops.conf      # 监听 8088
curl --noproxy '*' http://127.0.0.1:8088/ai-api/health
./nginx.exe -s stop -p <nginx-prefix> -c conf/smartops.conf
```
