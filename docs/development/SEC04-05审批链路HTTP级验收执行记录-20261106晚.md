## 四、本轮发现并修复的真缺陷

**grantToken 从未通过 API 下发（审批后执行链路在线上断裂）**

- 现象：`Run` 记录的 `grantToken` 标注 `@JsonIgnore`，HTTP 层的合法执行人永远拿不到
  一次性凭据；前端 `TeamCollaborationView.vue` 却按 `run.grantToken` 回传执行。
  进程内单测直接读 record 组件，掩盖了这个问题——正是 HTTP 级验收该抓的形态。
- 修复：`TeamAgentRunService.forRequester(run, actor)` 视图——token 仅在
  `APPROVED` 可执行窗口内、对申请人本人可见；`create/detail/list` 出参统一套用。
  审批人/其他成员视角永不含 token；已消费（RUNNING/终态）后库里已置 NULL。
  token 本就只能在 `consumeGrant` 中由申请人本人使用，下发不扩大任何权限。
- 测试：`TeamAgentRunServiceTest` 新增
  `grantTokenOnlyVisibleToRequesterWithinApprovalWindow`（待审不可见 / 申请人可见 /
  审批人不可见 / 只读即批可见 / 消费后不可见），12/12 通过。

## 五、过程记录（非缺陷）

1. 后台任务里的 redis-server 会随 shell 会话结束被回收——E2E 首跑时 redis 已死，
   总体 health 503。重启 redis 后恢复 200。**演示前请确认 redis 进程存活**。
2. 注册接口有频控（429）：连续重放 E2E 会触发；脚本已做 SQL+bcrypt 建号兜底。
3. mock SSH 服务器是一次性主机密钥（进程生命周期内有效），演示重放时重启即换指纹，
   首次 connect 需 `decision=TRUST_ONCE`（脚本已带）。
4. SEC-04 的 Python agent 侧审批（run_id 指纹、legacy 审批不可用、reviewer≠requester）
   无 HTTP 面（进程内判定），HTTP 级等价约束由 S3 体现；跨 run 复用拒绝已有
   `tests/agent/test_execution_approval.py` 42 项单测，不重复验证。
