## 1. 结论

- **PERF-03 已实现并通过本地单元/集成验证**：同用户同会话的连接建立合并为一次拨号（等待者共享结果）、会话索引 O(1)、按用户/会话配额、空闲 TTL 清理、命令输出按字节预算截断并有截断标志贯穿到前端。
- **PERF-04 已实现并通过本地集成验证**：批量命令不再"写进 shell 就返回"，而是复用 Runbook 的"一条 Run + 逐目标子任务"，一个有界并发的 Run、逐目标 `SUCCEEDED/FAILED/UNKNOWN/CANCELLED`、可取消、未派发单列，证据仍写同一张 `operation_run_record`，与 OPS-11 是同一实现。
- 清单验收里的**真实 SSH 主机连接复用**与**真实 100 MB 远端输出**本机没有条件执行，因此不作为完成依据；本批用可复现测试覆盖算法与状态口径，限制见第 5 节。
- 本批未新增数据库迁移：只使用 OPS-08/OPS-11 已存在的列（`operation_run_output.truncated`、`runbook_run_target.dispatch_status` 等）。

## 2. PERF-03：SSH 运行通道

### 2.1 原子连接建立（[OperationConnectionCoordinator.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/operations/OperationConnectionCoordinator.java)）

| 步骤 | 行为 |
| --- | --- |
| 快路径 | 先按 `userId + sessionId` 查注册表，已有通道直接 `ConnectionResult.reused(runtimeId)`，不拨号 |
| 慢路径 | `inFlight.putIfAbsent(key, future)`；只有一个线程执行真正的 `connector`，其余线程等待同一个 future |
| 结果共享 | 等待者拿到 leader 的结果；leader 抛异常时等待者解包为同样的 `RuntimeException`，不会被伪装成 ONLINE |
| 失败不粘滞 | `finally` 中移除键，下一次请求可以重新尝试；不会缓存失败的连接结果 |
| 复用标记 | `ConnectionResult.reused=true` 明确告诉调用方这是复用还是新建 |

范围说明：合并发生在**进程内**，多副本部署时各副本各自合并，不做跨进程互斥（见第 5 节）。

### 2.2 索引、配额与生命周期（[OperationRuntimeRegistry.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/operations/OperationRuntimeRegistry.java)）

- 双索引：`runtimes`（runtimeId → runtime + 最近访问时间）与 `bySession`（`userId:sessionId` → runtimeId），按会话查找由线性扫描改为 O(1)。
- 配额：默认每用户 20 条、每会话 4 条；超限抛 `BusinessException(429, "RUNTIME_QUOTA_EXCEEDED")` / `"RUNTIME_SESSION_LIMIT_EXCEEDED"`，不静默淘汰正在使用的通道。
- `requireOwned` 保持旧语义：不因已关闭返回 404（避免会话重连时误报），同时刷新 `lastAccessMillis`。
- `removeOwned` / `removeEntry` 统一关闭通道并清理两个索引，避免"注册表里还有但实际已关"的悬挂条目。
- `findBySession` 命中已关闭通道时清理索引并返回空，交给上层重连。

### 2.3 空闲回收（[OperationRuntimeJanitor.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/operations/OperationRuntimeJanitor.java)）

- `@Scheduled` 默认 30 秒后首次运行、之后每 60 秒扫描一次（可配置）。
- `sweep(now, idleTtlMillis)`：关闭已 closed 的通道；`lastAccess < now - idle-ttl`（默认 15 分钟）的通道一并关闭并清理索引。
- 清理只影响本地通道，不向远端发送任何命令。

### 2.4 命令输出预算（[BoundedOutput.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/operations/BoundedOutput.java)）

- SSH `exec` 的 stdout/stderr 直接接到 `BoundedOutput`：只保留前 N 字节，超出部分只累计字节数，不进入堆内存；`truncated()` 标记是否发生截断。
- `OperationRuntime.CommandResult` 增加 `boolean truncated`；[SshConnectionAdapter.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/operations/SshConnectionAdapter.java) 返回 `stdout.truncated() || stderr.truncated()`。
- 默认预算 1 MiB（`smartops.operations.ssh.output-limit-bytes`），运行记录侧仍另有 512 KiB 预算，`OperationToolService` 取两者或运算后的截断标志。

截断标志的传递链：

| 层 | 落地 |
| --- | --- |
| SSH 执行 | `CommandResult.truncated` |
| 工具/命令执行 | `OperationToolService` 写入 `ToolCommandResult.truncated` 与 `runRecorder.recordCommand(...)` |
| Runbook 执行 | `recordCommand(..., truncated(...) \|\| result.truncated())` |
| 权威存储 | `operation_run_output.truncated`（TINYINT，OPS-08 已有列） |
| 查询接口 | `OperationRunQueryService.CommandOutput.truncated` |
| 前端 | [RunHistoryDetailPanel.vue](file:///d:/SmartOpsAgent/frontend/src/components/operations/RunHistoryDetailPanel.vue) 在 stdout/stderr 标题旁显示"已截断"胶囊 |

### 2.5 配置项（[application.yml](file:///d:/SmartOpsAgent/backend/src/main/resources/application.yml)）

```yaml
smartops:
  operations:
    ssh:
      max-per-user: 20
      max-per-session: 4
      idle-ttl-ms: 900000
      sweep-interval-ms: 60000
      sweep-initial-delay-ms: 30000
      output-limit-bytes: 1048576
```

全部支持同名环境变量覆盖，默认值即生产建议值。

## 3. PERF-04：批量命令复用 Runbook Run

### 3.1 一条 Run、逐目标子任务（[RunbookExecutionService.prepareAdHocBatch](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/runbook/RunbookExecutionService.java)）

- 内部隐藏 Runbook：`__multi_exec__dev` / `__multi_exec__prod`（`enabled=0`），每批命令生成一个新版本（`version = MAX+1`），步骤正文即原始命令。
- `prepareAdHocBatch` 依次完成：校验批次/命令/确认码 → 去重目标 → 建版本 → 建 Run（`AWAITING_TARGETS`）→ 走与手动计划同一个 `applyPlan`（目标快照 + 内容哈希）→ 校验审批次数未漂移（`MULTI_EXEC_APPROVAL_DRIFT`）→ 置 `APPROVED` 并写入 `nonce_hash`。
- **没有新建第二条执行通路或审批链**：审批仍是 multi-exec 的"预览 + 二次确认"，权限/审计/证据/状态机全部沿用 Runbook 与 OPS-11。
- 原始命令模式：ad-hoc 版本跳过 `SentinelVariables` 的 `${VAR}` 校验（批量命令常带 shell 变量），只做风险策略评估。
- 内部 Runbook 在目录列表中被过滤（`RunbookCatalogService.list` 排除 `__multi_exec__` 前缀），不会出现在用户可见清单里。

### 3.2 并发、状态与取消

| 能力 | 实现 |
| --- | --- |
| 有界并发 | 版本 `concurrency = clamp(1..10)`（`MAX_PARALLEL`），批次 `batch_size = clamp(1..100)`；默认 10 |
| 逐目标状态 | 每个目标一条 `runbook_run_target`：`SUCCEEDED/FAILED/UNKNOWN/CANCELLED`；`UNKNOWN` 表示已派发但结果不可确认，不自动重试写操作 |
| 派发证据 | `dispatch_status = SENT/NOT_DISPATCHED`，与最终 `status` 分开记录；"已发送"不会被写成成功 |
| 逐目标证据 | 每个目标每次尝试一条 `operation_run_record`（与 OPS-11 相同） |
| 停止派发 | `markRunning` 改为条件更新（仅 `PENDING/TIMEOUT` 可进入 `RUNNING`）；更新 0 行即返回 `CANCELLED` 且不执行命令，取消后队列中的目标不再派发 |
| 运行收口 | `finishRun` 改为按 `runbook_run_target` 聚合计数（不再依赖内存计数），全为 `CANCELLED` 时运行状态为 `CANCELLED` |
| 取消幂等 | 预览在 `execute` 中被原子认领，重复执行返回 `409 MULTI_EXEC_PREVIEW_ALREADY_EXECUTED`；计划阶段失败才恢复预览 |

### 3.3 接口与前端

- [MultiExecService.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/service/MultiExecService.java)：`execute` 返回 `runId`、`status`、`succeeded/failed/unknown/cancelled`、逐目标 `results`、`unknownTargets`、`notDispatchedTargets`；`cancel` 只按 Runbook 状态机返回 `cancelled=true/false`，未命中返回 `NOT_RUNNING`/`NOT_CANCELLABLE`，不猜测。
- [MultiExecController.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/controller/MultiExecController.java)：新增 `POST /api/operations/multi-exec/cancel`。
- [useConnectionsWorkspace.js](file:///d:/SmartOpsAgent/frontend/src/composables/useConnectionsWorkspace.js)：只有 `SUCCEEDED` 才算成功；失败提示汇总 failed/unknown/cancelled/notDispatched。
- [MultiExecDialog.vue](file:///d:/SmartOpsAgent/frontend/src/components/operations/MultiExecDialog.vue)：文案明确"审批后才会执行；逐目标返回 SUCCEEDED/FAILED/UNKNOWN/CANCELLED，已发送或未派发不会被当作成功"。

## 5. 未验证项与已知限制

1. **没有真实 SSH 主机**：单飞合并、配额、TTL 回收都只在本机内存/假 runtime 上验证；真实网络下的握手次数、断线重连、跳板机场景未实测。
2. **没有真实 100 MB 远端输出**：`BoundedOutput` 用 100 MB 合成数据验证"不保留全量字节"，但没有在真实 SSH 通道上观测内存与耗时。
3. **单飞仅进程内**：多副本部署时每个副本各建各的通道；跨副本合并需要外部协调，本批未做。
4. **配额与索引为进程内状态**：重启后清空；不使用数据库配额，避免给每次连接加持久化开销。
5. **H2 与 MySQL 差异**：集成测试期间发现 H2 2.2.224 在并发插入 `auto_increment` 列时会偶发重复主键（已用最小用例复现），这是测试数据库缺陷。测试通过"Flyway 独立连接 + 连接池串行化"规避，生产 MySQL 不受影响，但本机**未对 MySQL 做同等并发验证**。
6. **前端只做了构建**：新增的"取消"接口、截断徽标、成功判定文案没有在浏览器里做交互验证。
7. **取消只停止"未派发"**：已发出的远端命令不会因为本地取消而被终止；远端是否真的停止需要单独核验，本批不把取消成功写成远端已终止。
8. **性能数字未采集**：100 目标测试只断言正确性与并发上限，没有记录真实耗时/p95。

## 6. 回滚方式

- 本批无数据库迁移，回滚只需回退代码与配置。
- 代码回退后 multi-exec 恢复旧的"预览 + 发送"语义；前端需同批回退（新旧字段不兼容）。
- 遗留的内部 Runbook 行（`__multi_exec__*`）不影响使用：`enabled=0` 且在列表中不可见，可按需手工清理。
- 新增配置项均有默认值，不配置也能运行；如需关闭空闲回收，可调大 `smartops.operations.ssh.idle-ttl-ms`。
