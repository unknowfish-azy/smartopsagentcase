## 1. OPS-01 统一工具能力目录

### 改动
- `backend/src/main/java/com/smartops/service/OperationToolService.java`
  - 工具声明从"id + 只读 + 渲染器 + capability"扩展为完整能力目录：
    `version`、`implementationStatus(REAL/TEMPLATE/UNAVAILABLE)`、`targetType`、
    `inputSchema`、`outputSchema`、`risk`、`requiredScope`、`credentialRef`、
    `deadlineMs`、`outputLimitBytes`、`idempotency`、`verification`、`unavailableReason`。
  - 目录构造改为 `real(...)/template(...)/unavailable(...)/mutating(...)` 四类声明器，
    **同名 id 直接启动失败**（`TOOL_CATALOG_DUPLICATE_ID`），不再依赖 Map 覆盖静默吞掉。
  - 实现状态如实标注：
    - `TEMPLATE`：`knowledge-retrieval`、`database-readonly`、`grafana-dashboard`、`mysql-slow-query`
      （仓库内无对应 `smartops` CLI / 适配器，只是命令模板）；
    - `UNAVAILABLE`：`alerts-suppress`（告警平台静默写入未接入）；
    - 其余为 `REAL`。
  - 执行入口对非 `REAL` 工具直接返回 501 `TOOL_IMPLEMENTATION_UNAVAILABLE`，
    避免把"没有实现"伪装成"执行失败（退出码 127）"。
- `agent/sdk/tool.py`：`ToolDefinition` 增加同一组目录字段 + `ImplementationStatus`；
  `PluginTool` 暴露 `name / risk_level / requires_approval` 属性（此前策略引擎读取
  `tool.risk_level` 会 AttributeError，插件工具实际永远无法执行）。
- `agent/executor/executor.py`：统一调用契约
  - 插件工具：`async execute(arguments, context)`
  - 旧式内置工具：同步 `execute(**arguments)`
  - 非 `REAL` 工具在授权后、执行前拒绝。
- `frontend/src/views/operations/ToolsView.vue`：页面目录与后端目录对齐。
  后端不存在的工具标 `UI_ONLY` 并禁止执行；`TEMPLATE/UNAVAILABLE` 同样禁止；
  徽标显示 `IMPL REAL/TEMPLATE/UNAVAILABLE/UI_ONLY`。

### 对照差分
| 项 | 改前 | 改后 |
|---|---|---|
| 目录字段 | 5 个（id/只读/风险/需确认/capability） | 17 个，含实现状态、Schema、幂等、预算、核验 |
| 模板工具 | 与真实工具混在一起，执行得到 127 | 501 + 目录显式 TEMPLATE |
| 同名冲突 | `Map` 覆盖，一个静默消失 | 启动即抛出 `TOOL_CATALOG_DUPLICATE_ID` |
| Python 插件 | `execute(arguments, context)` 与 `execute(**kwargs)` 错配 | 统一分派，两种契约都可用 |
| 前端 | 页面目录可点、后端无入口 | 以后端目录为准，不可执行的直接拦截 |

## 2. OPS-04 执行恢复与资源治理

### 改动
- 迁移 `backend/src/main/resources/db/migration/V20261105.2__operation_run_governance.sql`
  新增 `idempotency_key / attempt / deadline_at / lease_expires_at / heartbeat_at /
  cancel_requested / output_bytes`，`(user_id, idempotency_key)` 唯一索引，
  `operation_run_output` 增 `truncated / output_bytes`。
- `OperationRunRecorder`：新增 `RunSpec` 与 `heartbeat / cancelRequested / recordEvidence`，
  全部为 `default` 方法，旧实现与测试替身不受影响。
- `JdbcOperationRunRecorder`
  - 幂等键重复 → 409 `OPERATION_RUN_ALREADY_EXECUTED`（并发同时唯一索引兜底）；
  - 心跳写入 `heartbeat_at + lease_expires_at`；
  - 输出超预算截断并写 `OUTPUT_TRUNCATED` 证据；
  - `UNCERTAIN` 状态自动写 `RUN_UNCERTAIN` 证据。
- `OperationToolService` 执行循环
  - 整单 `deadlineAt`（默认 120s），逐条命令取 `min(30s, 剩余预算)`；
  - 命令之间检查取消标记 → `CANCELLED`；预算耗尽 → `TIMEOUT`；
  - 写操作命令超时 → `UNCERTAIN`（远端是否生效未知，禁止直接重试）；
    ｜只读工具超时仍为 `FAILED`；
  - 每条命令后心跳；输出按工具声明预算截断。
- 新增 `OperationRunRecoveryScheduler`：每 60s 扫描 `RUNNING` 且心跳/租约超时的 Run，
  条件更新为 `UNCERTAIN` 并写 `RUN_STALE` 证据，**不自动重试**。
- `OperationRunQueryService.requestCancel` + `POST /api/operations/runs/{id}/cancel`：
  协作式取消，只在命令之间生效，不中断远端正在执行的命令。
- `TeamAgentRunController`：以 `team-run-{runId}` 作为幂等键，二次执行被拒绝。

### 对照差分
| 场景 | 改前 | 改后 |
|---|---|---|
| 重复执行同一审批单 | 可能重复产生副作用 | 409，唯一索引兜底 |
| 进程崩溃/悬挂 | 永远 RUNNING | 租约到期 → UNCERTAIN + 证据（不重试） |
| 远端动作后超时 | FAILED（诱导重试） | UNCERTAIN + 核验要求 |
| 单条命令输出 100MB | 全量落库 | 按预算截断 + 标记 |
| 取消 | 无入口 | 命令之间停止派发，状态 CANCELLED |
| 整单时长 | 无上界 | 绝对 deadline |

## 3. PERF-01 哨兵采集有界并发调度

### 改动
- 迁移 `V20261105.3__sentinel_scheduler.sql`：`claimed_by / lease_expires_at /
  next_run_at / consecutive_failures` + 到期索引。
- `SentinelService.pollDueTasks()`
  - 单条条件 UPDATE 认领（`claimed_by IS NULL OR lease_expires_at < NOW()`），
    多副本并发轮询不会重复采集同一任务；
  - 固定线程池 + 信号量做**有界并发**；额度耗尽即停止本轮认领（背压），
    未认领任务留到下一轮，不进入无界队列；
  - 单轮等待上限为一个租约，超时任务由租约回收给下一轮；
  - 成功写 `next_run_at = now + interval`（轻微抖动），失败写
    **指数退避 + 抖动**（`interval × 2^n`，上限 `max-backoff-sec`，默认 3600s）；
  - `consecutive_failures` 成功后归零；
  - `schedulerStats()` 暴露本轮 due/claimed/背压推迟/耗时/等待耗时。
- 配置：`smartops.sentinel.poll.{max-concurrency,batch-size,lease-ms,max-backoff-sec}`。
- `SentinelPoller` 不变（仍按固定间隔调用）。

### 对照差分
| 项 | 改前 | 改后 |
|---|---|---|
| 执行方式 | 串行 for，50 个慢目标 ≈ 750s | 有界并发（默认 8），慢目标只占有限槽位 |
| 多副本 | 同一批任务会被两台机器同时采集 | 条件 UPDATE 认领 + 租约，只允许一个 |
| 失败任务 | 只累加计数，下一轮立刻重采 | 明确的 `next_run_at`（退避+抖动） |
| 队列 | 无（同步阻塞） | 信号量背压，超额任务留给下一轮 |
| 可观测 | 无 | `schedulerStats()` 日志与接口 |

- 镜像与发布

  - 新增 `ai-service/Dockerfile`（Python 3.12 + uvicorn + HEALTHCHECK）；

  - startup/readiness/liveness 三探针分离；
  - `terminationGracePeriodSeconds: 40` + `preStop sleep 5` 摘流。
