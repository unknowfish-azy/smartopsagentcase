## 3. 分批实施路线

每批开始保存精确前像与必要快照；一批只改变一个主要边界。新增依赖先锁版本、验证退出路径，再进入默认启动。

| 顺序 | 当前问题与实施范围 | 验收证据 | 回滚与前置条件 |
|---|---|---|---|
| A：演示门禁 | 本批执行审批绑定、一次消费与工具真实失败传递；清理已退役组件的遗留测试；默认 Knowledge 就绪切换 | 审批 36 项通过、相关 Python 198 项通过、前端 470 项通过；默认 8002 READY 且 RAG 3 条命中 | 已交付本批哈希保护文件回滚；Knowledge 进程变更单独记录，文件回滚不自动切换进程 |
| B：鉴权测试契约 | 整理 16 项匿名 API/CSRF 失败；建立隔离登录 fixture、鉴权失败与业务成功双断言，统一 8000/8001 测试地址 | 授权路径测试通过，匿名仍 401/403；独立测试库清理完成；缺环境时显式说明 | 先明确测试环境与账号来源；不对现有真实数据库写入测试服务器，不降低生产鉴权 |
| C：真实浏览器演示 | 使用现有 Playwright 覆盖登录→问答→引用、模型选择/history、流中断与故障恢复；核对在线 AI 进程版本 | trace/截图与断言支持每一步；真实 provider 和降级状态可追溯；完整启动记录 | 新建隔离数据与运行目录；重启服务前保存旧命令和配置；当前 8001 未重启，不宣称加载本轮源码 |
| D：观测与质量基线 | 统一 request/task/run ID、跨服务错误；独立人工检索与假成功样本；仅脱敏元数据进入观测 | 能从一次真实失败追到执行/RAG/provider；固定版本和样本再对照，报告未评分项 | 先以现有日志验证；再做 OTel 小试验；默认不采集凭据与私有原文 |
| E：持久化与数据入口 | 核验向量索引重启恢复、版本/租户过滤、删除；检查采集 URL 重定向/DNS/私网边界与输入体积 | 重启不丢已摄入语料、跨租户零命中、删除一致；网络边界故障注入与限额测试 | 先设计迁移/备份与可导出格式；Qdrant 通过同工作负载比较后才替换适配层 |
| F：长期任务与交付 | 需跨重启长任务时评估 checkpoint/interrupt/resume；迁移、CI、依赖锁定与一键运行文档 | 断点恢复、重复回调幂等、重启后过期授权拒绝；新环境安装/迁移/回滚演练 | LangGraph/自动化平台各做独立 PoC；避免重复审批源和同时替换 Java、Agent、RAG |

当前本批只完成 A 及上述只读调研。B—F 是后续待执行任务；数据库迁移、SSRF 修复、OTel 接入、浏览器 E2E、新向量库、持久审批均未在本批实施。下一批先处理 B，再以 C 的浏览器证据检验演示完整性。

## 4. 后续版本选择方法

为每项拟引入组件单独记录选定 release/tag 对应的 commit、完整依赖树与 LICENSE/NOTICE，复核 Windows/Java17/Python/Node 兼容性及离线部署需求；用相同语料/任务比较当前实现的正确性、延迟、内存与恢复成本。只有收益可测且退出步骤通过，才更新默认依赖和部署方式。本次未用浮动分支直接安装任何项目。
