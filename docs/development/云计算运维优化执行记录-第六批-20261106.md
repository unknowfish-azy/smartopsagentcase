## 2. 关键实现与验收口径

### 2.1 OPS-10 SLI/SLO（[SloService.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/observability/SloService.java)）

`GET /api/observability/slo?windowHours=24`（1..168 小时，越界 400），逐项返回下述三个 SLI。

| SLI | 分子 | 分母 | 目标 | 最小样本 |
| --- | --- | --- | --- | --- |
| `execution_success` | `operation_run_record.status='SUCCEEDED'` | 窗口内 `ended_at` 非空的运行 | 0.99 | 20 |
| `collection_freshness` | `last_seen_at` 在 `max(2×interval_sec, 60s)` 内的启用任务 | 启用 `sentinel_task` 总数 | 0.95 | 5 |
| `recovery_verification` | `verdict=VERIFIED && receipt_state=ACTIVE && valid_until` 未过期 | 窗口内回执数 | 0.95 | 5 |

- 状态机：`NO_DATA`（分母 0）→ `INSUFFICIENT`（样本 < minSamples，标 DEGRADED）→ `EXHAUSTED`（实际错误率超预算）→ `WARNING`（剩余 ≤ 预算 20%）→ `OK`。
- `burnRate = 实际错误率 / 预算`，`budgetRemainingRatio = 剩余 / 预算`；不把样本不足写成达标。
- 数据质量由部署侧声明：`REAL`（生产真实）、`MOCK`、`FIXTURE`（测试夹具），未知值统一 `UNKNOWN`，不会默认为真实。

### 2.2 OPS-10 HTTP 层指标与告警（[slo.yml](file:///d:/SmartOpsAgent/infrastructure/prometheus/rules/slo.yml)）

- 记录规则基于 Micrometer 标准指标 `http_server_requests_seconds_*`：总请求速率、可用率（非 5xx 占比，目标 99.5%）、错误率、P95 延迟（目标 1s）、1h/6h 错误预算燃烧率（允许错误率 0.005）。
- 告警：`SmartOpsHttpFastBurn`（1h >14.4x，2m）、`SmartOpsHttpSlowBurn`（6h >6x，30m）、`SmartOpsHttpAvailabilityLow`（<0.995，5m）、`SmartOpsHttpLatencyHigh`（P95 >1s，10m）。
- Prometheus 只算 HTTP 层；执行成功率、采集新鲜度、恢复核验率由业务事实表计算，避免同一口径两套数。

### 2.3 OPS-10 恢复判定

`GET /api/observability/recovery/{contractRecordId}`（`X-User-Id` 归属校验，非本人与不存在均 404）：

判定顺序 `verdict` → `receipt_state` → `valid_until`：

| 条件 | 结论 |
| --- | --- |
| 无回执 | `UNKNOWN` / `NO_RECEIPT`（"告警关闭不等于业务已恢复"） |
| `verdict != VERIFIED` | `NOT_RECOVERED` / `VERDICT_*` |
| `receipt_state != ACTIVE` | `INVALIDATED` / `RECEIPT_*` |
| 缺 `valid_until` | `NOT_RECOVERED` |
| 已过期 | `STALE` |
| 其余 | `RECOVERED` |

证据同时返回 `observationCount`、`latestObservedAt`、运行链路 `traceId`，判定依据可复核。

### 2.4 OPS-11 下发证据（[RunbookExecutionService.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/runbook/RunbookExecutionService.java)）

- 迁移 `V20261106.12__runbook_target_evidence.sql` 为 `runbook_run_target` 增加 `dispatch_status`、`dispatched_at`、`executed_at`、`verified_at`（全部可空，历史数据不回填）。
- 首次进入 `Phase.EXECUTE` 时置 `dispatched=true` 并记录 `dispatchedAt`；`dispatch_status` 写 `SENT` / `NOT_DISPATCHED`。
- `executed_at` 仅在命令真实执行后写入；`verified_at` 仅在 post-check 为 `SUCCEEDED` 时写入。**`SENT` 只表示命令已下发，不等于执行成功，更不等于验证通过。**
- 未下发路径（注册表缺失、runtime 关闭、记录冲突）统一 `NOT_DISPATCHED`；异常路径时间留空表示"未知"，不猜测。
- 目标集来自审批时冻结的快照（`target_id` 列表 + 内容哈希），执行期与刷新/重启后均读取同一份快照，结果一致。
- 复用既有 Run/审批/审计体系与 OPS-04 Runbook 实现，未新建平行执行链；`PERF-04` 的批量作业复用本实现。
