## 二、连接期 IP pin（SEC-06 残余收口：DNS rebinding 防护）

**问题**：`OutboundUrlPolicy` 校验时解析 DNS 拿到公网地址，但 JDK
`java.net.http.HttpClient`（JDK 17）建连时会**再次自行解析**——攻击者控制 DNS
可在"校验通过"与"建连"之间切换应答（rebinding），让真实连接落进内网。

**方案**：`java.net.http` 在 JDK 17 上没有解析钩子，爬取 HTTP 层改用
Apache HttpClient 5（`org.apache.httpcomponents.client5:httpclient5:5.3.1`）：

- 新增 `com.smartops.security.PinnedDns`：进程内 pin 登记（host → 已校验地址集），
  **fail-closed**——未登记的主机在该 resolver 上直接 `UnknownHostException`，
  保证挂载它的客户端不可能连接任何未经校验的地址。
- `KnowledgeCrawlService`：连接管理器 `DnsResolver` 委托 `PinnedDns`；
  `fetch()` 每跳先 `OutboundUrlPolicy.inspect`（校验+解析）→ `PinnedDns.pin`
  → 建连（resolver 只回已校验地址）→ 响应后 `clear`。并发下 pin 按主机覆盖
  （后写赢），所有 pin 均来自校验通过的公网地址集，不构成绕过。
- 语义保持：手动逐跳重定向（`disableRedirectHandling`）、每跳重新校验、
  10MB 下载上限、8s 连接/响应超时、禁自动重试；不再依赖 JDK 客户端的
  `ProxySelector.of(null)`（HC5 默认不读系统代理）。

**验证**：`PinnedDnsTest` 5 项（精确返回 pin 地址 / 未登记 fail-closed /
大小写与尾点归一 / clear 生效 / 空 pin 忽略）；
`KnowledgeCrawlServiceTest` 5 项回归通过。

**边界（如实）**：未做真实 DNS rebinding 注入实验（需可控 DNS 服务器）；
爬取功能默认关闭（`KNOWLEDGE_CRAWL_ENABLED=false`），暴露面本身受限。
