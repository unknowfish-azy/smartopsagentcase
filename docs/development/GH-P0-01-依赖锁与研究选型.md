## 4. CANDIDATE_ONLY — 候选框架（3 项，零 import）

### 4.1 LangGraph（Agent Orchestration）

| 项 | 值 |
|---|---|
| 分类 | agent_orchestration |
| 为什么考虑 | LangGraph 的显式 StateGraph 对应当前手写的 Inspector 三态 + RecoveryContract 多步 plan。LangGraph 的节点/边/条件分支模式可以替代手写的"while + 状态分支"代码 |
| 为什么还没 | 当前代码零 import；RecoveryContract（VER-P0-01 已在写）已能表达多步状态 + 证据义务 + 时效截止，**无状态图管理开销**。引入 LangGraph 会增加依赖（langgraph + langchain-core 全套）且增加可观测性难度（需要 OTel 嵌套 span） |
| 当前状态 | **零 import / 零 requirements 声明** ✅ 符合任务书"先参考机制" |

**升级为 VERIFIED 的 PoC 条件**（三条同时满足）：

1. PoC：用 LangGraph 重写单一故障族（nginx 502）的三态状态机，与现有手写版本对比 — 路径数 ≤ 当前、状态显式性 ≥ 当前、OTel 接入准备不降级
2. PoC：状态图表达能覆盖 ≥3 故障族，不出现"图结构比代码更绕"的情况
3. PoC 完成后，**才能** `pip install langgraph` 加入 requirements.txt，作为 CANDIDATE 依赖（不替代现有 Inspector，允许并存）

### 4.2 Qdrant（向量存储）

| 项 | 值 |
|---|---|
| 分类 | vector_store |
| 为什么考虑 | Qdrant HNSW ANN 对应当前 HashEmbedding（256-dim bigram hash）+ SQLite 向量存储的精确匹配召回率提升。Qdrant 支持 distance / payload filtering / hybrid 融合 |
| 为什么还没 | 当前 retrieval 栈：BM25 精确（rank-bm25）+ hash embedding cosine + hybrid 0.6/0.4 融合。HashEmbedding 是词袋哈希（无语义），但 sentence-transformers>=3.0,<6 **已声明但未安装** — BGE 是**第一优先级替换**目标（语义 embedding 先于 ANN 存储） |
| 当前状态 | **零 import / 零 requirements 声明** ✅ |

**升级为 VERIFIED 的 PoC 条件**（先 BGE，后 Qdrant）：

1. PoC 先跑 BGE 替换 HashEmbedding：同 corpus（移除 RH 后 16 docs / 299 chunks）Recall@5 提升 ≥15%，且不引入 torch 依赖冲突（ONNX backend 优先）
2. PoC 对比 Qdrant ANN vs SQLite 精确匹配：Qdrant ANN 在 1k+ chunks 场景下查询 P95 ≤ 精确匹配的 1.5x，且 Recall@5 下降 ≤5%（可接受近似）
3. PoC 完成后，Qdrant 作为**可选存储后端**引入（不替换 BM25，hash embedding 作为 fallback）

### 4.3 OpenTelemetry（可观测性）

| 项 | 值 |
|---|---|
| 分类 | observability |
| 为什么考虑 | OTel trace/span 模型对应当前 correlation header（X-Request-ID / X-Task-ID / X-Run-ID）跨层传播。OTel 可自动埋点（FastAPI / httpx / aiopg instrumentation），手动埋点量减少 |
| 为什么还没 | 1. 当前 correlation 契约已实现（E2E-OBS-P0-01 验证过 run_id 全链路 5 处对齐），手工埋点足够；2. OTel 引入需要跨进程 collector + 后端（Jaeger/Zipkin）配套，基础设施重 |
| 当前状态 | **零 import / 零 requirements 声明** ✅ |

**升级为 VERIFIED 的 PoC 条件**（三条同时满足）：

1. PoC：OTel FastAPI instrumentation 能**不手工修改现有代码**就产出和 correlation header 对齐的 trace_id — trace_id 和 run_id 能稳定映射（OTel context propagation 走 HTTP header）
2. PoC：OTel httpx instrumentation 在 AI→Knowledge 调用链上产出嵌套 span，且**不覆盖**（enrichment，不是 replacement）现有 correlation headers
3. PoC 完成后，OTel 作为**可选观测后端**引入（不替代 correlation；OTel span 是 enrichment）
