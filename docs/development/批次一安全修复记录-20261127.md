# 批次一安全修复记录（2026-11-27）

本批次覆盖 6 项安全问题：bootstrap 默认口令（P0）、巡检台 v-html XSS（P0）、SSH 目标白名单与
identityPath 收口（P1）、dev/h2 默认可用内部凭据（P1）、Prometheus 指标端点鉴权（P2）、
模型网关 key 限流与审计（P2）。

## #1 bootstrap 默认管理员口令（P0）

**问题**：首启引导建号使用内建示例口令 `Admin@2026 Secure!`，且应用启动断言不校验该值；
部署方容易漏配后直接使用弱默认口令。

**修复方案**
- `security/SecurityAssertions.java`：`verifyDeploymentSecrets` 增加第 5 个参数
  `bootstrapPassword`，校验空值 / trim 后 <16 字符 / 命中已知默认值，错误文案指向
  `SMARTOPS_BOOTSTRAP_PASSWORD`。
- `config/SecurityAssertionConfig.java`：注入 `${smartops.bootstrap.password:}` 并传入断言。
- `config/UserAccountConfig.java`、`resources/application.yml`：移除内建默认值；留空则
  不创建首个管理员（fail-closed），不再“静默用默认口令”。
- `security/UserAccountService.java`：首启建号固定 `mustChangePassword=true`（沿用既有改密链路）。
- `deploy/docker/docker-compose.yml`：backend 增加
  `SMARTOPS_BOOTSTRAP_PASSWORD: "${SMARTOPS_BOOTSTRAP_PASSWORD:?...}"` 必填。
- `.env.example`：注明生产必填与留空语义。

**验证方式**
- `SecurityAssertionsTest`：全部改为 5 参调用；新增“缺 bootstrap 拒绝 / 已知默认拒绝 /
  长度不足拒绝”用例；生产强口令与非生产放行用例保持通过。
- 后端全量 `mvn test` 通过。

**影响范围**
- 全新部署必须注入 `SMARTOPS_BOOTSTRAP_PASSWORD`，否则不会自动创建 admin；已有账户的实例不受影响。
- 首次登录强制改密的既有行为不变。

## #3 SSH 目标白名单与 identityPath 收口（P1）

**问题**：会话创建/连接对 `host`、`port` 不做白名单校验，`identityPath` 可指向主机任意文件，
连接中心可被当作任意目标的跳板。

**修复方案**
- 新增 `operations/SshTargetPolicy.java`：
  - `requireAllowedTarget(host, port)`：按 `SMARTOPS_SSH_ALLOWED_TARGETS`
    （逗号分隔：主机名、IPv4/IPv6、CIDR、`host:port`）匹配；构造期校验配置语法，写错即启动失败。
  - `requireAllowedIdentity(identityPath)`：私钥路径必须位于 `SMARTOPS_SSH_IDENTITY_ROOT`
    之内且为可读普通文件，拒绝目录穿越。
  - 生产环境未配置白名单/私钥目录时一律拒绝（403 `TARGET_NOT_ALLOWED` /
    `IDENTITY_PATH_NOT_ALLOWED`）；非生产未配置时放行并打 WARN。
- `service/OperationSessionService.java`：创建期做协议/host/port/username 边界校验并调用策略；
- `service/OperationConnectionService.java`：连接期二次校验（防止库中被直接改写或策略生效前的存量会话）。
- 配置：`application.yml` 的 `smartops.operations.ssh.allowed-targets` / `identity-root`，
  环境变量 `SMARTOPS_SSH_ALLOWED_TARGETS` / `SMARTOPS_SSH_IDENTITY_ROOT`。

**验证方式**
- `operations/SshTargetPolicyTest`：6 个用例（生产空名单拒绝、非生产空名单放行、精确 host:port、
  CIDR 命中/不命中、私钥越界拒绝、非法配置快速失败）。
- 后端全量 `mvn test` 通过。

**影响范围**
- 生产升级后若未配置白名单与私钥目录：所有 SSH/SFTP 会话创建与连接返回 403，属预期收紧；
  配置后仅名单内目标可用。此前已验收的 CentOS 连接（密码认证）不受影响。
- 非生产环境未配置时行为不变。

## #10 dev/h2 默认可用内部凭据（P1）

**问题**：`application-dev.yml` 内建 AES 密钥、`application-h2.yml` 内建 AES 密钥与内部 token，
这些已知默认值一旦随包进入生产（误用 profile）即可直接解密/鉴权。

**修复方案**
- `resources/application-dev.yml`：`api-key-encryption-key` 改为
  `${SMARTOPS_API_KEY_ENCRYPTION_KEY:}`，无内建值。
- `resources/application-h2.yml`：`api-key-encryption-key`、`internal-token` 同样去默认。
- 测试 profile（`application-test.yml`）自持密钥，CI/本地 `mvn test` 不受影响。

**验证方式**
- 后端全量 `mvn test` 通过（含 H2/测试 profile 的集成测试）。
- 无 `.env` 直跑 dev/h2 会在加密服务/启动断言处以明确错误失败，而非使用弱默认值。

**影响范围**
- 本地开发需通过安装脚本生成的 `.env` 注入这两个变量；容器 compose 早已必填。
- 生产无变化（本就由环境变量注入）。

## #27 Prometheus 指标端点鉴权（P2）

**问题**：`/actuator/prometheus` 匿名可读，暴露 JVM/请求量等运行指标。

**修复方案**
- `config/SecurityConfig.java`：将 `/actuator/prometheus` 移出 `permitAll` 白名单，纳入
  `INTERNAL`（要求 Bearer `SMARTOPS_INTERNAL_TOKEN`）；health/liveness/readiness 仍匿名且仅 GET。
- `infrastructure/prometheus/prometheus.yml`：抓取配置增加
  `authorization.type=Bearer` + `credentials_file: /etc/prometheus/secrets/smartops_internal_token`。

**验证方式**
- 代码审查 + 后端全量 `mvn test` 通过；上线后需实测：带 token 抓取成功、匿名抓取 401/403。

**影响范围**
- 所有匿名抓取立即失效；Prometheus 侧需挂载凭据文件（内容 = 后端 `SMARTOPS_INTERNAL_TOKEN`），
  否则监控断数。K8s/面板直连同理需要携带令牌。

## #28 模型网关 key 限流与审计（P2）

**问题**：网关只有 24h 配额（且此前拒绝不留痕），没有分钟级速率上限；突发调用可在额度耗尽前
打满上游，且配额超限无任何审计痕迹。

**修复方案**
- `service/ModelGatewayService.java`：
  - 每把 key 增加近 60 秒调用上限，默认 60 rpm，配置 `SMARTOPS_GATEWAY_RATE_LIMIT_RPM`
    （0=关闭，不推荐）；超限抛 429 `Gateway rate limit exceeded`。
  - 配额/限流拒绝统一经 `reject(...)` 写入 `model_gateway_invocation`，状态
    `REJECTED_QUOTA` / `REJECTED_RATE_LIMITED`，保证拒绝也有审计痕迹。
  - 用量统计口径：缓存命中与拒绝类不计入请求/token 消耗（`CONSUMED_STATUS_FILTER`）。
- 迁移 `V20261127.2__model_gateway_rate_limit.sql`：补 `(key_id, created_at)` 复合索引。
- 配置：`application.yml` `smartops.gateway.rate-limit-rpm`，`.env.example` 增示例。

**验证方式**
- `ModelGatewayServiceTest`：新增“限流拒绝并写审计”“配额拒绝并写审计”用例；既有回退/审计/组
  配额用例更新桩数据后通过。
- 后端全量 `mvn test` 通过。

**影响范围**
- 高频调用（含被拒重试）超过阈值会被 429 限流，属预期保护；上游费用受控。
- 分析页的 24h 汇总不再把拒绝请求计入调用量（口径更准确）；DB 多一条 Flyway 迁移与索引。
