# 智维Agent 项目创新点设计

> 项目名称：**智维Agent —— 面向中小企业的可信 AI 智能运维与知识协同平台**
> 文档版本：v1.0（2026-10-24）

## 1. 创新总体思路

本项目的创新不是"给运维系统加一个大模型入口"，而是重新设计了 AI 在运维场景中的**权责边界**：

```text
知识获取 → 知识检索 → 证据验证 → AI 分析 → Agent 规划
   → 风险控制 → 安全执行 → 结果验证 → 审计留痕 → 经验沉淀
```

三个设计原则贯穿全链路：

1. **证据先行**：没有证据支撑的结论不得表述为确定事实。
2. **风险分级**：AI 可以规划，但不能自行决定执行高危动作。
3. **全程留痕**：每一次判断与动作都可回溯、可复盘。

## 2. 与现有方案的对比

| 维度 | 通用问答机器人 | 传统 AIOps 平台 | 通用 Agent 工具 | 智维Agent |
| --- | --- | --- | --- | --- |
| 回答依据 | 模型参数记忆 | 规则/阈值告警 | 工具返回，缺少证据链 | 混合检索 + 证据验证 + 版本过滤 |
| 可信度表达 | 无 | 告警等级 | 无 | 引用 + `trust_score` 可信度评分 |
| 知识版本 | 不区分 | 弱 | 不区分 | 版本感知检索（`version_filter`） |
| 执行权限 | 不执行 | 部分自动化，缺少审批 | 默认权限过大 | 策略引擎 + 人工审批 + 沙箱 |
| 过程透明性 | 黑盒 | 有日志无推理 | 有轨迹无用户视图 | SSE 分阶段思考可视化 |
| 审计与沉淀 | 无 | 有日志 | 有限 | 审计留痕 + 经验回流长期记忆 |
| 多模态隐私 | 直接上传 | 不涉及 | 直接上传 | 分层边界（音频不上传 / 图像仅文件名 / 附件隔离） |

## 3. 核心创新点

### 创新点一：可解释的"可信 AI 闭环"

**做法**：把运维任务拆成"规划—审批—执行—核查—沉淀"五个可审计阶段，由 Agent 五模块分别承担。

- `planner` 生成带依赖关系的步骤计划（`agent/planner/steps.py`）。
- `policies` 依据权限与风险注册表给每个动作打风险等级（`agent/policies/policy_engine.py`）。
- 高风险动作进入 `safety/approval.py` 的人工审批队列，未获批不执行。
- `executor` 在沙箱与权限约束下执行，产出结构化结果与审计记录（`agent/executor/audit.py`）。
- `inspector` 用规则判定 + 证据判定 + AI 判定四级证据核查（规则→证据→AI→状态核验）验证结果（`agent/inspector/judges/`）。
- 处置结论写回 `operator_memory`，形成"越用越懂你"的长期经验。

**为什么是创新**：多数作品把"AI + 运维"停留在对话层，本项目把**权限、风险、审批、核查、审计**做成了可运行的代码路径，而不是文档里的理念。

**可演示证据**：管理端可见审批记录与审计事件；执行动作带风险等级与审批人。

### 创新点二：版本感知的混合检索 + 证据可信度评分

**做法**：

- 召回层：BM25 关键词召回与向量召回并行（`knowledge/retrieval/hybrid.py`），避免单一路径漏召回。
- 过滤层：`version_filter` 按目标环境版本过滤候选，解决"知识正确但版本不对"的行业通病。
- 收敛层：词法重排器对候选重新排序（`knowledge/reranker/lexical_reranker.py`）。
- 表达层：检索结果转为 Citation（来源 / chunk / 版本 / 分数），聚合为 `trust_score`（`knowledge/evidence/`）。
- 评测层：`knowledge/evaluation` 内置指标与样例数据集，支持回归评估。

**为什么是创新**：中小企业最常见的故障不是"查不到"，而是"查到的是旧版本"。把版本作为检索的一等公民，是本项目与通用 RAG 的实质差异。

### 创新点三：把"黑盒回答"变成"透明推理"的交互设计

**做法**：

- `ai-service` 的 `chat_stream` 以 SSE 输出三类事件：`thinking`（思考阶段）、`token`（流式正文）、`done`（引用与可信度）。
- 思考阶段固定为六步：`vision`（图像证据解析）→ `retrieve`（知识检索）→ `evidence`（证据验证）→ `plan`（Agent 规划）→ `risk`（风险判定）→ `answer`（生成回答）。
- 前端 `src/api/stream.ts` 逐事件渲染：左侧思考步骤逐条点亮，右侧正文带流式光标；结束后展示引用来源与可信度。

**为什么是创新**：用户能"看见"AI 在哪一步检索了什么、命中了多少条证据、判定为什么种风险。这直接提升运维人员对 AI 的信任度，也是与传统聊天 UI 的核心体验差异。

### 创新点四：多模态输入的隐私边界分层

| 输入类型 | 处理方式 | 数据是否出端 |
| --- | --- | --- |
| 语音 | Web Speech API 在浏览器内识别为文本，仅填入输入框（`domain/chat/speechInput.ts`）；不支持时入口自动隐藏 | 音频不出端 |
| 图像证据 | 本地暂存，随消息仅传**文件名列表**给 ai-service，触发"图像证据解析"阶段 | 图片内容不出端 |
| 文本/日志附件 | 走私有附件会话（`chat_conversation` / `chat_attachment`），仅保存证据，不参与模型分析 | 由用户显式上传，与模型分析隔离 |

**为什么是创新**：行业常见做法是"多模态 = 全部上传"。本项目把"能用"和"该传"分开：演示多模态交互的同时，明确划出隐私红线，并用 UI 文案提示用户遮盖密码与密钥。

### 创新点五：插件化 Agent 工具生态

**做法**：

- 工具与插件通过 `AgentPlugin` 契约注册（`agent/sdk/plugin.py`），运行时由 kernel 完成注册、依赖解析、生命周期管理与事件分发。
- 已内置 Docker、Kubernetes、MySQL、Nginx、Redis 五类运维插件，提供只读诊断与受控重启等工具。
- 会话存储支持 Redis / MySQL / PostgreSQL / SQLite / 文件五种后端（`agent/plugins/session/`）。
- 通过 MCP 适配器（`agent/tools/adapters/mcp.py`）可接入外部工具生态。

**为什么是创新**：把"运维能力"从硬编码变成可插拔资产，新环境只需增加插件，不改主流程。

### 创新点六：可切换模型网关 + 零密钥可演示

- 默认 `mock` 提供方，无任何密钥即可完整演示全链路。
- 支持 Ollama 本地模型与 OpenAI 兼容接口，运行期切换（`ai-service/app/services/model_gateway.py`）。
- 后端维护模型连接、路由、密钥（AES-GCM 加密存储）、Token 预算与用量统计。

**为什么是创新**：评委与用户无需配置密钥即可复现；企业落地时又能无缝切到自有模型，兼顾"可演示"与"可生产"。

### 创新点七：前端工程化创新（双入口同源架构）

- 用户层（:5173）与管理层（:5174）共用一个代理工厂 `vite.shared.mjs`，避免两端口各写一份代理导致会话与 CSRF 分裂。
- 共享逻辑层 TypeScript（48 个模块）承载 `api / domain / utils / types`，`tsc --noEmit` 纳入门禁。
- 分包策略统一：`vendor-echarts` 510 kB → 346 kB（zrender 独立拆分），Three.js 保持懒加载。
- 563 项前端测试覆盖契约、安全不变量与领域逻辑。

**为什么是创新**：双入口是很多团队工程化的第一道裂缝。本项目用共享工厂 + 契约测试把"两个入口必须同源"变成可执行的不变量。

## 6. 边界与后续演进（诚实声明）

- 图像当前为**文件名级**参与演示链路，尚未做图像内容级理解；路线图为接入 OCR（`knowledge/ocr/`）与多模态大模型，并在用户授权后上传。
- 语音仅做浏览器内识别，不涉及声纹与音频留存。
- 混合检索的向量嵌入默认使用轻量哈希嵌入（`hash_embedding.py`），可切换 Sentence Transformers（`sentence_transformer.py`）。
- 后续演进：端侧推理（Transformers.js / WebGPU）、多节点会话、MFA 强化、团队协同深化。
