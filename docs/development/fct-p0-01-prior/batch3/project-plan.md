### 一句话定位

智维Agent 把大模型能力约束在"证据驱动、风险可控、全程留痕"的闭环里，让 AI 从"会回答运维问题"走向"可信地完成运维任务"。

## 2. 背景与问题

中小企业的 IT 运维普遍具备三个特征：**人手少、系统杂、知识散**。具体表现为：

| 现实痛点 | 现有方案的不足 |
| --- | --- |
| 运维知识散落在聊天记录、老员工经验、历史工单中 | 传统搜索引擎按关键词命中，返回的常是过期版本 |
| 故障定位依赖个人经验，新人上手周期长 | 通用问答机器人给不出可核对的证据链 |
| 大模型能"说"但不能"做"，或做了没人敢用 | 缺少风险分级、人工审批与审计留痕 |
| 一次误操作可能造成生产事故 | 通用 Agent 工具默认拥有过大的执行权限 |
| 故障处理过程无法复盘 | 操作缺少结构化记录，经验无法沉淀 |

因此，企业真正需要的不是"更会聊天的机器人"，而是**一个敢把生产环境交给它的 AI 同事**：结论要有证据、动作要有边界、过程要有留痕。

## 3. 目标用户与核心场景

**目标用户**：10–200 人规模企业的运维负责人、驻场运维工程师、技术负责人；以及高校实验室、实训机房等具备同类运维诉求的场景。

**核心场景**：

1. **故障问答与定位**：工程师用自然语言（可附截屏/拍照）描述故障，系统检索版本正确的知识并给出带证据的处置建议。
2. **证据驱动的知识检索**：同一主题存在多个版本时，按目标环境版本过滤，回答附来源与可信度评分。
3. **受控执行**：Agent 生成处置计划，策略引擎判定风险等级，高风险动作转人工审批后才执行。
4. **结果核查与经验沉淀**：执行后由 inspector 核查结果并写入审计，处置经验回流知识库。
5. **团队协同**：共享会话、团队工作区、资源授权与通知，支撑多人协作。

## 4. 项目目标

### 4.1 功能目标

- 完成"监测 → 分析 → 知识检索 → 证据验证 → 决策规划 → 风险判断 → 人工审批 → 安全执行 → 结果验证 → 审计留痕 → 经验沉淀"的可信闭环。
- 提供对话式统一入口，支持流式输出与 AI 思考过程可视化。
- 支持多模态输入：语音描述、截屏/拍照/图片证据。
- 提供用户层与管理层双入口，覆盖账户、权限、审计、系统治理。

数据流（一次对话）：

```text
用户提问（文本 / 语音 / 图像文件名）
  → 前端 SSE 客户端（解析 thinking / token / done）
  → ai-service：RAG 检索 → 证据验证 → Prompt 组装（系统提示 + 知识证据 + 图像证据段）
  → LLM 网关（mock / Ollama / OpenAI 兼容）
  → SSE 回流：thinking（vision→retrieve→evidence→plan→risk→answer）→ token → done（引用 + trust_score）
  → 高风险动作：策略引擎 → 人工审批 → 受控执行 → 结果核查 → 审计留痕
```

## 7. 关键技术路线

### 7.1 Agent 能力分层

- **planner**：把故障描述拆解成有依赖关系的步骤（`steps.py`）。
- **executor**：按步骤调用工具，产出结构化结果与审计记录。
- **inspector**：规则判定 + 证据判定 + AI 判定四级证据核查（规则→证据→AI→状态核验），输出验证结论。
- **memory**：短期上下文与长期经验（`operator_memory`）双层记忆。
- **policies**：风险等级与权限策略，高危动作默认拒绝或转审批。
- **kernel**：插件注册、依赖解析、事件总线、生命周期与运行时加载。

### 7.2 检索与证据

- 混合检索：BM25 关键词召回 + 向量召回（`retrieval/hybrid.py`），合并后由词法重排（`reranker`）收敛。
- 版本感知：`version_filter` 按目标环境版本过滤，避免错误版本知识污染。
- 证据链：检索结果生成 Citation（来源 / chunk / 版本 / 分数），并聚合为 `trust_score`。
- 评测：`knowledge/evaluation` 提供指标与样例数据集，便于回归。

### 7.3 可切换模型网关

- 默认 `mock` 提供方，无需任何密钥即可完整演示。
- 支持 Ollama 本地模型与 OpenAI 兼容接口，运行期切换。
- 后端维护模型连接、路由、密钥（AES-GCM 加密存储）、Token 预算与用量统计。

### 7.4 多模态与隐私边界

| 输入 | 处理方式 | 隐私边界 |
| --- | --- | --- |
| 语音 | Web Speech API 识别为文本填入输入框 | 不上传音频；不支持时入口自动隐藏 |
| 图像证据 | 本地暂存，随消息仅传**文件名**参与演示链路 | 图片内容不出浏览器 |
| 文本/日志附件 | 私有附件会话存储（`chat_attachment`） | 仅保存证据，不参与模型分析 |

### 7.5 前端工程化

- 共享逻辑层 TypeScript（48 个模块），`tsc --noEmit` 作为门禁。
- 双入口（用户层 / 管理员层）共用 `vite.shared.mjs` 的代理与分包配置，避免配置分裂。
- 构建分包：`vendor-echarts` 从 510 kB 降至 346 kB（zrender 独立拆分），Three.js 保持懒加载。

## 8. 安全与合规

| 层 | 措施 |
| --- | --- |
| 账户 | BCrypt(12) 哈希；密码强度分级（用户 ≥12、管理员 ≥16 字符）；登录失败窗口限流 |
| 会话 | 会话固定攻击防护（登录后 changeSessionId）、管理员 10 分钟 / 用户 30 分钟超时、会话吊销 |
| 请求 | CSRF Token；写操作校验；附件下载强制 `X-Content-Type-Options: nosniff` 与 CSP sandbox |
| 人机校验 | 离线图形点选（不访问外网、不加载第三方脚本），可切换 Turnstile |
| 管理端 | 管理员 MFA + 恢复码；敏感操作需二次密码确认 |
| 审计 | 登录、注册、审批、执行等关键事件结构化留痕 |
| 密钥 | 模型密钥 AES-GCM 加密存储；`.env` 不入库；仓库内无明文密钥 |
| 执行 | 风险策略引擎分级，高危动作人工审批；沙箱与权限注册表约束工具能力 |
