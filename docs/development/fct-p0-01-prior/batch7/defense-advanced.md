## 1. 临场技术追问 60 题（深挖级）

> 每题结构：**评委想挖什么 → 通透过答 → 证据锚点 → 别踩的坑**。打 ⚠️ 的是"真短板"，必须按第 0 节话术答。

### A. 检索与算法（14 题）

**A1 ⚠️ BM25 中文怎么分词的？**
想挖：你有没有真处理中文。答：当前 `tokenize()` 用正则，**连续中文整体当一个 token，未分词**——所以长中文句召回弱，但英文标识符/错误码（`max_connections`、`502`）召回强，中文语义由向量路补。升级：jieba/HanLP 或字符 2-gram。证据：`knowledge/retrieval/bm25.py`。

**A2 BM25 参数？**
答：`k1=1.5, b=0.75`（经典默认），IDF 用 `log(1+(N-df+0.5)/(df+0.5))`。可调，未用数据调优——诚实说"经验默认值"。

**A3 向量维度多少？相似度怎么算？**
答：维度随嵌入后端而定；相似度用**余弦**（`vector_store.py` 手写实现，含零向量保护）。默认 hash 嵌入，可切 Sentence Transformers。

**A4 ⚠️ 内存线性扫描，规模大了怎么办？**
答：当前 `InMemoryVectorStore` 是 O(N) 线性，适合小语料/演示；规模化换 **FAISS / pgvector / Milvus**，`search()` 接口已隔离，替换不影响上层。诚实承认"没做大规模"。

**A5 两路分数怎么融合？为什么 0.6/0.4？**
答：各自按本路 max 归一化，再加权（向量 0.6、BM25 0.4）。权重是**可配置初值**，理由：语义是主诉求，精确词是补充。未用数据拟合——诚实。

**A6 🔥 为什么不用 RRF？**
答：RRF 秩融合鲁棒、免调参；我们用归一化分加权，可解释、可按场景调权。两者都合理，RRF 在消融计划里。**别贬低 RRF。**

**A7 只用 max 归一化，离群值会压扁其他分？**
答：会。max 归一化对离群敏感，min-max 又依赖最小值；当前选简单稳定版，可切。承认局限 + 给替代。

**A8 版本过滤怎么做的？会不会误杀？**
答：`version` 为空或 `latest` 不过滤，否则**精确匹配** `chunk.version`（召回阶段已下推）。同义版本号会误杀 → **精度换召回**，升级语义化版本区间。

**A9 重排用的什么？为什么不用 cross-encoder？**
答：词法重排（`lexical_reranker.py`）做确定性收敛；cross-encoder 效果好但重、需模型，**当前为可复现选了轻量**，是路线图。

**A10 知识库怎么更新/增量索引？**
答：文档解析→分块→嵌入→入索引；当前偏全量重建，**增量索引是待补**。诚实。

**A11 多版本文档冲突怎么处理？**
答：检索按目标版本过滤 + 证据层做版本一致性检查（不匹配给 WARNING）；这是"版本为一等公民"的落点。

**A12 RAG 幻觉怎么压？**
答：三层——提示词"无证据不下确定结论"；证据链让用户可核对；inspector 证据层判 SUPPORTED/UNSUPPORTED。**承认不能完全消除**。

**A13 top_k 怎么定？**
答：默认 5，可配；两路各取 top_k 再融合。未做系统性调参。

**A14 你的检索"算法创新"能不能形式化？**
答：能——融合是归一化加权函数；可信度是 `0.5·mean(score)+0.3·support+0.2·coverage`；纠察是"多信号 → 状态机"。**都可写成公式、可消融**，这是"算法"而非"调包"。

### B. Agent 与执行（12 题）

**B1 ⚠️ Planner 是 LLM 还是规则？**
答：**规则基线**（关键词：含"nginx+状态"→查状态；含"重启/restart"→重启且 `requires_approval=True`；否则查知识库）。好处：确定性、可测、零成本。LLM Planner 是插件化替换项。证据：`agent/planner/planner.py`。**别说成"LLM 自主规划"。**

**B2 规划失败/多步依赖怎么办？**
答：当前规划是单步为主、带 `requires_approval` 标记；多步依赖结构与 Re-plan 在路线图。诚实。

**B3 ⚠️ 工具执行失败会重试吗？有回滚吗？**
答：**没有自动重试/幂等键/回滚**。Executor = 策略校验 → dry_run → 执行 → 审计；异常返回失败并记审计，交由 inspector 触发 Re-plan。幂等/回滚是明确的下一步。证据：`agent/executor/executor.py`。

**B4 有 dry_run 吗？**
答：有。`context.dry_run=True` 时只返回"未实际执行"+参数，不碰生产。**演示安全动作时可先 dry_run。**

**B5 循环/滥用怎么防？**
答：RuleJudge 统计单工具调用次数，**>10 次判 LOOP（HIGH）**。阈值可配。

**B6 权限模型？**
答：RBAC（角色/部门/岗位）+ `PermissionChecker` 允许角色集（admin/operator）；策略引擎 + SafetyGuard 双闸。

**B7 Agent 内核有什么？**
答：五类注册表（plugin/skill/tool/model/permission/risk）+ 事件总线 + 生命周期（MOUNTING→MOUNTED→FAILED→STOPPED）。证据：`agent/kernel/runtime/runtime.py`。

**B8 插件怎么装？**
答：`AgentPlugin` 契约注册，`mount/unmount` 生命周期；内置 Docker/K8s/MySQL/Nginx/Redis；MCP 适配器接外部。

**B9 会话隔离/并发？**
答：会话按 conversation_id 隔离；存储支持 Redis/MySQL/PostgreSQL/SQLite/文件五种。**高并发未压测**，诚实。

**B10 上下文太长怎么办？**
答：目前靠检索注入少量证据（top_k 小）+ 短期记忆；**长上下文压缩/滑窗是待补**。

**B11 记忆怎么写入/遗忘？**
答：短期上下文 + 长期 `operator_memory`；写入以处置结论为主；**遗忘/衰减策略未细化**，诚实。

**B12 Agent 会不会自己"发明"工具？**
答：不会。工具必须先在注册表注册，Executor 只执行**已注册**工具；未知工具直接返回"工具不存在"。

### C. 证据与可信（10 题）

**C1 trust_score 公式？**
答：`clamp(0.5·mean(证据分)+0.3·[被支持]+0.2·min(证据数/3,1), 0,1)`，4 位小数。可逐项拆解。

**C2 权重 0.5/0.3/0.2 凭什么？**
答：经验初值（检索准 > 结论有据 > 证据量），**待消融标定**。诚实。

**C3 ⚠️ 证据一致性用词重叠，太粗？**
答：是确定性启发式（重合率 ≥0.5 支持 / ≥0.2 部分 / 否则不支持）。好处：**不被"自信的错误答案"骗过**；语义升级走 NLI/模型（L3）。

**C4 四级纠察是哪四级？**
答：Rule（规则）→ Evidence（证据）→ AI（可插拔）→ State Verifier（状态核验）。聚合：false_success→REJECTED；HIGH/CRITICAL→VIOLATION；其余有 issue→WARN；否则 PASS。

**C5 假成功怎么判？**
答：`StateVerifier` 拿"声称已解决/恢复"对比 `actual_state.resolved`；声称解决但实际 `false` → **false_success** → REJECTED + Re-plan。

**C6 ⚠️ AI Judge 默认是空的，那"AI 判定"是不是摆设？**
答：是**可插拔钩子**，默认 passthrough 保证"无模型也不阻塞安全链路"；生产注入评审模型。**真正的确定性安全来自 Rule+Evidence+Verifier，不依赖 LLM**——这反而是优点。

**C7 审计日志能防篡改吗？**
答：当前是结构化留痕 + 数据库存储；**哈希链/WORM 未做**，生产可接哈希链或不可变存储。诚实。

**C8 怎么证明不是"自评自嗨"？**
答：评测契约要求统一分组集、留 artifact hash、缺失记 `null` 不记 0、零分母不报 0；无观测强制 `NOT RUN`。**这是防自嗨的机制。**

**C9 用户凭什么信 trust_score？**
答：它是**可溯源**的（每条 Citation 带来源/版本/分数），不是模型黑盒；但权重未标定，所以定位是"证据强度参考"，不是"绝对正确率"。

**C10 证据不足时系统怎么表现？**
答：证据层给 WARNING/UNSUPPORTED；提示词要求"明确说明无法确认"；不会硬编一个确定结论。

### D. 安全与隐私（8 题）

**D1 沙箱是真隔离还是逻辑约束？**
答：当前是**策略/权限层约束**（sandbox policy：文件/进程/网络规则）+ 权限注册表；**非容器级强隔离**。生产可叠 ns/cgroup/seccomp。诚实。

**D2 密钥怎么存？**
答：环境变量注入 + AES-GCM 加密存后端，绝不入库/明文；`.env` gitignore。**未接 KMS/HSM**，生产可接。

**D3 MFA、CSRF 怎么做的？**
答：管理员 MFA + 恢复码；CSRF Token 校验写操作；SSE 经 Vite 代理去前缀，跨端口同源由 `vite.shared.mjs` 统一，防会话/CSRF 分裂。

**D4 越权怎么防？**
答：RBAC + 允许角色集 + 策略引擎；管理端敏感操作二次确认 + 审计。

**D5 符合哪些合规？**
答：隐私最小必要（音频/图片不出端）、密钥加密、审计留痕，对齐 **PIPL 最小必要**思路；**等保测评未做**，诚实。

**D6 多模态隐私边界？**
答：语音浏览器内识别（音频不出端）、图像仅文件名（内容不出端）、附件隔离不参与模型分析。

**D7 高危动作被拦截后能强执行吗？**
答：CRITICAL 直接禁；HIGH 必须审批；**没有"绕过"开关**（这是设计约束，不是缺陷）。

**D8 如果审批人点错了批准？**
答：执行前有 dry_run/风险提示；执行后有 inspector 核查 + 审计可回溯；**误批仍是风险**，靠流程+审计兜底。

### E. 工程与性能（8 题）

**E1 610 个 Python 用例 + 656 个后端 @Test是不是凑数？**
答：覆盖契约、安全不变量、领域逻辑，是"防单人阻塞"的交接保证，不是纯断言堆砌。

**E2 有压测/QPS 吗？**
答：**没有**。分包做过优化（echarts 510→346kB、Three 懒加载），但**未做系统压测**；水平扩展在计划内。诚实。

**E3 119 张表会不会太重？**
答：完整域模型（账户/审计/团队/知识/模型/哨兵/远程运维）；迁移幂等；**可模块化裁剪核心子集**。

**E4 服务间一致性（AI/知识/后端）？**
答：AI→知识走 HTTP，知识不可用时**优雅降级为空结果**（`rag.py` 的 `_empty_result`），不阻塞对话；**无分布式事务**，因为场景不强依赖。

**E5 单点故障？**
答：单机部署，**无高可用**；生产可多实例 + 网关。诚实。

**E6 前端首屏/包体积？**
答：zrender 独立拆分、Three 懒加载、管理员层独立产物、图表面板按需加载。

**E7 数据库迁移怎么保证不炸？**
答：迁移脚本**幂等**，启动自动补齐；H2（MySQL 兼容）跑真实迁移做测试。

**E8 为什么四端而不单体？**
答：职责分层——Spring 管权限事务、FastAPI 管 AI 流式、知识服务独立可评测算、Python Agent 管执行。**代价是运维复杂度**，用 docker-compose 收敛。诚实承认权衡。

### F. 模型与评测（8 题）

**F1 为什么不自己训模型？**
答：竞赛周期内训不出可靠领域模型；价值在**约束与工程**，模型可换。自训/微调是路线图。

**F2 SFT/LoRA 计划？**
答：有训练管线骨架（`training/`），但**未执行**（缺真实模型/数据/依赖）；属于下一步。

**F3 评测指标有哪些？**
答：任务成功率、根因准确率、证据准确率、工具/风险/审批准确率、验证成功率、Inspector P/R、幻觉率、假成功率、安全违规率、延迟、Token 成本。

**F4 消融怎么设计？**
答：RAG 六组（Vector→BM25→Hybrid→+Rerank→+Version→+Evidence）、Inspector 五组（Agent→+Rule→+Evidence→+AI→+Verification）。

**F5 数据泄漏怎么防？**
答：按事件族/根因/环境/版本/场景**分组切分**，写 `leakage_report.json` 才算接受。

**F6 为什么用 mock？**
答：零密钥可复现，不是能力上限；`model_gateway` 可切 Ollama/OpenAI 兼容。

**F7 评测没跑，竞赛怎么算？**
答：如实标注 `NOT RUN`；评的是算法设计与工程实现，这两层可演示可验证。

**F8 ⚠️ 你的算法"可证伪"吗？**
答：可——融合/可信度是公式，纠察是状态机，消融可跑；**设计上允许被数据推翻**，这是科学态度。

### G. 多模态（4 题）

**G1 图像为什么只传文件名？**
答：刻意隐私取舍（内容不出端）；OCR 模块已在，授权后接内容级+多模态大模型。

**G2 语音识别准吗？方言？**
答：Web Speech API 浏览器内置识别，**准确率/方言依赖浏览器**；不支持时入口自动隐藏（渐进增强）。

**G3 多模态算不算"假多模态"？**
答：文件名级参与是**如实边界**，不包装成"看懂图片"；这是可信的一部分。

**G4 接视觉模型要改架构吗？**
答：不用大改，`ChatRequest.images` 已是扩展点，换内容级解析即可。

### H. 架构与选型（6 题）

**H1 和微服务比，你这算微服务吗？**
答：算**轻量多服务**（前端/后端/AI/知识/Agent），docker-compose 编排；不是完整 service mesh。

**H2 为什么后端用 Java，AI 用 Python？**
答：Java 成熟权限/审计/事务；Python AI 生态与异步流式。职责分层。

**H3 为什么自研 Agent 内核？**
答：要"策略与审批优先"，把风险判定插在**每步执行前**；通用链式编排做不到执行前拦截。

**H4 能上云/容器吗？**
答：docker-compose 一键起；可容器化上云；生产需配 TLS/网关/多实例。

**H5 数据库为什么 MySQL 不用 PG？**
答：团队熟悉 + 生态成熟；会话存储已支持 PG 等多后端，切换成本低。

**H6 前端为什么部分 TS？**
答：共享逻辑层（48 模块）迁 TS 拿类型收益，组件层留 JS 控成本；`tsc --noEmit` 进门禁。有意取舍。

## 2. 产品 / 项目优势（评委问"凭什么"时用）

### 2.1 一页差异化矩阵

| 维度 | ChatGPT/通用问答 | Coze/Dify 编排 | 传统 AIOps | 本产品 智维Agent |
|---|---|---|---|---|
| 回答依据 | 模型记忆 | 工具返回，缺证据链 | 规则/阈值 | 版本感知混合检索 + 证据验证 |
| 可信度 | 无 | 无 | 告警等级 | Citation + trust_score 可溯源 |
| 知识版本 | 不分 | 不分 | 弱 | 版本一等公民（过滤+一致性检查） |
| 执行权限 | 不执行 | 默认偏大 | 部分自动化缺审批 | 策略引擎 + 人工审批 + 沙箱 |
| 过程透明 | 黑盒 | 有轨迹无用户视图 | 有日志无推理 | SSE 分阶段思考可视化 |
| 审计沉淀 | 无 | 有限 | 有日志 | 审计留痕 + 经验回流 |
| 多模态隐私 | 直接上传 | 直接上传 | 不涉及 | 分层边界（音频/图像/附件） |

### 2.2 五大硬优势（背这五句）

1. **可信闭环工程化**——权限/风险/审批/核查/审计是**可运行代码**，不是 PPT 理念。
2. **版本感知检索**——解决"知识正确但版本不对"的行业通病，版本做进召回。
3. **透明推理**——用户看得见检索了什么、命中多少证据、判了什么风险，直接建立信任。
4. **隐私边界分层**——"能用"和"该传"分开，合规友好。
5. **零密钥可复现 + 模型可切换**——评委能自己跑，企业能接自有模型，兼顾演示与生产。

### 2.3 真正的壁垒（评委最爱问"护城河"）

> **不是模型，是"约束工程 + 领域知识资产 + 插件生态 + 评测框架"的系统性整合。**
> 模型谁都能换；把"可信"做成可拦截、可追溯、可复现的闭环，才是壁垒。

### 2.4 成本 / 部署优势
- **演示零成本**：mock 零密钥跑通全链路。
- **落地可控**：私有化自托管数据；核心子集可裁剪，降低 119 表的部署门槛。
- **模型可换**：Ollama 本地省成本，OpenAI 兼容按需用。

## 4. 临场刁钻题（新增 20 题，练心态）

**Z1 "给你 100 万怎么花？"**
答：40% 真实评测与数据（把 NOT RUN 跑成数）、30% 检索/向量工程化、20% 多模态与端侧、10% 合规与压测。**先补最硬的短板（数据）。**

**Z2 "能用在哪三个行业？"**
答：高校实验室/实训机房（同源）、中小企业 IT 运维、MSP/IT 外包服务商（多租户运维）。

**Z3 "大厂明天做一个一样的怎么办？"**
答：大厂做通用平台，我们做**垂直可信 + 私有化 + 轻量可复现**；它们不会为 50 人企业做深度定制，这是我们的空间。

**Z4 "你给自己打几分，扣在哪？"**
答：设计/工程 8 分，**真实评测 4 分**（还没跑），多模态深度 5 分。扣分点我清楚，也知道怎么补。

**Z5 "一句话说服我投资。"**
答：企业不敢把生产交给只会回答的 AI；我们让它变成**敢托付的 AI 同事**——结论有证据、动作有边界、过程有留痕。

**Z6 "只能保留一个功能，留哪个？"**
答：**风险审批闸门**。没有它，AI 越强越危险；有它，才谈得上"可信"。

**Z7 "你项目最大的风险是什么？"**
答：真实数据闭环没跑通——评测算不出来，一切效果都是设计推断。这是最硬短板，也是第一步要补的。

**Z8 "怎么证明不是 AI 帮你写的？"**
答：架构/算法/验收由人把关，关键路径我讲得出为什么这么设计、边界在哪、代码在哪。**能追到实现细节，就是证明。**

**Z9 "如果模型免费了，你还剩什么？"**
答：约束闭环、证据链、审批审计、版本治理、领域知识——**模型免费，信任不免费**。

**Z10 "用户凭什么信你的 trust_score？"**
答：可溯源（来源/版本/分数可拆）；且定位是"证据强度参考"不是"绝对正确率"，诚实。

**Z11 "为什么不用现成大模型 Agent 平台？"**
答：平台给你编排，给不了"执行前风险闸门 + 假成功检测 + 版本感知检索"；这些是垂直可信的关键。

**Z12 "你的系统能替代运维吗？"**
答：不替代，**增强**。AI 负责思考与执行建议，人负责授权，系统负责留痕——是"AI 同事"不是"AI 替身"。

**Z13 "为什么评委要给你奖，而不是给一个更炫的？"**
答：炫的很多，**敢把"可信"做成可运行闭环**的少；我们每个创新点都有代码与演示路径，经得起追问。

**Z14 "如果现场断网/模型挂了？"**
答：mock 本地兜底，全链路不依赖外网；演示有 60 秒备用录屏。

**Z15 "你做这个花了多久？团队几个人？"**
答：据实说；强调模块化与门禁让"小团队也能交付完整系统"。

**Z16 "你觉得 AI 运维的终局是什么？"**
答：从"辅助回答"到"可信代理"——关键不是更聪明，而是**可授权、可拦截、可追溯**。我们押"信任基础设施"。

**Z17 "为什么不用更小的模型/端侧？"**
答：端侧是路线图（隐私/成本/离线）；当前先保证可信闭环与可复现。

**Z18 "你的项目有什么社会价值？"**
答：把大厂级运维能力普惠给中小企业与高校，降低对少数"老师傅"的依赖，缓解运维人才缺口。

**Z19 "如果只能改一个技术点，改哪个？"**
答：**中文分词**——它直接决定 BM25 召回质量，是当前最影响效果的单点。

**Z20 "用三个词总结你的项目。"**
答：**可信、可控、可复盘。**（或：证据、边界、留痕。）
