0. 一句话战略

四份材料不是四篇文章，是同一个论证被四把不同的尺子量。
你要做的不是"写四遍"，而是先锁死一套事实，再按四种视角各讲一遍。

绝大多数队伍死在三件事上，全都可以提前消灭：

死法后果本方案的对策
四份材料数字打架评委交叉一读，直接判"材料不实"单一事实源 + 一致性矩阵（第 3、8 节）
四份材料内容重复评委觉得注水、篇幅凑数分工矩阵，一份只答一个问题（第 4 节）
佐证撑不起正文正文越漂亮，越像编的三级证据设计，L2 全覆盖（第 7 节）

1. 评委怎么读这四份材料（四把尺子）

先想清楚"谁在读、想验证什么"，再决定"写什么"。

材料评委的潜台词他在找什么一票否决点
技术方案"你想清楚了吗？"问题定义是否真、方案是否自洽、有无可行性论证需求是编的、方案与问题不匹配、没有技术路线图
技术报告"你真做出来了吗？"实现深度、关键算法、可复现的验证、诚实的局限只有截图没有数据、指标无来源、无局限性说明
佐证材料"我凭什么信你？"可核验、可复现、有第三方痕迹全是自制截图、无可运行路径、时间线对不上
商业报告书"这值钱吗？谁付钱？"痛点强度、付费意愿、单位经济、壁垒市场规模靠"万亿"堆、财务全靠拍、无竞品分析

关键认知：技术方案与商业报告书是"应然"（应该这样设计 / 应该这样赚钱）；技术报告与佐证是"实然"（实际做成什么样 / 凭什么证明）。应然可以宏大，实然必须精确。越界吹牛 90% 发生在把"应然"写进了"实然"。

三条贯穿全案的主线（四份材料必须讲同一个故事，一句不改）：

  1. 主线一 · 定位：不是"会聊天的运维助手"，是敢让它动手的可信运维智能体。
  2. 主线二 · 机制：三道锁 + 一本账 —— 证据锁（回答有出处）、风险锁（高危必审批）、边界锁（能力有白名单）+ 全链路审计。
  3. 主线三 · 主张：AI 负责思考，人负责授权，系统负责留痕。
这三句要出现在：技术方案摘要、技术报告结论、佐证材料说明页、商业报告书价值主张。同一句话，四种语气。

第 5 章怎么写才不塌（核心）

采用"三层证据结构"，从强到弱排列，先亮最强的：

  1. 可复现的功能验证（最强）：108 个自动化用例 + 一键脚本 → 证明系统按设计工作。
  2. 小样本量化评估（次强）：M01–M04，每个指标必须带 n=，并给出置信区间或"样本量不足以支撑统计显著性"的说明。
  3. 人工盲评（补充）：M05，3 评者 + Cohen's κ，κ>0.6 即可称"一致性良好"。
写法示范（照抄这个句式）：
"在 14 条自建运维样本（全部为 DRAFT 状态，未经领域专家复核）上，检索模块 Top-3 命中率为 __%（n=70 query）。受样本量限制，该结果仅用于验证链路有效性，不作为泛化性能结论。"

这句话的价值：它同时展示了结果、暴露了局限、划清了边界。评委看到这种表述，会认为你懂科研规范。

致命扣分点

  • ❌ 有"实验结果"章节但没有原始数据/脚本 → 必须附 评测明细.csv。
  • ❌ 只报最好的一组参数 → 给参数敏感性（至少 2 组对比）。
  • ❌ 局限写成"未来会更好" → 局限要写技术原因（如"BM25 未分词，因零依赖约束；影响：中文长 query 召回下降，量化见 §5.4"）。

5.3 佐证材料（建议 15–25 页 + 附件包）

定位：不解释、不抒情，只提供可核验的痕迹。评委翻它的时间不超过 3 分钟，所以结构必须"3 秒见结论"。

三级证据体系（务必 L2 全覆盖）

级别定义本项目可交付物状态
L1 自证证明"存在"代码仓库、目录树、模块清单、数据库表结构✅ 现成
L2 可复现证明"能跑"① 一键启动脚本 ② Docker/依赖清单 ③ 3 分钟演示录屏 ④ 测试执行日志 ⑤ 评测脚本 + 原始输出⚠️ 需补 ③④⑤
L3 他证证明"别人也认"① 软著/专利受理 ② 部署上线地址 ③ 用户/运维人员访谈记录 ④ 开源 star/issue ⑤ 第三方测试或 CI 记录 ⑥ 导师/企业推荐意见❌ 全缺，至少补 2 条
L3 是分水岭。 只有 L1+L2 的队伍是"学生作业"，有 L3 的队伍是"可信项目"。最容易补的两条：软著申请受理号（1–2 周可下）、1 位一线运维人员的书面评价（一页纸，签字即可）。

7 财务预测3 年，收入/成本/毛利，全部标注假设3附敏感性分析
8 团队与风险分工 + 3 个主要风险及对策2风险要真

市场规模怎么算才不被笑（重点）

❌ 错误写法："中国 IT 运维市场规模超 3000 亿，我们占 1% 就是 30 亿。"
✅ 正确写法（自下而上，每一层可查）：

TAM = 中国规模以上企业数 × 年均 IT 运维软件支出
SAM = 其中有专职运维团队、且存在合规审计要求的企业数 × 可承受客单价
SOM = 3 年内可触达客户数（按获客能力测算）× 客单价
三个数都要标"数据来源 / 假设依据"。宁可 SOM 只有 3000 万，也不要 TAM 写 3000 亿。 评委会认为前者是做过功课，后者是套模板。

财务预测的护栏

  • 每个数字后面加 （假设：__）；
  • 必须有一张敏感性分析：客单价 ±30%、获客成本 ×2 时，盈亏平衡点怎么变；
  • 第一年不要写盈利。学生项目第一年盈利 = 明显拍脑袋。

致命扣分点

  • ❌ 竞品分析只列"我们更好" → 必须有一栏"我们不擅长"。
  • ❌ 壁垒写成"技术领先" → 技术会被追上，要写"追上来要付出的代价"（数据积累、合规适配、客户切换成本）。
  • ❌ 通篇没有"谁付钱" → 每一页都要能回答"这句话跟收钱有什么关系"。

6. 三条红线与标准话术（背下来）

这三条是本项目特有的风险，评委只要真读材料就一定会碰。

红线一：数据集只有 14 条，且全是 DRAFT

危险表述：任何形如"准确率 9X%"的句子。

标准话术（书面）：

"本项目构建了覆盖 7 类 Linux 运维场景的种子数据集（14 条），当前状态为 DRAFT，用于打通'数据—检索—纠察—执行'全链路。本文报告的检索指标基于该种子集的小样本评估（n=70 query），仅用于验证链路有效性，不构成泛化性能结论。扩样与专家复核方案见 §8.2。"

标准话术（口头）：

"样本量小是我们最清楚的短板。所以我们没有报准确率，而是报'链路是否打通'和'失败案例在哪'——这两件事 14 条样本足够说明。"

红线二：实验标记为 NOT RUN

危险表述：报告里出现空白的"实验结果"表格，或用"预计""理论上"填数。

标准话术：

"我们的评测分为已完成与未完成两部分，报告中只呈现已完成部分，未完成部分明确标注 NOT RUN 并给出执行协议。知道哪些结论还不能下，比什么都敢写更可信。"

红线三：多个组件是"规则基线"

涉及：Planner（规则）、BM25（未分词）、向量检索（内存 + hash 嵌入）、AI Judge（可插拔未绑模型）。

统一表述模板：

"该模块当前为确定性基线实现，设计目标是先保证可测、可复现、零外部依赖；接口已按可替换设计（__init__ 注入 / 策略模式），生产环境可平滑切换为 LLM Planner / jieba 分词 / FAISS 索引，替换成本见 §8.3。"

为什么这样答反而加分：评委见惯了"我们用了最先进的大模型"，见到"我们知道哪里是基线、以及为什么先做基线"，会认为你工程判断力成熟。

11. 我需要你确认的 4 件事

这四点会直接改变四份材料的写法，越早定越省返工：

  1. 提交截止时间是哪天？——决定第 9 节排期是压到 3 天还是放宽到 10 天。
  2. 格式与页数限制（秩序册里通常有"不超过 X 页/A4"）——PDF 是扫描件我读不出文字，你截图那一页给我即可。
