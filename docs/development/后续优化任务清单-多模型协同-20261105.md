# SmartOpsAgent 后续优化任务清单（多模型协同）

日期：2026-11-05  
性质：方案、分工和验收清单；本文件不要求本轮修改业务代码。  
目标：把现有“工程链路已能演示”推进到“真实平台可验收、数据可审计、模型结论可解释、发布可回滚”。

## 使用方式

每个任务交给一个独立 AI 模型或专门角色处理。模型只对自己的交付物负责，不能自审自己生成的数据、标签或分数。任务完成后由发布审查模型检查证据，再由人工负责人决定是否放行。

证据状态统一使用：

- `DONE`：有命令、原始输出和可复核文件。
- `IN_PROGRESS`：已有部分产物，尚未达到验收条件。
- `BLOCKED`：存在外部依赖、人工审核或环境条件，不能用推测补齐。
- `NOT_STARTED`：只有计划，没有执行证据。

当前必须保持的事实边界：Edge 黄金浏览器是 API fixture；qwen3:1.7b 直连记录不是浏览器全链路；训练 formal gate 仍为 BLOCKED；GitHub 新候选联网核验曾被审批服务 HTTP 404 阻断；Qdrant/OTel 尚未部署。

## 当前基线

| 领域 | 已有证据 | 尚未解决 |
|---|---|---|
| 前端 | 475 项 Node 测试通过，TypeScript 和构建通过；Edge fixture 4/4 | 真实平台浏览器 E2E 连续 3 次 |

架构专项审阅发现：默认产品聊天入口是 Java `AssistantController → AssistantService → MiniAssistantEngine`，当前证据不能把它描述成已经贯通 Python AI 8001 与 Knowledge 8002 的生产链路；Python ApprovalManager 和部分运行状态仍是进程内状态；`server/server_metric/inspector_event` 等域的用户/团队过滤还没有形成统一基线。后续任务必须先解决这些事实边界，再讨论新增向量库或观测平台。

## 总体顺序

```text
P0 数据权利与人工 Golden
  → P0 真实平台 E2E 与启动预检
  → P0 统一运行关联和失败恢复矩阵
  → P1 REAL Prompt/Agent baseline
  → P1 RAG/Inspector/Verification 单变量消融
  → P1 可访问性、性能、长会话和发布门禁
  → P2 Qdrant/OTel 隔离 PoC
  → P2 SFT
  → P2 Preference Optimization 与长期自动化
```

依赖顺序不能反过来：没有人工审核和许可，不能放行正式准确率；没有 REAL baseline，不能把 RAG 或训练改进写成提升；没有真实 E2E，不能把 fixture 证据写成平台通过；没有回滚和租户过滤，不能引入持久外部服务。

## AI 模型分工与任务模板

### 模型 A：架构与平台

负责接口边界、状态机、依赖、租户和回滚。必须输出：架构图、状态转移、故障模式、迁移/退出成本、验收命令。不能自行批准其提出的新依赖。

### 模型 B：数据与评测

负责 Golden、许可、血缘、标注规范、分层统计、RAG/Agent 指标。必须输出：manifest、标注协议、review receipt 结构、分子/分母和置信区间。不能读取或批准自己生成的标签。

### 模型 C：浏览器与体验

负责真实 E2E、失败恢复、a11y、性能和答辩脚本。必须输出：trace、截图、页面错误、环境摘要、fixture/real 标签。不能把 fixture 通过改写成 provider E2E。

### 模型 D：发布与风险

负责许可证、凭据、匿名性、发布门禁、回滚和证据完整性。必须输出：风险矩阵、阻断项、发布签字表、回滚演练记录。不能因为测试数量多而自动放行模型或数据。

### 通用分派提示词

```text
你只负责任务 <TASK_ID>。先读取本项目已有实施记录和证据，不修改无关代码。
输出必须包含：现状证据、假设、输入、具体交付物、验收命令、失败/阻塞条件、回滚方式。
所有结论标记 DONE/IN_PROGRESS/BLOCKED/NOT_STARTED；没有原始输出不得写 DONE。
不能把 fixture、mock、AI自生成标签、框架自报分数或根 LICENSE 当成真实生产证据。
```

## 发布风险矩阵

| 风险 | 触发条件 | 处理 | 放行条件 |
|---|---|---|---|
| 真实 E2E 被误报 | `fixture=true` 或 `provider_e2e=false` | 分账并保留原始 trace | 连续3次真实平台运行 |
| 数据权利不清 | LICENSE/数据条款/内部授权缺失 | `pending`，不下载或入库 | 许可、PII、删除机制齐全 |
| 模型自审 | 生成模型同时产标签/批准/分数 | 外部人工 review receipt | 双标、裁决、可信 predictions |
| 假成功 | denied/partial/502 被标 succeeded | 规则状态机和 StateVerifier 优先 | failed/denied/recovery 分母完整 |
| 运行关联断裂 | Java/AI/Knowledge ID 不一致 | 停止全链路宣称，先做对照表 | 6 类终态一致率100% |
| 新依赖失控 | Qdrant/OTel 未测退出、租户、回滚 | 保持 `BLOCKED`，只做隔离 PoC | 资源、成本、退出和回滚数据齐全 |
| 凭据/隐私泄露 | 日志或 UI 出现 token、Prompt、私有原文 | 立即阻断发布并清理证据 | 白名单字段审查通过 |
| 审批服务不可用 | 外部只读采集返回模型/网关错误 | 保存原始错误，不绕过，不改全局配置 | 审批恢复后重新采集并 hash 固定 |

## 每个任务的四件交付

任何任务完成时必须同时提交：

1. 改后方案或实现文件；
2. 相对任务前像的精确差分；
3. 验证记录和原始输出；
4. 哈希保护回滚脚本，并在副本中演练。

若任务只做方案，第一项是 Markdown，后三项仍是方案文档差分、Markdown 校验记录和文档回滚脚本；不得为了凑齐四件交付修改业务代码。
