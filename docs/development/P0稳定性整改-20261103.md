## 本批结果

已修复纠察待核验结果被汇总 PASS、规则规划器服务目标写死 nginx、Knowledge 缺少就绪判断三条源码路径，并改进启动脚本的重复实例处理。相关回归 **162 通过**；完整 Python 测试 **201 通过、16 失败、7 跳过**，16 项仍是已有匿名 API 测试与当前登录/CSRF 契约不一致，未隐藏或取消权限。

默认本机 `127.0.0.1:8002` 仍被旧空索引进程遮蔽。系统权限与自动审批服务故障阻断停止旧实例，因此**源码修复、隔离实例验证与默认运行实例切换分别记录**，不把本批描述为完整演示验收通过。

## 修改与行为

| 路径 | 先前问题 | 本批行为 |
|---|---|---|
| InspectorPipeline | 无 probes 或未知结论+异常探针可汇总 PASS | 必需执行验证却缺观测时 WARN + requires_human；新增 verification_result.required/status |
| 风险判定门禁 | 风险大小写约定不一致 | high/HIGH、critical/CRITICAL 一致要求观测 |
| 成功结论分类 | “解决方案/如何解决”子串误认完成 | 移除非完成短语后按句分类；另一句实际“服务已恢复”仍会核验，502 仍 REJECTED |
| AI Chat Inspector 集成 | 验证标志未透传；仅验证标志的请求被跳过 | metadata.verification_required=true 传入流水线，也可单独触发检查 |
| AgentPlanner | “重启 mysql”生成 nginx restart | 只对完整、单一、受支持的 nginx/mysql/redis 请求绑定目标，action/arguments 一致；未知、否定、多目标、混入命令与英文拼接词转知识查询 |
| Knowledge HTTP | UP 并不代表索引可检索 | `/api/health` 保留存活；`/api/ready` 空索引 503，非空 200；返回实例、启动时间、语料文档数与哈希 |
| Windows 启动 | 重复拉起同端口；Python 仅测 TCP | 有监听则复用并检查就绪；Knowledge 必须 READY、ready=true、正整数 chunks；隐藏窗口、日志落盘 |
| 本地状态脚本 | 只取一个监听，未看 AI/Knowledge | 显示全部绑定/PID、多进程提醒和 Knowledge HTTP readiness |

现有 PASS/WARN/VIOLATION/REJECTED 枚举没有扩展。新增验证状态为 verified、failed、uncertain、unverified、not_required。verified 表示观测与结论一致，**不单独等价于系统健康或执行成功**；调用方还应使用原有 passed/false_success/claim_state 及实际探针。

没有实际执行任何 nginx/mysql/redis 重启；规划测试与展示只生成计划。requires_approval 是请求审批标记，不能当作批准。现有 PolicyEngine 仍存在将该标记当作允许的旧实现，本批不宣称已打通真实批准、参数绑定和执行授权闭环，需后续独立整改。

探针时间新鲜度、目标绑定与可信来源也仍待完善；本批解决的是汇总待核验门禁，不据此声称所有探针已完成真实性验证。
