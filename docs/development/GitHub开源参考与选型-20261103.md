日期：2026-11-03 初稿；2026-11-04 更新抓取状态。目标：服务现有演示稳定与逐步产品化，不用仓库热度替代项目需求。

**抓取状态：2026-11-04 已完成 10/10 官方仓库 metadata、README 与 LICENSE 原文采集。** 11 月 3 日曾受网络限制和自动审批模型 404 阻断；本轮只读联网自动审批已成功，未修改全局审批配置。原始记录见 [仓库证据](../../.runtime/execution-gate-20261104-084309/github/github-repositories.json) 和 [LICENSE 固定 blob 证据](../../.runtime/execution-gate-20261104-084309/github/license-evidence.json)。下表保留机制候选，最新取舍及许可修订见 [11 月 4 日调研与路线](GitHub开源调研与后续路线-20261104.md)。尚未锁定引入版本或完成兼容性试验。

## 1. 先借鉴哪些能力

| 候选源 | 对应本项目问题 | 最值得借鉴的机制 | 初步采用方式 | 引入门槛/代价 |
|---|---|---|---|---|
| [LangGraph](https://github.com/langchain-ai/langgraph) | Agent 长任务、人工审批后恢复、跨重启状态 | checkpoint、interrupt/resume、节点状态与错误边界 | 演示期先借鉴状态机；需要长任务时再做小范围试验 | 不能把现有 Java 业务工作流整体再包一层；必须证明恢复/幂等优于当前实现 |
| [LlamaIndex](https://github.com/run-llama/llama_index) | 摄入、分块、索引和检索配置分散 | 文档到索引的生命周期、检索/评价组件接口 | 阅读设计并与现有 Knowledge 做同一语料对照 | Python 依赖与抽象复杂度；不同时迁入多个 RAG 框架 |
| [Qdrant](https://github.com/qdrant/qdrant) | 内存索引重启丢失、租户/版本过滤、删除更新 | 持久向量索引、payload filters、集合生命周期 | 产品化阶段可替换 VectorStore 适配层 | 需实测租户隔离、删除一致性、备份、内存与本地部署成本 |
| [Phoenix](https://github.com/Arize-ai/phoenix) | RAG/LLM 调用缺少统一链路与可对照评测 | 检索、引用、模型调用的 trace 与人工评价 | 暂缓整合；优先标准 OTel 链路 | 本次 LICENSE 为 ELv2，含第三方托管服务限制；产品化需单独核对服务模式与分包许可 |
| [OpenTelemetry Collector](https://github.com/open-telemetry/opentelemetry-collector) | Java/Python/浏览器日志孤立、定位慢 | 标准 trace 上下文、采集/导出边界 | 先统一 request/task/run ID，再按需接入 | 不为展示而安装整套观测栈；须能定位一次真实失败 |
| [StackStorm](https://github.com/stackstorm/st2) | 事件触发执行、动作治理、审计 | sensor → rule → action、权限和执行历史 | 借鉴动作协议与规则边界 | 不与现有哨兵重复建设；评估维护和运维成本 |
| [Rundeck](https://github.com/rundeck/rundeck) | Runbook、目标选择、审批执行、团队操作 | job/runbook、参数、执行记录、权限模型 | 与 StackStorm 对比，选择适合机制；不默认同时部署 | 确认社区版具体能力和对应许可证；不将商业版能力写成开源现成能力 |
| [Alertmanager](https://github.com/prometheus/alertmanager) | 告警重复、分组、静默与升级 | grouping/dedup/silence/inhibition | 先补哨兵事件语义，已有 Prometheus 场景再接入 | 统一事件标识、恢复状态与接收者策略，避免告警循环 |
| [promptfoo](https://github.com/promptfoo/promptfoo) | 小合成集、回归漂移、模型/提示比较 | 固定测试集、provider 对照、回归门禁 | 先试验离线评价流程，不引入运行链路 | 人工独立集先行；核验执行/联网边界及当前许可证 |
| [Playwright](https://github.com/microsoft/playwright) | 源码匹配测试多、真实用户路径验证不足 | 登录、权限、模型选择、流中断等浏览器行为测试 | 已有前端依赖，优先使用现有版本补关键 E2E | 需要隔离账号/数据库、固定测试数据；测试输出脱敏 |

“借鉴机制”与“引入依赖”分开决定。短期优先 Playwright 的关键流程测试与标准任务状态；中期评估 Qdrant/观测；LangGraph、RAG 框架、自动化平台均需独立试验，不做整栈搬迁。

## 2. 每项候选的审阅清单

| 维度 | 必须取得的证据 | 通过标准 |
|---|---|---|
| 身份与版本 | 官方 repo、默认分支、选定 tag/commit、README 摘要 | 引用可复现；不以浮动 latest 作为依赖基线 |
| 许可证 | LICENSE 原文、SPDX、商业/企业目录与依赖许可 | 明确复制/分发/网络服务/署名义务；模糊时不整合代码 |
| 维护 | 最近 release/commit、归档状态、issue 响应抽样 | 能理解升级和维护责任；不凭 stars 直接决定 |
| 本地适配 | Windows/Java17/Python/Node 与现有部署依赖 | 全新环境可启动，资源成本适合当前演示机器 |
| 功能收益 | 用同一任务/语料与现有实现对照 | 有实际缺口和可量化收益，没有重复状态源 |
| 安全与退出 | 数据出口、日志、身份、配额、备份/导出 | 不扩大默认暴露；停用后可回到既有适配层 |

已取得官方 README、仓库状态与根 LICENSE 原文；版本锁定、依赖许可、维护响应抽样和本地适配仍待核验。根 LICENSE 不代表全部插件、商标、商业服务和传递依赖。

## 3. 已准备的采集工具

脚本：[fetch_github_candidates.py](../../scripts/research/fetch_github_candidates.py)。只读抓取 10 个固定候选的公开 metadata、README、license 文件元数据；不 clone、不安装、不执行下载内容，不保存凭据。限制单响应 2MiB、请求 20 秒；连续网络失败会保留部分结果并返回非零。

```powershell
python scripts/research/fetch_github_candidates.py --output .runtime/github-research/github-repositories.json
```

产出包括抓取时间、官方 URL、默认分支、更新字段、归档状态、GitHub license 标签、README blob/hash。2026-11-04 已实际执行采集；另按已取得的 LICENSE blob SHA 下载原文并验证 Git blob 哈希与 SHA256，见上述证据。未 clone、安装或执行下载内容。

采集结束后按以下顺序继续：

1. 检查所有 status，不把部分成功写成全部抓取完成。
2. 抽样阅读 README 与 LICENSE，选定 tag/commit；记录具体借鉴文档/源码路径和适用版本。
3. 选一个痛点试验：索引重启恢复或真实对话回归；不要同时迁移 Agent、RAG、监控。
4. 用相同数据对比正确性、延迟、资源和恢复成本，形成采用/暂缓/拒绝记录。
5. 采用后才添加锁定依赖、署名、维护说明和回滚步骤。

## 4. 当前决策记录

| 决策 | 原因 | 复议条件 |
|---|---|---|
| 保留 Spring Boot + Vue 主体 | 业务与安全基础已有较多代码和后端测试支撑 | 出现可量化扩展瓶颈或边界冲突 |
| 演示前不替换全部 Agent/RAG | 当前主要失败来自契约、状态与就绪问题 | 现有主流程通过并形成独立评测基线 |
| 不以候选框架自动补齐“AI Judge/多模态”宣传 | 框架能力不等于本项目已经接通并验证 | 实际模型/图像内容接入与验收证据齐全 |
| 不用 stars/合成集 F1 选型 | 热度与小集回归不证明业务质量 | 同一真实工作负载对照、许可证和维护审阅完成 |

总体执行顺序与 P0 问题见 [全面体检与优化方案](全面体检与优化方案-20261103.md)。
