## 1. 接单说明

目标是把路演中暴露的短板转成可验证的工程与算法改进：真实调用链、证据有效性、业务恢复判据、规划与审批、检索质量、独立评测以及演示证据。

本文件可独立阅读。接单模型能访问仓库时，应先复核源码与最新原始记录；只能读取本文件时，先产出方案、接口和验收协议，把待核查项标为 `UNKNOWN`，不虚构当前实现。

执行模式以用户实际转发指令为准：`PLAN` 产出方案，`IMPLEMENT` 在认领范围内实现并验证，`RUN` 执行已具备条件的隔离验收。任务书中出现实现步骤或运行命令，本身不表示本轮已执行。用户明确要求实施某任务后，在其授权范围内连续推进，无需对常规可逆步骤逐项确认。

**接单第一步：选定一个任务 ID，登记负责人、基线、输入版本、独占文件和交付目录；先核查已有成果，再补缺口。**

## 2. 优先结论

1. **先补事实与闭环。** 最影响可信度的是稿件数字、实际调用路径和评测产物不一致。
2. **先修恢复判定。** 错目标、过期观测、HTTP 200 但业务失败，比扩充“成功表达词表”更值得优先处理。
3. **已有能力做验证与接线。** BGE 适配、三态声明、基础审批、运行关联已有部分实现，接单者须避免重复开发。
4. **创新收敛到证据与恢复契约。** 以“结论需要什么证据、缺什么、下一步查什么、何时足以确认、何时失效”为主线；BM25、向量和四级纠察作为已有基础和对照。
5. **新框架按收益引入。** LangGraph、Qdrant、OTel 等先参考机制或做条件 PoC，不同时迁移整套 Agent、RAG 与监控系统。

### VER-P0-01：证据义务、恢复判据与有限期回执

**目标**：让恢复判定依赖结构化业务条件；自然语言“已恢复”的识别仅作辅助。需要结果核验的动作在计划/工具契约中声明，即使模型换一种措辞，也进入核验流程。

**实施范围**：沿用 `RecoveryContract / Claim / EvidenceObservation / ObligationResult / ProbeDecision / VerificationReceipt / ReplayBundle`。契约至少绑定 scope、target、期望 revision、必需业务谓词、来源组、采样窗、证据 TTL、总预算、停止规则和有效期。

义务值为 `TRUE/FALSE/UNKNOWN`。合格业务观测明确失败才为 FALSE；缺失、错目标、旧任务、过期、来源未决通常为 UNKNOWN。连接超时默认表示采集不足；只有契约将从该位置可达作为业务条件时，才能据此判对应义务失败。

有必需 FALSE 则 `CONTRADICTED`；无 FALSE 但有 UNKNOWN 则 `INSUFFICIENT`；全部满足才 `VERIFIED`。只有 VERIFIED 可签发 ACTIVE 回执；其余 `NOT_ISSUED`。到期、已知新反例或目标 revision 变化追加 EXPIRED/INVALIDATED 事件；历史证据保留。工具成功、审批批准、Inspector结果与恢复结论各自保存。

**验收反例**：HTTP200但业务字段false；nginx声明搭配另一host/port及2020年观测；跨run/租户；缺采集器身份；过期健康记录；缺版本；部分实例恢复；单样本抖动。再提供有效真恢复正例，避免“全部暂缓”刷低风险。区分旧任务绑定r16的观测（不合格）与本轮期望r17但实际响应r16（版本义务反例）。

**依赖/回滚**：N01 先冻结规范，N02 求值，N04 窗口与回执；复用现有三态逻辑，保留 `StateVerifier.passed` 原义。停用新签发能力后仍可读历史审计。

### PROBE-P1-01：有预算的只读补证调度

**实施范围**：V1 使用登记探针的加权缺口覆盖，分数为“当前可检查的缺失义务权重和 / 登记成本”。权限过滤后再评分，同分按成本、固定probe_id选择。每次取得结果后重算；等待未来采样槽时输出 WAIT，到期或预算不足 STOP。

**机制原型**：仅自持有 loopback 服务、固定 GET 和登记端口；禁任意URL/代理/重定向，限定响应体、格式和整体截止时间。建议初始参数沿用既有蓝图：1秒单探针完整调用、4KiB响应、总12次/30秒、3组双路径有效采样、首末至少4秒、证据TTL15秒；组内偏差、间隔和预算可满足性由N01冻结。这些是原型参数，没有生产SLO含义。

**验收**：连接+完整读取+解析共同受绝对deadline约束；慢速滴流、超大body、重复ID、错来源、超时、预算耗尽均有证据。重试计费；新轮次不重置run预算；重启后不比较旧单调时钟。与同目录、同预算、同停止机会的固定顺序策略比较，所有失败/暂缓均入报告；不承诺贪心全局最优。

**依赖/回滚**：N01/N02 后实施；停用调度器仍可人工选择登记只读探针。无成本收益时保留可解释性，删除“更省调用”主张。

### DATA-P0-01：独立标签、来源与强基线

**实施范围**：分开治理开发合成集、受控机制实验、独立人工测试和实际业务观测。人工Golden沿用既有来源/标注协议，记录来源、许可、PII、血缘、证据hash、双标与裁决；按故障族/来源/时间切分，派生问法不当作新增独立事故。

**原型评测**：可先做24—40个受控病例，独立控制器提供业务真值；同时冻结 `oracle_health` 和 `proof_sufficient`，不复用被测契约求值代码作oracle。至少比较完整Inspector+StateVerifier、增加恢复契约的版本、同预算固定顺序；单独消融目标/时效/版本/窗口/调度。

**验收**：先冻结指标、分母、参数与阈值，再看候选结果。报告错误放行、正确签发覆盖、UNKNOWN、人工负担、成本、p50/p95及适用置信区间；按故障族解释统计单位。两路径三组最小例仅验证窗口，不据此宣称调度优于同样6次调用的专家SOP。

**依赖/阻塞**：受控原型不等人工Golden完备；正式效果结论须有独立人工审核与真实baseline。AI可协助整理，人工批准和独立审核不由生成模型冒签。缺条件时 formal 指标为 null。

### VERSION-P0-01：版本、环境与租户检索契约

**实施范围**：建立共享 VersionPolicy，先实现 `exact / latest-resolved / unknown`，有真实适配需求时再加 `compatible`。版本对象分开记录产品、发行版、组件版本和适用区间；不能用一个“22.04”推断所有组件兼容。

召回前按服务端确认的 tenant/workspace/ACL 过滤；两路使用同一约束，并在证据引用保存解析结果。`latest` 必须解析为明确适用版本并记账；目标版本未知时，请求补证或标 `INSUFFICIENT`。允许返回泛化背景材料时，显式标注其用途，避免进入版本敏感执行依据。

**验收**：旧/新/缺失版本、无适用版本、latest解析失败、两个用户/团队、删除撤权场景；过滤理由可追溯。不在top-k后才做唯一权限过滤；兼容区间必须有明确规则，不能让LLM临时猜测。

**依赖/回滚**：与身份/scope owner共同冻结字段；机制测试可用隔离数据先做。保留旧索引与版本化适配器，出现泄漏即停止新路径。

### RAG-P1-01：真实语义后端、检索对照与持久化分轨

**实施范围**：复核已有BGE、工厂和缓存，输出 `backend_requested / backend_actual / model_revision / dimension / fallback_reason`。不同模型/维度/分词或chunk版本分别建索引与缓存命名空间，禁止混用。hash回退对日志和界面可见。

同一冻结语料/split/top-k比较 BM25、hash、BGE、Hybrid、rerank、版本策略；BM25中文切词/倒排优化另作单变量实验。报告 source与chunk双口径 Recall@1/3/5、MRR、nDCG、版本误召回、引用支撑、p50/p95与内存。现有114条自动生成评测只能作回归线索。

**持久化**：先文档/chunk/embedding/scope/ACL/manifest适配与重启恢复，再根据规模与同工作负载收益评估FAISS或Qdrant；FAISS索引本身不提供完整租户/生命周期管理。不将“千级够用”当性能结论。

**验收/回滚**：真实加载指定模型、离线加载与回退各有记录；重启、删除、模型更换、撤权、跨租户矩阵通过。Qdrant映射既有P2条件PoC，达到预注册收益和资源门槛后才切默认，旧路径保留。

### PLAN-RUN-P1-01：多步计划、权威运行状态与持久审批

**实施范围**：先取证实际产品入口，复用既有Java运行域作为整合目标；Python若参与，作为受限worker，不拥有第二审批源。强类型Plan/Step至少包含工具、参数、依赖、风险、前/后置条件、超时、验证步骤和plan_digest。

先用确定性Runbook完成“只读诊断→变更候选→审批→执行→独立核验”；再让LLM仅生成允许工具范围内的候选计划。策略服务决定实际风险与授权，不相信模型自报低风险。失败或UNKNOWN生成补证/re-plan事件，设置总预算及停止条件；未经新授权不自动重做变更。

审批grant绑定主体、scope、目标、计划/参数快照、有效期、一次性消费与幂等键；持久状态、事件与审计沿既有ARCH任务收敛。审批后的计划修改需生成新digest及授权。

**验收**：未知工具、环依赖、目标含糊、参数被改、拒批、过期、重复请求、进程重启、执行失败、验证失败。外部动作结果不明时进入结果待核验，避免盲目重试；不以数据库幂等键宣称任意外部动作“恰好一次”。

**回滚**：旧规则Planner可切回，暂停新变更执行；已发生外部动作另按Runbook处理，代码回滚不等于撤销动作。

### TRUST-L3-P1-01：证据支持与可选语义辅助

**实施范围**：拆开检索相关度、逐结论支持、证据独立覆盖、业务恢复核验；当前trust_score保持版本化启发式分，不解释成正确概率。先标注结论与证据的 `support / contradiction / unknown`，去重同源片段，检查多条重复证据能否虚增覆盖。

L3可选引入受限judge，仅提供语义建议。模型超时/错误/不确定显式展示，不覆盖有效业务反例、不改审批、不签发恢复回执。默认passthrough和启用配置分别评测。

**验收**：空命中、检索有结果但不支撑、相互矛盾、同源重复、成功声明含否定/部分恢复等难例；报告风险—覆盖与人工负担。只有定义概率事件、独立标签和校准方法后才计算Brier/ECE，否则记 `NOT_APPLICABLE`。

**依赖/回滚**：协议可先写，效果依赖独立数据。旧分数保留版本字段，L3一键停用，不降低L1/L2/L4约束。

### E2E-OBS-P0-01：真实主链路、失败矩阵与可观察性

**实施范围**：核查普通聊天、SSE、Agent指令等真实入口，标明每条实际经过的服务，避免为验证架构图而强行串联无关组件。复用现有run对照与事件，补 request/task/run、parent、attempt、schema版本、provider/model、degraded、fixture/real、错误原因。

**验收**：真实隔离账号登录→问答→RAG→引用→刷新连续3次；provider与检索后端有运行证据。模型不可达、空流、首token后中断、Knowledge503、审批拒绝、执行失败、502假成功、重启恢复分别有trace/日志/界面断言。每段明确 REAL / CONTROLLED / MOCK，不把其中一段真实外推为全链路真实。

**边界**：degraded作为属性与动作终态分开；有trace不等于业务恢复。只采白名单元数据，不记录凭据或完整私有原文。优先Playwright与现有日志，OTel/Collector映射P2条件PoC，可关闭可退出。

**依赖/回滚**：先记录现状，再验证补丁。缺账号/模型/隔离库时保留阻塞，继续完成不依赖它的协议/fixture验证，不降低鉴权或改日常数据库。

### REPLAY-P1-01：同证据的策略差分回放

**实施范围**：冻结契约、声明、观测、来源、策略/配置版本、显式判定时钟、预算及事件顺序。离线运行旧/新策略，逐义务解释差异，不联网、不调用模型、不改用回放当天墙钟。

**验收**：同包重复100次确定性输出摘要一致；摘要校验依赖外部受信expected digest；篡改拒绝。新增策略选择未录制探针时返回 `REPLAY_INCOMPLETE`，不补造结果。删除证据/增加反例的变形测试另建带parent与新digest的派生包，历史原包保持不变。

**边界/依赖**：N01/N04后实现；回放解释证据下的决策差异，不预测未执行修复的因果效果，不称“数字孪生”。停用回放不影响在线审批。

### GH-P0-01：相近工作、机制选型与采用证据

**实施范围**：核查第6节候选的官方仓库、固定commit/tag、README及许可原文、具体参考章节、子包差异、采用状态和退出路径。既有快照不自动等于完整commit锁定；根代码许可证不代替数据集或托管服务条款。

相近工作覆盖 evidence-based diagnosis、active test selection、runtime verification、temporal contracts、provenance、deterministic replay。输出“已有思想/本项目领域约束/实际新增实现/待验证收益”的比较矩阵；结论允许是工程组合贡献。

**验收**：每个开源引用可追溯；未核验写 `UNVERIFIED`，仅候选写 `CANDIDATE_ONLY`，借鉴机制写 `REFERENCE_ONLY`，实际采用需版本/路径/运行证据。访问失败记 `NOT_RUN`，不虚构当天联网调研。

**边界**：不以stars或框架自报分数选型；数据候选先核数据条款，不自动下载大数据或执行仓库脚本。研究与本地机制规范可并行，对外原创主张等待研究结论。

### DEMO-P1-01：两类演示与答辩证据

**机制原型**：复用N07缺口卡、契约卡、回放卡。用自持有测试服务展示HTTP200但业务false→CONTRADICTED；过期/错目标记录→INSUFFICIENT；测试控制器显式改变环境并开启新round后，满足采样窗才VERIFIED；随后版本变化/到期失效。动作若未执行，明确 `NOT_PERFORMED`；控制器注入标 `TEST_CONTROLLER`。

**真实平台40秒演示（完成接入后）**：0—8秒输入/版本依据；8—18秒展示变更候选及人工审批；18—28秒真实受控动作与原始结果；28—35秒业务核验反例；35—40秒运行ID与审计。仅在真实路径已验收时展示审批/执行；原型不得借用未来能力。40秒并非伪造采样窗的理由，必要时将完整核验另作标明时间的录屏。

**验收**：一个运行证据索引串起界面、请求、审批快照、动作结果、观测与核验；允许“动作成功、恢复未证实”并列。准备60秒备用录屏和静态证据页，注明实时/预录/fixture。稿件删除重复堆数字，将参数放附录；保留一个失败案例及其修复证据。

**依赖/回滚**：机制演示消费N02—N05及独立受控oracle；真实演示另等平台身份/审批/执行/E2E。未就绪时使用明确标识的机制演示，不宣称真实自动修复。

## 7. 推荐分派顺序

1. **第一批并行**：FCT-P0-01冻结事实；SCORE-P0-01修计分协议；DATA-P0-01建立独立协议；GH-P0-01做来源研究。数据模型可整理标签协议，人工审核由实际人员完成。
2. **第一批取证后**：N01 owner统筹VER-P0-01；平台模型记录E2E真实路由与Run现状；Knowledge模型设计VERSION-P0-01。共享scope/状态字段由owner统一。
3. **规范冻结后**：求值器、受控oracle和Vue组件可并行；之后按N02→N03→N04推进，再做N05回放和机制演示。此分支不依赖生产账号或正式Golden完备。
4. **平台分支**：完成PLAN-RUN-P1-01及身份/持久化前置，再接真实E2E与审批执行演示。禁止把loopback原型直接写成平台已接通。
5. **质量分支**：独立人工数据就绪后做RAG/TRUST/REAL baseline和单变量消融；持久索引、Qdrant和OTel按条件PoC进入，不阻塞基本证据语义修正。

建议三类实施负责人：A负责契约与核验，B负责平台/规划/检索接入，C负责数据/计分/E2E；独立审阅可用第四角色或错开审阅。B的共享文件改动顺序执行，不让一个模型同时修改多个任务的同一store、schema或迁移。

## 9. 完成与交付标准

每个任务交付四件：改后文件、对照差分、验证记录、哈希保护回滚脚本。设计任务交付相同四件文档产物，不为凑交付改业务代码。回滚先在副本演练，只针对本任务文件；数据库/外部动作另有恢复边界。

验收至少有一组成功正例和对应失败反例；状态机任务还须覆盖未知/中断/重复/过期。保存实际命令、退出码、工具版本、输入hash、逐样本/逐事件输出。不复用历史通过数量冒充本轮结果，不将测试注解数量当成通过数。

对外新能力只有实现和验证均完成后才写“已实现”。创新收益须经过强基线和独立评测；没有收益时保留失败结果，调整主张。当前建议主张为：**为运维结论建立可计算的证据义务、受预算约束的补证和可失效的恢复核验记录，并验证其边界。**
