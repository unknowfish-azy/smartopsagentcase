## 0. 一句话结论

**不要重写，要做「补齐 + 对标 + 接线」**：本项目八层能力**均有实现**（多数在 L3 自主任务型，局部到 L4/L5），
真正缺的不是"有没有"，而是**四件工程化的东西**——
① 长期记忆的**分页置换与时效失效**（现为进程内 dict）；② 长流程的**检查点恢复**（现无 checkpoint）；
③ **反事实/因果**评测闭环（现仅骨架）；④ **统一的 OTel 埋点 + 自建 trace 平台**（现有 Prometheus/Grafana 偏系统指标）。

开源侧的正确用法是：**协议层接 MCP/A2A，能力层抄组件设计，评测层接 harness，模型层继续用小尺寸国产开源**。

## 2. 开源对标地图（查证 2026-11；许可证一律以官方仓库 LICENSE 为准）

### 2.1 协议与标准层 —— 必接，别当底座

| 项目 | 归属 | 对我们的意义 |
|---|---|---|
| **MCP**（modelcontextprotocol） | Anthropic 发起，规范仓活跃（最新 revision 2026-07-28） | 我们**已实现自有 MCP server/client/stdio transport**。建议：对齐规范的 capability 协商与 streamable HTTP，避免私有扩展成为技术债 |
| **A2A**（a2aproject/A2A） | Google 发起，已交 Linux Foundation 治理，v1.0 | 若做多节点/跨框架委派，用 Agent Card 发现 + 任务委托；我们当前多 Agent 在单进程内，可先借鉴 `RemoteA2aAgent` 桥接思路 |
| **Agent Skills**（anthropics/skills） | Anthropic 开放标准 | **性价比最高**：把我们的 ASR/OCR/情绪 SOP 做成 SKILL.md + 脚本的技能包，比硬编码 prompt 易治理、可热更 |

> 注：调研中出现的「MCP 规范 Apache-2.0 / 捐给 Linux Foundation」与本次核验的 MIT/工作组治理**不一致**，一律以官方仓库为准。

### 2.2 厂商官方 SDK —— 读设计，不整体引入

- **OpenAI Agents SDK**（MIT，活跃）：四原语 Agent / Handoff / Guardrails / Session + 内置 tracing。**护栏 tripwire 语义**与「可恢复 run state」值得对照我们的 `guard/*` 与 executor 事件持久化。
- **Google ADK**（Apache-2.0，多语言，活跃）：图式 Workflow Runtime + Task API + Session/Memory Bank + 内置 eval + Tool Confirmation（HITL）。**state prefix 作用域（app/user/session）**可直接映射我们的多租户状态隔离。
- **AWS Strands Agents**（Apache-2.0，2026-11 仍在高频更新）：`@tool` 装饰器、原生 MCP Client、OTel 追踪、多 Agent 模式、`load_tools_from_directory` 热重载——**工具注册表的工程样板**。
- **Microsoft Agent Framework**（MIT，2026-04 GA）：检查点 + 人工审批 + 暂停恢复 + 内容安全 + Entra ID。**治理层对标**，但绑定 Azure 生态。
- **Pydantic AI**（MIT）：Harness 把 memory / guardrails / sub-agents / planning / persistence 做成可插拔 capability，Evals 是 pytest 式。**能力目录最贴我们需求**。

### 2.3 记忆与编排 —— 按需抄组件

- **Letta（原 MemGPT）**：Core/Recall/Archival 三层 + **memory-pressure 换页中断** + 记忆块版本化 + sleeptime 后台整理。→ 正对我们「三级记忆」缺口，是最值得精读的工程范本。
- **Zep / Graphiti**：双时态（valid-time / transaction-time）知识图谱，**矛盾事实自动失效而非删除**。→ 运维状态漂移场景（同一指标前后矛盾）可直接借设计。
- **mem0**：ADD-only 抽取 + 图实体链接 + 多信号融合检索。轻量，可作长期记忆的写入管道参考。
- **LangGraph**：super-step checkpointer + pending writes + `interrupt()`/`Command(resume=)` + time-travel。→ **长流程恢复的事实标准**，也契合我们因果/反事实评测对「可追溯轨迹」的要求。
- **CrewAI**：认知记忆（相似度×时效×重要度复合评分、scope 树隔离）+ Flow `@persist()`。角色粒度较粗，**只抄记忆 scoring**。
- **MetaGPT**：共享消息池 blackboard + SOP 阶段令牌 + **下游对上游产出的隐式评审退回**。→ 最接近我们四角色辩论的结构性升级方向。

### 2.4 评测与安全 —— 直接接

- **inspect_ai**（UK AISI，MIT）：私有化评测主框架，可跑 AgentHarm 等用例集。
- **terminal-bench / Harbor**：容器化 CLI Agent 任务 + **终态程序化验证**（非 LLM-judge）+ 每任务成本统计。→ 运维命令行场景的天然验收器。
- **τ-bench**：多轮工具-用户-策略一致性，适合工单类评测。
- **garak**（NVIDIA）/ **PyRIT**（微软）：模型层红队与多轮攻击编排；**AI-Infra-Guard**（腾讯朱雀）扫 MCP Server/越狱风险——与我们 MCP 面高度相关。
- **AgentHarm / ASB**：有害行为与注入/记忆投毒的系统用例。

### 2.5 国产模型与感知件 —— 本地约束下选型

**硬约束**：本机无独显、云主机 1.7GB 内存且无 GPU → 大 MoE/VLM 一律不进该机器。

- 模型：延续 **Qwen 小尺寸**（已在用 qwen3:1.7b/qwen2.5 系）+ 关注 **DeepSeek R1 蒸馏小模型**、**智谱 GLM 小尺寸**；**Qwen-Agent**（Apache-2.0）作 function calling/MCP/RAG 的参考实现。
- 感知：**FunASR**（SenseVoice-Small / Paraformer，CPU 低内存）+ **RapidOCR / PaddleOCR** + **emotion2vec+ seed**。VLM（Qwen-VL 4B 约需 3.5GB）放独立推理节点。
- 已在用的 RapidOCR / torch / qwen 路线不变；新增件须过「1.7GB 峰值内存实测」。

## 3. 集成设计：三条升级主线 + 一个底座

### 主线 A：记忆从「有接口」升级到「可分页、有时效」
- **借**：Letta 的 Core/Recall/Archival + memory-pressure 中断；Graphiti 的双时态边失效。
- **接在哪**：`agent/memory/*` 与 `app/services/memory.py` 之间加一层 **MemoryPressure 控制器**；长期记忆事实带 `valid_from/valid_to` 与来源 id。
- **验收判据**：上下文达阈值时自动摘要+归档并续跑；矛盾事实不覆盖、只失效；记忆命中可回溯到来源条目。
- **禁止**：把进程内 dict 说成「长期记忆已实现」。

### 主线 B：长流程可恢复（Plan-and-Execute 2.0）
- **借**：LangGraph 的 super-step checkpoint + pending writes + interrupt/resume。
- **接在哪**：`agent/executor/event_persistence.py` 已有事件持久化 → 在其上加 **run snapshot（步骤级）与 resume token**；`agent/orchestrator` 增加「失败→回退到最近检查点重规划」分支。
- **验收判据**：任意步骤失败后从最近成功检查点续跑，**不重放**已完成副作用；人为中断可恢复。
- **禁止**：把「记录了日志」当成「可恢复」。

### 主线 C：因果/反事实闭环（承接 P2-7/C 骨架）
- **借**：Terminal-Bench 的终态验证思路（程序化判据，不靠 LLM 自评）。
- **接在哪**：C1/C2 生成器 + `eval_counterfactual` + Holm/bootstrap（已就位）；把 A@1 增益做成**消融表**而非单点数字。
- **验收判据**：`flip_rate` 与误伤率成对报告；有效 n（ICC/DEFF）缺失时结论不可解释。
- **禁止**：沿用已登记的循环口径（见 fact-sheet 口径⑲）。

### 底座：GenAI 可观测 + 成本硬闸
- **借**：OTel GenAI 语义约定（`gen_ai.operation.name`/`usage.*`）+ OpenLLMetry 埋点；Langfuse（MIT，可自建）或 Arize Phoenix 做 trace 平台。
- **接在哪**：现有 `app/core/metrics.py`（系统指标）旁并列 **agent 语义 span**；前端 `ExecutionTraceView.vue` 接 trace 详情。
- **验收判据**：一次运行可追溯「输入→工具调用→token/延迟→决策→产物」；预算超限**硬停**而非仅告警。
- **禁止**：私有 trace 格式绑死单一商业平台。

## 5. 选型建议（拿来即用 vs 仅参考）

**优先精读/试点（5 个）**
1. **Letta** —— 三级记忆分页与置换、sleeptime 后台整理（对 P1）
2. **LangGraph** —— checkpointer / interrupt / time-travel（对 P2、P3）
3. **Zep/Graphiti** —— 双时态事实失效（对 P1）
4. **Pydantic AI** —— capability 组合与 durable execution 选型目录（对底座）
5. **terminal-bench / Harbor** —— 终态验证式评测（对 P3/P5）

**只读形态、不押注代码**
- MetaGPT（blackboard+SOP 退回）→ 改造我们的辩论协议；
- AG2/AutoGen 经典 GroupChat → **维护模式**，仅学 round_robin + judge 形态；
- CrewAI → 只抄记忆 scoring 与 scope 隔离；
- Flowise → **已 EOL**，排除；Swarm → 已被 Agents SDK 取代；transformers-agent → 已移除。

**许可证红线（务必复核原文）**
- Claude Agent SDK 的 TS/CLI 为商业条款（≠自由使用）；AgentCore/MAF 部分能力为托管闭源；
- Dify/n8n 为非 OSI 许可（多租户受限）；MiniMax、Kimi 部分权重有商用门槛；
- 结论：**本项目的默认技术栈保持 MIT/Apache-2.0 依赖**，任何新件入栈前先读 LICENSE。

## 6. 本项目特有的治理红线（方案的一部分）

以下不是"建议"，是已登记的纪律，任何升级不得违反：

1. **数字口径**：数字只能来自 `docs/competition/fact-sheet.md`（带 n 与状态）；`NOT_RUN`/`null` 不得写成达标。
2. **覆盖对照**：凡"多角色/多步骤提升"实验必须设覆盖对照，否则会把"信息更全"误当"机制更好"。
3. **循环披露**：合成数据由生成器给定结构时，必须写明"结论只说明模型在该生成器下的相对优劣"。
4. **诚实交底**：未证明增益就写"未证明"，不写"无差异"；低分/失败如实登记。
5. **范围收敛**：不做因果发现（PC/GES/NOTEARS）、不替换默认模型（除非消融显著）、不引入纯装饰动效。
6. **协作边界**：本智能体默认只出方案/计划；编码构建测试交其他模型，除非用户显式点名落地。

## 7. 主要风险与反模式

| 风险 | 说明 | 对策 |
|---|---|---|
| 盲目换底座 | 引入大框架重写既有八层 | 只在既有模块**之间**加层（记忆压力层、检查点层、埋点层） |
| 记忆越存越脏 | 无时效/无失效 → 旧结论污染 | 双时态 + provenance + 冲突只失效不覆盖 |
| 评测自嗨 | 金标与候选同源 | 沿用循环披露 + 覆盖对照 + 独立抽样核对 |
| 小模型陷阱 | qwen3 思考模式吃光输出预算（实测 104/104 空响应） | 客户端强制 `think=False`；延迟不可承诺时不写性能指标 |
| 硬件错配 | VLM/大 MoE 塞进 1.7GB 机器 | 感知件过内存实测；大模型放独立推理节点 |
| 许可踩坑 | 把商业条款件当开源 | 入栈前读 LICENSE；默认 MIT/Apache-2.0 |
