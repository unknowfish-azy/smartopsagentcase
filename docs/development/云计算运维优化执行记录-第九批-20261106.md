依据：[云计算运维专业化不足与优化清单-20261105.md](./云计算运维专业化不足与优化清单-20261105.md)（OPS-16）

## 1. 结论

三个组件（Karmada / KubeEdge / ChaosBlade）本批**均不引入**，只完成评估与"可退出"验证机制：

- 清单要求"需求成立时评估"。当前没有已记录的业务触发条件：跨集群故障迁移、边缘节点纳管、可重复故障注入都还没有真实需求单；
- 单集群内的恢复目标已由 OPS-13 备份演练与 OPS-10 SLO 证据覆盖；
- 因此本批把"引入前必须说清楚什么、演练必须证明什么"固化为可执行约束，而不是先装一套控制面再补文档。

引入门槛由代码固化：`canAdopt` 只有在"至少一次 `VERIFIED` 隔离演练 + 卸载已留证"时才为 `true`，任何一项缺失都保持 `false`。

## 2. 评估矩阵

> 下表的开销与兼容性均为**评估口径与待验证项**，不是本机实测结果。接入前必须在隔离环境逐项验证并回填。

| 组件 | 解决什么问题 | 业务触发条件（需同时成立） | 额外控制面 | 权限 | 内核/集群兼容 | 开销 | 卸载步骤 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Karmada | 多集群分发、策略、故障迁移 | 同一业务跨 ≥2 个真实集群；人工切换超过 30 分钟且无法由单集群 RTO 满足；第二集群有独立容量与网络 | `karmada-controller-manager`、`karmada-scheduler`、`karmada-webhook`、独立 etcd，需自身高可用 | 成员集群 `cluster-admin`；跨集群网络与证书分发；镜像仓库拉取 | 成员集群 K8s 版本差 ≤1 minor；CRD、CNI、CSI 与准入 webhook 不冲突 | 至少 3 个控制面节点与 etcd 存储；跨集群带宽随成员数增长 | 先摘除 `PropagationPolicy`/成员集群 → 删除 CRD → 命名空间 → RBAC，确认无残留 finalizer |
| KubeEdge | 云边协同、边缘节点与设备接入 | 存在弱网/离线边缘节点；中心集群无法直连；需要设备模型管理 | `cloudcore`（需高可用）、每节点 `edgecore`，按需 `EdgeMesh`/MQTT | 边缘节点 root/systemd；云端证书签发；开放 10002/10350 等端口 | 边缘内核版本、容器运行时（containerd/docker）、边缘 OS 均在支持矩阵内 | 每节点 `edgecore` 常驻内存；云边带宽；设备模型维护成本 | 停止 `edgecore` → 清理 systemd 与 iptables → 删除 `cloudcore` 与 CRD → 摘除节点 |
| ChaosBlade | 可重复的故障注入与恢复演练 | 需要重复演练且 OPS-13 恢复演练不足以覆盖；有隔离命名空间或隔离集群与演练窗口 | `chaosblade-operator` + CRD，可按命名空间部署，不需要独立 etcd | 目标命名空间 DaemonSet 权限；部分实验需要宿主机特权 | 内核版本限制可注入类型；CRI 类型与 Windows/边缘节点支持不全 | 注入期间目标节点资源抖动；需单独的 CPU/内存与时间预算 | 删除实验 CR → operator → CRD → 命名空间，确认 DaemonSet 与特权容器已清理 |

## 3. 可退出验证机制

### 3.1 数据模型（[V20261106.17__platform_experiments.sql](file:///d:/SmartOpsAgent/backend/src/main/resources/db/migration/V20261106.17__platform_experiments.sql)）

- `platform_experiment_evaluation`：`(user_id, component)` 唯一；必填必要性、业务触发条件、额外控制面、权限、兼容性、开销、卸载步骤；`exit_verified_at / exit_evidence` 记录卸载留证；
- `platform_experiment_drill`：每次隔离演练一条，保存 `stop_conditions`、`stop_triggered`、`stop_evidence`、`recovery_evidence`、`backup_drill_id`、`result`、`gaps_json`。

### 3.2 接口（[ExperimentController.java](file:///d:/SmartOpsAgent/backend/src/main/java/com/smartops/experiment/ExperimentController.java)）

| 接口 | 约束 |
| --- | --- |
| `POST /api/experiments/evaluations` | 组件仅 `KARMADA/KUBEEDGE/CHAOSBLADE`；八项说明逐项必填；同组件重复登记返回 `EXPERIMENT_EVALUATION_EXISTS` |
| `GET /api/experiments/evaluations` | 返回 `drillCount / verifiedDrillCount / exitVerifiedAt / canAdopt` |
| `POST /api/experiments/evaluations/{id}/drills` | 只接受 `ISOLATED`；必须先声明非空停止条件；`finishedAt > startedAt` |
| `POST /api/experiments/evaluations/{id}/exit` | 卸载证据必填，写入后 `exit_verified_at` 才有值 |

### 3.3 演练结果判定

| 情形 | 结果 | 缺口 |
| --- | --- | --- |
| 停止条件非空 + 恢复证据完备（或引用已验证备份演练） | `VERIFIED` | 空 |
| 停止触发但没留停止证据 | `FAILED` | `STOP_EVIDENCE_MISSING` |
| 缺恢复证据；或引用的备份演练未验证/不属于本用户 | `UNVERIFIED` | `RECOVERY_EVIDENCE_MISSING`、`BACKUP_DRILL_NOT_VERIFIED` |

恢复证据可以直接引用 OPS-13 的备份演练（`backup_drill_id`）：只有同用户且 `result=VERIFIED` 的备份演练才算数，不另建一套恢复验证。

## 5. 已知限制

1. **没有真实集群与边缘节点**：所有演练记录都是集成测试夹具；本机没有 Karmada/KubeEdge/ChaosBlade 环境，未做任何真实安装、故障注入或卸载。
2. **评估字段为人工填写**：服务端只保证"必须写清楚"，不校验内容是否正确；兼容性与开销需接入前的隔离验证回填。
3. **不自动下发任何变更**：本批只有登记与取证接口，没有安装/卸载动作，也不与 Run/审批体系耦合。
4. **SLO 证据未自动抓取**：`recovery_evidence` 可引用 OPS-10 的 SLO 窗口，但目前由填写者提供引用字符串，系统不自动查询。
5. **`canAdopt` 只是必要条件**：通过门槛也不等于批准引入，仍需业务方按触发条件决策。

## 6. 回滚方式

- `git revert <sha>` 回退代码；迁移只新增两张表，回滚代码后遗留表不影响运行。
- 回滚后 `/api/experiments` 接口消失，已登记的评估与演练记录保留在库中作为审计材料。
- 本批未安装任何组件，因此不存在集群侧卸载动作需要回滚。
