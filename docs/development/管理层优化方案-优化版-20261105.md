## 2. 对原计划的四处优化

| 优化 | 原计划 | 调整后 | 理由 |
|---|---|---|---|
| ① 基线不作为独立交付 | 单列 ADM-00 产出 `admin-baseline.md` | 并入第一批开工前的**半小时核对**，只记录与本批相关的页面/接口/权限事实 | P0 缺陷修复不需要先写一份大文档；文档易变成二次失真来源 |
| ② 安全缺陷前置 | ADM-03/04 与前端任务同批并列 | ADM-03/04 **先于**全部 UI 工作 | “异常回退 root”“admin 入口即 root”是提权风险，优先级高于任何交互打磨 |
| ③ 砍掉无来源的聚合 | ADM-15 首页待办/风险聚合列 P1 | **降为 P2**，仅在有真实后端来源后再做 | 与计划自身“不接受无来源统计”的第一原则冲突，先做必然后悔 |
| ④ 外部调研收缩 | 8 个候选仓库逐个出适配记录 | 只保留 **LiteLLM（额度语义）** 与 **vue-vben-admin（表格/抽屉交互规格）** 两个一次性核验；其余不立项 | P0 修复不依赖外部调研；8 份适配记录是纯文档成本 |

同时保留原计划的正确约束：唯一权威在 Java 侧（Run/审批/审计/网关），管理端只消费服务端结果；管理员入口不授予私人数据读取权；已发布 migration 只做向后兼容的增量。

## 3. 优化后的批次与任务卡

### 第一批（P0，安全与可用性）

| 任务 | 内容 | 主要文件 | 验收（可执行） |
|---|---|---|---|
| P0-1 权限收敛 | 撤销后不得重新扩权：区分“历史未建档 / 已建档有效 / 明确撤销”；`platformLevel` 查询异常返回明确错误而非 ROOT；移除 `TeamResourceAuthorizer` 的 admin 兜底 root | `UserAccountService.java`、`TeamResourceAuthorizer.java`、增量 migration、对应测试 | 撤销→改密→重登后能力矩阵不回升；缺表/查询故障返回 5xx 明示错误；admin 入口不再绕过团队权限；`PlatformAdminGovernanceTest`、`TeamResourceAuthorizerTest` 通过 |
| P0-2 组额度早退修复 | key 额度未配置时仍需检查组额度；null/-1/0 语义写死在契约与测试里 | `ModelGatewayService.java:91-108`、`ModelGatewayServiceTest` | 新增用例“key 不限 + 组有限”“组 0”“临界并发”，现有 key 额度用例不回归 |
| P0-3 审计目录与结果 | 补齐平台任命/撤销/转移、团队邀请链接事件；outcome 固定三值，依据进 `decision_basis` | `SecurityAuditService.java`、`TeamAgentRunService.java:166-168`、DTO/前端动作映射 | 带依据审批写入后 `outcome=SUCCESS` 且依据可在详情查到；按新事件可精确筛选；历史记录展示兼容 |
| P0-4 七页首次加载 | 统一挂载加载 + 失败重试；子资源按选中对象加载，避免重复请求 | `views/admin/system/*.vue`、`useAdminResource.js` | 七个页面首次进入各发一次预期 GET；覆盖空数据/500/切页卸载；无重复请求 |
| P0-5 密码复核组件 | 扩展 `AdminDialog` 取代 6 处 `window.prompt`；busy、掩码、秘密清零 | `components/admin/AdminDialog.vue`、6 个系统页、拟增 `AdminConfirmAction.vue` | 全站管理写操作无文本 prompt；取消/失败/成功/卸载后秘密字段为空；重复点击只发一次请求 |

P0-4 与 P0-5 同文件，**串行合入**（先 4 后 5）；P0-1/2/3 与前端两任务可并行。

### 第二批（P1，闭环）

`ADM-07 交互底座 → ADM-08 账户/会话上下文 → ADM-09 审计工作台 → ADM-13 接入检查 → ADM-14 组织与数据范围`。入口条件：第一批 P0 全部通过；ADM-08 的能力选择必须消费 P0-1 定下的能力目录。

### 第三批（P2，按场景）

`ADM-10 审批监督`、`ADM-11 模型治理视图`、`ADM-12 知识质量`、`ADM-15 工作台聚合`、`ADM-16B 多实例`。每项须先有真实契约（Run 权威、组织策略、评测版本、聚合查询），否则不挂空壳入口。

### 持续

`ADM-17` 随批验收：真实浏览器旅程（隔离 fixture）、直接 API 拒绝矩阵、真实 MySQL 关键 migration、浅深主题与 200% 缩放；模拟测试与真实端到端分开记录。

## 4. 明确不做（本轮）

- 不引入 Casbin/Keycloak/OpenTelemetry Collector 等新依赖；需要时先出 ADR。
- 不重建第二套 Run 状态机、审计账或模型计费账；全部对接既有权威。
- 不做批量操作、审计导出、配置写入/回退——契约未冻结前不开口子。
- 不改写已发布 migration 的校验和，只追加向后兼容脚本。
- 不给首页堆统计卡片；无来源即“暂无数据”。

## 5. 验收与回滚约定

- 每个任务一个独立补丁，附：改动文件、可直接执行的测试命令、真实/模拟证据区分、回滚步骤。
- 权限类回滚**不得**恢复“宽泛 admin 兜底”；只能关闭入口或前滚修复。
- 审计与授权只追加历史，回滚不删记录。
- 前端验证顺序：`npm run build` → 对应 `frontend/test/admin-*` → 浏览器旅程；后端：对应 `mvn -Dtest=... test`，H2 结果不包装成 MySQL 通过。
