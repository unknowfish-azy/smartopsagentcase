修改前：测试依赖 pytest 默认系统临时目录，在当前 Windows 权限环境中部分用例创建目录失败。

## 七、下一步优化建议

### P0：Approved Dataset

1. 导入可追踪的 `REAL` Agent Trace/日志，或明确标记的 `SYNTHETIC` 候选数据。
2. 执行 `CANDIDATE → VALIDATED → QUALITY_CHECKED → SAFE → REVIEW_PENDING → APPROVED` 状态流。
3. 只有人工审核为 `APPROVED` 的样本进入正式 Dataset。
4. 重新生成 Manifest、Grouped Split、Leakage Report 和数据哈希。

### P0：真实 Baseline

1. 手动配置真实 Ollama 或 OpenAI-compatible Provider。
2. 固定模型、Prompt Version、Knowledge Version、Retriever、Reranker、Tool Policy 和 Evaluator。
3. 使用 approved test split 运行 Baseline，保存输出、配置、延迟、Token 成本和指标分母。
4. Mock 只能用于开发测试，不得作为 REAL Benchmark 结论。

### P1：算法消融与数据闭环

```text
Prompt Baseline
→ Vector / BM25 / Hybrid
→ Reranker / Version / Evidence
→ Inspector Ablation
→ Verification Ablation
```

同时打通：`Agent Trace → Inspector → Verification → Training Candidate → Human Review → Approved Dataset`。自动收集只能生成 Candidate，不能自动批准。

### P2：SFT 与 Preference 门禁

只有 `Approved Dataset > 0`、Leakage/Safety/Split/Model/训练依赖全部 READY 后，才允许 SFT；SFT 完成并评测通过后才允许 Preference Optimization。没有 GPU 时只做 Dataset Validation、Baseline、Evaluation 和 CPU Dry Run。

### P2：环境收口

1. 处理根目录 `.pytest_cache` 权限 warning。
2. 启动 Backend、AI Service、Knowledge Service 后重跑 24 个 skipped。
3. 安装缺失的 `mysql.connector` 和 `redis` 后重跑集成测试。
4. 保留真实 PASS、FAILED、SKIPPED、NOT RUN 分类。
