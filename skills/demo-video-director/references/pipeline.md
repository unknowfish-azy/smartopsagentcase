# 案例拆解：46 镜 / 13 章 / 8 分钟技术展示片

这是 `demo-video-director` 的来源案例，可作为写分镜和排标注的参照。

## 成片规格

| 项 | 值 |
| --- | --- |
| 分辨率 / 帧率 | 1920x1080 / 30fps |
| 时长 | 约 8 分 15 秒（46 镜） |
| 视频编码 | H.264 high@4.1，CRF 18，yuv420p，faststart |
| 音频 | 克隆声线，合成 1.2 倍 + 成片 1.5 倍语速，AAC 192k，loudnorm -16 LUFS |
| 结构 | 开场 2 镜 + 11 个能力章 + 工程边界 2 镜 + 结尾 1 镜 |
| 画面 | 真实页面录制 + 7 张章节卡 + 红框/箭头/鼠标/点击环 + 底部大字幕 |

每章第一镜通常是章节卡，后面接 2–4 个真实页面。章节卡负责“告诉观众接下来看什么”，页面负责“拿证据”。

## 分镜写法

一个合格的分镜同时回答四件事：

1. 画面是什么：`route` 或 `visual`。
2. 观众听什么：`text`，45–85 字。
3. TTS 怎么读：`spoken`，英文缩写拆字母，如 `B M 二十五`、`A P I`、`D A G`、`V R M`。
4. 观众看哪里：`overlay` 卖点 + `events`/`actions` 标注。

示例：

```json
{
  "id": "S02C",
  "chapter": "02 证据驱动问答",
  "target": 12,
  "route": "/chat",
  "visual": "展开参考来源，再进入知识空间，红框指向来源和版本",
  "text": "系统融合 BM25 与向量召回，关键词精确命中，向量覆盖语义相近，再按版本过滤重排。回答附带来源，可回到原文核对版本。",
  "spoken": "系统融合 B M 二十五与向量召回，关键词精确命中，向量覆盖语义相近，再按版本过滤重排。回答附带来源，可回到原文核对版本。",
  "overlay": "BM25 + 向量｜版本信息｜Citation｜可追溯"
}
```

## 标注排布经验

- 一镜最多 2 个标注。先标“结论”，再标“依据”，不要标操作过程。
- 红框只框一个控件/一块结果；原案例第一版框太大，后来统一收窄到目标四周 8–16px。
- 箭头最多 1 根；起点标签、终点目标，不跨正文。占位箭头必须删掉，不能留英文调试词。
- 鼠标轨迹只服务点击，不要为了“有动效”绕路。点击环只给真实点击。
- 字幕自动避让：合成器会在 1016/916/816/716 四档里选与框、箭头、鼠标重叠面积最小的一档。
- 字幕每行最多 30 字；英文词、版本号、文件名不能断行。原案例出现过 `Spring Boo / t` 这类断行，必须在 `wrap_subtitle()` 的 `cut_allowed()` 里禁止。

## 剪辑节奏

- 页面之间硬切。第一版每镜压黑 0.2s，46 镜后节奏被切碎，后来改为只给卡片淡入淡出。
- 每镜开头留 0.2–0.4s 静止，让观众看清页面，再出标注。
- 旁白结束后留 0.3–0.5s 尾音，不要一句话卡在切点上。
- 8 分钟目标不要靠拉长画面凑，先按 1.2 倍合成，再用 1.5 倍成片节奏压缩；旁白内容不够就补“原理/边界/证据”，不要重复 UI 文案。

## 配音与响度

- 克隆参考音频 10–20 秒，逐字文本必须和音频完全一致，否则音色漂移。
- 合成参数：`speed=1.2`，长静音压缩到 320ms；成片 `atempo=1.5`。
- `atempo` 超过 1.6 会明显电音；需要更快时拆句，不要硬拉。
- 每段配音做一次 ASR 回检：字数、缺句、吞字；同音字差异不用重录，缺句必须重录。
- 成片只做一次 `loudnorm=I=-16:TP=-1.5:LRA=11`；分段音频各做一次轻量 afade，避免爆音。

## 诚实边界

技术展示片最容易翻车的是“把演示说成真实”。原案例固定保留这些标识，并在结尾单独用一章讲边界：

- `DEMO`：演示数据/演示事件。
- `REHEARSAL`：演练，只改界面反馈，不写运行时。
- `模拟帧`：机器人视频流未接真机。
- `未接引擎`：实景还原只完成素材接入和流程编排。
- 小样本不写成“普遍准确率”，高风险操作不绕过审批。

这些标识不是减分项，而是可信度的一部分；删掉才会在答辩时被追问。
